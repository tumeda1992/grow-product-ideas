# target-user-voices: 旧い振替の資料から、経験の不足と候補の着想を分けた返り

## 依頼と粒度

| 依頼した層と決めるもの | 何のため | 求めた粒度 | この材料で満たしたか |
| --- | --- | --- | --- |
| 検査callerの候補の成立 | 「親が実際にどう管理・共有しているか」という旧依頼の根拠を照合する | 経験として使える所と、勧め・機能と不足を区別する | 既存資料の記載の意味を照合した。親の経験は未取得 |

## 中身

原資料は[旧い振替のtarget-user-voices](../product-plans/20261103-track-kids-makeup-lessons/archive/2nd/materials/target-user-voices/README.md)。歴史として保存された資料を読む検査であり、旧案件の採否を変更しない。
旧資料自身が、親の個人の声の本文は読めておらず、解説・教室の規則・アプリの説明で補ったと記す。その範囲で、親が実際に続けている経過を確認したとは言えない。

| 旧資料の記述 | 返す使い道と不足 |
| --- | --- |
| 共有calendarやホワイトボードを解説が勧める | 候補の着想として残せる。誰がいつ取り込み、引き受け、変更や不在でも続いたかは未確認 |
| 教室の案内が規則と期限を述べる | 原資料で確認する規則の手がかり。親の認識・しのぎ方の経験には替えない |
| アプリの説明に月謝やタスクの管理がある | 候補の機能を調べる手がかり。振替を親が実際にその道具で管理したとは言えない |
| 親は道具の延長で扱っていると読む | その経験の原資料が足りない。候補の仮説としては残せるが、実際の継続の事実としては渡せない |

依頼側へは、候補を広げる着想を返しつつ、その成立条件を既存の本人の行い・公式の性質・費用で確かめる問いを返す。他者にも成り立つと主張するなら、実際の経験と条件の根拠が別に必要になる。

## 確かめた方法と限界

旧資料の依頼・本文・自ら記した取得の限界を読んだ。リンク先の解説2件は今回のCloudの許可範囲に無く、本文を取得できなかった。原記事の中にも経験の引用があるかは未確認であり、解説というラベルだけで経験が一切無いとは結論しない。
この探索で親の声を得られなかったことと、親の声が世の中に無いことを分ける。元の資料の記載の範囲の監査であり、旧要約の全事実を再確認した結果ではない。
