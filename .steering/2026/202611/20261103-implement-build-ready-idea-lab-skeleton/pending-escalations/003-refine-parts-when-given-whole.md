# 保留メモ: 全体を構成する最低限の要素を析出する

## 保留時の内容

### 提案

宛先は思考の作法の`think-through`とし、次の項を足す。この節の文面は初稿であり、このsteeringの営みが終わるまでに、起きた具体例で磨き、escalateの時に使える形にする。

#### 初稿

全体（層、仕組み、問いのまとまり等）を扱う時の目的は、全体を構成する最低限の要素を析出することである。クリティカルシンキングを込めて、最強のロジックツリーを作ることと言ってもよい。最初は思いつきの要素で進めてよい。その代わり、要素の一つ一つを厳しく選別し続け、生き残ったものだけを要素とする。

選別の問い:

- それ無しで、全体は構成できるか。できるなら、要素ではない
- 他の要素が、それを機能させられるか。上位互換なら、完全に置き換える。部分的なら、その部分を他に任せ、自分からは抜く
- それ無しでも全体は構成できるが、より良くこなすものがあるなら、最初の要素に固辞せず、それに挿げ替える
- 残った要素だけで、全体は構成できるか。全体の目的と、後ろ（それを使う側）がそれで何をするかに照らして確かめる

選別は一度で終えない。要素の一つが磨かれて変わったら、残りの要素を所与とせず、同じ選別をやり直す。

選別は、名前付けとセットで行う。要素の名前は、名前だけで中身が引けるものにする。中身に広く知られた呼び名があれば、それに寄せる。比喩や文の切れ端を名前にすると、何がその要素に入り、何が入らないかが名前から引けず、選別の是非（それ無しで構成できるか、他が機能させられるか）を判断できない。

要素を上位互換で置き換える時、概念の移行と、名前の移行は分けて判断する。名前の移行は、細部まで見た時の厳密な正しさだけでなく、初見の人がその名前を見て、名が体を表すと思えるかでも判断する。厳密には正しくても、初見の人が中身を思い描けない名前（例: 情報の流れの選択肢。中身は解き方の選択肢であり、情報の流れは書き方である）は、選び直す。

選別で残った要素から、誤ると何が崩れるか（効く範囲）、今の仕組みで誤りやすいか、誤った時に後ろで拾われるかを見て、クリティカルなものを選び、実際の件の中で、意味、使われ方、崩れる所、境目まで磨く。磨いた結果で、また選別する。

- やってしまいがちな行動（このsteeringで起きたもの）:
  - 全体を与えられると、全体の骨組み（決めること、受け取るもの、渡すもの、観点の一覧）を整え、個々の要素は欄を埋める程度で通す。「詰めたか」と問われると、要素の中を深めずに、別の観点や欠けを足して、装いを変えた一覧を出し直す
  - 要素を、既にある部品（今ある問いの並び）や、試しの件で下した判断から作る
  - 磨く要素を、試しの件（例）の一部分から選び、後から理由を付ける
  - 見直しを、今あるものをどう整理するかにする。全て忘れて、初めて見る賢い人が整理され尽くしていると思えるものを、ゼロから考え直していない
  - 一つの見方（確かめる人の一点等）だけで要素を並べる
  - 行うこと（分解、当て方、確かめる作業）を要素に数える
  - 要素に、比喩（経路、網）や文の切れ端（選んだ理由）で名前を付ける。名前だけでは中身が分からず、選別の是非を判断できない
  - 既に磨いた要素の働きで済むことを、別の要素に立てる
  - 一つの要素が大きく変わったのに、残りの要素を再考せず、所与のまま進む。最初に挙げた要素に固辞する
  - 整理し尽くした結果、要素が抽象化されすぎて肉感が無く、要素をつなげても現実の問題解決に使えない。`documentation_standards/content_density.md`の、具体と抽象の往復が無い状態（お題目）である。抽象は方針と移植性を、具体は肉感と検知を渡す。最低限の要素を選り分ける選別は、抽象へ寄せるほど要素が減って整って見えるため、この形へ最も落ちやすい
  - その形へ至る経路として、最大公約数的な抽象（どの件にも当てはまる共通部分だけを残し、件ごとに判断を変える具体を落とす）と、意味抜き（形式・構造・欄だけを決め、中身の意味を詰めない）がある
- それをやると何が起きるか: 要素の中身が動かないまま言葉が増えるか、要らない要素が残って重なり合う。全体は、中身の無い要素や重複した要素の並びになり、後続に丸投げされる。全体を見ている風で、全体にも触れられていない
- 正しい判断のための問い:
  - 「この要素無しで、全体は構成できるか。他の要素がこれを機能させられないか」
  - 「一つの要素が変わった時、残りの要素を同じ選別にかけ直したか」
  - 「要素の名前だけを見て、何が入り何が入らないかが分かるか」
  - 「初見の人がこの名前を見て、名が体を表すと思えるか。厳密な正しさだけで名前を選んでいないか」
  - 「今出しているものは、一つの要素の中身を動かしたか。それとも要素の並べ方や言い方を変えただけか」
  - 「どの要素を選んだか、なぜそれが全体を最も左右するかを言えるか。例の一部分から選んでいないか」
  - 「この要素を実際の件に当てると、判断や手が一つでも変わるか。変わらないなら、抽象化されすぎて肉感を失っていないか。当たる件と当たらない件の両方を示せるか」

### 具体例

利用先repositoryで、アイデアを詰めるレールの一つの層（何を作るか層）を、層→問い→skillの順に立て直していた。

- assistantは、層が決める三つと閉じ条件を先に置いた。利用者は、形式だけを決めるやり方が前回の失敗の原因だと指摘した。
- assistantは、層の四つの問い（A〜D）について、なぜ要るか、どうあるべきか、どう連携するかを一度に書いた。
- 利用者がAの中の要素（観点、整理の形、成果物、Bへの渡し方、この段階で研ぎ澄ます深さ）を個々に詰めよと言うと、assistantは観点の一覧を出した。
- 利用者が「詰めきれたと言える？」と問うと、assistantは欠けを六つ挙げ、観点を足し、一般通説との対応表を足し、他のアイデアでの当て方を足した。どれも一覧の装いを変えただけで、一つの要素の中身は動いていなかった。
- 要素を一つ選んで磨けと言われると、assistantは、試しの件（振替）の答えの一部（状態S2）を磨く対象に選び、後から理由を付けて正当性を問うた。利用者は、対象はレールの構成要素であり、架空の例の一部分を演繹的に選ぶのは筋違いだと指摘し、これも全体の中の個の話として大事だとした（論点22「提案6へのフィードバック（論点22）」）。この追記はassistantが書いた。
- 構成要素を出して選ぶ順を利用者が良しとした後、利用者は、その元になった四つの問い（A〜D）自体も恣意的に決められていると指摘し、何を作るかが整理され切った時に要る構成要素は今のA〜Dかを問うた。A〜Dは、今の層fileの問いと試しの件の判断から作ったものであり、整理され切った時の中身から出したものではなかった。中身から出し直すと、選んだ理由と選び直す条件が欠けていること、外に置く状態の扱いの置き場所が違うことが分かった（論点22「提案7へのフィードバック（論点22）」と提案8）。この追記はassistantが書いた。
- 構成要素を出し直したものを厳しくゼロベースで見直せと言われると、assistantは、出したもの（中身1〜5）を一つずつ判定し、分け・言い直し・足して整理し直した。利用者は、見直しとは今あるものをどう整理するかではなく、全て忘れて、初めて見る賢い人がその層ではこれを考えていれば整理され尽くしていると思えるものを、ゼロから考え直すことだと指摘した（論点22「提案9へのフィードバック（論点22）」）。この追記はassistantが書いた。
- ゼロから考え直せと言われると、assistantは、利用者の言葉（初めて見る賢い人が整理され尽くしていると思えるか）を、品質の物差しではなく問いを生み出す唯一の見方として使い、確かめる人の一点から、答えられるかの七つを並べた。利用者は、それに答えられても価値のあるものができるのか、一点だけで考えた大喜利だと指摘した（論点22「提案10へのフィードバック（論点22）」）。この追記はassistantが書いた。
- 要素を一つ良しとした後、次の要素（満たし続ける仕組み）の構成要素を出すと、assistantは崩れ方を構成要素に立て、その出し方（崩れる季節を作る）を磨いた。利用者は、それは確かめ方のところでやることではないかと問うた。崩れる季節は、既に磨いた要素（条件の確かめ方）を、崩れやすい時点で問うことにすぎず、新しい物差しを持っていなかった。層の核で、ブレイクダウンと研ぎ澄ましを要素に並べた誤りと同じく、行うことを要素に数えていた（`implementation_review/implementation_review-26-30.md` 論点26「提案0へのフィードバック（論点26）」と提案1）。この追記はassistantが書いた。
- 手段の層の最初の要素（条件ごとの手段）を、事実の経路（発生源から終点への置き場所と移し）として磨き直した後、assistantは、残りの要素（きっかけと担い手、気づきと戻し方、作るもの、選んだ理由、依るもの・守るもの）を所与として、次はきっかけを磨くと進めようとした。利用者は、最初の要素がガラッと変わったのに残りを再考なく所与のまま進むのかと指摘し、このメモの目的を、全体を構成する最低限の要素の析出に改めた（`implementation_review/implementation_review-26-30.md` 論点28「提案1へのフィードバック（論点28）」）。選別し直すと、きっかけ・気づき・依るものは経路の網に入り、作るものは網から切り出せる渡し方になり、受け入れと守るものは他に任せられ、選んだ理由は重み付けと決定と選び直す条件だけが残った。要素は六つから二つになった（提案2）。この追記はassistantが書いた。
- 選別し直した二つの要素に、assistantは「事実の経路の網」「選んだ理由」と名付けた。利用者は、名前が散文的・詩的で、名前だけでは何を意味するか直感的に分からないと指摘した（`implementation_review/implementation_review-26-30.md` 論点28「提案2へのフィードバック（論点28）」）。中身に広く知られた呼び名（情報の流れ、選定）に寄せて「対案ごとの情報の流れ」「対案の選定」と直すと、利用者は、要素の選別はラベリングとセットであり、名前を磨かなければ選別の是非を判断できなかったとした（提案3へのフィードバック）。この追記はassistantが書いた。
