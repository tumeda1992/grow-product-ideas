# design-core-logic

材料`core-logic`を作る。受け取るもの、粒度、再利用は`what-defines-a-product/README.md`の「材料」節に、置き方と入口の形は`product-plans/README.md`に従う。

心臓部のロジックとは、そのプロダクトが痛みを解くために、データを受け取って結果を出す中核の処理である。画面の表示や保存の出し入れではない。

## 対象によらず問う四つ

どのアイデアでも、次の四つを書く。

1. 入力と出力: 何を受け取り、何を返すか。具体的な値の例を添える。
2. 例外と境界: 入力が空、重複、範囲外、途中で失敗した時に何が起きるか。
3. 一番難しい部分: このロジックの中で、実現が一番難しい、または間違えやすい部分はどこか。
4. 回避案と正面から解く案: 一番難しい部分を、仕様や運用で避ける案と、正面から解く案。

## 作る手順

1. 正本の「要求」「解き方」「体験」の節（書かれている分だけ）を読む。受け入れ時の入力の「既にある着想」に心臓部の思いつきがあれば、それを案の一つにする。
2. 四つを書く。
3. 一番難しい部分について、回避案と正面から解く案を少なくとも一つずつ作り、案ごとに、何が楽になり、何が残るかを書く。
4. 一番難しい部分が実現できるかが動かさないと分からない時は、その旨を書き、`verify-technical-feasibility`での確認が要ることを`settle-question`へ返す。

## 落とし穴

ロジックを、テーブルやモジュールを決めた後に考えると、まとめて考えた方がよかったロジックが複数の場所に散る。この材料は、テーブルとモジュールの問いより前に作られる。
