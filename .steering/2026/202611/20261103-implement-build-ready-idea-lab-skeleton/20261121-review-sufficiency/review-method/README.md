# 大きなテーマの重要な不足を一回の依頼で返せるか

**9.1.0には重要な不足を発見し、誤指摘を退ける働きがある。通常の一依頼でその働きを引き出すには、反例にする場面の選び方と、監督者が返す結論の範囲を詰める必要がある。** 旧レビューは版8.2.5と利用者の明示指示で10件を有効とし、後の9.1.0再レビューがその10件を直しても成立する2件を見つけた。両回は入力も異なる。前者を9.1.0の失敗、後者を改訂だけの成果と数えることはいずれもできない。[対象版](evidence/source-versions.json)・[当時の判断と検証の範囲](coverage.md)

| 優先 | 独立した指摘 | 必要な変化 |
| --- | --- | --- |
| P1 | [MR-001　確認例が利用者の結果を見分けられるか](findings/MR-001-test-the-result.md) | 受け手が選び分けたいことを依頼・契約から取り出し、現行と既出の修正が実際に合格へ使う情報へ照らす。両方が合格のまま選択・仕事の結果が変われば、同じ依頼で探索へ戻る。 |
| P2 | [MR-002　監督から利用者へ返す結論の範囲](findings/MR-002-preserve-the-scope-of-the-conclusion.md) | 最終返答で最も広い主張を停止根拠と照らす。重要な使い方を含める根拠が足りなければ、その使い方を確認してから答える。 |

教室の週次案内では、既出の重複修正が同じように成功しても、夏時間の切替週に参加者へ誤った時刻が届いた。親も正解を渡される前に別の地域・日付でこの差を再現した。レビュー手続の判断に使える対照は実行できた。一般化したプラグイン改訂の採否・適用、通常呼出しによる改訂後の有効性判定は別に残る。[手続を当てて比べた結果](evidence/decision-comparisons.md)・[修正前の依頼](../request.md)
