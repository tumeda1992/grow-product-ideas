# 大きな企画を任せられるという判断の根拠と限界

## 問いをどう判別したか

依頼の「大きい」を文字数で定義しなかった。原文の離れた望みが同時には満たせず、誰の体験・どの時点の成果を選ぶかで実装の境界が変わり、作る物の外にも既に別の仕事がある場合を選んだ。初演の驚きと自分で観劇へ戻る自由、同時に相手を感じることと離席後にも形を継げることは、単に画面を増やすほど一緒に良くなる関係ではない。最初の着想を捨てる理由まで比べられ、選んだ一版の操作・記録・外の結果が繋がり、初めて読む実装者が採否を発明し直さずに済むかを問うた。[今回の依頼](../request.md)・[劇場で分かれる判断](evidence/theatre.md)・[海辺の模型で分かれる判断](evidence/tide.md)

弱い版の例は、送信数が増えたため観客が復帰できたと書く案、相手のいない同期動作を「触れ合えた」と扱う案、字幕だけ正常で従来の上演を壊す案である。良い版には、自作の個人端末を使わなくても紙で観客が自分の時機に戻れるもの、長期の価値を選ばず二つの体験を公平に選び比べられる週末の版、同じ進行表を使いながら既存の指示番号を保存するものを置いた。これらを見分けるのに、毎回全員に聞く、全製品に同じ表を持つ、必ずどちらかの案を選ぶ、といった義務は要らない。

## 探索と、見つけた指摘に対する反証

| 問い直した点 | 現物へ戻した判断、集合の変更 |

| 最初の発想を豊かにできるか | 「個人端末で字幕を出す」から、オチを観客と共有する、一人で自分のタイミングを選ぶ、演者が即興を変えられる、別劇団が翻訳の工夫を継ぐ、へ戻した。同じ先読みが価値を高める人と失わせる人を仮定し、範囲の縮小で何を失うかを見た。why 73–106、142–177、183–205、243–273行を使うと、元の希望も新しく見つけた価値も選定に戻せる。着想をそのまま仕様にする欠陥は確定しない |

| 紙・既存・自作がすべて候補に載るだけで十分か | 袖が台詞17を消す、役者が19へ飛ぶ、客席と袖が復帰する流れを紙・会場投影・私用端末へ通すと、誰にいつ何が届かず、どの人の視線や作業が増えるかが異なった。how-to-solve 94–106、249–263、293–301行は、同じ原状との差、部分版の一巡と損失、手間が増えても本人が選ぶ新体験を扱う。選んだ目的の最低線を満たす安い案一つで終える必要はない。一方、複数の局所最良でも同じ人にだけ価値が届く例と、初版で後の選択肢を消す例には、それぞれIR-001とLR-005を使った |

| 正しい版を渡した先から逆に辿ると何が壊れるか | 新版の全操作が同じ二つの構成で、旧音響ノートの18だけが違う指示に届いた。前方から選んだ字幕フローの各接続を厚くしても、そのフローが使わない既存のノートは出てこない。初期移行（新しい仕事へ取り込む旧データ）、第三者の引受け、既存repoの同定（旧IR-002）の各々と対照した。同じ物理的なファイルを使う理由だけで不具合を一つにまとめず、[SR-001](findings/SR-001-existing-consumers.md)を追加した |

| 正しい保留が、作れる版を止めていないか | 会場Bの許諾だけが未知なら、Aで許された素材・当番で採用可能な案まで止めない。実機確認が必要な案は、現行の技術検証の「対象・条件・失敗点を分ける」で調べ、紙で同じ価値まで試せるなら比較に残す。装置が壊れているのに同時触覚を観測できたことにはしない。撤回・新事実・保留の各出口にはLR-008・011、非開発を選んだ時の初日にはLR-007を対応させた |
| 修正案にない力を足していないか | 旧12提案を個票ごとの能力に限定した。資料原文を配れない場合の証拠はLR-009、稼働を頼む人の権限はLR-001、初日8千円を払える人が必要な問題はLR-006、移した後の現在の採否はLR-010である。新しい字幕が依存する対象にならない音響ノートをこれらへ足さなかった。木曜の開演、旧ノート、配れる資料、保持できる地形を同時に変えても、場所・時期・主体のどれが変わるかに応じて上の判断を辿れる。[12件すべての修正仮定と対照](evidence/proposed-changes.md) |

## 停止判断

今回の設計上の否定は一つの反例で決まる。12件を記載どおり直しても、字幕と元の上演を両立する構成を選ばずに設計を渡せる。追加のSR-001を直せば、進行表を変更する候補から独立した既存の利用例へ辿る。その結果は既存の選定へ戻り、同じ番号の保存、対応表を用いた移行、字幕表示順の分離を、運用負担・費用とともに本人が比較できる。今度は新旧双方の一件で設計を受け入れられる。旧ノートの存在を最初から字幕要件へ書くことに頼らない。

その13件を仮定し、初演での一回と二会場全体、匿名の同期と将来の持越し、紙の初日とソフトの移行、新しい仕事の受け手と古い仕事の受け手から通し直した。それぞれで、異なる目標を選ぶ時の得失、外せない約束と受け入れる未達、案の全体比較、具体の操作・状態・復旧、持出しに必要な根拠が、現行の判断か個別の改善へつながった。残った色・機器名・画面数や、初回構築の作業順は、選んだ価値・成立が変わる時だけ既存の戻り先へ返せばよい。したがって今回の規模・性質で重要と判別できた**設計上の不足**はこの集合で覆うと判断した。件数や「直前に増えなかった」ことは判断理由に使っていない。

## 確認できた範囲と、なお必要な実証

- 現物は固定版のroot READMEとAGENTS、四層・共通規約・案件の配置と雛形、growの受入れ・再開・採否・差し戻し・出口、八つの専門の責任と受け渡し、旧LR・IRの個票・索引・coverage・提案・関連証拠。旧16件は適用済みの現行テキストと、過去の試運転の到達点を区別した。[過去のカード・夕食・替芯の記録](../../integration-check/README.md)・[学校の設計と実行の限界](../../how-to-build-trial/README.md)
- 新しい二依頼では各層・専門間の静的な手順追跡を実施。実行したのは、架空の表と日程についてのPython照合、成果物のリンク・固定対象の検査である。この作業で通常の `grow-product-idea` を新案件として起動し、独立した利用者応答を得て四層を閉じた実績はない。過去のカード案件で四層の設計に到達したことは、今回の入力や未適用の改善の性能を示さない。[照合コード](evidence/check_examples.py)・[実行結果](evidence/check-results.json)
- 残る実証は「通常の依頼から別の実行者が、着想を広げ、魅力と代償が異なる選択肢を本人に返し、選択後に新旧の業務が両立する設計を渡せるか」である。修正後、上演の依頼だけを渡し、資料から音響ノートを発見できる条件にする。別の実行者には指摘名・正解・選択済みの案を渡さない。初演期限・誰が何を許可したか、選んだ体験は応答として与え、出力を受ける人が字幕17→消去→19と鐘18の業務を別々に辿れるかを見る。海辺では手による交換案と装置案の価値差を本人が選べ、仮説のまま残った反応を実績へ替えていないかを確かめる。実装担当が再発明する意味や、形式だけ整った保留が出れば診断を戻す。ここで与えた追跡・対照・テストデータまでは現物から用意できたが、採用・修正・通常入口での修正後の実行はこの依頼の対象外である。
- 実行元は指定された9.1.0のプラグイン配布sourceで両manifestを照合した。Astra担当が `exhaustive-review` と指摘テンプレート、`review-findings` と `think-through` の場面別規範を用い、発行時に `document-review` の根拠、読み手が辿れる操作、仮定と確認結果、機密性を再読した。元作業に有効な暫定指示のディレクトリはない。本文が正しいかと、通常の呼出しでその考え方を実行者に引き出せるかは別の問いで、後者は[レビュー方法側の検討](../review-method/README.md)が扱う。
