## 論点1: CR-009 — 採用前の閉じ提案と採用後の正本をどう参照し、検査するか

**ステータス:** 決定

**種別:** レビュー指摘

### イテレーション0（論点1）: 提案を先に保存し、受け入れ後に正本へ切り替える

#### 提案0（論点1）

採用前は決定過程の具体的な閉じ提案を参照し、受け入れ後に正本へ切り替える。
先に存在する提案を保存してから検査する順序まで揃える。

```text
決め方の経過 → 閉じ提案を保存 → 層から提案へ参照 → 案件全体の検査 → 利用者へ提示

受け入れ応答を保存 → 採用版を正本へ反映 → 層の参照・状態・正本の表示を同期 → 全体再検査 → 次の層
```

## 論点2: CR-008 — 層を未閉じのまま正式保留し、出口と新入力から再開先を選ぶにはどうするか

**ステータス:** 決定

**種別:** レビュー指摘

### イテレーション0（論点2）: 案件の出口と層の合否を別々に扱う

#### 提案0（論点2）

**正式保留は「案件の出口」、層を閉じることは「その層の内容の受け入れ」として分ける。**
未閉じの層からも正式保留を選べるようにし、再開では最初に出口と今回の依頼を読む。

| 場面 | 進め方 |
| --- | --- |
| 自力で調べられる不足 | 専門への依頼を続ける |
| 利用者の事実・採否の応答待ち | 未完の論点を待つ。出口は変更しない |
| 今は得られない不足で止まる | 不足と再開する判断を示して正式保留を提案する。層は未閉じのまま |
| 保留中、新入力なし・条件未達 | 保留を維持して必要な入力を返す。同じ問答を再探索しない |
| 保留中、新入力あり | 停止判断へ差を返し、進められる未完判断から続ける。全層をやり直さない |
| 作らない・build-ready後の照会 | 完了結果を返す。選び直しの明示があった場合だけ、影響する判断へ返す |

保留の記録には、どの層のどの判断で止まったか、不足と、何が変わればどの判断を再開するかを残す。
保留を記録するために層を仮合格にしたり、単なる離席を正式保留にしたりしない。

進行をgrow-product-idea、状態の意味を共通README、出力に残す情報をcanonical雛形で揃える。
