# CR-008の進行確認

2026年11月21日。論点2・提案0の適用後の文書を用いた机上追跡。
新規の自律agentセッションや外部の事実取得を実行した試運転ではない。
参照checkerの実行とは区別する。

## 読み戻した入口と出口

- [grow-product-idea](../../../../../../.agents/skills/grow-product-idea/SKILL.md): step1で状態・出口・依頼を読む。step2は続行可能な案件だけを扱う。step3から未閉じでstep5へ保留を提案できる。
- [層共通README](../../../../../../what-defines-a-product/README.md#層の状態): 案件の保留と層の合否を分け、層に新しい保留状態を足さない。
- [正本の雛形](../../../../../../.agents/skills/grow-product-idea/templates/canonical.md#出口): 不足、停止判断への案件内の参照と、何が変わればどこを再開するかを残す。

## 八つの入力を追った結果

| 入力と保存済みの状態 | 実際の手順を辿った次の行い | 保持するもの・進めない所 |
| --- | --- | --- |
| 検討中。whyの認識合わせで本人の体験を質問し、まだ返答がない | step1の検討中から保存済みの質問へ戻る。step3の通常の応答待ちで止まる | 出口を保留へ変更せず、質問や本人の返答を捏造しない |
| whyで目標の選択を変える事実が現在取得できず、版も未選定。作る指定はrequire-build | step3からstep5へ正式保留を提案する。未選定のための選定やhowを始めない。利用者が採用した後に案件を保留とする | whyは未閉じ、作る指定は保持、正本に採用アウトカムや選定版を先置きしない |
| 指定C3と同じく、howの比較中に商品と実店舗の対応が未提供で確かめられない | step3から層を未閉じのまま保留提案へ進める。出口に比較を止めた判断と不足を示す | 取得できないという現在の不足をAPI不存在・購入不可能へ替えず、候補と採否の未完を保持する |
| 正式保留中のC3へ「続けて」のみ。商品・店舗対応は依然未提供 | step1の保留で新入力と条件を照合し、保留の理由と必要な入力を返す | 同じ比較を最初からやり直さず、how-to-buildへ進まない |
| 正式保留中に包装の記載が追加され、利用者が再開を求める。実店舗対応はなお不明 | step1で商品情報の差を停止したhow又は材料へ返し、進められる未完判断を判じる。続行可能な所があれば、その根拠と位置から再開する | 店舗情報を取得済みにせず、why・whatを一律に開け直さない。候補ごとの不足の分解方法はCR-015の未採否に残る |
| openで非開発を選び、状態は作らない。how-to-buildは未着手。「今どうなっている？」と照会する | step1で作らない理由と完了結果を返して終える | 最初の未閉じ層を探して設計を始めない |
| 全層を受け入れbuild-readyになった案件の状況照会 | step1で採用済みの版と完了結果を返す | 製品の実装・導入を自動実行せず、閉じた層を開け直さない |
| 非開発で閉じた案件に「運用担当を確保できたので、自作案と改めて比べたい」と依頼する | step1から選定を持つhow-to-solveへ差を返し、step6で影響を確かめる。再判断する所から検討中へ戻す | 前の非開発の理由は決定過程へ保持し、現在の状態・出口表示を揃える。新しい価値が依頼されていなければwhyを自動的に再設計しない |

版未選定のwhyから保留へ進む例で、従来のstep5冒頭の選定済み版の適格性照合が前提になっていた。
既に選定した版がある時だけ照合し、未選定ならその不足と開発方針を保って保留を確認するよう同じstep5を補正した。
それ以外は承認された3ファイルのdiffと一致する。
