# CR-003の目標選択に必要な予備比較の確認

2026年11月21日。適用後の[層の順](../../../../../../what-defines-a-product/README.md#層の順)、[whyの方法](../../../../../../what-defines-a-product/why-to-build.md)、[比較skillの入力](../../../../../../.agents/skills/propose-alternatives/SKILL.md#入力)を使った机上追跡。
例の選好・運用・値は説明用の仮定で、実在の利用者の採用や実測費用ではない。
新しい企画の全体ドライランは行っていない。

## 1. 一つの公開仕様で目標の優先が決まる

利用者が「この会場で遠隔参加を認められるなら広域、認められなければ地域内を優先」と明示し、答えが会場の公開仕様一つに依る場合を仮定する。
既存の専門への事実照会で規約と適用範囲を確かめ、その結果を本人の選択へ戻せる。
運営配置の複数案や継続費用全体を比べる必要はなく、予備比較の全手順を増やさない。
取得していない規約の内容を作ったり、専門が目標を採用したりはしない。

## 2. 分担と継続負担を比べないと目標を選べない

利用者が遠隔で参加できる価値を望み、運営者の恒常的な確認が週2時間を超えるなら地域内の継続を優先すると明示した場合を仮定する。
スタッフが確認する方法、参加者が分担する方法、地域で行う方法では、誰が確認・訂正し、誰の参加機会や負担が変わるかが違う。
仕様を一つ読むだけでは、運用全体の負担と得失を比べられない。

比較前に、遠隔・地域の目標候補、本人の条件付きの優先、維持する参加の約束、比較する人・場面・期間をwhyの記録へ残す。
専門へ渡す入力を、採用済みの正本の価値の節ではなく、次の検討中の内容として追える。

| 入力 | 今回渡す内容 |
| --- | --- |
| 覆う状態と条件 | 候補ごとの遠隔参加・地域内での継続の仮の状態。参加機会の意味を保ち、仮の条件は未採用と示す |
| 比較範囲と制約 | 同じ対象期間の行い・頻度・訂正と分担を比べる。週2時間という本人の境目と、他の人へ移る負担を分ける |
| 体験と価値 | 検討記録にある条件付きの価値候補と、元の依頼の該当箇所、何を知れば選択が変わるか |
| 求める粒度 | 目標の選択を変える範囲の行い・分担・費用と根拠・値の幅。全候補の本実装や詳細設計ではない |

propose-alternativesの入力は、この未採用という状態だけで拒まない。
一方、「何となく遠隔にしたいので安く」のように状態・対象範囲・判断の問いが曖昧な入力は、既存の不足の返しへ戻る。
仮の比較条件を許すことは、何も決まっていない依頼を専門が勝手に分解・採用する権限ではない。

返る材料の出典・仮定・値の幅から本人が目標を選ぶ。現時点で値を得たという仮定は置かず、今回、目標の採用結果を創作しない。
予備比較の解き方も採用済みにはしない。
whatで条件が正式に決まった後、howはその物差しで材料を再利用し、違う仮定・期間・必要な行いを再評価してから正式に選定する。

## 3. 見積りの幅が選択の境目を跨ぐ

仮に運営確認の見積りが週1〜3時間と返り、本人の境目が週2時間なら、下限の1時間だけを選んで遠隔目標を閉じられない。
平均2時間を根拠なく「必ず2時間以下」と読むこともできない。
どの頻度・訂正・分担の未知が幅を作り、その答えを何で確かめるかを返す。
今は得られず本人が目標を選べないなら不足を残し、CR-008の正式保留を提案できる。

CR-002で認めた未観測の効果の仮説は、この費用又は負担を満たしたことにする札ではない。
今の採否を変える条件の答えと、目標を選んだ後に実践で知る効果を分ける。

## 4. 方法の答えで目標は変わらない

遠隔で参加できる価値を優先し、今回想定する方法の負担の差ではその優先を変えないと本人が選べる場合を仮定する。
目標は通常のwhyの探索・比較で選べるため、全ての方法を予備比較し終わることを新しい閉じの条件にはしない。
費用を無視するわけではなく、how-to-solveで届ける版と未達・負担・保留を選ぶための比較へ渡す。
本人がどの差でも同じと選んだ根拠が無ければ、その優先をassistantが代作しない。

## 採用前後の受渡しと限界

仮の目標・比較条件はwhyの検討記録と決定過程にあり、採用済みだけを書く正本を先に埋めない。
専門は層名を知らず、渡された状態・根拠・比較の問いと粒度から材料だけを返す。
目標は本人がwhyで、条件はwhatで、解き方はhowで採用する責任を保つ。

四ケースで責任と順序を文書上で追えた。
サービス仕様、運営の実時間、利用者の採用、新しい企画の全工程を実測した検証ではない。
