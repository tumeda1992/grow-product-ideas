# CR-001の原文照合の確認

2026年11月21日。適用後の[whyの方法](../../../../../../what-defines-a-product/why-to-build.md)と[記録規約](../../../../../../product-plans/README.md)を使った机上照合。
以下の入力・応答は方法を確かめるための仮定であり、実在の利用者が希望・採用した証拠ではない。
1000字の新規依頼や壮大なwhyをレール全体へ通す試運転は実施していない。

## 1. 段落の末尾にある約束を見落とした案

仮の原文は次の三つの記述からなる。

> 資料を誰でも見つけられるようにしたい。
>
> 提供者に継続して寄稿してもらえる場にしたい。
>
> 提供者が掲載を撤回できることも守りたい。

検索と寄稿の価値を比較しても、三つ目を候補・前提・採否に載せなければ、原文から判断先を辿ると行き先が無い。
適用後の「原文から、探索と採否の行き先を確かめる」に従い、提供者が公開を続けるか選べることを、目標・前提に含めるかの比較へ戻す。
原文ファイルの存在を示しても、この欠けは埋まらない。

同じ案の末尾へ「撤回は後で」と一行だけ足した対照も、誰の何を守るかが採用した約束・後続への入力へ繋がらなければ不十分となる。
単に「撤回は範囲外」と分類した対照も、利用者の採否と失う価値がないため、合意した見送りとは扱えない。
閉じへ進めない理由は原文の語の不在ではなく、意味を判断へ載せていないことにある。

採用するなら、公開を続けるか選べる約束を目標又は前提に残し、whatがその意味から条件を導ける形で渡す。
撤回ボタン等の操作方式をwhyで確定することは要求しない。

## 2. 損失を理解して、目標と範囲を選び直した案

上と同じ依頼について、利用者が「まず既存の公開資料を探せるようにする。提供者から寄稿を集める目標は今回は選ばない」と選んだ場合を仮定する。
比較で、寄稿による資料の増加と提供者との関係を育てる価値を今回は得られず、投稿を受ける約束も今回の対象ではないことを示す。
この仮定の選択と理由を決定過程へ、採用する目標と含めない範囲を正本へ結ぶ。

原文の寄稿・撤回を同じ提供者の関係として辿り、何を約束しない選択なのかと、その採否が見える。
これは要求の照合上は未検討の脱落と区別できる。
架空の選択を実案件の合意に転用したり、提供者の公開投稿を受けながら撤回を黙って外す案を合格にしたりはしない。
目標全体を閉じるには、現行whyの体験・価値・範囲を選ぶ他の根拠も別途必要である。

## 3. 機能名を必須の手段へ替えない案

仮の原文「期限の三日前にスマホへ通知が欲しい」からは、通知という着想と、期限前に知ることへの望みを分ける。
なぜ三日前か、知った後に何を選びたいか、自分からは見に行けない事情を、体験理解で確かめる先へ結ぶ。
原文に機能名があるだけでスマホ通知を必須要件へ固定しない。
一方、通知を手段として扱うことで、期限前に知って選べる望みまで捨てない。
必要な価値はまだ仮説であり、質問・比較を経ずに利用者が採用した目標としない。

## 4. 単一目的の短い依頼

仮の原文「使っていないサブスクに払い続けている。無駄な支払いを減らしたい」では、症状と望みを本文の中で分け、その体験・価値を探る。
原文と検討内容の対応が本文から辿れ、独立した別の約束もないなら、この照合のためだけの専用表・file・論点は足さない。
短いことを根拠に既存whyの探索を省いたり、目標を既に選んだことにしたりはしない。

## 文書reviewと限界

入口の読み分けから旧来の「症状」を意図せず落とさないよう、その語を保持した。
それ以外は合意済み2ファイルのdiffに沿っている。
発散・対抗仮説・範囲の比較は維持し、照合で未検討が見つかった時にその仕事へ返す。

四ケースから、要求の照合でどこが不十分となり、何を判断へ戻すかを文書上で追えた。
agentが実際の長文で全ての意味を拾えることを実証したものではない。
CR-002の過去の体験がない願望、CR-003の条件付き目標の順序は未解決として残る。
