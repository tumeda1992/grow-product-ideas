# CR-013の適用と検証 — 引用の参照定義とコード境界を検査する

## 現物の問題と修正

checkerが引用・入れ子の引用の参照定義を解析し、元の行番号で欠損を返す。引用のコードfenceの終端とコンテナの終了を扱い、コード内の例を参照として誤検出しない。実CLIの12回帰テストを追加した。

## 具体例の机上追跡

引用内のmissing.md定義はexit2、missing-target、local_links1となる。存在する資料と見出しはexit0となる。
入れ子の引用と後置の定義でも検査される。引用のコード内はリンク0件で、引用の終了後にある本当の参照は検査する。
本文のfence内の引用記号や、引用fence内の余分な引用記号がコードを閉じないことも実CLIで確認した。
[回帰実測](CR-013-regression.json)では12テストが成功し、追跡済みMarkdown全体の不備は既存4件から増えなかった。未展開の雛形3件と凍結した過去の入力の見出し1件は、当該修正で生じたものではないため過去を改稿しない。

## 検証の意味と限界

本文と雛形を入口・判定・記録・後続への順に読み戻し、上の判断が手順から導けるかを照合した。
文書reviewでは初見の実行可能性、誤用の境界、旧版から削った要素、根拠と仮説、参照・現在表示を確認した。
この原因の恒久的な知識は修正本文へ収めたため、doc-enricherの独立した重複提案は行わない。
机上追跡を自律agentの実利用・外部仕様の実測とは扱わない。機械検査は隣のJSONへ記録する。
