# 学校外部反映版（不足時の停止の試運転専用）

学校の次の行いを外部calendarへ自動反映するが、成立の根拠が未確認の検査用の版。

- 状態: 検討中（APIと利用条件の選定、結果不明からの照合・再送等の根拠が不足。自動版のどう作るか層は閉じない）
- 閉じた層: 今回実演した上流層はなし。なぜ・条件・解き方は下記の固定入力として受領する

## 受け入れ時の入力

### アイデア

学校の申込み・同意について、原本から家族が対応を選び、引受け・残る行いと根拠を渡し、実際の提出まで進める版の設計を検査する。

### 作りたい動機

妻が全件を覚え、家族を動かし、最後まで追う役割を変え、望む先生・子どもとの関わりと余白を保つ。
これは既存の架空の模型から引き継いだ価値であり、今回の利用者の発言や実利用の観測ではない。

### 既にある着想

学校の用件・引受け・次の行い・実際の根拠を家族が区別して読めるようにする。
このdirectoryの上流は検査用の固定入力であり、why・what・howを今回のskillで最初から実演した記録ではない。

## 前提にする条件

| 出所 | 固定する条件と、この検査での意味 |
| --- | --- |
| 既存模型から維持 | 家族二人以外に新しく子どもの管理情報を開示しない。学校への既存の必要な提出は続ける |
| 既存模型から維持 | 管理・手続の全作業は夫週60分・妻週30分を物差しにし、通常19:30–20:00。20:00–20:30の親子の時間を使わない。不在・繁忙週も上限は同じ |
| 既存模型から維持 | 通常週は学校一件と振替一件、繁忙週は学校二件と三教室の振替各一件・担当の二日間の不在。今回の版は学校だけを支え、振替の負担は残す |
| 既存模型から維持 | 学校S1は原本の確認・同意・署名準備15分、通常は金曜の登校時の担任による原本回収が提出完了。署名・持ち出しは提出と別 |
| 検査専用の追加設定 | 日付は2026-11-16月曜受付、R1の回収2026-11-20金曜08:00。R2では学校が回収を11-19木曜08:00へ変更。時刻は全てAsia/Tokyo、実在の学校の規則ではない |
| 検査専用の追加設定 | 夫は11-17火曜と18水曜に不在で連絡できず、妻は家のPCと原本を使える。最後の作業枠は18日19:30–20:00。15分なら19:45開始まで収まる |
| 検査専用の追加設定 | 締切だけの変更なら同じ同意本文への署名は有効。本文の変更は古い署名を現行の同意とせず再確認する。何が変わったか不明なら要確認として候補を確定しない |
| 検査専用の追加設定 | 家族の紙の受け口と原本の置き場は二人とも使える。学校での回収を当日保護者が確認でき、時刻・確認した人・根拠を記録できる。実際の学校で可能かは調べていない |
| 検査専用の追加設定 | 家族の既存calendarは二人だけの共有で、人は予定の題名・メモを読めて変更できる。用件と行いの識別子を記載できる。実APIの機能・検索・再送の性質は仮定しない |
| 検査専用の追加設定 | 導入準備は夫60分までを分割して使い、維持と照合・復旧も管理の時間へ計上する。ソフトウェアの初回構築の上限は112時間、比較用の見積りは24/56/112時間、追加月額支払い0円とする。これはこの試験のhow入力であり、今回の版の費用を実測又は専門が見積もった結果ではない |

この入力を固定した後は、設計を通すために担い手・設備・上限・選定を足さない。
発見した差は層記録の差し戻しへ残し、元の入力が成立したことにしない。
起点は2026-11-03から検討した架空の学校・三教室の模型である。既存模型の今回の選定は学校限定の三週の非開発試行のまま維持する。

## なぜ作るか

### 体験と価値

妻に全件の仕分け・割当・催促・照合が残れば、夫が署名だけ代わっても望む変化には届かない。
学校の原本が届いた所から、本人たちの選択・実施可能な人の引受け・原本の提出まで繋ぎ、妻が望む関わりへ参加するために全件管理へ戻る形も避ける。
夫へ毎晩の長い照合を移すだけでも足りない。学校部分を支える版を試すが、三教室の振替と失効の痛みは残す。

### アウトカム

> 三つの教室の振替と学校の申込み・同意で、妻が全件を覚え、家族を動かし、完了まで追い続ける暮らしから離れ、家族が望みと事情を踏まえて機会を選び対応を果たし、望む関わりと余白を保てている状態が続く。

これは全体の物差しである。学校部分の設計だけで全体の達成としない。
役割と時間・望む関わりの変化は、日常・繁忙・不在の具体の一巡で見る。未観測を成功へ替えない。

### 作ることで得たいもの

暮らしの改善と作る楽しみは別の理由である。この検査では、howが作る版を選んだ入力を与える。作る楽しみが改善の必要性を証明したとはしない。

## 満たすべき条件

| 条件 | 全体での意味と、今回学校部分で確かめる行い |
| --- | --- |
| A 着手 | 原情報・変更を、妻の全件の仕分け待ちにせず、選択と行いが間に合ううちに把握する。受け口の確認と変更後の着手を辿る |
| B 選択 | 規則・予定・本人たちの望みと事情から参加・見送りと次の行いを決める。無応答を意図した見送りにしない |
| C 引受け | 実施できる本人が必要な根拠を使って引き受け、未完を進める。担当名や画面の既読だけでは満たさない |
| D 実際の完了 | 規則と期限に従った原本の回収までを辿る。署名・準備・持ち出しを提出と混同しない |
| E 現状 | 判断に必要な時、現行の対応・残り・期限・担当と完了の根拠が分かる。旧版と現行を混同しない |
| F 関わり | 先生・子どもとの望む関わりに間に合って加われ、参加のため全件管理を引き受け直さない |
| G 余白 | 受領・照合・実施・修正・復旧まで人別に計上し、上記の生活時間と両立する。学校以外も含む全体の合格はこの設計だけでは言えない |
| H 引継ぎ | 元担当へ連絡できなくても、次の本人が根拠と残りから間に合ううちに引き受けて続けられる |

根拠はこの正本の固定入力である。技術・使いやすさ・所要時間・価値の実測と、検査用の設定を分ける。

## 解き方

### 解き方の選定

検査用のhowは、次の行いを外部calendarへ自動反映し、変更・取消しと結果不明からの復旧も扱う版を選んだとする。
人による全件の予定の照合・転記を不要にする点を選定の決め手とし、日常の全件照合へ黙って差し替えることは許容しない。
ただし使うAPIは未選定である。認証・scope・料金、照合用の根拠を書き残せるか、検索・読取り・再送や重複の性質も未確認のまま開始する。
この不十分な入力は停止を調べるための検査設定であり、十分なhow選定だったとみなさない。

### 今回届ける範囲と、受け入れる未達

学校だけを三週試す部分案で、三教室の負担と失効、Gと効果の未観測は残る。
自動反映を手動へ変える場合は、転記と照合の負担を含む版の選び直しを要し、この自動版の設計が完成したとは扱わない。
外部へ新しく子どもの情報を開示する権限は与えていない。既存calendarの利用という入力だけから、追加API・scopeや新しいサービスへの開示を許可されたとしない。

設計の進行と不足は[どう作るか層](how-to-build/README.md)へ残す。
