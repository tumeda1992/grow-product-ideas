## 中身

### 必要な結果と根拠

[固定入力](../README.md)と[体験](experience-sketch.md)から、次の結果が要る。

| 結果 | 必要な入力と、推測してはいけないこと |
| --- | --- |
| 今の残り | 現行の原情報、家族の参加・見送り・要確認、対象本文への署名、学校での回収の根拠。画面で押したことだけを外の完了にしない |
| 本人が引き受けられる行い | 現行を読んだ本人の引受け、使える原本・場所、残作業と必要時間、使える枠。不明を0分や実施可能へ替えない |
| 実施候補の枠 | 開始可能時刻、期限、時間帯、必要時間、同じ人の確定済みの他の作業。両者の望みの優先を勝手に点数化しない |
| 変更時の再判断 | 原情報の何が変わったか、過去の根拠が対象にする本文、引受けと予定が対象にした原情報。旧い署名を消すだけにも、無条件に現行へ使うだけにもしない |

### 状態と規則

| 前提・入力 | 結果と残る人の行い |
| --- | --- |
| 参加・見送りがまだ決まっていない | 要選択。原本・望み・規則の不足を表示し、無応答を見送りにしない |
| 本人たちが見送りと理由を決めた | 意図した見送り。得られなかった機会の価値は実現済みにしない。必要な連絡があれば人が行う |
| 参加、現行本文への署名なし | 同意・署名準備と提出を残す。予定作成の有無では完了にしない |
| 参加、本文が同じ旧版への署名のみ | その署名の事実は使えるが、準備・持出し・回収は根拠に応じて残す。残時間は人が確かめる |
| 本文が変わった又は変更点が不明 | 旧い根拠は残し、現行への有効性は要確認。必要な再確認・署名の時間が得られるまで枠を確定しない |
| 学校での原本回収の根拠が現行本文に対応する | 学校の提出を完了と読める。誰がいつ何で確認したかを表示する |
| 原本の持出し又は署名だけの根拠 | 回収未確認。期限を過ぎても自動的に回収済みにしない |
| 現行と異なる前提で引受けた担当、不在の担当 | 残りと期限を示して再引受けが必要。元担当へ聞ける前提にしない |

受け取った締切変更だけで古い出来事を上書きしない。現行の判断と、過去に実際に起きたことは分ける。
署名の有効性の規則はこの検査専用の入力であり、一般の学校の規則として使わない。

### 枠の方式と、具体の境界

作業jの必要時間をd_j、開始可能時刻をa_j、本人の使える枠を[s,e)、行いの期限をt_jとする。
候補は開始xについて、x >= max(a_j,s)、x+d_j <= min(e,t_j)、同じ人の他の確定作業と非重複であることを満たす。
当日の原本提出は08:00に相手が回収する別の行いであり、前夜の15分へ押し込まない。
不明なd_j、使えない原本、選択や引受けの不足があれば、枠の数値だけから実施可能としない。

同じ人の確定枠を引いた空き区間を列挙し、条件を満たす区間を返す。複数候補があれば本人が選ぶ。
新しい学校二件が競合する場合、片方の候補だけから両方の成立を確定しない。並べた必要時間と選択済みの枠を全体で照合する。
価値の順位や自動的な優先を受け取っていないため、最短締切で一つへ強制する最適化は作らない。
この版は候補と成立しない理由を出せばよく、弱い別algorithmを増やす必要は無い。

| 入力 | 計算・判定 | 返す結果 |
| --- | --- | --- |
| 11/18 19:45、残り15分、空き19:30–20:00 | 19:45+15=20:00 | 時間だけは収まる。本人の引受け・原本の利用も必要 |
| 19:46、残り15分 | 20:01になる | 候補なし。親子の時間へ延ばさない |
| 19:46、残り5分を本人が確認 | 19:51になる | 空きがあれば候補。19:45を固定の規則にしない |
| 残時間不明 | 計算不可 | 要確認。0分の候補は作らない |
| S1/S2とも15分、同じ人の空きが19:45–20:00だけ | 必要30分 > 空き15分 | 両方は確定不可。別の時間・人があるか又は対応の判断へ返す |
| R1向けの確定予定の後にR2へ変更 | 引受けと予定の対象が現行と異なる | 現行を再読込みし再引受け・予定の再照合へ。R1の成功をR2の成功にしない |

### 情報・機能へ返す条件

情報へは現行の本文と期限、根拠が対象にする本文・原情報、本人の引受けと枠、calendarへ反映した対象、保存時の比較の印が要る。
原情報の版だけでは、同じ原情報の中の別の引受け・根拠記録の競合を見分けられない。
機能へは、候補の表示時だけでなく確定時にも同じ人の他の確定枠を検査する責任を返す。
別の用件の保存は用件単位の比較で拒まれないため、資源の検査を同じ保存のまとまりで行う必要がある。
実施後の根拠が古い画面から届く時は、古い入力を無言で現行へ当てず、対象を保って再照合できることを要請する。

## 確かめた方法と限界

必要な結果から入力を導き、状態の決定表と同じ枠への具体の計算で境界と反例を机上照合した。
所要時間の見積り、現実の利用者の選択、保存やAPIの実証はしていない。今後の技術の検査は、この規則そのものと区別する。
この材料は案の採否を決めず、枠の方式と規則を次の設計へ返す。

### 保存構造との照合からの追加要請

D1初稿に参加等の選択と未予約の必要時間の保持が無かったため、これらを現行原情報と根拠付きで読める条件を返した。
R1の行だけをR2の入力へ自動転用しない。現行の選択・必要分数が無ければ、以前の数値や0を推測せず要確認を返す。
