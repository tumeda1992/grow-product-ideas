# 実装後レビュー（論点111〜115）

## 論点111: 検査の操作制限で製品の目標を縮めないよう、本線の仕組みのどこを直すか

**ステータス:** 反映済み

**親論点:** 論点110

**種別:** レビュー指摘への改善検討

### イテレーション0（論点111）: 目標・範囲の未解消を先に吟味する

#### 提案0（論点111）

**C3の全体の目標を入手まで含めて置き直し、行いを選べるだけの改善は、その目標に対する部分案として評価する。** 既存whyの方法をこの原事例へ当て直し、whatと候補の判定がどう変わるかまで局所再評価する案とする。

##### 置き直す目標と、その理由

| | 目指す姿と、そこで止めると残るもの |
| --- | --- |
| 現在の目標 | 必要な品と入手見込み/未確認を区別し、来週までの一組のために次の行いを選べる。選んだ後に実施せず未購入でも、この姿だけは真になり得る |
| 推奨する全体の目標 | **C3が、根拠のない店回りや確認のやり直しを減らしながら、固定入力でいう来週までに、指定のペンに合う黒0.5mmの替芯一組を手元に用意できている。** |
| 部分案として残す改善 | 互換/在庫/情報の意味を取り違えず、寄らない・追加確認・別の入手方法を理由付きで選べる。実際の入手へ残す行いと、得られない価値・追加負担を示して選ぶ |

入手を含める理由は、元の一回が「二店35分の移動」だけでなく「必要な品を買えず帰った」体験であり、一組を必要とする時期も入力にあるため。購入しないのは今回のassistantの操作制限であって、製品の価値をそこまでにする理由ではない。

判断だけを目標にする案にも、無駄な移動を避ける独立した値打ちはあり得る。ただし、今回それを全体の目標にして入手を外す理由は、固定入力と今の比較からは支持されていない。原入力に無い「今回は手に入らなくてもよい」という優先選択は足さない。小さい改善を選ぶ余地はhow-to-solveに残す。

##### whatと選定へ、何が変わって渡るか

whyでは、適合する一組が必要時期までに手元へ揃うことと、そのための無根拠な移動/確認のやり直しが減ることを、言い分・範囲・測りへ割る。範囲は次の行いの選択で止めず、必要な確認・入手の実施・受取り/現物確認までを対象に吟味する。店頭/通販/人の手配等の手段はここで固定しない。

whatでは、旧W1〜W3を新目標に足りる条件群としてそのまま閉じない。正しい照合/選択と、実際に必要な行いが完了して適合品が手元にあることを分け、元の一回から条件を導き直す。例えば「正しい入手先を選んだが、その後何もせず期限を迎えた」という例が、新目標の達成を満たしたことにならないかを当てる。完成した条件文はこの提案で未検討のまま一括採用せず、局所再評価の実物で根拠と共に確認する。

候補は、照合→情報/未知の確認→行いの選択だけでなく、その道で誰が何を実施して何を受け取り、入手と負担をどう確かめるかまで、同じ一組・時期の一巡へ当てる。取得処理や台帳が作れるだけで、入手の改善に届いたとはしない。実施/受領へ不足する商品/店舗/情報源/納期の事実は、今あると仮定しない。

全体に届かない小さい作る版も、届ける改善・未達・負担を明らかにして比較できる。目標に入手を含めることは、あらゆる外部事情での入手保証や、全候補の完全達成を要求することではない。在庫変動等で入手できなかった時は「合理的に行動した」と「目標に届いた」を分ける。require-build・初期1時間・新規継続契約0円・買物前5分程度なら検討できるという元の条件は保つ。

##### 今回の採否と、採用後に返す結果

今回の判断対象は、**入手までを含む目標への置き直しと、その意味でwhat/候補を当て直す局所是正**を採るかである。採用後は既存のwhy・what・how-to-solveの方法を実際に使い、上記の実物と「どの判定が変わり、何が未確認で止まるか」を返す。方法の欠けを新たに発見した場合は、その具体の差を提示し、黙って共通規則を足さない。

実商品/店舗/在庫/取得条件の不足は残るので、今の根拠でbuild-readyへはしない。保留を維持することは、目標の欠けを放置したという意味にも、是正が失敗したという意味にもせず、直せた判断と外から必要な事実を区別して報告する。

##### 何が弱く、どの判断を変えるか

現行には、価値を落とさず範囲を吟味するwhyの方法と、検証の段階/届ける版を分ける原則がある。一方、依頼に混ざる「今回は購入しない/送信しない」が誰のどの作業への制限かを受け入れから保持し、外した範囲の理由へ使ってよいか照合する接続は明示されていない。
C3の出力は、選ぶ段階までの範囲に「実際の購入は今回の実行範囲外」を並べ、入手までを外す製品側の得失/選択理由を十分に示さず閉じていた。実行者の思考の因果は断定できないが、この出力と現行の接続の弱さを対象にする。

例えば、同じ原入力を次のように扱う。

| 受け取ったもの | 変更後に保持し、判定へ使う意味 |
| --- | --- |
| 来週までに適合する替芯一組を得たい事情 | 製品の目標を比較する根拠。検査で購入しないことから消さない |
| このdry-runでは購入/店舗への連絡を行わない | 今回の検査の操作制限として原文/出典の近くへ残す。禁止は守り、未取得の在庫を確認済みにしない |
| 目標案は「次の行いを選べる」まで | 「選べたがその先を行わず未入手の一回」を当て、その範囲を選ぶ理由が製品側の価値/得失にあるかを問う。操作制限だけが理由なら閉じず、価値と範囲の比較へ戻す |

**C3の目標を必ず入手までにせよ、という規則は作らない。** 判断だけの改善にも独立した値打ちはある。その範囲を選ぶ理由と損失を吟味した目標や、how-to-solveで未達を受け入れる部分案は選べる。単に「今回の作業で実施しない」を根拠に、その選択が済んだことにはしない。
