# 議論記録（論点21〜25）

## 論点21: 全体制御・層・問い・skillのエコシステムで、それぞれが何を持つか

**ステータス:** 子論点待ち

**種別:** 認識合わせ

### イテレーション0（論点21）: 前回designの見込みと、今のずれ

#### 提案0（論点21）

論点19（模型の層ごとの記録の洗い直し）、論点18の提案7（問いの残し方）、論点20（閉じた問いの答え直し）は、どれも「全体制御・層・問い・skillのそれぞれが何を持つか」が決まらないと決められない。直し方の前に、前回design（[design.md](../../../202609/20260912-design-build-ready-idea-lab-skeleton/design.md)）がそれぞれに何を見込み、今それがどうずれているかを揃えたい。

##### 前回designの見込み

| 要素 | 前回designの見込み | 記録 |
| --- | --- | --- |
| 問いのセット | このリポジトリの中核。工程ではなく問いを中核にする。問いは依存の有向グラフを成し、未回答の問いのうち下位を最も多く規定するものから答える。各問いは問い・水準・定石の三属性と、閉じるのに必然的に要る材料を持つ | 「中核は工程ではなく問いのセット」「問いが持つ三属性」「品質は材料の有無で担保する」 |
| 層 | 工程ではなく依存の方向。層の閉じ条件が、その層に置く問いを決める（「この問いに答えないと層が閉じない」だけが問いを置く理由）。答えの依存と材料の供給は逆向き | 「問いは四つの層を持つ」「広がりは層の閉じ条件で担保する」 |
| 問いの源泉 | 利用者が弱いと述べた領域（要求定義、作るべきか、スコープの伸縮、代案検討、リサーチ）と、パッチワークで負債が出た領域（体験、テーブル設計）。定石から問いが導かれることもある。初期セットは1件通せる程度でよく、1件ごとに育てる | 「初期の問いセットの出所」 |
| 全体制御 | 厚い。受け入れ、次の問いの選択、材料の有無の判定（一段目）、層skillの起動、層の閉じでのユーザー確認、出口判定 | 「skillを立てる基準と、skillの一覧」 |
| 層skill | 中。材料を取りに行く順序と、その層固有の落とし穴 | 同上 |
| 材料skill | 材料の種類ごとに、失敗が起きやすいかで厚さを決める。中身（判断基準）は問いのセット側が持てばよい | 同上 |
| 還元skill | 出口の後、問いの過不足、水準の妥当性、定石の有効性を判定してレールへ戻す | 「`what-defines-a-product/`への還元」 |

##### このsteeringで変わったこと

| 要素 | 変わったこと | 論点 |
| --- | --- | --- |
| 層skill | 四つの層skillを`settle-question`一つにまとめ、層ごとの中身は層fileへ移した。層を担うskillは無くなった | task-design論点20〜22 |
| 問い（`settle-question`） | 一般の問いを件ごとに立て直す、詰める深さを決める、判断ごとに論点を立てる、正本の節を書く、利用者しか持たない事実を問う、を持つようになった | task-design論点20〜22、本論点2・6・11 |
| 全体制御 | 前提にする条件を拾って確かめる、照らし合わせの確認、出口の論点、層の状態の記録が足された。出口判定のきっかけは、層の閉じから、どの問いの答えからでも、へ変わった | 論点11・12・15 |
| 層 | 出口判定を持たなくなり、層の閉じは利用者の確認だけになった。なぜ作るか層の閉じ条件が変わった（痛みと得たいもの） | 論点12 |
| 材料skill | 一つ（`propose-alternatives`）を、専門の仕事のやり方と水準を持つ厚いskillに作り直した。他の材料skillは薄いまま | 論点16〜18 |
| 問いのセット | 要求を代案より前に移し、満たされた状態で書くことにした。対案の材料を一つにしたことで、代案・解き方・スコープ・費用の問いが同じ材料の切り口に見えるようになった（提案7、保留） | 論点18 |

##### ずれていそうな所

直し方ではなく、前回designの見込みと今とのずれである。

1. 中核の置き場所: 前回designは問いのセットを中核にし、skillは薄くてよい（中身は問いのセット側）とした。今は、件ごとの立て直し（`settle-question`）や専門の仕事のやり方（`propose-alternatives`）といった中身が、skillの側に積もっている。中核が問いのセットにあるのか、skillにあるのかが曖昧になっている。
2. 問いの源泉と、材料の形の向き: 前回designは、層の閉じ条件が問いを決め、問いが材料を要求する向きだった。提案7では、材料（対案）の形を見て、問い（代案・解き方・スコープ・費用）をまとめようとした。問いの構造が、層の閉じ条件からではなく材料の形から決まりかけている。
3. 層が誰にも担われていない: 層skillを無くした後、層は「層fileの並び」と「全体制御が利用者に確認する区切り」としてだけ残った。前回designが層skillに置いた「材料を取りに行く順序と、その層固有の落とし穴」は層fileへ移ったが、層の中の問いの間の整合（ある問いの答えが変わった時に、同じ層の他の問いが崩れないか）を見る者がいない。論点20の下流の洗い出しは、ここに当たる。
4. 全体制御が太る向き: 前回designは全体制御を「厚い」とし、このsteeringでも条件、照らし合わせ、出口、層の状態が足された。task-designの論点7（[task-design-discussion-6-10.md](../task-design-discussion/task-design-discussion-6-10.md)）で利用者は「オーケストレーション側が太らない？」と指摘し、判定を全体制御から外した。論点20の推す案（答え直しを全体制御が持つ）を利用者が「もっての他」としたのも、同じ向きへの違和感と読める。
5. 問いと材料の線引き: 材料skillは「問いへ答えない」が、`propose-alternatives`は要求の分解の不足を見つけて返し、対案という判断に近いものを差し出す。`settle-question`は材料の水準を確かめる。問いと材料の間で、判断と事実の線がどこにあるかが、材料が厚くなるほど細かく問われる。

- 上の前回designの見込みと、このsteeringで変わったことの整理が、利用者の認識と合っているか
- ずれていそうな五つのうち、どれが本当にずれか、他にずれがあるか

### イテレーション1（論点21）: 一つの層を振替の件で深め、そこから輪郭を出す

#### 提案1（論点21）

##### 最初に深める層

何を作るか層（`what-to-build`）を推す。

| 理由 | 中身 |
| --- | --- |
| 今、意味の詰まりが一番ここにある | 要求を満たされた状態で答え直し、対案の材料（`alternatives`）を作った。その材料を使う代案・解き方・リスク・スコープの問いは、まだ古い答えのままである |
| 保留が三つともここに集まる | 提案7（代案・解き方・スコープ・費用を一つにまとめるか）は、この層の問いの話である。論点20の下流の洗い出しも、要求を変えた下流がまずこの層にある。論点19の模型の記録の薄さも、この層の要求で最初に見えた |
| 深めたskillとすぐ接続できる | 論点16〜18で深めた`propose-alternatives`の主な使い手がこの層である |

なぜ作るか層は、この層の入力（痛みの核心、得たいもの）であり、今の答えで要求のmustの線を引けている。何を作るか層を深める中で、なぜ作るか層の答えの足りなさが見えたら、そこで上がる。

##### 進め方

1. 振替の件の何を作るか層の問いを、一つずつ、新しい要求と`alternatives`を入力に、`settle-question`の手順で答え直す。手順はskillを起動して通す。ユーザー役はassistantが演じ、層の閉じで利用者（実在）に応答を求める
2. 答え直しながら、それぞれの問いが本当は何を決めているのか（意味）を確かめる。問いが重なっていれば、重なりがどの判断の上で起きているかを、実物で見る（提案7はここで決める）
3. 問いが材料skillに何を求め、材料skillから何を受け取っているかを、実物で見る（問いと材料の線引き）
4. 層の中で、ある問いの答えが変わった時に他の問いがどう崩れるかを、要求を答え直した実物で見る（論点20はここで決める）
5. この層が練れたら、そこで見えた全体制御・層・問い・skillの持ち分を書き出し、他の層に当てて確かめる

#### 検討記録（論点21・イテレーション1）

提案0の表は前回designの記録から作ったもので、どれも件の中身を通していない。前回のskill群も、designの表の項目名を写して作ったことで薄くなった。持ち分は、件の中で問いを答える時に、誰が何を判断しているかを見て初めて決まる。

#### 提案1へのフィードバック（論点21）

**結果:** 合意

> ok。今後もそうだけど私は意味抜きして形式だけ決めるやり方1番嫌うからね

### 決定（論点21の進め方）

振替の件の何を作るか層を、問いを一つずつ`settle-question`の手順で答え直して深め、その中で、問いが本当に決めていること、問いの重なり（提案7）、問いと材料の線引き、層の中で答えが変わった時の崩れ方（論点20）を実物で見る。この層が練れた後に、全体制御・層・問い・skillの持ち分を書き出し、他の層に当てて確かめる。意味を詰める前に形式や対応表を決めない。

### 経過（論点21）

決定の後、振替の件の何を作るか層の問い（要求、代案、解き方、リスク）を、順に`settle-question`の手順で答え直した。記録は振替の模型の`what-to-build/`（論点5〜11）と[試運転の摩擦](../self-play-frictions.md)の11〜22にある。

##### ここまでの筋

| 段 | 何から何へ | 見えたこと |
| --- | --- | --- |
| 1 | 対案の材料 → 要求の問い | 対案を挙げるには、要求が機能ではなく満たされた状態で、代案を見る前に書かれている必要があった（論点18） |

##### 次に辿る所

段3の先、根の側へ泳ぐ。要求の状態が要った「場面の条件」は、本来は痛みの問いが持つべきものだったのではないか。痛みの答え（散らばる、気づけない、妻だけが担う）は、痛みの種類と核心は言えたが、その痛みが起きる場面（誰が、いつ、どこで、何をしようとして）を、要求が状態の条件にできる細かさで持っていなかった。

振替の件で、なぜ作るか層の痛みの問いを、要求が求めたもの（場面の条件）から見直す。そこで、痛みの問いが何を決めるべきか、要求の問いとの境目はどこかを確かめる。段2で見えた何を作るか層のまとまり（提案7）は、根の側が見えてから決める。

スコープの問いは、段2で解き方にほぼ吸収されたことが見えたため、今は答え直さない。

#### 検討記録（論点21・イテレーション2）

論点21の決定（何を作るか層を深める）を、層の問いを順に答え直すことと読み替えたのが迷子の原因だった。深めるとは、問いの変化がどこへ波及し、その元がどこにあるかを辿ることであり、問いを順に消化することではない。

##### 次の一手

1. まず、土台の2（何を作るか層の問いのまとまり）を、手元の実物の根拠で決める。提案7は、問いがwhyやwhatの洗い直しで揺れると見て保留したが、今回の答え直しで、何を作るか層の中の揺れは見えた。2を決めないまま次へ進むと、何を作るか層の問いの形が未確定のまま、上の層の見直しの結果を受け止める側が決まらない。
2. 次に、土台の5を確かめる。痛みの問いと要求の問いのどちらが場面の条件を持つかを決める。これは、2で決めた何を作るか層の入口（要求）と、なぜ作るか層の出口（痛み）の境目を決めることになる。
3. 3と4は、1と2を決めた後に、持ち分（問いが判断軸を持ち、材料skillが手法を持つ、層をまたいで要るものを誰が渡すか）としてまとめて決める。

#### 検討記録（論点21・イテレーション3）

提案2の「段1〜3」は、辿った順を語っていたが、どれが決まり、どれが観察だけで、次に何を決めるかを分けていなかった。土台を固めるとは、観察を、根拠を付けて決定に変えてから次へ進むことである。

これまでの答え直しで見えた観察（提案3の土台の表）は、上から立て直す時の根拠として使う。持ち分の決定（この論点の目的）は、何を作るか層の立て直し（論点22）の後に、そこで固まった層・問い・skillの関係から決める。

## 論点22: 何を作るか層（`what-to-build`）を、層→問い→skillの順に立て直す

**ステータス:** 分解済み

**親論点:** 論点21

**種別:** 提案

### イテレーション0（論点22）: この層は何を決める層か

#### 提案0（論点22）

この回では、層が何を決めるかだけを揃える。問いとskillは、層が決まってから立て直す。

##### この層が受け取るものと、渡すもの

| | 中身 | 振替の件では |
| --- | --- | --- |
| 受け取るもの（なぜ作るか層から） | 誰のどの痛みを解くか（痛みの核心）、作ることで何を得たいか | 痛みの核心は妻だけが振替を担うこと。得たいものは分担の解消と作る楽しみ |
| 渡すもの（どこまで作るか層へ） | 作るものが何で、何を作らずに済ませるか。最初に作る分、運用で済ませること、AIに任せる範囲は、この範囲の中で決まる | 作るのは、規則で期限と残り回数を出す計算と、毎朝期限をカレンダーへ写すscript。知らせは家族のカレンダー、記録はフォームに任せる |
| 渡すもの（どう作るか層へ） | 作るものが満たすべき状態と、作るものの形（何を受け取り、何を出し、どこに置くか）。体験・画面・テーブル・モジュールは、この形の中で決まる | 満たすべき状態はS1〜S4（must）とS5・S6・S8（better）。形は、フォームから入り、表計算で計算し、家族のカレンダーへ出す |
| 渡すもの（build-ready後の後続へ） | このプロダクトが何で、何でないか | 振替を二人で持つための、表計算とカレンダーをつなぐ小さな仕組み。予約の代行はしない |

##### この層が決めること

この層は、作るものの目標の形を決める。中身は三つであり、どれもこのアイデアについて一つに決まる。

1. 何が満たされれば痛みが解けるか（満たすべき状態と、must・betterの線）
2. 満たすべき状態のそれぞれを、何で満たすか（作るもの／既にある道具／やり方を変える／運用／我慢）。作らずに全てのmustを満たせるなら、作らないへ向かう
3. 作るものの形（作るものが何を受け取り、何を出し、既にある道具とどうつながるか）と、その形で起きうるリスク

この層が決めないこと:

- 作る順番と、作る間の当座のしのぎ（どこまで作るか層）。振替の件の「今日から家族のカレンダーで覆い、作ったら移る」のうち、移る順番と当座のしのぎはどこまで作るか層が決め、この層が決めるのは移った先の目標の形である
- 作るものの中身の設計（どう作るか層）。体験、画面、テーブル、モジュール

##### 閉じ条件の言い直し

今の閉じ条件は「スコープの内側と外側が言える」である。上の三つを決めた状態として、次へ言い直す。

> 満たすべき状態のそれぞれを何で満たすかが決まり、作るものの形（何を受け取り、何を出し、何とつながるか）が言える

スコープの内と外は、この「何で満たすか」の作るもの／それ以外の線であり、言い直した閉じ条件に含まれる。

##### 揃えたいこと

- この層が決めることを、上の三つ（満たすべき状態、何で満たすか、作るものの形とリスク）とし、作る順番と当座のしのぎをどこまで作るか層へ渡す、でよいか
- 閉じ条件の言い直しでよいか

#### 検討記録（論点22・イテレーション0）

渡すものは、どこまで作るか層とどう作るか層の層fileの冒頭（それぞれが何の範囲の中で決めるか）と、build-ready後の後続が正本から読むものから引いた。三つの中身は、振替の件の答え直しで実際に決めたもの（要求の状態、覆い方の選択、作るものの形とリスク）から取った。「今日から家族のカレンダーで覆い、作ったら移る」は、論点10で何を作るか層の解き方として決めたが、目標の形と、そこへの道のりの二つが混ざっていた。

**結果:** 修正要求（形式を決めず、要素を有機的に研ぎ澄ませる）

### イテレーション1（論点22）: なぜ問いが要り、問いはどうあるべきで、どう連携するか

#### 提案1（論点22）

##### なぜ、この層に問いが要るのか

利用者が前回steeringで弱いと述べたのは、要求定義、作るべきか、スコープの伸縮（拡大解釈するか、狭く研ぎ澄ませるか）、代案（あり物の組み合わせ）である。問いが無いと、振替の件では次のように進む。

1. 着想（期限の前にLINEで通知）の形を、そのまま作るものにする。要求は、着想の形の機能の一覧（登録する、通知する、一覧を見る）になる
2. 着想の形の中で、便利そうなものを足す（予約の代行、月謝の記録）か、気分で削る。スコープの伸縮に根拠が無い
3. 家族のカレンダーで期限に気づけることを試さずに、通知の仕組みを作る
4. 作り始めてから、規約（子どもの情報を外部へ送る）や、作る量（約76時間）に当たり、継ぎ足しと作り直しになる

この層の問いは、着想（解き方の一つ）を一度ほどき、痛みが解けた状態に戻してから、その状態を何で満たすのが一番よいかを選び直し、作るものの境目を固めるために要る。振替の件で、それを問いに沿って行った結果、作るものは「通知の仕組み」から「規則で残り回数を出す計算と、期限をカレンダーへ写すscript」に変わり、作る時間は着想どおりの半分以下になった。

##### 問いごとに、何を防ぎ、どうあるべきか

| 問い | 防ぐ失敗 | どうあるべきか（これを外すと失敗に戻る） | 振替の件で効いた所 |
| --- | --- | --- | --- |
| A. 痛みが解けたと言える状態は何か | 着想の形を要求と取り違える | 道具の形を含まず、満たされた状態で書く。状態ごとに、誰が、いつ、どこで、の条件を持つ。must・betterの線を、痛みの核心が解けるかで引く。代案を見る前に書く | 「夫が平日の夜に家で、期限と残り回数を知れる」という条件が、外出先で見る仕組みを不要にし、家族のカレンダーで足りる道を開いた |
| B. 状態のそれぞれを、何で満たすか | あり物で済むのに作る。作るべきかを判断しない。思いつきをそのまま作る | 作らない道（やり方を変える、毎日の道具、組み合わせ）を作る道と同じ重さで比べる。比べる時は、作る時間だけでなく、満たし続けるのに誰が何を払うか、覚えていないとできない操作があるかを見る。作らない道でmustが満たせる時は、得たいものと照らす | 家族のカレンダーで期限に気づける（S1）。作る必要があるのは残り回数を数えることと期限を写すことだと分かった |
| C. 作るものは、何を受け取り、何を出し、何とつながるか | スコープの伸縮が気分で決まる。作るものの責任があいまいで、どう作るか層が継ぎ足しになる | Bで作ると決めた部分だけを作るものとし、その入力・出力・既にある道具とのつながりを言い切る。作らない状態は、誰が何で満たすか（既にある道具、運用、我慢）を書く | 作るものは「フォームの記録を受け取り、規則で期限と残り回数を出し、家族のカレンダーへ期限の予定を出す」。予約の代行は満たす手段が無く、外に置く |
| D. その形で、何が起きうるか | 作ってから規約や依存先で詰む | Cで言い切った形について、規約、依存の継続性、実現性、運用を見る。取り返せないものがあれば、Bへ戻って別の道を選ぶ | LINEを使わない形にしたことで、子どもの情報を外部へ送るリスクが消えた。残るのはscriptが止まることへの気づき |

##### 問いはどう連携するか

```text
なぜ作るか層（痛みの核心、得たいもの）
        ↓ Aの線引きの基準、Bの照らし合わせ
A 解けた状態 ──→ B 何で満たすか ──→ C 作るものの形 ──→ D 起きうること
                    ↑                                   │
                    └──── 取り返せないリスク ─────────────┘
```

- AはBの比べる物差しである。Aが道具の形を含むと、Bで作らない道が比べられなくなる（振替の件の前の答えがそうだった）
- BとCは、粗い形と細かい形の関係にある。Bは、道ごとの粗い形と粗い費用で比べる。Cは、選んだ道の作る部分だけを細かく言い切る。Cを先に決めると、Bで比べる前に形が固まる
- DはCの形を確かめ、取り返せないものがあればBへ戻す。Dは、Bで比べた全ての道ではなく、選んだ一つの形だけを深く見る。全ての道を深く確かめるのは、作らない道まで技術検証することになり、手間に見合わない

##### 後続へどうつながるか

| 渡す先 | 渡すもの | なぜそれが要るか |
| --- | --- | --- |
| どこまで作るか層 | Cの作るものの形と、Bの状態ごとの満たし方 | 最初に作る分は、作るものの中のどれを先に作るかであり、作る間の当座は、作らない道（Bで比べた道）で埋める。振替の件では、作る間は家族のカレンダーで手で覆う |
| どう作るか層 | Aの状態（作るものが満たすべきもの）、Cの入力・出力・つながり、Dの手当て（作るものに入れるもの） | 体験・画面・テーブル・モジュールは、Cの形の中で、Aの状態を満たすように決める。Dの手当て（止まった時に知らせる）は、作るものの機能になる |
| build-ready後の後続 | このプロダクトが何で（C）、何でないか（Bで外に置いたもの） | 初回構築でスコープの外へ手を出さないため |

##### 揃えたいこと

この層の問いを、A〜Dの四つの判断として研ぎ澄ませる方向でよいか。特に、BとCを「粗い形で比べる」と「選んだ形を言い切る」に分けること、Dを選んだ形だけに当てることが、振替の件でやった判断と合っているか。

#### 検討記録（論点22・イテレーション1）

A〜Dは、今の層fileの問い（要求、代案、解き方、リスク、スコープ）の名前から作ったのではなく、振替の件で実際に下した判断と、問いが無い時に起きる失敗から作った。今の代案・解き方・スコープの問いは、BとCの判断を、比べる前と後に分けずに三つへ割っていたため、代案は作るかを閉じきれず（摩擦12）、解き方はスコープまで決め（摩擦16）、スコープは解き方の問い直しになっていた。

### イテレーション2（論点22）: A〜Dを一つずつ研ぎ澄ませる

#### 提案2（論点22）

A〜Dのそれぞれを、決めること、受け取るものと渡すもの、どうあるべきか（水準と、振替の件で実際に起きた浅い答え）、判断軸（定石）まで詰める。満たさない例は、振替の件の前の答えと、答え直しの途中で実際に出た浅い答えから取った。

##### A. 痛みが解けたと言える状態は何か

| 項目 | 中身 |
| --- | --- |
| 決めること | 満たすべき状態と、状態ごとの条件（誰が、いつ、どこで）、must・betterと線を引いた理由 |
| 受け取るもの | なぜ作るか層の痛み（場面と核心）と、得たいもの |
| 渡すもの | Bへ: 比べる物差し。どう作るか層へ: 作るものが満たすべき状態 |
| 材料 | 材料skillは要らない。痛みの答えが場面の条件を持たない時は、利用者しか持たない事実として認識合わせで問う。その時は、痛みの答えに場面が足りなかったことを記録に残す（なぜ作るか層の見直しの根拠） |
| 判断軸 | 線は、痛みの核心がその状態無しで解けるか。条件は、痛みの場面で実際に誰が何をするかから取り、最も広い条件を置かない |

満たさない例:

- 「期限前にLINEで知らせが届く」。手段（LINE）を状態に混ぜている。Bで、手段の違う道を比べられなくなる
- 「夫もどの端末からでも見られる」。条件を確かめずに最も広い条件を置いている。作るものが不要に大きくなる
- 必須とあれば嬉しいが分かれているが、線の理由が痛みの核心と結び付いていない
- 代案を見た後で、代案で満たせる所を下げている

##### B. 状態のそれぞれを、何で満たすか

| 項目 | 中身 |
| --- | --- |
| 決めること | 状態を満たす道（覆い方）を一つ選ぶ。作らない道を選ぶ時は、作らないへ向かう（得たいものと照らす） |
| 受け取るもの | Aの状態。なぜ作るか層の得たいもの。前提にする条件 |
| 渡すもの | Cへ: 選んだ道と、その中で作る部分。どこまで作るか層へ: 作る間の当座に使える作らない道 |
| 材料 | `alternatives`（候補の事実、覆い方の対案、対案ごとの粗い費用）、`experience-sketch`（道ごとの操作の流れ。粗くてよい） |
| 判断軸 | 日常で触る場所に置けるか。満たし続ける手間を誰が払い、その操作にきっかけがあるか。弱い所が痛みの核心にあるか。作る時間（粗い）。得たいもののどれを満たすか |

満たさない例:

- 候補を一つずつ痛みと比べ、組み合わせた道を見ていない（振替の件の前の答え）
- 着想の形を前提に、作る道どうしだけを比べている（前の答えの「LINEだけ」「ウェブの一覧とLINE」「表計算と定期の通知」）
- 作る時間だけで比べている。知らせの無い表計算の道は時間だけで見ると安いが、毎週末に表を見る、覚えていないとできない操作が残る
- 「作らない道で足りるので作らない」。得たいものと照らしていない。弱い所が核心にあることも見ていない

##### C. 作るものは、何を受け取り、何を出し、何とつながるか

| 項目 | 中身 |
| --- | --- |
| 決めること | Bで作ると決めた部分の、入力・出力・既にある道具とのつながりと、形の種類（記録・閲覧、通知、自動化、既にある道具への追加）。作らない状態を誰が何で満たすか（既にある道具、運用、我慢） |
| 受け取るもの | Bの選んだ道。Aの状態 |
| 渡すもの | Dへ: 確かめる形。どこまで作るか層へ: 作るものの範囲（この中で最初に作る分を決める）。どう作るか層へ: 入力・出力・つながり。build-ready後へ: このプロダクトが何で、何でないか |
| 材料 | `alternatives`の選んだ道の作る部分、`core-logic`（作る部分の心臓部の入力と出力、例外）、`experience-sketch`の選んだ道の流れ |
| 判断軸 | 既にある道具が持つ機能は作らない。作るものの入力と出力は、Aの状態のどれを満たすためかで説明できる |

満たさない例:

- 「表計算とscriptを作る」。何を受け取り、何を出し、どこへつながるかが無く、どう作るか層が形を決め直すことになる
- 便利そうなものを足している（予約の代行、月謝の記録）。Bで作ると決めていない
- 外に置いたものを、誰が何で扱うかが書かれていない

##### D. その形で、何が起きうるか

| 項目 | 中身 |
| --- | --- |
| 決めること | Cの形について、規約、依存の継続性、実現性、運用の四つの観点で起きうることと、手当て（避ける・減らす・受け入れる・待つ） |
| 受け取るもの | Cの形。前提にする条件 |
| 渡すもの | Bへ: 取り返せないリスクがあれば、別の道を選び直す。どう作るか層へ: 作るものに入れる手当て（例: 止まったら知らせる） |
| 材料 | `technical-feasibility`（Cの形の一番難しい部分）、`alternatives`の候補の事実（依存先の規約、今も使えるか） |
| 判断軸 | 起きた時に取り返せるか |

満たさない例:

- 前の形のリスクを写している（解き方が変わったのに、LINEへ送るリスクを残す）
- 「scriptが止まっても困らない」。止まったことに気づけないと、状態が黙って欠ける

##### 今の層fileの問いとの関係

| 今の問い | A〜Dとの関係 |
| --- | --- |
| 要求（`requirements`） | Aそのもの。identifierを保つ |
| 代案（`existing-alternatives-fall-short`） | Bの一部（作らない道で覆えるか）。Bにまとめる |
| 解き方（`solution-shape`） | 道を選ぶ部分はBへ、作るものの形の種類（記録・閲覧、通知等）はCへ分かれる |
| リスク（`risks-of-building`） | Dそのもの。確かめる相手を、Cの形に絞る |
| スコープ（`scope-in-and-out`） | Cの一部（作るものの範囲と、外に置くものの扱い）。Cにまとめる |

BとCは新しいidentifierにする（問いを統合・分割した時は新しいidentifierを付ける規則）。

#### 検討記録（論点22・イテレーション2）

判断軸は、振替の件で実際に選ぶ決め手になったものから取った。Bの「満たし続ける手間とそのきっかけ」は、表計算だけの道が時間では安く見えて弱いと分かった時の決め手であり、Cの「既にある道具が持つ機能は作らない」は、知らせを家族のカレンダーに任せた時の決め手である。今の解き方の問いの定石（記録・閲覧、通知、自動化、既にある道具への追加）は、道を選ぶ判断軸としては半分しか効かなかったが（摩擦18）、作るものの形の種類としてはCで効く。

**結果:** 修正要求（一つずつ詰めていない）

### イテレーション3（論点22）: Aだけを掘り下げる

#### 提案3（論点22）

AからDへ、一つずつ詰める。最初はA（痛みが解けたと言える状態は何か）。Bの物差しであり、ここが浅いとB以降が全て崩れる。

##### Aが無いと何が起きるか

この問いの仕事は、利用者が持ち込んだアイデア（多くは解き方の一つ）を、どの手段でも満たしうる「解けた状態」へ戻すことである。個人開発では、頼む人と作る人が同じであるため、要求は作りたい形へ寄りやすい。Aが無いか浅いと、次が起きる。

- 着想の形がそのまま仕様になる（振替の件の前の要求「期限の7日前と前日に、家族の二人へ知らせが届く」）
- 作らない道を比べる物差しが無く、代案の検討が「その機能があるか」になる
- スコープの伸縮に錨が無く、便利そうなものが足される
- どう作るか層と、build-ready後の後続が、出来たかを確かめる基準を持たない

##### 掘り下げて見えたこと

振替の件の答え直し（S1〜S8）を、この問いの仕事に照らして見直すと、四つの所でまだ浅い。

1. 満たし方の好みが、状態に混ざっている。S5「1分以内に記録できる」とS6「期限の計算が人の手を介さない」は、痛みが解けた状態ではなく、S3（規則が妻の記憶に頼らない）をどう満たすかの好みである。カレンダーに手で予定を作る道も、計算式で出す道も、S3を満たす。S5・S6を状態に置くと、手間の少ない道（作る道）が、要求の段階で有利になる。満たし続ける手間は、Bで道ごとに比べる軸であり、Aの状態ではない。
2. mustの線の基準が狭い。今の水準は「痛みの核心が、その状態無しで解けるか」で線を引く。S1（7日前に気づく）はmustにしたが、理由は核心（分担）ではなく失効である。線は、核心だけでなく、解くと決めた痛み（振替の件では、散らばる・気づけない・分けられない）のどれかが、その状態無しで残るかで引くべきである。
3. 状態の粒度に基準が無い。S1〜S4は、互いに別の手段で満たせる単位に分かれていた（S1はカレンダー、S2は表計算）。この分かれ方が、Bで組み合わせの道を作れた理由である。「振替を二人で管理できる」のような粗い状態だと、一つの手段で全てを満たすか満たさないかの二択になり、組み合わせが見えない。粒度の基準は「別々の手段で満たしうるか」である。
4. 二次の状態を探す手がかりが無い。S4（予約済みが二人の間でずれない）は、着想にも痛みの答えにも無かった。痛みの核心が解けた後の場面（夫が予約を代わる）を思い描くと、新しく起きる失敗（二重予約、取り忘れ）が出て、それが状態になった。核心が解けると新しい場面が生まれ、そこに要る状態がある。これは着想の外にある状態であり、発案者の視野を広げる所でもある。

##### 条件（誰が、いつ、どこで）の出どころ

条件は、痛みの場面から取る。振替の件では、痛みの答えに場面の条件が無く、Aの認識合わせ（夫は平日の夜に家で予約する）で初めて得た。痛みの答えが場面を持たない時、Aは認識合わせで問うが、それは痛みの答えの浅さでもある。Aは問うと同時に、痛みの答えに場面が足りなかったことを記録に残し、なぜ作るか層の見直しへ渡す。

条件は、確かめずに最も広く置かない（「どの端末からでも」）。最も広い条件は、作るものを不要に大きくする。逆に、利用者の好み（「スマートフォンで」）を条件にもしない。それは1と同じく満たし方の好みである。

### イテレーション6（論点22）: Aの中で一番効く要素を一つ選び、磨く

#### 提案6（論点22）

##### 選んだ要素と理由

Aの成果物の最小単位である「状態の一文」を選ぶ。Bは、候補ごとに、状態の一文に照らして「覆う／一部／覆わない」を判定する。一文があいまいだと、判定があいまいになり、Bの比べ方全体が崩れる。観点（提案4・5）は、この一文を出すための手がかりにすぎず、一文が磨かれていなければ、観点をいくら増やしても判定は良くならない。

その中でも、痛みの核心そのものであるS2を磨く。

> S2 夫が、妻に聞かずに、どの子のどの教室の振替がいつまで何回残るかを知れる（条件: 平日の夜に、家で、予約する時に）

##### S2を磨く

「何回残るか」の意味を問うと、二つが混ざっている。

| 意味 | 中身 | 誰が、いつ要るか |
| --- | --- | --- |
| 使える振替の残り | 欠席で生まれ、まだ予約も受講もしておらず、期限が切れていない振替が、何件あり、それぞれいつまでか | 夫が、平日の夜に、予約する時 |
| 生まれる上限の残り | その期間（スイミングなら月、ピアノなら年度）に、あと何回欠席すると振替が生まれるか | 欠席を連絡する人が、欠席する時（休ませるかを決める時） |

S2の条件は「予約する時」であり、夫が要るのは前者だけである。しかも前者は「回数」ではなく、「予約していない振替の一件ずつと、その期限」である。回数はそこから数えれば出るが、夫が予約で決めるのは「どの振替を、いつまでに、どの日に入れるか」であり、一件ずつの期限が要る。後者（生まれる上限の残り）は、欠席する時の別の場面の要るものであり、S3（欠席した時に、期限が規則から決まる）の側に属する。

磨いた一文:

> S2 夫が、平日の夜に家で予約する時、妻に聞かずに、まだ予約していない使える振替の一件ずつについて、どの子のどの教室のもので、いつまでに受講する必要があるかを知れる

確かめ方:

> 夫が妻に聞かずに「まだ予約していない振替はどれで、それぞれいつまでか」に正しく答えられる

##### 磨いた一文で、Bの判定が変わる

| 候補 | 前のS2での判定 | 磨いたS2での判定 |
| --- | --- | --- |
| 家族の共有カレンダー（振替一件ごとに、期限の日に終日の予定を作る） | 一部（残り回数を予定の名前に手で書き、数え間違える） | 覆う。予定一件が振替一件であり、「予約済み」の付いていない予定が、まだ予約していない振替の一件ずつとその期限になる。数える必要が無い |
| フォームと表計算 | 覆う | 覆う |

前の判定で、家族のカレンダーの道（P1）の弱い所を「痛みの核心（S2）の残り回数を手で数えること」とし、作る必要があるものを「残り回数を数えること」と「期限を写すこと」とした（何を作るか 論点9・10）。磨いたS2では、カレンダーの道はS2を数えずに覆う。残る作る必要は、欠席した時に規則から期限と「生まれる上限の残り」を出すこと（S3の側）だけになる。

つまり、作るものは「残り回数を数える仕組み」ではなく、「欠席した時に、規則から期限と、その欠席で振替が生まれるかを出す計算」に縮む。何を作るか層の答え（論点9・10）を、この一文で答え直す必要がある。

##### S2を磨いて分かった、状態の一文の書き方

| 書き方 | 中身 | S2で何が起きたか |
| --- | --- | --- |
| 数や集計を含む時は、その数で何を決めるかを問い、決めるのに要る一件ずつの事実に言い直す | 数は決めるための途中の値であり、決めること次第で、要るのが数か一件ずつかが変わる | 「何回残るか」を「まだ予約していない振替の一件ずつと期限」に言い直すと、数える仕組みが要らなくなった |

この四つは、S2を磨いた中で実際に効いたものであり、他の状態（S1、S3、S4）に当てて確かめるまでは、状態の一文の書き方として一般にはしない。

### イテレーション7（論点22）: 何を作るか層と問いAの構成要素を出し、クリティカルなものを決める

#### 提案7（論点22）

##### 選ぶ基準

構成要素ごとに、次の三つで見る。三つとも高いものがクリティカルである。

| 基準 | 中身 |
| --- | --- |
| 効く範囲 | その要素を誤ると、層の中と、後ろの層・後続のどれだけが崩れるか |

| 後で拾われるか | その要素を誤った時に、後ろの問いや層が気づいて直せるか。拾われないものほど重い |

##### 何を作るか層の構成要素

この層の仕事（提案1で合意: 着想をほどいて解けた状態に戻し、何で満たすかを選び直し、作るものの境目を固め、その形で起きうることを確かめる）から、構成要素を出した。

| 要素 | 効く範囲 | 誤りやすさ | 後で拾われるか |
| --- | --- | --- | --- |
| 解けた状態の定義（何が満たされれば解けたか） | 層の全ての判断（何で満たすか、境目、確かめ）と、どう作るか層の受け入れの基準、後続の出来たかの確かめ | 高い。利用者が持ち込むのは解き方であり、状態へ戻す仕組みが無いと、解き方の形がそのまま状態になる | 拾われない。後ろは全て、状態を所与として使う |

| 作るものの境目（入力・出力・つながり、外に置くものの扱い） | どこまで作るか層、どう作るか層、後続 | 高い（今の層fileには、境目を言い切る問いが無く、スコープと解き方に割れている） | 拾われない。どう作るか層は、境目を所与として中を設計する |

| 後ろへの受け渡し | どこまで作るか層、どう作るか層 | 高い | 拾われない |

クリティカルなのは、解けた状態の定義、作るものの境目、後ろへの受け渡し、の三つである。後ろへの受け渡しは、前の二つの成果物の形そのもの（状態と境目を、後ろがそのまま使える形で渡すこと）であり、前の二つを磨く中で決まる。そのため、磨く順は、解けた状態の定義（層の入口）→作るものの境目（層の出口）とする。

##### 問いA（解けた状態の定義）の構成要素

| 要素 | 効く範囲 | 誤りやすさ | 後で拾われるか |
| --- | --- | --- | --- |
| 着想をほどくこと（持ち込まれた解き方を、それが満たそうとしている状態へ戻す） | Aの全て | 高い。前の答えは着想の形の機能の一覧だった | 拾われない |
| 状態の文の形（誰が、いつ、何を知れる・できるか。手段を含まない。確かめられる） | Bの判定（覆う／一部／覆わない）、どう作るか層の受け入れ | 高い。言葉があいまいだと、Bの判定が割れる | 拾われない |
| 状態の単位（別々の手段で満たしうる大きさ） | Bの組み合わせの道 | 中 | 一部拾われる（Bで粗さに気づける） |

クリティカルなのは、着想をほどくこと、状態の文の形、研ぎ澄ます深さ、の三つである。

### イテレーション11（論点22）: 決まっていることと、価値があること

#### 提案11（論点22）

##### 提案10が見ていなかったこと

提案10の七つは、何を作るかが「決まっているか」（言い切れているか）を確かめる。何を作るかが「価値のあるものか」（それを作ることが、この痛みとこの利用者にとって良い選択か）は確かめない。振替の件で言えば、「ウェブの一覧とLINE」も、七つに答えを書き足せば、決まってはいる。それでも、家族のカレンダーで済む部分まで作る、価値の低い選択である。

前回steeringで利用者が弱いと述べた中には、「思ったプロダクトを拡大解釈したり、狭く研ぎ澄ませて作るべきなのか」がある。これは、決まっているかではなく、何を作るのが一番良いかを探すことである。何を作るか層は、決めることの前に、良いものを探す層である。

##### 価値は、誰から見て、何で決まるか

価値は一つの見方では決まらない。何を作るかに関わる見方ごとに、価値のあるものが満たすことが違う。

| 見方 | 価値のあるものが満たすこと | 満たさないと |
| --- | --- | --- |
| 痛みから | 痛みの核心に効いている。周りの痛みだけを解いていない | 作っても、一番困っていることが残る |
| 使い続ける利用者から | 利用者の暮らし（毎日開く道具、今の習慣、手が空く時）に馴染み、使い続けられる | 作った直後だけ使われ、使われなくなる |
| 作る量から | 作る量に対して、解ける痛みが大きい。既にあるものが担える所は担わせ、作るものは作らなければ解けない所に集まっている | 既にあるもので済む所まで作り、作る量だけが膨らむ |
| 大きさの選び方から | 広げる方向（同じ形の痛みを他にも解く、近い痛みを一緒に解く）と、絞る方向（核心の一点だけを解く）の両方を考えたうえで、大きさを選んでいる | 着想の大きさのまま作る。広げれば大きな価値があったか、絞れば早く効いたかを知らないまま進む |
| 着想の外から | 発案者が着想の時点で見ていなかった道や状態（作らずに済む部分、解けた後に生まれる場面）を、取り込むか退けるかを決めている | 着想の範囲の中だけで最適になる |
| 作る人から | 作ることで得たいもの（作る楽しみ、学び）を、作る部分が満たしている | 作る理由の片方が満たされず、作り切る前に止まる |
| これからの変化から | 暮らしの変化（子どもの習い事が変わる、教室の規則が変わる）に、作り直さずに付いていける | 一度の変化で作り直しになる |

##### 振替の件で当てると

| 見方 | 今の答え（家族のカレンダーと表計算をつなぐ小さな仕組み） |
| --- | --- |
| 痛みから | 核心（規則を知る人が妻だけ）に効く。期限を出すことを作るものに任せた |
| 使い続ける利用者から | 二人が毎日開く家族のカレンダーに出す。記録はスマートフォンのフォームで、欠席の連絡の直後に入れる |
| 作る量から | 知らせと一覧は家族のカレンダーに任せ、作るのは規則から期限を出す所だけ |
| 大きさの選び方から | 絞る方向は考えた（期限を出す所だけにした）。広げる方向は考えていない。例えば、同じ形の痛み（期限のある権利の失効）は、家族の中で他にもあるか（学校の提出物の期限、図書館の返却、病院の予約）。あれば、振替だけの仕組みより、期限のあるもの全般を家族で持つ仕組みの方が、大きな価値を持つかもしれない。退けるにしても、考えたうえで退ける必要がある |
| 着想の外から | 作らずに済む部分（知らせ）と、解けた後に生まれる場面（予約がずれない）は取り込んだ |
| 作る人から | 作る部分（規則の計算と写しのscript）は小さく、作る楽しみが満たされるかは利用者に確かめていない。小さすぎて楽しみにならない、ということもありうる |
| これからの変化から | 規則が変わる時は計算式を直す。教室や子どもが増える時に作り直さずに済むかは、見ていない |

価値の見方を当てると、今の答えには、広げる方向を考えていないこと、作る楽しみを満たすかを確かめていないこと、の二つの穴がある。決まっているかの七つでは、どちらも見えなかった。

##### 何を作るか層の仕事の言い直し

## 論点23: アウトカムは、なぜ作るか層が渡すものか

### イテレーション0（論点23）: アウトカムの構成要素と、クリティカルなもの

#### 提案0（論点23）

##### 核から見えたこと: 今までの「状態」はアウトプットの側にある

決定した核では、アウトプットは「アウトカムに近づくために、何が満たされればよいか」である。振替の件で要求として書いたS1〜S8（期限の7日前に気づく、夫が予約していない振替と期限を知れる、規則が妻の記憶に頼らない、予約がずれない等）は、まさに「何が満たされればよいか」であり、アウトプットの側にある。アウトカムは、その上にある、痛みが解けた時の暮らしの姿である。振替の件で言えば「振替のことを妻が一人で抱えず、二人のどちらが動いても、使える振替を期限の内に使い切れている」に当たる。

これまでアウトカムの話として磨いてきたこと（着想をほどく、状態の一文の形）の多くは、アウトプットの側の話だった。アウトカムは、まだ一度も磨いていない。

##### アウトカムの構成要素

アウトカムの仕事（痛みが解けた時に何が成り立っていればよいかを決め、アウトプットを比べる物差しになる）から、構成要素を出した。

| 要素 | 中身 |
| --- | --- |
| ゴールの姿 | 痛みが解けた時、利用者の暮らしの中で、誰の何（役割、行い、失われていたもの）が、どう変わっているか |
| ゴールの大きさ | どこまでを解けた姿に含めるか。広げる（同じ形の痛みも解けている）か、絞る（核心の一点だけが解けている）か |
| 近づいたかの測り | アウトプットが、ゴールにどれだけ近づけるかを、何で見るか |
| 痛みとのつながり | ゴールが、なぜ作るか層の痛み（核心と中身）のどれを解くか |
| 続くこと | 一度成り立つのではなく、続いている姿か |

##### クリティカルなもの

| 要素 | 効く範囲 | 誤りやすさ | 後で拾われるか |
| --- | --- | --- | --- |
| ゴールの姿 | アウトプットの全ての比べ方と、作った後の確かめ | 高い。症状の裏返し（「失効しない」）で止まり、核心（分担）を落とす。あるいは着想の形（「通知が来る」）で書く | 拾われない。アウトプットはゴールを所与として比べる |
| ゴールの大きさ | 作るものの価値の大きさそのもの | 高い。何もしなければ着想の大きさのままになる。振替の件では一度も考えていない | 拾われない |
| 近づいたかの測り | アウトプットを比べる時の決め手 | 中〜高。測りが無いと、アウトプットの比べ方が感覚になる | 一部拾われる（作った後に気づく） |
| 痛みとのつながり | ゴールの向き | 低い（なぜ作るか層が痛みを決めている） | 拾われる（なぜ作るか層） |
| 続くこと | ゴールの言い方 | 中 | ゴールの姿を磨く中で拾える |

クリティカルなのは、ゴールの姿、ゴールの大きさ、近づいたかの測り、の三つである。磨く順は、ゴールの姿→ゴールの大きさ→近づいたかの測りとする。大きさは「どの姿をどこまで」であり、測りは「その姿にどれだけ近いか」であり、どちらも姿が決まらないと決まらない。

#### 検討記録（論点23・イテレーション0）

核の「アウトプットは、何が満たされればよいか」という言い方から、振替の件の要求（S1〜S8）がアウトプットの側にあると分かった。アウトカムの構成要素は、アウトカムがアウトプットの物差しになるという仕事から、物差しとして何が要るか（何を測るか＝姿、どの範囲か＝大きさ、どう測るか＝測り）と、物差しの元（痛み）、物差しの性質（続くこと）で出した。

## 論点24: 「アウトプットが満たせた」は何で成り立つか

**ステータス:** 決定

**親論点:** 論点22

**種別:** 提案

論点22から分けた論点である。分ける前の論点22では、イテレーション15だった（提案の番号も同じ）。分けた時に、イテレーションと提案を、この論点の中で0から振り直した。

### イテレーション0（論点24）: 「アウトプットが満たせた」の構成要素

#### 提案0（論点24）

##### 「満たせた」は、三つのつながりが成り立つこと

アウトプットは、受け取ったアウトカムに近づくために、何が満たされればよいか、何を作り何に任せるかである。アウトプットが満たせたとは、次の三つのつながりが、どれも成り立っていることである。

| つながり | 中身 | 成り立たない時 |
| --- | --- | --- |
| 条件→アウトカム | 満たすと決めた条件が全て満たされれば、アウトカムに届く | 条件を全て満たしたのに、痛みが残る（振替の件の前の要求は、通知が届いても、規則を知るのは妻だけのままだった） |
| 手段→条件 | 条件のそれぞれが、決めた手段で、その条件（誰が、いつ、どこで）の下で満たされ、満たされ続ける | 作った直後は満たされても、人の手が続かずに崩れる。表計算だけの道は、毎週末に見る人がいなくなると、期限に気づけない |
| 選んだこと→価値 | 探した道の中で、この組み合わせが、作る量・暮らしへの馴染み・作る楽しみ・変化への強さで最も良い。守る条件を破らない | 満たせてはいるが、既にあるもので済む所まで作っている（ウェブの一覧とLINE） |

##### 構成要素

三つのつながりを成り立たせるために、決めなければならないもの。

| 要素 | 中身 | どのつながりのためか |
| --- | --- | --- |
| 満たすべき条件 | アウトカムに届くために満たされなければならない条件の集まり。必要（どれを欠いてもアウトカムに届かない）で、十分（全てを満たせば届く） | 条件→アウトカム |
| 条件ごとの手段 | 条件のそれぞれを、何で満たすか（作るもの、既にある道具、やり方を変える、人の手、満たさずに受け入れる） | 手段→条件 |
| 満たし続ける仕組み | 手段が条件を満たし続けるために、誰が、何をきっかけに、何をするか。きっかけ無しに覚えておく必要がある所はどこか | 手段→条件 |
| 作るもの | 手段のうち作るものの、まとまりと、既にある道具とのつながり（何を受け取り、何を出すか） | 手段→条件、選んだこと→価値 |
| 選んだ理由 | 探した道（作らない道を含む）と、その中でこの組み合わせを選んだ理由 | 選んだこと→価値 |
| 依るものと守るもの | この組み合わせが成り立つために真であるべきこと（依るもの）と、破ってはいけない条件（守るもの） | 手段→条件、選んだこと→価値 |

##### クリティカルなもの

| 要素 | 効く範囲 | 誤りやすさ | 後で拾われるか |
| --- | --- | --- | --- |
| 満たすべき条件 | 他の全ての要素（手段も作るものも、条件に対して決める）と、どう作るか層の受け入れ | 高い。機能の形で書く、必要だが十分でない（例外を落とす）、一語が二つを指す（振替の件の「残り回数」） | 拾われない |
| 条件ごとの手段 | 作る量 | 高いが、材料（`alternatives`）が切り口を持つようになった | 一部拾われる |
| 満たし続ける仕組み | アウトカムに届き続けるか | 高い。作る時間と代金で比べると見えない | 拾われない。崩れるのは作った後 |
| 作るもの | どこまで作るか層、どう作るか層 | 高い | 拾われない |
| 選んだ理由 | 後続が比べ直さないか | 中 | 一部拾われる（決定過程に残る） |
| 依るものと守るもの | 成り立つか | 中 | 一部拾われる（守る条件は全体制御が拾う。依るものは確かめる作業で出る） |

クリティカルなのは、満たすべき条件、満たし続ける仕組み、作るもの、の三つである。磨く順は、満たすべき条件→満たし続ける仕組み→作るもの、とする。手段と作るものは条件に対して決まり、満たし続ける仕組みは手段を選ぶ時の決め手になり、作るものはその結果として形が決まる。

#### 検討記録（論点24・イテレーション0）

構成要素は、アウトプットを決めた後に「満たせた」と言えるために何が成り立てばよいかを、アウトカムとアウトプットの間（条件→アウトカム）、アウトプットの中（手段→条件）、アウトプットの選び方（選んだこと→価値）の三つのつながりに分けて出した。それぞれの「成り立たない時」は、振替の件の前の答えと、答え直しの途中で実際に起きた形から取った。

### 決定（論点24）

##### 導き方: アウトカムの言い分を割り、言い分ごとに、成り立つために要ることを問う

アウトカムは一文の言い切りであり、その中に、成り立っていなければならない言い分がいくつか入っている。条件は、言い分ごとに「これが成り立つには、何が成り立っていなければならないか」を問うて出す。

振替の件のアウトカム（なぜ作るか層から受け取るもの）:

> 振替のことを妻が一人で抱えず、二人のどちらが動いても、使える振替を期限の内に使い切れている

言い分は三つに割れる。

| 言い分 | 成り立つには、何が要るか |
| --- | --- |
| ア 妻が一人で抱えない | 振替について知っておくべきこと（どの振替が使えて、いつまでか。規則）が、妻の頭の外にあり、二人とも見られる |
| イ 二人のどちらが動いても | 振替の一生の中の行い（欠席を記録する、期限に気づく、予約する、受講を記録する）のどれも、片方だけでできる。片方が行ったことが、もう片方に分かる |
| ウ 使える振替を期限の内に使い切る | 使える振替が一件ずつ、正しい期限とともに分かる。期限より前に、予約が間に合う時に気づく。使えないもの（上限を超えた欠席、期限切れ）が、使えるものと取り違えられない |

| まだ予約していない使える振替の一件ずつと、その期限を、二人のどちらも、相手に聞かずに知れる | ア・イ・ウ |

| 前のS1〜S8 | 導き方で見ると |
| --- | --- |

must・betterの線は、この導き方では要らなくなる。アウトカムの言い分から出たものは全て、欠ければアウトカムに届かない条件（must）であり、どの言い分からも出ないものは条件ではない（手段の好みか、アウトカムを超える上乗せ）。betterに置いていたものは、条件ではなく、手段を比べる時の見方へ回る。

### イテレーション1（論点25）: 十分さの確かめを磨く

#### 提案1（論点25）

##### 確かめ方: 全ての条件が成り立っているのに、言い分が崩れる日を作る

十分さは、条件を並べて眺めても分からない。全ての条件が成り立っていると置いたうえで、それでもアウトカムの言い分が崩れる具体的な一日を、言い分ごとに作ってみる。作れたら、十分ではない。作れなければ、その言い分については十分である。

作れた崩れ方は、次の四つのどれかに分ける。分け方で、打ち手が違う。

| 崩れ方 | 打ち手 |
| --- | --- |
| 条件が足りない（利用者の手の内で、まだ条件にしていないことがある） | 条件を足す |
| 条件の一文が緩い（条件はあるが、崩れる日を許す言い方になっている） | 一文を締める |
| 利用者の手の外にある（相手の都合、体調等） | 条件で寄せる（手の内で、崩れにくくする条件を足す）か、届かないものとして受け入れ、その旨を書く。どちらを取るかは利用者の採否が要る |
| アウトカムの言い方が強すぎる、または測りが無い | なぜ作るか層へ返す（アウトカムの言い方か、近づいたかの測りを見直す） |

止めるのは、全ての言い分で崩れる日を作ろうとし、作れた崩れ方を全て四つのどれかに分け終えた時である。

##### 振替の件で確かめると

導き方で出した六つの条件が全て成り立っていると置いて、崩れる日を作った。

| 言い分 | 崩れる一日 | 崩れ方 | 打ち手 |
| --- | --- | --- | --- |
| ウ 使い切る | 期限の7日前に、二人とも通知で気づいた。二人とも「相手が予約するだろう」と思い、どちらも予約せずに期限が過ぎた | 条件が足りない。気づくことと、予約する人が決まることは別である。二人に同時に知らせると、かえって誰も動かないことがある | 条件を足す: 「気づいた後、その振替を予約する人が一人に決まる」 |
| ウ 使い切る | 夫が期限の4日前に予約しようとしたら、ピアノは振替の予約を1週間前までに入れる決まりで、もう入れられなかった | 条件の一文が緩い。規則に、期限だけでなく予約の締切（何日前までに予約が要るか）がある。「予約が間に合う時に気づく」は、予約の締切を知らなければ確かめられない | 一文を締める: 規則の条件を「振替が生まれるか、期限、予約の締切が、規則から決まる」にし、気づく条件を「予約の締切より前に気づく」にする |

| ア 妻が抱えない | 条件は全て成り立ち、失効も無いが、妻が不安で、毎週こっそり教室のアプリを開いて確かめている | アウトカムの測りが無い。条件が成り立っても、妻の頭から振替が外れたかは、条件では確かめられない | なぜ作るか層へ返す: アウトカムの測りに「妻が確かめに行かなくても回っていると妻が思えている」を入れるかを見直す |

##### 確かめて分かったこと

- 導き方で出した条件だけでは、十分ではなかった。足す条件（予約する人が一人に決まる）、締める条件（予約の締切、欠席を連絡できること）、利用者の手の外（空き枠、体調）、なぜ作るか層へ返すもの（妻の頭から外れたかの測り）が出た
- 二人に同時に知らせることが、かえって誰も動かない形を生む。これは、前の答えで「二人へ知らせる」を良しとしていた所であり、条件を一つ足すことで、手段の選び方（知らせを二人に送るか、担当を決めて一人に送るか）が変わる

#### 検討記録（論点25・イテレーション1）

十分さの確かめは、条件を見直す（観点で漏れを拾う）のではなく、条件を全て成り立たせたうえで崩れる日を作る、反証の形にした。観点で拾う形では、前のS1〜S8でも例外を落とした。崩れる日を作ると、利用者の手の内か外か、条件か言い方か、アウトカムの側か、が分かれ、打ち手が決まる。

### イテレーション2（論点25）: 一文の形を磨く

#### 提案2（論点25）

##### 一文がしなければならないこと

条件の一文は、手段を比べる物差しである。どんな手段を持ってきても、その一文に照らして「満たす／満たさない」を決められなければならない。決められない一文は、比べる時に、判定を比べる人の感覚に預けることになる（振替の件で、家族のカレンダーの道のS2を「一部」と判定したのは、一文が「何回残るか」で、何を満たせばよいかが決まっていなかったためだった）。

##### 一文の組み立て

| 部分 | 中身 | 無いと |
| --- | --- | --- |
| 誰が | 言い分から出る主語。言い分が「どちらも」なら「二人のどちらも」 | 主語が狭くなる（前のS2の「夫が」） |
| いつ | その人が何かを決める、または行う時点。出来事（欠席した時、予約しようとする時）か、期限からの距離（予約の締切の◯日前まで） | 「すぐ」「いつでも」になり、手段が満たすかを決められない |
| 何が成り立つか | その時点で、その人が知れること・できること・取り違えないこと。決めるのに要る一件ずつの事実で書き、集計は、決めるのに集計が要る時だけにする | 「残り回数」のように、何を指すかが割れる |
| どこまで | 満たしたと言える最低の線（閾値）。取り違えない、のように許す幅が無いものは「一件も」と書く | 程度のある条件で、どこからが満たしたかが決まらない |
| 確かめ方 | その人がその時点で答えられる問い、またはできる行い | 一文が言葉だけになり、判定できない |

手段の言葉（通知、一覧、アプリ、LINE、カレンダー）は入れない。

##### 決められるかの試し方

一文を書いたら、性質の大きく違う二つの手段（例: 紙とホワイトボードだけのやり方と、作る仕組み）を当て、どちらについても「満たす／満たさない」が迷わず決まるかを試す。どちらかで「一部」「場合による」と言いたくなったら、一文のどこか（いつ、何が、どこまで）が緩い。

##### 補足への答え: 迷うものと、程度のあるもの

| 種類 | 例（振替の件） | 一文での扱い |
| --- | --- | --- |
| 程度がある（満たすほど良く、どこかに最低の線がある） | 気づく時期。早いほど空き枠が取りやすいが、最低限は予約の締切より前 | 最低の線を一文の「どこまで」に書く。最低の線より上の良さ（もっと早く気づけるか）は、条件ではなく、手段を比べる時の見方へ回す |
| 最低の線が事実に依る | 気づく時期の最低の線は、教室の枠がどれくらい早く埋まるかで決まる | 一文の「どこまで」を空けたまま、何の事実で決まるかを書き、認識合わせで問う。問う前に線を推測で置かない |
| 要るかが事実に依る（条件に入るか迷う） | 「二人のどちらも、教室へ欠席を連絡できる」。夫が欠席を連絡することが実際にあるかで、要るかが変わる | 迷う条件として、何が分かれば入る・入らないが決まるかを書き、認識合わせで問う |
| 要るかが利用者の考えに依る | 「妻が確かめに行かなくても回っていると思えている」。妻の安心をアウトカムに含めるか | なぜ作るか層へ返す（アウトカムの言い方と測りの話） |

must・betterの線を落としても、この四つの扱いで、迷うものと程度のあるものは条件の中で行き場を持つ。

##### 振替の件の条件を、この形で書くと

導き方の六つと、十分さの確かめで足した・締めた条件を、一文の形にした。

| 条件の一文 | 確かめ方 | 迷うもの・程度 |
| --- | --- | --- |
| 欠席した日のうちに、その欠席で振替が生まれるか、生まれる振替の期限と予約の締切が、教室の規則のとおりに決まり、二人のどちらも、妻の記憶に頼らずに分かる | 妻がいない日に欠席を連絡した夫が、その振替が生まれるか、期限と予約の締切を言える | 許す幅は無い（一件も間違えない） |
| 欠席を教室へ連絡した人が、その日のうちに、相手に頼らずに、その欠席を記録できる | 夫が欠席を連絡した日に、妻に頼まずに記録が済んでいる | 無い |
| 二人のどちらも、教室へ欠席を連絡できる | 夫が、妻に頼まずに、どの教室にも欠席を連絡できる | 要るかが事実に依る（夫が欠席を連絡することがあるか）。認識合わせで問う |
| 予約しようとする時（平日の夜、家で）、二人のどちらも、相手に聞かずに、まだ予約していない使える振替の一件ずつについて、子ども・教室・期限・予約の締切が分かる | 夫が妻に聞かずに「まだ予約していない振替はどれで、それぞれいつまでに、いつまでに予約が要るか」に答えられる | 無い |
| 予約の締切の◯日前までに、二人のどちらかが、その振替に気づく | 締切の◯日前の時点で、二人のどちらかが、その振替の締切を知っている | 程度がある。最低の線◯は、教室の枠がどれくらい早く埋まるかで決まり、認識合わせで問う |
| 気づいた日のうちに、その振替を予約する人が一人に決まる | 気づいた日に、二人とも「誰が予約するか」に同じ答えを言える | 無い |
| 片方が予約した、受講した日のうちに、もう片方がそれを知れる | 夫が予約した日の夜に、妻がその振替を予約済みと言える | 無い |
| 使えないもの（上限を超えた欠席、期限切れ、規則の外の振替）が、使える振替の一件として数えられない | 期限切れの振替を、二人とも使える振替に数えない | 許す幅は無い |

決められるかを試すと、例えば「予約の締切の◯日前までに気づく」は、ホワイトボードのやり方では「二人が毎朝見る」なら満たすが、見る習慣に頼る（満たし続ける仕組みの話であり、一文の緩さではない）。作る仕組みでは、知らせを出す日を締切から逆算すれば満たす。どちらも、一文に照らして迷わず決まる。

#### 検討記録（論点25・イテレーション2）

一文の形は、前のS2の判定が割れた理由（何を満たせばよいかが一文で決まっていなかった）から、一文の仕事を「どんな手段でも満たす／満たさないを決められる物差し」と置いて組み立てた。補足の「迷うもの、グラデーション」は、十分さの確かめで出た事実待ちの条件（枠の埋まり方、欠席の連絡）と、程度のある条件（気づく時期）にそのまま当たった。

### イテレーション3（論点25）: ここまでで行ったことと、残り

#### 提案3（論点25）

##### ここまでで行ったこと

なぜ作るか層から受け取ったアウトカム（要求: 何が変われば痛みが解けたと言えるか）を、満たすべき条件（要件）へ落とした。ただし、ここまでの要件は手段に中立であり、作るものの要件（作る仕組みが何をしなければならないか）ではない。どの手段で満たしても同じく満たすべきもの、という段の要件である。

| 段 | 中身 | ここまで |
| --- | --- | --- |
| 要求 | アウトカム（なぜ作るか層から受け取る） | 受け取った |
| 手段に中立な要件 | 満たすべき条件（導き方、十分さの確かめ、一文の形） | 行った |
| 作るものの要件 | 選んだ手段のうち、作るものに割り当てた条件を、作るものが何を受け取り、何を出し、何をしなければならないかとして言い切ったもの | まだ |

##### 何を作るか層で、これ以外に行うこと

論点24の提案0で出したアウトプットの構成要素のうち、残りである。

| 行うこと | 中身 |
| --- | --- |
| 条件ごとの手段を選ぶ | 条件のそれぞれを、作るもの・既にある道具・やり方を変える・人の手・満たさずに受け入れる、のどれで満たすかの対案を出し（作らない道を含む）、比べて一つの組み合わせを選ぶ。比べる見方は、作る量、暮らしへの馴染み、作る楽しみ、変化への強さ、着想の外 |
| 満たし続ける仕組みを決める | 選ぶ組み合わせの中で、誰が、何をきっかけに、何をして条件を満たし続けるか。きっかけ無しに覚えておく所はどこか。手段を選ぶ時の決め手になるため、手段を選ぶことと行き来する |
| 作るものを切り出す | 選んだ組み合わせのうち作るものに割り当てた条件から、作るものの要件（何を受け取り、何を出し、何をしなければならないか、既にある道具とどうつながるか）を言い切る |
| 依るものと守るものを言い切る | 選んだ組み合わせが成り立つために真であるべきこと（例: 家族のカレンダーで、相手の予定にも自分の通知が付く）と、破ってはいけない条件（子どもの情報を二人の外に出さない） |
| 選んだ理由を残す | 比べた道と、選んだ理由。後ろが比べ直さないため |

磨く順は、合意した順（満たすべき条件→満たし続ける仕組み→作るもの）に、条件ごとの手段を選ぶことを、満たし続ける仕組みと行き来する形で入れる。依るもの・守るもの・選んだ理由は、手段を選び、作るものを切り出す中で出る。

#### 提案3へのフィードバック（論点25）

**結果:** 合意（満たすべき条件の進め方を一旦良しとする）

> OK。周りを見ると、さっきの満たすべき条件進め方は一旦良しと言えるね

満たすべき条件の三つのクリティカルな要素（導き方: アウトカムの言い分を割って問う、十分さの確かめ: 崩れる一日を作って四つに分ける、一文の形: 誰が・いつ・何が・どこまで・確かめ方と、迷うもの・程度のあるものの扱い）を、一旦良しとする。

### 決定（論点25）

満たすべき条件は、次の決め方で決める。中身は`what-defines-a-product/what-must-hold.md`の「満たすべき条件」に書いた。

- 導く: アウトカムの言い分を割り、言い分ごとに、成り立つために要ることを問う。痛みの場面や観点から寄せ集めない。mustとbetterには分けない（提案0）
- 十分さ: 全ての条件が成り立っているのに言い分が崩れる日を作り、作れた崩れ方を分けて打ち手を決める（提案1）
- 一文の形: 誰が・いつ・何が成り立つか・どこまでと、確かめ方で組み、性質の違う二つの手段で、満たす／満たさないが迷わず決まるかを試す（提案2）
- 迷う条件と程度のある条件: 何で決まるか（事実か、利用者の考えか）で扱いを分ける（提案2）

十分さの確かめは、提案1で是非を保留し、一文の形まで進めた後に、この進め方として一旦良しとした（提案3へのフィードバック）。崩れる日を作る五つの進め方（時を進める、人を抜く等）と、確かめ方が本当の記録と一致するかまで問うことは、論点26（提案0・1）で足した。
