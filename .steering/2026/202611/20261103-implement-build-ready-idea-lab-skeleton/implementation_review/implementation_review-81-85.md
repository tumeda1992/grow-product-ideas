# 議論記録（論点81〜85）

## 論点81: レール整備の進め方と、各レイヤで合意する範囲・完了条件を立て直す

**ステータス:** 反映済み

**種別:** 作業全体の進め方の修正

### イテレーション0（論点81）: 全体構造・実行方法の詳細・結合検証を、段階の意味と成果で分ける

#### 提案0（論点81）

**レール整備を、全体構造を揃える → 各仕事の実行方法を詳細化・実体化する → 一式として適用・受入れを確かめる、の順で立て直す。**
今回合意するのは、この仕事の進め方と各段で完成とする範囲である。
個々の役割・skillの採否や本文、次の試運転の題材は、この案への合意だけでは採用したことにしない。
合意後は利用者の指定どおり、一旦現時点のコミット計画を立てる。

##### 大上段の目的と、仕事の順序

作る成果は、AIがアイデアを受け取り、体験に根ざして価値の可能性を広げ、選んだアウトカムから条件・解き方を詰め、作る版なら実装・導入へ渡せる設計まで進み、出口と残る未知を判断し、得た知見を次へ戻せる方法・文書・skillの一式である。
実行者が会話に無い本質的な判断を毎回発明し直さず、その一式を読んで仕事を進められることを目指す。

ここでいう整備のレイヤは、レールそのものを作る仕事の階層である。
why・what・how・how-to-buildは、そのレールを使う時に個々のプロダクトを検討する層であり、今回の整備の階層とは区別する。

```text
今回：進め方と、各レイヤの完了条件を合意する
  |
  v
一旦、現時点のコミット計画を立てる
  |
  v
A. レールの全体構造を揃えて合意する       ← 今、作業として戻る位置
  |
  v
B. 各仕事の実行方法を詳細化し、本文と例へする
  |
  v
C. 一式を新しい案件へ適用し、詳細まで繋がることを確かめる
```

検証はCだけに集めない。Aでは代表場面で仕事の受渡し、Bでは担当の方法と出力の具体、Cでは入口から出口への結合を確かめる。
下で上位の前提を変える欠けが分かったら、影響する判断だけへ戻す。毎回全体を白紙へ戻す運びにはしない。

##### A — 今詰めるレイヤ：レールの全体構造

この段で詰めるのは、「必要な仕事が全体として揃い、誰が何を受け渡して進める構造か」である。
skillの名前や既存のfile一覧から仕事を逆算しない。

まず、利用者の入力を受ける所から、体験と価値の探索、目標とアウトカム、条件、対案と版・未達の選定、実装・導入へ渡す設計、出口、知見の還元まで、必要な仕事を一つの全体図へ置く。
その中で、画面と操作のラフ、業務機能と規則、情報、技術の根拠、導入・訂正・復旧、必要な本人・関係者の事実が、どの判断へ何を供給するかを対応させる。
これは固定の工程数・skill数を採用することではなく、期待する仕事の欠落・重複・統合の余地を確かめるための範囲である。

仕事ごとに、その目的・責任範囲、受け取る前提と入力、返す成果と使われ方、依存する他の仕事、不足や変更を返す先、次に詳細化する内容を揃える。
どの仕事を層が持ち、専門の方法へ頼み、既存のplugin等を使うかもここで定める。
必要な仕事の受け皿が決まってから、統合・分割と配置・skillの要否を決める。
各部は全体の中で使える対象・前提・結果と不足を返し、全体制御が専門の規則を重ねて持つ構造にはしない。

元々期待した仕事と現在の構成を照合し、現行へ保持・統合・委ねた仕事と、未整備・判断が必要な仕事を区別する。
アーカイブしたskillは、この照合に使う設計の仮説・候補として読む。復元し切ることも、全て削ることも目的にしない。
声の根拠を得る仕事や出口後の還元も、この全体の中で役割と起点・返却先を扱う。

Aで残してよい未決は、担当と次に詰める内容が定まった内部の具体である。
例えば、ある仕事を担う本文の具体の手順がまだ無いことはBの未完として残せる。
一方、必要な仕事自体の有無、誰が引き受けるか、何を次へ渡すかが不明なまま「後で考える」としてAを閉じない。

Aの完了は、合意した全体図と仕事の対応から、必要な仕事の受け皿・責任・入出力・依存と差し戻し、次の詳細化の担当が読め、代表場面を辿って渡す相手のいない成果や引受け先のない仕事が残らないこととする。
ここでは各仕事の詳細な本文・全ての試験まで完了した扱いにはしない。

##### B — 次に下りるレイヤ：各仕事をやり切れる実行方法

Aで必要性と役割を合意した仕事について、実行者が何を読んでどう判断・生成・照合し、どんな成果を返すかを具体化する。
新しいskillを作るか、既存へ統合するか、既存の方法を使うかは、Aで定めた仕事を果たすための選択として扱う。

層file・SKILL.md・記録の雛形等へ、入力の確認、仕事の手順と分岐、判断の根拠、具体の出力、欠けと反例の検知、依頼の粒度に対する止める線、変更時の返しを実行できる内容で書く。
この段で作るのは、個々の案件で詳細を詰めるための方法と、その方法が使えることを示す具体の例・局所の検査である。

| 詰める仕事 | Bで方法と具体例が要求する深さ |
| --- | --- |
| 体験・画面と操作 | 対象の全場面、必要な画面・状態、表示・入力・操作と前後の結果をラフへ落とせる。情報が得られない所や中断・エラー後の続きを検知できる |
| 業務機能と規則 | 誰がどの前提で何を行い、どの規則・分岐で状態を変え、何を根拠に終わるかを具体にできる。例外・取消し・訂正・担当交替も対象の約束から扱える |
| 情報と保存 | 表示と判断が使う情報を、どこからどう読み、何を保って変更するかを具体にできる。必要な意味・項目・関係・制約と読み書きが欠けた時に検知できる |
| 技術・導入・復旧 | 設計が依る性質を条件付きで確かめ、未確認を返せる。誰がいつ何を使って導入・修正・復旧し、どこで終わるかを設計できる |
| 制御・確認・知見の還元 | 本人や専門への依頼、採否、記録、差し戻し、出口後の知見の判定と反映を、担当と実際の入力・成果に沿って回せる |

これは画面を必要としない版にも全画面設計を要求する指定ではない。合意した範囲に必要な詳細へ育てる方法を確認する。
実装内部の選択は、上位の価値・業務上の振舞い・保存や失敗時の保証へ影響する判断を解消し、委ねるものには保つ条件を渡す。
必要な本質的な未決を、実装担当の自由という欄へ追い出さない。

Bの完了は、各担当の実物の本文と出力例を使い、次の担当が会話外の補完をせず仕事を進められ、条件を変えた例・反例でも不足と返す先を判定できることとする。
「見出しがある」「例が一つある」だけでは閉じず、隣の仕事との入出力まで照合する。

既に作った本文・ラフ・schema・検査結果は捨てない。Aの仕事との対応を確認し、その射程に使えるものを再利用し、欠ける所を補う。
本文があること、部分の検査を通したこと、全体が成立したことは別の状態として保持する。

##### C — 一式としての適用・結合検証

現行の方法を使って新しい案件の入力から出口まで進め、選んだ価値が条件・解き方・設計へ保たれること、必要な依頼と返り・採否・差し戻しが実際に回ることを確かめる。
ここでは個別の案件のラフ・業務機能の詳細・情報と実現の根拠・導入と復旧等の実際の成果まで作る。

作る版では、業務の一巡をラフの操作・規則と状態・情報の読み書き・外の出来事・次の行いへ通す。
正常な一件だけでなく、選んだ版の約束が崩れる変更・失敗・再開・不足の戻しを確かめる。
作らない・保留も根拠と採否を持って扱い、一件がその出口に着いただけで画面・設計の詳細を検査済みにしない。
必要な仕事と分岐に対応する題材・入力を選び、同じ条件の成功を重ねるために件数を増やさない。

Cの完了は、入口から出口までの実行の記録と具体の成果から、担当の仕事と接続が機能し、作る版では実装担当が本質的な業務・設計を発明し直さず着手できることを確かめられることとする。
必要な枝に未確認があれば、その範囲を完了に数えない。
新しいsessionでの読込み等、既存の受け入れ条件も実際の実施と未実施を分ける。
レールの適用検証と、作った製品の実運用・価値の実測は分けて報告する。

##### 途中で不足を見つけた時と、合意の単位

各段で、担当や接続が変わる欠けならA、担当の手順や具体の出力の欠けならB、既知の方法の適用漏れなら実行の修正へ戻す。
戻すのは影響する差であり、既に有効な合意と成果を一律にやり直さない。
構造の判断を確かめるための小さな例や局所検査はAでも使えるが、全体の役割の未決を飛ばして個別の詳細の仕上げを進めない。

全体の成立を崩さない個別の追加確認は、何が未確認で何に影響し、いつどの仕事が引き取るかを宿題として残せる。
必要な仕事の引受け先が無いこと、業務の本質的な振舞いが未決であること、無い根拠で成立とすることは、その段を完了するための宿題へ押し出さない。

合意はAの全体の構造と責任・接続、Bの仕事単位の実行仕様と一体の変更、Cの成果と未確認・受入れについて、それぞれの具体が判断できる単位で取る。
内部の資料読取り、合意した範囲の反映、表記の補正、必要な検査の一回ごとに追加の合意待ちは作らない。

##### 今回の合意後の直近の動き

この提案で進め方を合意したら、まず現時点の差分と採用状況を確認し、コミット対象・分割・依存・確認方法を整理したコミット計画を提示する。
未採用の提案や未完の検証を、完了した機能として扱わず、議論・方法の実物・検査用の資料と根拠を追える境界を検討する。
コミット計画を立てる前に、別のskillの整備や読書の通し検証を開始しない。
コミット計画の後、Aの全体構造の点検・具体案の合意へ戻る。

論点78の声の専門と論点80の読書の試運転は、未採用の保留として保持する。
この提案への合意は、それらや全体構造そのもの・各担当の本文への合意ではない。

そのため、全体構造・実行方法・適用のそれぞれで何を確かめ、何が次へ渡ればよいかを分けた。

作らないへ着く一件では作る版の詳細を検査できないため、Cでは確認する仕事と分岐に応じた実際の成果を求める。

提案と背景のdocument-reviewを終えた。今回の合意前に全体構造の具体や新しい試運転、コミット計画・実行を始めてはいない。
