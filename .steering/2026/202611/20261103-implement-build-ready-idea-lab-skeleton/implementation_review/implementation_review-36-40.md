### イテレーション0（論点36）: alternativesは、層の外の材料であり続けるか

#### 提案0（論点36）

##### 答え: 自明ではない。層の外の材料ではなく、どう解くか層の解き方の選択肢そのものである

手段の層の構成要素を、解き方の選択肢と解き方の選定に変えた時（論点28の提案4、論点31の提案0、論点32の提案0）、材料`alternatives`を選別し直さずに残していた。一つの要素が変わったら残りも選び直す、という基準（escalation 003）を、自分で外していた。

選別し直す。

| 材料`alternatives`が持つもの | 解き方の選択肢が既に持つか |
| --- | --- |
| 対案を挙げ、選ばない（選ぶのは問い） | 持つ。挙げるのが解き方の選択肢、選ぶのが解き方の選定であり、二つの決めるものの分け目そのものになった |
| 候補の事実（状態の条件で覆うか、状態を保つ操作、規約・安全、今も使えるか） | 持つ。当てにする事実と、それを確かめたか（出典を読んだ、利用者に問うた、動かした）。状態を保つ操作は、受け渡しの担い手ときっかけになった |
| 対案ごとの費用（六つの列、部品ごとの三点、補正） | 持つ。得るもの・払うものの八つの軸（決め方の5） |
| 利用者の事実を先に返す（毎日開く道具、今のしのぎ方、過去の見立てと実績） | 一部だけ持つ。出どころの事実は決め方の1にある。過去の実績は決め方の5に補正として書いてあるが、いつ問うかが無い。毎日開く道具と今のしのぎ方は無い |
| 候補を探す切り口（毎回使う三つと、件で選ぶ七つ）と、手段の種類 | 持たない。決め方の3は「材料`alternatives`に求める」と書くだけである |
| 候補×状態の表と、覆い方の対案（振替の件のP1〜P6を丸ごと並べる） | 上位のもので置き換えた。決め方の3は、対案を丸ごと並べることを外れている時に挙げている。振替の件では、補う点ごとに出して初めて、教室ごとに予約の担当を決めておく選択肢が出た |

解き方の選択肢が、材料`alternatives`の上位互換になっている。残るのは、候補を探す切り口と、毎日開く道具・今のしのぎ方・過去の実績を先に問うことの二つで、どちらも解き方の選択肢を出すためにしか使わない。

終わり方も重なる。材料の止める時（新しい切り口を使っても、mustを覆う新しい候補が出なくなった時）は、解き方の選択肢の止める時（新しい切り口を使っても、足りない点を満たす新しい選択肢が出なくなり、全ての選択肢が情報の流れと八つの軸で書けた時）に含まれる。終わり方が同じ仕事を二つに分けると、同じ判定が二か所に書かれる。

##### 場所: 層の外に置き続けると何が起きるか

- 読む人は、層の決めるものを決めるための入力だと読む。実際は、層が決め、閉じで利用者が確かめるものの中身である
- 層の記録と材料の両方に、補う点、選択肢、当てにする事実が書かれる。直す時に、どちらを直せばよいかが割れる
- 層fileの決め方（選択肢をどう出すか）と、`propose-alternatives`の手順（対案をどう出すか）が二重になる

置き場所は、どう解くか層の記録（論点35の提案0の`how-to-solve/README.md`）にする。正本には、補う点ごとの選択肢と情報の流れの要点を書く。層の記録には、確かめた事実の出典、使った切り口と使わなかった切り口、部品ごとの見積りを書く。

##### 名前: 材料（materials）は、中身を絞らない名前だった

「材料」は、判断に使うもの全てを指せる。そのため、層が決めるものの中身である`alternatives`が、引っかからずに入った。名前が、入るものを絞っていなかった。

層の外に残るとすれば、次の全てに当たるものである。

- どの層の決めるものでもない（閉じで利用者が確かめるものではない）
- 層の推論の外で調べて得たもの（ウェブ上の声、動かして確かめた事実）であり、確かめた方法と限界を持つ
- 複数の層が読む、または層を跨いで粒度を育てる

吟味済みの二つの層には、これに当たるものが今は無い。何が成り立てばよいか層の限界で照らす`target-user-voices`と、どう解くか層の当てにする事実を動かして確かめる`technical-feasibility`は、どちらも退避中で吟味していない。動かして確かめた事実は、当てにする事実（確かめた方法: 動かした）として層の記録に置ける見込みもある。層を跨いで育てるもの（ウェブ上の声、粗いラフ画から細かいラフ画）が本当に残るかは、なぜ作るか層、どこまで作るか層、どう作るか層を磨く時に分かる。

そのため、今はproduct-plansの置き方に、層の外の場所を置かない。層を跨ぐものが実際に出た時に、それが何かを見て、名前を付けて置く。名前は、材料のような使い道の名前ではなく、中身の名前にする（例: 調べて分かったこと、`findings`）。

振替の件に当てると、置き方は次になる。

```text
├── README.md              # 正本。満たすべき条件、解き方の選択肢、解き方の選定の節
├── what-must-hold/
│   ├── README.md          # 層の記録
│   └── discussion.md

```

##### 何が変わるか

- `what-defines-a-product/how-to-solve.md`の決め方の1・3から「材料`alternatives`に求める／渡す」を外す。候補を探す切り口と手段の種類を決め方の3へ、毎日開く道具・今のしのぎ方・過去の実績を先に問うことを決め方の1へ入れる

### イテレーション1（論点36）: skillは層とどういう関係にあり、その結果をどこに置くか

#### 提案1（論点36）

##### 提案0の何が浅かったか

提案0は、`alternatives`と解き方の選択肢を、どう解くか層の中だけで並べ、重なるから吸収すると結論した。材料のskillが、他のどの層から、どの粒度で求められるか（どこまで作るか層が、部品ごとの見積りを求める等）を見ていない。置き場所はskillと層の関係から決まるのに、関係を決めずに、一つの層の中の重なりから置き場所を出した。

また、知識（専門の仕事のやり方）をどこに置くかと、結果（その件で作ったもの）をどこに置くかを、一つにしていた。skillを層fileへ吸収することと、結果を層の記録に置くことは、別の問いである。

##### 問いの依存

置き場所を決めるには、次が上から順に決まっている必要がある。

1. 専門の仕事を、層fileの決め方から分けてskillにする理由は何か（分ける理由）
   - 分ける理由が無い仕事は、層fileの決め方に入れる。知識の置き場所はこれで決まる
2. 専門の仕事ごとに、どの層の、どの決めるものが、どの粒度で求めるか（対応の洗い出し）
   - 一つの仕事を一つの層だけが求めるか、複数の層が求めるか。一つの層が、複数の仕事を求めるか
3. 仕事ごとの、層との結びつき方（層にべったりか、層と疎結合な外部の専門家か）
   - 2の対応から出る見込みである。複数の層に求められる仕事が、一つの層の決め方にべったりだと、その仕事が複数の層の中身を抱え込む（旧全体制御で避けたこと）
4. 結果の持ち方
   - 一つの成果物を層を跨いで育てるか、求めた層ごとに別の成果物にするか
   - 下の層では、決めるものそのものになるか
   - 閉じた層が判定に使った姿が、下の層で育てた時に変わってよいか
5. 結果の置き場所と名前（層の直下に一file、層と離す、跨いでも層ごとに置く）

1が判断の基準、2が事実、3〜5が2から出る帰結である。提案0は、2を飛ばして5を答えた。

##### 2を、今分かる範囲で当てる

吟味済みの二つの層は、今の決め方から当てた。未吟味の三つの層は、退避した旧問いの必要な材料から当てた（見込み）。

| 専門の仕事 | 求める層・決めるもの（粒度） | 対応 |
| --- | --- | --- |
| 候補を探し、候補の事実を確かめる（今の`propose-alternatives`の前半） | どう解くか層・解き方の選択肢（補う点ごと）。どう作るか層で、使う外部サービスやライブラリを選ぶ時にも要る見込み | 一つの仕事を複数の層が求める見込み |
| 作る時間を見積もる（今の`propose-alternatives`の費用） | どう解くか層・解き方の選択肢の払うもの（選択肢ごと）。どこまで作るか層の最初に作る分（部品ごとで、区切りの案ごとに足せる粒度） | 複数の層 |
| 覆い方の対案を組む（今の`propose-alternatives`の後半） | どう解くか層・解き方の選択肢だけ | 一つの層の、一つの決めるもの。決めるものそのもの |
| 声を集める（`target-user-voices`） | なぜ作るか層の痛み（旧）。何が成り立てばよいか層の限界（自分以外も使う時） | 複数の層 |
| 体験の流れと画面を描く（`experience-sketch`） | 旧では、何を作るか層（案ごとの操作の流れ）、どこまで作るか層（場面の流れ、画面の枚数）、どう作るか層（全場面、全画面）。今のどう解くか層は、選択肢を情報の流れで書き、ラフ画を求めていない。ただし、画面を作る選択肢の作る時間を部品で積む時に、粗い画面の枚数が要る見込み | 複数の層。どう作るか層では、決めるもの（画面）そのものになる見込み |
| 動かして確かめる（`technical-feasibility`） | どう解くか層・当てにする事実（確かめた方法: 動かした）。どう作るか層の実現性（旧） | 複数の層の見込み |
| 心臓部・テーブル・モジュールを描く | どう作るか層だけ（旧） | 一つの層。決めるものそのものの見込み |

ここから見えること（見込みであり、確定ではない）:

- 層とskillは1対1ではない。一つの層が複数の仕事を求め（どう解くか層は、候補の事実、見積り、動かして確かめる、粗い画面の枚数）、一つの仕事が複数の層に求められる（見積り、体験、声）。
- 仕事は二種類に分かれそうである。一つの決めるものの候補を作るもの（覆い方の対案、テーブル、モジュール）と、層を跨いで求められるもの（候補の事実、見積り、体験、声、動かして確かめる）。
- 一つのskillに、二種類が混ざっている。`propose-alternatives`は、層を跨ぐ候補の事実と見積りと、どう解くか層だけの覆い方の対案を、一つに持つ。`alternatives.md`の置き場所が一つに決まらないのは、このためと見ている。
- 体験は、上の層では判断の材料であり、どう作るか層では決めるものそのものになる。同じ成果物の役が、層によって変わる。
- 仕事が仕事を求める。見積りは、画面を作る選択肢では粗い画面の枚数を、確かめていない技術では動かして確かめた事実を求める。

##### 利用者が挙げた三つの置き方と、4の持ち方の関係

| 置き方 | 合う持ち方 | 起きること |
| --- | --- | --- |
| 層の直下に一file | 一つの層だけが求める仕事 | 層を跨ぐ仕事を置くと、下の層が、閉じた上の層の記録を書き換える |
| 層と離す | 層を跨いで一つの成果物を育てる仕事 | 一か所で読める。上の層が閉じた時に依った姿（決め手が依った見積り等）が、育てると上書きされる。残す手当てが要る |
| 跨いでも層ごとに置く | 層ごとに別の問いに答える仕事 | 閉じた時の姿が残る。同じ調べを層ごとにやり直すか、写す重複が出る |

##### まだ決められないこと

- 1（分ける理由）: 候補は三つある。複数の層に求められること、終わり方が決めるものと別であること、層fileに入れると決め方が専門の手順に埋もれること。どれを基準にするかで、一つの層だけの仕事（覆い方の対案、テーブル、モジュール）をskillにするかが変わる。
- 4（持ち方）: 層を跨ぐ仕事で、一つを育てるか、層ごとにするか。決め手は、閉じた層の判定の根拠を、下の層で育てた時に書き換えてよいかである。解き方の選定の選び直す条件は、決め手の境目を読む（`how-to-solve.md`）。閉じた時の姿が失われると、選び直せない。
- 2のうち、未吟味の三つの層は見込みである。特に体験は、どう解くか層が粗い画面を求めるかを、振替の件で確かめていない。

##### 進め方

1. 1（分ける理由）の基準を、上の表の仕事に当てて決める。
2. 層を跨ぐ仕事のうち、今の二つの層を通すのに要る二つ（候補の事実、見積り）で、4の持ち方を決める。見積りは、どこまで作るか層が後で育てるため、層を跨ぐ場合の試金石になる。
3. 3〜5を、二つの仕事について決め、振替の件の置き方に当てる。
4. 体験と声は、なぜ作るか層、どこまで作るか層、どう作るか層を磨く時に、同じ基準で当て直す。持ち方が覆ったら、置き方を直す。

#### 検討記録（論点36・イテレーション1）

提案0は、一つの層の中の重なりから置き場所を出し、skillと層の関係を決めていなかった。置き場所は、分ける理由、対応の洗い出し、結びつき方、持ち方の順に決まる。対応を今分かる範囲で当てると、層とskillは1対1ではなく、一つの決めるものの候補を作る仕事と、層を跨ぐ仕事の二種類があり、`propose-alternatives`は両方を持っていた。体験は、層によって判断の材料から決めるものそのものへ役が変わる。

### イテレーション2（論点36）: 専門の仕事を、層fileの決め方から分けてskillにする理由

#### 提案2（論点36）

##### 基準は新しく作らず、既にある基準を使う

skillから工程を切り出すかの基準は、`tumeda-dev`の`skill-update-review`（`find-split-candidates.md`）に既にある。提案1で挙げた三つの候補より、こちらが上位互換になっている。

- 分けるか: その工程が、固有の判断・状態・完了条件・改訂理由を持つか。入力や出力の形の違い、行数では分けない。混線の実績が無くても、抱え込んでいれば分ける候補にする。
- 分ける先: 同じ仕組みの内部の指示にするか、別skillにするか。別skillにするには、今ある単独の利用か、外の呼び手の具体的な求めが要る。将来の見込みだけでは独立させない。
- 確かめ方: 具体的な改訂を一つ当て、その改訂がどのfileのどこを直すかを見る。関係の無い所まで直す必要が出るなら、抱え込んでいる。

このレールでは、層fileは、レール（進め方の`grow-product-idea`と、`what-defines-a-product/`）の内部の指示に当たる（論点35）。そのため、専門の仕事の行き先は三つになる。

| 行き先 | 当たる仕事 |
| --- | --- |
| 層fileの決め方に入れる | 仕事の判断と止める時が、その層の決めるものの判断と止める時そのものである |
| 層fileから分け、レールの内部の指示にする | 層の決めるものとは別に、固有の判断・状態・完了条件・改訂理由を持つ |
| 別skillにする | 上に加えて、レールの外から、今、単独で使う、または呼ぶ具体的な求めがある |

##### 提案1の三つの候補の扱い

| 候補 | 扱い | 理由 |
| --- | --- | --- |
| 複数の層に求められること | 分ける理由にしない。5（置き場所）へ回す | 層はレールの内部である。複数の層が求めることは、別skillにする理由ではなく、レールの内部で、一つの層の下に置くか、層に共通の所に置くかの理由になる。また、求める層の多くは未吟味であり、見込みである |
| 終わり方が決めるものと別であること | 広げて、基準そのものにする | 完了条件は、四つ（判断・状態・完了条件・改訂理由）の一つである |
| 層fileに入れると、決め方が専門の手順に埋もれること | 外す | 埋もれるのは、固有の判断を抱え込んでいる時の症状であり、二つ目の候補で捉えられる。抱え込んでいないなら、それは層の中身であり、長くても層fileに書く |

##### 吟味済みの二つの層の仕事に当てる

今の二つの層（何が成り立てばよいか、どう解くか）が、今求めている仕事だけに当てる。未吟味の層からの求めは見込みなので、数えない。

| 仕事 | 固有の判断・状態・完了条件・改訂理由 | 当てた改訂 | 行き先 |
| --- | --- | --- | --- |
| 候補を探す（切り口、手段の種類）。先に問う、毎日開く道具と今のしのぎ方 | 持たない。どの補う点にどの選択肢があるかは、解き方の選択肢の判断そのものである。止める時も、解き方の選択肢の止める時（新しい切り口を使っても、新しい選択肢が出ない）に既に書かれている | 切り口に「相手（教室）に頼む」を足す。直すのは、どう解くか層の決め方の3だけである | 層file（どう解くか層の決め方の1・3） |
| 覆い方の対案を組む（候補×状態の表、組み方） | 持たない。解き方の選択肢（補う点ごと、組）に置き換わった | ― | 入れない（上位のものに置き換わった） |
| 事実を確かめる（出典を読む） | 持つ。判断: その事実は真か、出典は足りるか（第三者の記事だけか）、確かめること自体が規約・安全に触れるか。状態: 事実ごとに、確かめた／確かめていない／確かめられない。完了: 事実ごとに、出典か、確かめられない理由がある。選択肢が揃ったかとは別に終わる | 第三者の記事しか無い事実を、確かめていないものとして扱うように変える。直すのは確かめ方だけで、補う点、きっかけ、八つの軸、選定は直らない | 分ける（レールの内部の指示） |
| 作る時間を見積もる（部品に分けて積む、描かれにくい部品、三点、補正） | 持つ。判断: どの部品に分けるか、描かれにくい部品が抜けていないか、補正をどうするか。状態: 部品ごとの三点と、利用者の過去の見立てと実績（件を跨いで溜まる）。完了: 描かれにくい部品を含む全ての部品に三点があり、補正の有無が書かれている | 実際に作った後で、描かれにくい部品（例: 届かなかった通知の扱い）が抜けていたと分かり、一覧に足す。今は`how-to-solve.md`の決め方の5を直すことになるが、その層の決めるもの（どの選択肢があるか）とは関係が無い | 分ける（レールの内部の指示） |

事実を確かめる仕事は、どう解くか層の中の二つの決めるもの（解き方の選択肢の当てにする事実、解き方の選定の決め方の1「決め手が依る事実を確かめる」）が、今求めている。今の`how-to-solve.md`は、どちらにも確かめ方を書いていない。確かめ方は`propose-alternatives`の中にあった。

利用者に事実として問うこと（認識合わせ）は、この仕事に含めない。レールの会話で行い、結果は選択肢の中に持つ（論点31）。何が成り立てばよいか層の決め方の4（要るか、どこまでかが事実に依る条件）も、利用者に問う形であり、この仕事を求めていない。

未吟味の仕事は、今は行き先を決めない。

- 声を集める: 何が成り立てばよいか層の限界（自分以外も使う時）が求める。退避中で中身を吟味していないため、吟味する時に同じ基準で当てる。
- 動かして確かめる: 事実を確かめる仕事の、方法の一つと見る見込みである。判断と完了は同じで、違うのは、動かす前に規約・安全を見る関門と、秘密情報の扱いである。また、`tumeda-dev`の`task-design`のspikeと同じ考え方を持つ（退避した`verify-technical-feasibility`の冒頭）。レールの外に同じ仕事があるため、吟味する時に、そちらへ任せられるかを見る。
- 体験の流れと画面を描く: 吟味済みの二つの層は、今は求めていない。見積りで画面の枚数が要るかは、振替の件で確かめていない。どう作るか層では決めるものそのもの（層file）になり、上の層では粗い姿を求められる見込みである。同じ仕事が、層によって行き先を変えるため、この基準だけでは決まらない。4（持ち方）で決める。
- 心臓部・テーブル・モジュールを描く: どう作るか層の決めるものそのもの（層file）になる見込みである。吟味する時に確かめる。

##### 当てて見えたこと

- 別skillにする仕事は、今は一つも無い。事実を確かめる仕事と見積りは層fileから分けるが、行き先はレールの内部の指示である。別skillになるのは、レールの外から今使う求めがある時だけで、それは利用者しか知らない（下の問い）。
- `propose-alternatives`は、中身が三つの行き先（層file、分ける二つ、置き換わって入れない）に割れる。一つのskillとして残る理由は無い。ただし、退避するかは、結果の置き場所（5）と一緒に決める。知識をどこに置くかと、結果をどこに置くかは別の問いであるため（提案1）。
- 3（結びつき方）は、分ける二つについては、1で答えが出る。分けた仕事は、判断が層に依らない。層は、何を確かめるか、どの部品をどの粒度で見積もるかを渡すだけであり、層と疎結合である。層fileに残すものは、層にべったりであり、skillではない。結びつき方が、仕事ごとではなく、仕事と層の組ごとに変わるのは、今見えている中では体験だけである。
- 層とskillは1対1ではない。どう解くか層は、分ける二つの仕事を両方求める。事実を確かめる仕事は、一つの層の中の二つの決めるものに求められている。

##### 利用者に確かめたいこと（認識合わせ）

レールの外で、今、作る時間の見積りや、事実の確かめ（出典を読む、動かす）を、単独で頼むことがあるか。または、他のskillやリポジトリが、今それを求めているか。あれば、その仕事は別skillにする。無ければ、レールの内部の指示にする。

#### 検討記録（論点36・イテレーション2）

分ける理由の基準は、`skill-update-review`の切り出しの判断（固有の判断・状態・完了条件・改訂理由、別skillには今ある外の求め）が、提案1の三つの候補の上位互換だった。層fileはレールの内部の指示に当たるため、複数の層に求められることは別skillにする理由ではなく、置き場所の理由に回る。吟味済みの二つの層に当てると、候補を探すことは層fileに入り、覆い方の対案は置き換わり、事実を確かめることと見積りは層fileから分けてレールの内部の指示になる。別skillにするかは、レールの外からの今の求めがあるかで決まり、利用者に問う。

### イテレーション3（論点36）: 専門の仕事を層の決め方から分ける理由を、層と仕事の意味から出す

#### 提案3（論点36）

##### 起点: 旧レールが材料を問いから分けた理由

旧レールは、二つの理由で、材料を問いから分けていた。

| 理由 | 記録 |
| --- | --- |
| 問いは判断を持ち、材料は判断の根拠になる専門の仕事を持つ | 「材料を問いと分けたのは、問いが『詰めれば決まる判断』を持ち、材料が判断の根拠になる専門の仕事（調査、見積り、体験の設計、ロジック・テーブル・モジュールの設計、技術検証）を持つためである」（論点16の提案0）。見積りのskillを立てた理由は「尺度を毎回決めるとブレる」だった（論点17） |
| 答えは上から決まり、根拠は下から来る | 「ラフ画を描くことは『どう作るか』層の行為だが、『何を作るか』層で解き方の案を比べる材料になり、『どこまで作るか』層で最初に作る分の費用を見積もる材料になる」（退避した`what-defines-a-product/README.md`の「答えの依存と材料の供給」） |

今の層は、決めるものを決め、閉じで利用者と合意する所であり、旧の問いの「判断」に当たる。二つの理由が今も成り立つかを、具体の仕事ごとに、層の決め方の中に置いた時と、外に出した時に、何が壊れるかで確かめる。

##### 具体の仕事に当てる

| 仕事 | 層の決め方の中に置くと壊れること | 外に出すと壊れること |
| --- | --- | --- |
| 候補を探す（切り口、手段の種類） | 壊れない。どう解くか層の決めるもの（解き方の選択肢）を作ることそのものである | 実際に壊れた。`propose-alternatives`が対案P1〜P6を丸ごと作り、層の決め方は「選択肢は、材料`alternatives`に求める」（`how-to-solve.md`の決め方の3）だけになった。対案という単位が層の外で決まり、補う点ごとに出して初めて「教室ごとに予約の担当を決めておく」が出た。止める時も二か所に書かれた（提案0） |
| 作る時間を見積もる | どこまで作るか層も、最初に作る分を部品ごとに見積もる（見込み）。中に置くと、その層は方法を写すか、どう解くか層の決め方を読みに行く。写すと尺度が層ごとにずれ、解き方の選定で見た作る時間と、最初に作る分の作る時間を比べられない。また、見積りの方法は、利用者が実際に作った後の見立てと実績で磨かれる。それは、どう解くか層の磨き方と関係が無い | 何のための見積りかを知らないと、粒度を決められない。選択肢の境目を分けるだけでよいのに、全ての選択肢を細かく積む。後で別の層が細かく積み直した時、閉じた層が依った数字が変わる（4へ） |
| 事実を確かめる（出典を読む、動かす） | 確かめ方（公式の文書か第三者の記事か、確かめること自体が規約・安全に触れるか、今も使えるか）は、どの決めるもののための事実かに依らない。例えば、LINE Notifyが提供を終えたかを確かめる方法は、解き方を選ぶ時も、どう作るか層で使うものを選ぶ時（見込み）も同じである。中に置くと、求める層ごとに写すことになる | 決め手に効かない事実まで調べる。どの事実の、どの境目が依るかを、求める側が渡す必要がある。また、利用者しか知らない事実は、調べる仕事ではなく、認識合わせで問う（論点31） |
| 体験の流れと画面を描く | どう作るか層では、決めるもの（体験、画面）そのものであり、中に置く。ただし上の層は、作る時間を部品で積むために、粗い画面の枚数を、どう作るか層が開く前に求める（見込み）。どう作るか層の中だけに置くと、上の層は、どう作るか層の答えを先に決める（上の答えが変わると答え直しになる）か、形を見ずに見積もる（論点16の「約16時間」には内訳が無かった）しかない | どう作るか層でも外に出すと、候補を探す仕事と同じく、決めるものが層の外で作られ、層が殻になる |

##### 分ける理由

当てた結果から、分ける理由を次とする。

- 分けない: 仕事が出すものが、求める層の決めるものそのものである時。外に出すと、決めるものが層の外で作られ、単位も止める時も層の外で決まる。候補を探す仕事で、実際にこれが起きた。
- 分ける: 仕事が出すものが、求める層の決めるものではなく判断の根拠であり、かつ、その仕事のやり方が、どの判断のための根拠かに依らない時。中に置くと、求める層ごとにやり方を写して尺度がずれ、やり方の学び（実際に作った後の見立てと実績、調べ方の学び）が溜まる所も無い。見積りと、事実を確かめる仕事がこれに当たる。
- 1だけでは決まらない: 同じやり方が、ある層では決めるものを作り、別の層では根拠を作る時。体験の流れと画面がこれに当たる（心臓部・テーブル・モジュールも、見積りが求めるなら同じになる見込み）。層によって役が変わるため、3（結びつき方）と4（持ち方）で、仕事と層の組ごとに決める。

旧レールの二つの理由との関係は、次のとおりである。

- 一つ目（判断と、根拠を作る専門の仕事を分ける）は、「分ける」の条件として残る。ただし旧では、判断の中身そのもの（対案）まで専門の仕事に入れていた。「分けない」の条件は、これを外すために足した。
- 二つ目（答えは上から、根拠は下から）は、「1だけでは決まらない」仕事が起きる元であり、分ける理由ではない。3・4で扱う。

複数の層に求められることは、理由そのものではない。やり方が判断に依らない仕事は、多くの層に求められやすく、その表れである。

##### 外に出す時に要ること（3・4へ渡す）

外に出すと壊れることから、分けた仕事が成り立つ条件が出る。

- 求める側が、何を、何のために（どの境目が依るか）、どの粒度で求めるかを渡す。分けた仕事は、粒度を自分で決めない。
- 分けた仕事は選ばない。根拠を出すだけにする。
- 後で育てた時に、閉じた層が依った根拠が変わることの扱いは、4で決める。

##### 吟味済みの二つの層の仕事に当てた結果

| 仕事 | 1の結果 |
| --- | --- |
| 候補を探す（切り口、手段の種類、先に問う毎日開く道具と今のしのぎ方） | 分けない。どう解くか層の決め方に入れる |
| 覆い方の対案を組む | 分けない。解き方の選択肢に置き換わった |
| 作る時間を見積もる | 分ける。見積りが求める利用者の事実（過去の見立てと実績）も、こちらが持つ。問うのは認識合わせで行う |
| 事実を確かめる（出典を読む、動かす） | 分ける。動かす方法は退避中で、未吟味である |
| 声を集める | 分ける見込み（判断の根拠であり、やり方は判断に依らない）。退避中で、未吟味である |
| 体験の流れと画面、心臓部・テーブル・モジュール | 1だけでは決まらない。3・4で決める |

`propose-alternatives`は、分けない仕事（候補を探す、対案を組む）と、分ける仕事（事実を確かめる、見積り）を一つに持っていた。結果の`alternatives.md`の置き場所が一つに決まらなかったのは、このためである（提案1の見立て）。`propose-alternatives`をどうするかは、5（置き場所）まで決めてから、まとめて決める。

#### 検討記録（論点36・イテレーション3）

旧レールが材料を分けた二つの理由（判断と根拠の専門の仕事を分ける、答えは上から根拠は下から）を起点に、候補を探す、見積り、事実を確かめる、体験の四つで、層の中に置いた時と外に出した時に壊れることを当てた。候補を探す仕事は、外に出した時に実際に壊れていた（単位と止める時が層の外で決まった）。見積りと事実を確かめる仕事は、やり方が判断に依らず、中に置くと写しと尺度のずれが起きる。体験は、層によって決めるものにも根拠にもなり、1だけでは決まらない。

### イテレーション4（論点36）: 専門の仕事を、skillに切り出す理由

#### 提案4（論点36）

##### 1が問うこと

専門の仕事を、skillに切り出すか。切り出さない時は、層を決める者が、決め方の手順の一つとして自分で行う。違いは、誰が行うかである。skillに切り出すと、求める側は、何を、どの粒度で求めるかを渡し、skillが行って結果を返す。求める側は、その仕事を自分では行わない。

やり方をどこに書くか（層file、層に共通の所、skillの中）は、この問いに含めない（5）。

そのため、切り出す理由は、行う者を分けないと満たせないものに限る。やり方の書き場所を変えれば満たせる理由（層ごとにやり方を写さない、尺度を揃える、学びを一か所に溜める）は、置き場所の理由であり、5で使う。

##### 行う者を分けないと満たせないもの: 根拠を、選ぶ者の望みから離して作る

このレールは、選ぶ者の望みが判断を曲げることを、繰り返し防いできた。満たすべき条件を、選択肢を見る前に固めるのは、作りたい人が、作らない道の満たせない条件を足すことを防ぐためである（`what-must-hold.md`の冒頭）。旧レールの材料skillは、「材料を作るだけで、問いへ答えない。選ぶことは`settle-question`が行う」とした。

選ぶ者が、選ぶための根拠も自分で作ると、根拠が望みに寄る。

| 根拠 | 選ぶ者が自分で作ると |
| --- | --- |
| 作る時間 | 作りたい選択肢の部品を少なく数え、楽観の側に置く。一般に、個人の計画は楽観に寄る。`how-to-solve.md`が補正を求めるのも、そのためである |
| 当てにする事実 | 選びたい選択肢を支える事実を探し、見つかった所で止める。支えない事実（提供を終えた、無料の上限が小さい）を探しに行かない |
| 声 | 自分が思う痛みを支える声を集める |

skillに切り出すと、行う者は、選ぶ者の望みを受け取らず、何を、どの粒度で求めるかだけを受け取る。選ばずに、根拠と、確かめた方法と限界を返す。これは、行う者を分けて初めて成り立つ。選ぶ者の決め方の中に「望みに寄せない」と書いても、同じ者が望みを持ったまま行う。

##### 切り出さないもの: 出すものが、求める層の決めるものそのもの

仕事が出すものが、求める層の決めるもの（閉じで利用者と合意するもの）そのものである時は、切り出さない。切り出すと、選ばないはずの者が、決めるものを作ることになる。

これは実際に起きた。`propose-alternatives`が対案P1〜P6を作り、どう解くか層は「選択肢は、材料`alternatives`に求める」とだけ書いた。選択肢の単位（対案を丸ごと並べる）も、止める時も、層の外の者が決めていた。補う点ごとに出して初めて、「教室ごとに予約の担当を決めておく」が出た。

選択肢を出す仕事にも、選ぶ者の望みは入る（作らない選択肢を出さない）。ただし、出すものが決めるものなので切り出さず、決め方の「どの補う点にも、作らない選択肢と、受け入れ時の着想どおりの選択肢を入れる」で防ぐ。

##### 具体の仕事に当てる

| 仕事 | 出すもの | 1の結果 |
| --- | --- | --- |
| 候補を探す（切り口、手段の種類） | 解き方の選択肢（どう解くか層の決めるもの） | 切り出さない |
| 覆い方の対案を組む | 同上（解き方の選択肢に置き換わった） | 切り出さない |
| 作る時間を見積もる | 解き方の選択肢の払うもの（根拠） | 切り出す |
| 事実を確かめる（出典を読む、動かす） | 当てにする事実と、決め手が依る事実（根拠） | 切り出す |
| 声を集める | 何が成り立てばよいか層の限界で照らす声（根拠） | 切り出す見込み（退避中で、未吟味） |
| 体験の流れと画面を描く | どう作るか層では決めるもの（体験、画面）。上の層では、見積りの部品を数えるための粗い画面（根拠。見込み） | 層によって分かれる |
| 心臓部・テーブル・モジュールを描く | どう作るか層では決めるもの。見積りが求めるなら、上の層では根拠（見込み） | 層によって分かれる |

層によって分かれる仕事は、同じやり方が、ある層では決めるものを作り、別の層では根拠を作る。仕事と層の組ごとに、3で決める。

##### 3への見込み

skillに切り出す仕事は、選ばず、求められたものだけを返すため、どれも層に対して外の専門家の立ち位置になる。層にべったりの仕事は、切り出さない仕事である。そのため3は、層によって出すものの役が変わる仕事（体験、心臓部・テーブル・モジュール）について決めることになる見込みである。

##### 1では決めないこと

- やり方をどこに書くか、切り出したskillと結果をどこに置くか（5）
- `propose-alternatives`をどうするか。中身は、切り出さない仕事（候補を探す、対案を組む）と、切り出す仕事（見積り、事実を確かめる）に分かれる。置き場所（5）まで決めてから決める

#### 検討記録（論点36・イテレーション4）

1を、やり方をどこに書くかではなく、誰が行うかの問いとして立て直した。切り出す理由を、行う者を分けないと満たせないものに絞ると、根拠を選ぶ者の望みから離して作ることが残った。これは、満たすべき条件を選択肢より先に固めることや、旧材料skillが選ばないことと、同じ守りである。切り出さないのは、出すものが求める層の決めるものそのものである時で、`propose-alternatives`が対案を作った時に実際に壊れた。体験と、心臓部・テーブル・モジュールは、層によって出すものの役が変わる。

##### 選択肢を出すまとまりに、切り出す理由を当てる

望みは、どの選択肢が並ぶかに最初に入る。作りたい者は、作らずに済む方向（前提を外す、着想の反証、何もしない）を探しに行かない。並ばなかった選択肢は、後で事実や見積りをどれだけ確かめても、比べる対象にならない。選択肢を出す仕事は、根拠を作る仕事よりも先に、選ぶ者から離す必要がある。

そのため、まとまりのまま切り出す。

##### 対案P1〜P6で壊れたことは、切り出す時の条件として3へ渡す

切り出しても、skillは単位と止める時を自分で決めない。求める側が渡すものは、次になる見込みである。

- 単位: 補う点（どう解くか層の決め方の1・2で、出どころと基準から出す）
- 粒度: 何のために（どの境目を分けるために）、どこまで要るか

層を決める者は、補う点を出し、返ってきた選択肢が層の止める時を満たすかを確かめ、閉じで利用者と合意する。どう解くか層の決め方の1〜5のどこまでを層が行い、どこからをskillが行うかは、3で決める。

### イテレーション8（論点36）: 二つのskillと層の結びつき方

#### 提案8（論点36）

##### 3が問うこと

##### 結びつき方: どちらも、疎結合な外部の専門家

二つのskillは、1で合意した理由（別の専門の判断を持つ、選ばずに並べる、誰がどの粒度で読むかを自分で知る）から、層の決め方の手順ではなく、層が頼む外部の専門家である。

ところが今の姿は、二つの所で、べったりになっている。

| 所 | べったりの姿 | 起きたこと |
| --- | --- | --- |
| skillが層を知っている | `propose-alternatives`の「使う側」の表と、`sketch-experience`の粒度の表は、誰がどの粒度で読むかを、旧の問いの識別子（`what-to-build/solution-shape`等）で持つ。入力も、旧の問いの答え（`what-to-build/requirements`）と`settle-question`の名で書く | 問いのセットを層と決めるものに替えた時、二つの表と入力が、無い問いを指すようになった。`propose-alternatives`は、「問いのセットが変わった時はこの表を直す」と自分に書いていた |
| 層がskillのやり方を持っている | `how-to-solve.md`の決め方の5が、作る時間の見積り方（部品に分けて積む、描かれにくい部品、三点、補正）を写して持つ | 見積り方を磨く時に、skillと層fileの二か所を直すことになる。層fileを読む者には、層が自分で見積もるのか、skillに頼むのかが分からない |

疎結合にするとは、次の三つである。

1. 依存の向きを、層からskillへの一方向にする。層は、skillに何を頼めるか（何のために、何を、どの粒度で）を知る。skillは、層の名前も決め方も知らない。
2. 頼む時に、層は、skillの言葉で頼む。渡すのは、何のためか、何を覆う・描くか（とその条件）、既に分かっている利用者の事実、粒度である。層の決めるもの（満たすべき条件、補う点）を、skillの入力の言葉へ写すのは層である。
3. 読む時に、層は、返った形を自分の決めるものの形へ読み替える。skillの出す形を、層の形に合わせさせない。層が持つのは、受け取る時の基準（揃っているか、外れている時）であり、skillのやり方ではない。基準を満たさない時は、何が足りないかを付けて頼み直す。

skillの「使う側」と粒度の表は、誰がどの粒度で読むかを自分で知ること（1で合意した理由）そのものなので残す。持ち方を、旧の問いの識別子から、何のために読むかへ替える。例えば、作らずに覆えるかを見る、どの道で覆うかを選ぶ、依存するあり物の規約と継続性を見る、作る部分を部品ごとに見積もる、画面の枚数と主要な操作で作る時間を積む、全ての画面を決める、である。何をどの粒度で読むかの中身と、skillの判断・手順・水準は変えない。

旧のレールの頼み方（`archive/what-defines-a-product/README.md`の「材料」節。依頼した側が場所、要求した問い、粒度を渡す。skillは問いに答えない。skillは利用者へ問わず、依頼した側へ返す）が、この形の元である。要求した問いの識別子を、何のためかに替えれば引き継げる。

##### skillが別のskillを要る時

今のとおり、依頼した側へ返す。`propose-alternatives`は、作る部分の形が見積りに要る粒度に足りない時、依頼した側へ返し、依頼した側が`sketch-experience`に頼む。skillが直接頼むと、どの層が何のために、どの粒度で作らせたかが、層から見えなくなる。それは、4（一つを育てるか、層ごとに持つか）を決める時に要る。

## 論点39: 層をどの順で、いつ閉じ、閉じた後に返ってきたものをどう扱うか

##### 1. 層の順: 前の層が閉じてから、次の層を始める（摩擦29）

試運転では、何が成り立てばよいか層の採否（論点2 手の外の扱い、論点3 妻の安心）が応答待ちのまま、どう解くか層を進めた。その時、どう解くか層の記録に「応答待ちの二つは、この層の物差しを変えない」と書いた。これは誤りだった。論点2の「寄せる」を取ると、「欠席したその週のうちに予約する」という条件が増え、物差しが変わる。論点3も、なぜ作るか層がアウトカムに妻の安心を入れれば、条件を導き直すことになる。

物差しを変えうる採否が残ったまま選択肢を見ると、その採否が選択肢に寄る。例えば、作りたい一覧の束が「その週のうちに予約する」を満たしにくければ、「受け入れる」を選びたくなる。層を分けて先に閉じる理由（`what-must-hold.md`の冒頭）そのものである。

##### 2. 閉じた層への差し戻し（摩擦26、論点20、論点36の決定の4）

差し戻しは、次の時に起きる。

| 起き方 | 例 | 返す者 | 返す先 |
| --- | --- | --- | --- |
| 後の層の決め方で、崩れの元が前の層の側にあると分かる | どう解くか層の決め方の4で、規則が変わって古い期限を言えても満たすと出て、条件1の確かめ方が緩いと分かった | 後の層 | 前の層 |
| 材料が、閉じた層の読んだ所を変える | どこまで作るか層が部品を細かく積み直し、どう解くか層の選定が読んだ作る時間が変わる | skillが、今の依頼の返しに添える。依頼した層が受ける | 読んでいた層 |
| 前提にする条件が足される | どう解くか層で、子どもの情報を外部へ送らないと決まる | 足された層 | 閉じた全ての層 |

役割を次のように分ける。論点20で違和感が示された「全体制御が答え直しを決める」は取らない。

| 役割 | 持つもの | 中身 |
| --- | --- | --- |
| 開け直すかを判じる | 返された層（その層fileの決め方） | 返されたものが、自分の決めるものの何に効くかを、自分の決め方で見る。どう解くか層なら、選び直す条件（決め手の境目の得るもの・払うもの・当てにする事実が変わった時）に当たるかを見る。境目が動かなければ、開け直さずに「確かめ直した。変わらない」と書く。何が成り立てばよいか層なら、返された崩れ方を決め方の2で分け、打ち手を決める |
| 返し方と記録の仕方 | 共通の所 | 返す側は、層の記録に、何を見つけ、どの層の何に返したかを書く。返された側は、層の記録の状態を「開け直し」にし、「差し戻し」の節に、何が、どこから返り、前の姿と直した後を書く。直した後、閉じで利用者と合意し直す |
| 順に回す | 進め方（`grow-product-idea`） | 返された層を先に直して閉じ直し、その後で、その層を物差しや入力にしている下の層に、確かめ直しを回す。下の層も、開け直すかを自分で判じる。進め方は判じない |

正本には今の決めるものだけを書き、前の姿は層の記録の「差し戻し」の節に残す（論点38の正本の役割のとおり）。

##### 4. 層の閉じで示すもの（摩擦38）

試運転では、どう解くか層の出どころの事実（夫も教室のアプリにログインしている）が、材料の論点（そのアカウントを家族で使ってよいか）に依っていた。材料の論点は材料の決定過程にあり、層の閉じで示す決まりが無かった。

##### 5. 前提にする条件（摩擦40）

前提にする条件は、満たすべき条件とは別のものである。満たすべき条件は、アウトカムの言い分から出る。前提にする条件は、利用者が、どの手段にも課す制約である（子どもの情報を、家族の二人以外に見せない）。アウトカムの言い分からは出ないため、何が成り立てばよいか層の決め方では出てこない。

- 出た層の決定過程で、論点として立てる。利用者が、他の選択にも効く制約だと確かめる
- 合意したら、正本の「前提にする条件」に書き、根拠としてその論点へlinkする
- 閉じた層があれば、2の差し戻し（前提にする条件が足される）として回す

層の順は、試運転で物差しを変えないと書いた採否が、実は物差しを変えうると分かったことから、前の層が閉じてから次を始める形にした。例外を置かないのは、見分けることを選択肢を見たい側が行うためである。差し戻しは、論点20で違和感が示された全体制御が決める形を取らず、開け直すかは返された層が自分の決め方で判じ、進め方は順に回すだけにした。層の閉じでは、依っている材料の論点も示す。前提にする条件は、アウトカムの言い分から出ない、どの手段にも課す制約として、出た層の論点で確かめて正本に書く。

- 差し戻し: 後の層の決め方で前の層に元があると分かった時、材料が閉じた層の読んだ所を変えた時、前提にする条件が足された時に起きる。開け直すかは、返された層が自分の決め方で判じる（どう解くか層なら選び直す条件）。返し方と記録の仕方（返す側の層の記録に書く、返された側は状態を開け直しにし「差し戻し」の節に前の姿と直した後を書き、閉じ直す）は共通の所に書く。順に回すのは`grow-product-idea`で、判じない

## 論点40: 層fileの決め方の決まりのうち、実物に当てて満たせない、または重すぎる所をどう直すか

**ステータス:** 決定

**親論点:** 論点37

**種別:** 提案

論点37の束C（層fileの決まり）である。振替の件の試運転で、層の記録の確認に「一部」と書いた所を直す。

### イテレーション0（論点40）: 四つの決まり

#### 提案0（論点40）

##### 摩擦25: 崩れる日を作る進め方と、その記録（`what-must-hold.md`の決め方の2）

試運転で起きたこと: 言い分×五つの進め方の表にすると、「作ろうとした」が、作れた日か「作れなかった」の枡で見えた。一方で、「作ったものを止める」は、条件の段では作るものが無く、どの言い分でも作れなかった。また、二人とも締切の7日前に気づいたのに、二人とも相手が予約すると思った日は、どの進め方から出したとも言いにくかった。

直し:

- 何が成り立てばよいか層の進め方を、四つ（時を進める、人を抜く、置き場所を見比べる、外を変える）にする。作ったものを止めるは、手段が無いと問えないため、どう解くか層の決め方の4で問う（今もそこにある）
- 進め方は、日を作るための手がかりであり、日の分類ではない。どの進め方からとも言いにくい日は、そのまま書く
- 「揃えば満たした」を、「言い分×進め方の全ての枡に、作れた日（崩れ方と打ち手）か、作れなかったことが書かれている」にする

##### 摩擦30: 着想どおりの選択肢（`how-to-solve.md`の決め方の3）

試運転で起きたこと: 「どの補う点にも、作らない選択肢と、受け入れ時の着想どおりの選択肢を入れる」が、補う点2（誰が予約するか）では満たせなかった。着想（期限の前にLINEで知らせる）に当たるものが無い。

この決まりの目的は、着想を比べる対象から外さないことである（決め方の3の本文）。着想が触れない補う点に、着想どおりの選択肢を無理に作ると、目的に無い選択肢が増える。

直し: 「どの補う点にも、作らない選択肢を入れる。受け入れ時の着想が触れる補う点には、着想どおりの選択肢を入れる。着想が触れない補う点は、触れないと書く」にする。

##### 摩擦31: 崩れやすい時点で問う範囲（`how-to-solve.md`の決め方の4）

試運転で起きたこと: 「全ての選択肢について、五つの時点で問う」は、選択肢が十を超えると五十を超える問いになる。試運転では、選択肢ごとに効く時点だけを問うた。例えば、ついでに渡す選択肢（欠席を連絡した直後に予定を作る）には時を進める（習慣が薄れる）を、scriptの選択肢には作ったものを止めるを、一覧に写す選択肢には置き場所を見比べるを当てた。

効く時点は、選択肢の受け渡しから決まる。決め方の3のきっかけの表が、きっかけごとの「崩れる時」を既に持っている。

| 受け渡し | 効く時点 | 決め方の3の「崩れる時」 |
| --- | --- | --- |
| ついでに渡す | 時を進める、人を抜く | 出来事が、いつもと違う人・違う道で起きる時 |
| 知らせを受けて渡す | 外を変える、人を抜く | 知らせの来ない変化がある時。知らせが二人に届き、どちらも動かない時 |
| 決まった日に見比べる | 時を進める | 決まった日を起こす通知が無く、習慣に頼る時 |
| 自動で渡す | 作ったものを止める、外を変える | ― |
| 同じ情報を二か所に置く | 置き場所を見比べる | ― |

直し: 「選択肢（組を含む）ごとに、受け渡しから効く時点を選んで問う。選ばなかった時点は、なぜ効かないかを一行で書く」にする。「揃えば満たした」も同じにする。

##### 摩擦32: 得るもの・払うものの軸（`how-to-solve.md`の決め方の5）

試運転で起きたこと: 「選択肢（組）ごとに、八つの軸が埋まる」に対し、選ぶ所ごとにまとめて書き、どの選択肢でも値の無い軸（変化に強くなる、満たさない条件）は省いた。比べるのに要るのは、選択肢の間で差のある軸だった。

八つの軸の目的は、一つの軸だけで比べること（「作る時間が短い」）を防ぐことである。全ての枡を埋めることではない。

直し: 「揃えば満たした」を、「選択肢（組）ごとに、値のある軸が全て書かれている。どの選択肢でも値の無い軸は、無いと一行で書く。作る時間は部品ごとの三点で、補正の有無が書かれている」にする。外れている時（一つの軸だけで比べる）は残す。

##### 決めないこと

- 層fileの文面（論点36の行うことの2と一緒に直す）

#### 検討記録（論点40・イテレーション0）

試運転で確認に「一部」と書いた四つの決まりを、決まりの目的に照らして直した。作ったものを止めるは、手段の段でしか問えないため、どう解くか層へ寄せた。着想どおりの選択肢は、着想が触れる補う点だけにした。崩れやすい時点は、決め方の3のきっかけの表の崩れる時から、受け渡しごとに効く時点を選ぶ形にした。八つの軸は、全ての枡ではなく、値のある軸を全て書く形にした。

#### 提案0へのフィードバック（論点40）

**結果:** 合意（摩擦30・32の直し）。摩擦25は指摘と枠組みの提示。摩擦31は、assistantがゼロベースで厳しく見直したうえで良いなら良い

摩擦25について。手段が崩れる時（作ったものが止まる等）は、論点26で、どう解くか層の確かめ方（崩れやすい時点で問う）に入れた。ところが論点26は、同じ五つの進め方を、何が成り立てばよいか層の崩れる日の作り方にも足した。そのため、手段の側の進め方が、条件の層へ戻ってきていた。手段の側は、どう解くか層で問う。

何が成り立てばよいか層で崩れる日を作るのは、条件を一つずつ見ても分からない、条件同士の関連を見定め、条件群の輪郭を捉えるためである。

### イテレーション1（論点40）: 崩れる日の枠組みと、崩れやすい時点の選び方の見直し

#### 提案1（論点40）

##### 摩擦25: 崩れる日は、条件群の輪郭を捉えるために作る

何が成り立てばよいか層の決め方の2の目的を、次のように言い直す。

> 条件は、一つずつ見れば、それぞれ正しく書けていることがある。それでも、全ての条件が成り立つのに言い分が崩れる日があるなら、条件と条件の間に隙間がある。崩れる日は、条件同士の関連を見定め、条件群の輪郭（どこまでを覆い、どこに隙間があるか）を捉えるために作る。

振替の件で、どの進め方からとも言いにくかった日は、この枠組みで最もよく説明できる。二人とも締切の7日前に気づいた（条件5は成り立つ）が、二人とも相手が予約すると思い、どちらも予約しなかった。気づくことと予約することの間に、誰が予約するかという隙間があった（条件6を足した）。条件を一つずつ見ても、この隙間は見えない。

進め方は、日を作る手がかりとして、次の四つにする。

| 進め方 | 問うこと |
| --- | --- |
| 条件の間を辿る | 言い分に沿って、ある条件が成り立った次の一歩が、どの条件にも無いことは無いか（気づいた次に、誰が予約するか） |
| 時を進める | 一週間後、三か月後、一年後に、言い分はまだ成り立っているか |
| 人を抜く | 片方が二週間いない時、片方が忙しい月に、言い分は成り立っているか |
| 外を変える | 相手の決まり、使っている道具が変わった時に、言い分は成り立っているか |

置き場所を見比べると、作ったものを止めるは、何が成り立てばよいか層から外す。どちらも、手段（こちらの記録、作ったもの）が無いと問えない。どう解くか層の決め方の4で問う（今もそこにある）。どう解くか層の決め方の4は、時点を「満たすべき条件の決め方の2と同じ五つの進め方で選ぶ」と書いているため、自分の時点として持つように直す。

「揃えば満たした」は、「言い分×進め方の全ての枡に、作れた日（崩れ方と打ち手）か、作れなかったことが書かれている」にする。

##### 摩擦31: 崩れやすい時点の選び方を、ゼロベースで見直す

提案0は、選択肢の受け渡しの種類（ついで、知らせ、決まった日、自動、二か所）から、効く時点を選ぶ形にした。これを厳しく見直すと、次の穴がある。

| 穴 | 振替の件で落ちるもの |
| --- | --- |
| 受け渡しの種類だけで選ぶと、当てにする事実が落ちる。事実は、相手が変えれば崩れる（外を変える） | 基準（教室のアプリを直接見る）は受け渡しを持たないため、どの時点も選ばれない。教室のアプリが振替の残りを見せなくなる日を問えない |
| 計算（規則から期限を出す）は、受け渡しの種類に無い。規則が変われば崩れる（外を変える） | 試運転で外を変えるを問うた3ア・3イ（規則のメモ、計算式）は、提案0の表からは選ばれない |
| 人を抜くを、ついでと知らせにしか当てていない。人が行う全ての受け渡しと、家族の決めごとに効く | 決まった日に見比べる（補う点5）と、教室ごとに担当を決めておく（2イ）に、人を抜くが選ばれない。2イは、人を抜く日（担当の夫が出張）で確かめるべき選択肢そのものである |
| 選択肢ごとに問うと、同じ部分を何度も問う | 家族のカレンダーの通知は、1アにも1イにも入っており、二度問うことになる |

試運転そのものも、直感で時点を選んでいて問い足りなかった。1アに外を変える（カレンダーの通知の仕様が変わる）を、3ア・3イ・5に人を抜くを、問うていない。

崩れやすさは、選択肢そのものではなく、選択肢を組み立てる情報の流れの要素（置き場所、受け渡し、当てにする事実）が持つ。選択肢は、決め方の3で既に、要素で書かれている。そのため、時点は要素ごとに選び、要素ごとに一度だけ問う。選択肢は、自分の要素の答えを受け継ぐ。

| 情報の流れの要素 | 効く時点 | なぜ効くか |
| --- | --- | --- |
| 人が渡す受け渡し（担い手がいる） | 人を抜く。きっかけが習慣に依る時（ついで、決まった日、覚えていて）は、時を進めるも | 担い手がいない日がある。習慣は薄れる |
| 自動で渡す受け渡し（作ったもの、あり物の通知） | 作ったものを止める（作ったものの時）、外を変える | 黙って止まる。あり物の仕様が変わる |
| 当てにする事実（相手の仕組みが見せるもの、相手の決まり、あり物の振る舞い） | 外を変える | 相手やあり物の側が変える |
| 置き場所のうち、同じ情報の二か所目（写し） | 置き場所を見比べる | 片方だけが変わる |
| 置き場所のうち、家族の決めごと（担当等） | 人を抜く | 決めた人がいない日がある |

一緒に選ばないと成り立たない組は、組の中の置き場所どうしにも、置き場所を見比べるを問う。

振替の件に当て直すと、提案0の表で落ちた五つ（基準の事実、3ア・3イの規則、5と2イの人を抜く、1アの通知の仕様）が全て選ばれる。カレンダーの通知は一度だけ問う。

この形で、元の決まり（全ての選択肢を、五つの時点で）の目的である、問うべき時点を落とさないことは保たれる。要素は情報の流れに全て書かれ、要素の種類ごとに効く時点が決まっているためである。問う数は、選択肢の数ではなく、要素の数で決まる。

直し:

- 決め方の4を、「情報の流れの要素ごとに、要素の種類から効く時点を選んで問う。選択肢は、要素の答えを受け継ぐ。組は、組の中の置き場所どうしも見比べる」にする
- 「揃えば満たした」を、「全ての選択肢の要素について、種類から効く時点で確かめ方を問い、答えられない所の扱いが決まっている」にする。選ばなかった時点の理由は書かない（種類から決まるため）

#### 検討記録（論点40・イテレーション1）

摩擦25は、論点26で手段の側の崩れを確かめ方へ入れたのに、同じ五つの進め方を条件の層にも足したため、手段の側の進め方が戻ってきていた。条件の層の崩れる日は、条件同士の関連を見定め、条件群の輪郭を捉えるために作る、と目的を言い直すと、どの進め方からとも言いにくかった日（気づくと予約の間の隙間）が最もよく説明でき、進め方に「条件の間を辿る」が加わった。摩擦31は、受け渡しの種類で選ぶ形を見直すと、当てにする事実、計算、決めごと、人を抜くの当て先が落ち、同じ部分を何度も問うていた。崩れやすさは情報の流れの要素が持つため、時点を要素ごとに選んで一度だけ問う形に直した。

### 決定（論点40）

- 何が成り立てばよいか層の決め方の2: 崩れる日は、条件同士の関連を見定め、条件群の輪郭を捉えるために作る。進め方は、条件の間を辿る、時を進める、人を抜く、外を変える、の四つにする。置き場所を見比べると、作ったものを止めるは、どう解くか層の決め方の4で問う。「揃えば満たした」は、言い分×進め方の全ての枡に、作れた日か、作れなかったことが書かれていることにする（提案1）
- どう解くか層の決め方の3: どの補う点にも作らない選択肢を入れる。着想どおりの選択肢は、着想が触れる補う点に入れ、触れない補う点は触れないと書く（提案0）
- どう解くか層の決め方の4: 時点を自分の五つとして持つ。情報の流れの要素ごとに、要素の種類から効く時点を選んで一度だけ問い、選択肢は要素の答えを受け継ぐ。組は、組の中の置き場所どうしも見比べる（提案1。利用者は、よく分からないとの留保付きで合意）
- どう解くか層の決め方の5: 選択肢（組）ごとに値のある軸を全て書き、どの選択肢でも値の無い軸は無いと一行で書く（提案0）
