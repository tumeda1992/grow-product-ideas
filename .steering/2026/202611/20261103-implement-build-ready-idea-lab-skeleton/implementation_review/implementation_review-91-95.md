#### 利用者の指示（論点91）

> ok。あと、直近の往復について、エスカレ対象にしておいて。適用は後で。何をエスカレ対象にするかは、codexでtask-designする時に限り、雲を掴むような茫洋な抽象的なことを決めるときには、進め方を決める論点を作ってほしいということ。1つの論点ではなく、今回だったら、abcで進めるという全体の進め方、aについての進め方、bについて、aと混ぜてbの表層の進め方、bの実質の進め方について分けること。最後に検証1本通すのではなく、小さなブロックで完結したら検証通して、安定性のある確定したブロックを増やして最後に検証でちゃぶ台返ししないようにすること。つまりは、進め方が自明じゃない時に進め方自体を論点とするって言うこと。進め方自体に軌道修正があったら、新しいイテレーション立てて。そうすれば同じ論点で話が進まず堂々巡りになったり、一気に話を詰め切ってないのに進めようとするとかもなかったはずだから。こう思うと、今回ってロードマップにすればよかったかもって思った。

#### 保存内容0（論点91）

Codexでtask-designを行う時に限り、抽象的で進め方が自明でない設計では、進め方そのものを論点とする改善を、[007の保留メモ](../pending-escalations/007-codex-design-process-and-local-validation.md)へ保存する。
全体の進め方、各段の進め方、隣の段と重なる表層、実質の詰め方を、異なる判断の単位として分ける。進め方の軌道修正は、その進め方の論点の新しいiterationへ残す。
小さなまとまりが完結するごとに検証し、確定したブロックを増やす。最後の全体の検証に必要な確認を全て預け、そこで全体の前提が大きく崩れる進め方を避ける。
適用は後で、という指示に従い、plugin側への引渡し・skillの改稿・今の作業への暫定適用はまだ行わない。後の明示的な再開指示を待つ。作業完了や設計完了で自動的に適用する条件は補わない。

## 論点93: 選定を左右する技術の性質を、検証担当へ依頼して比較へ戻す

**ステータス:** 反映済み

**種別:** Bの実行方法の詳細化・技術依頼の接続

### イテレーション0（論点93）: 未吟味という旧記述を、依頼・受領・未確認の扱いへ置き換える

#### 提案0（論点93）

**how-to-solveの「解き方の選定 → 1. 決め手が依る事実を確かめる」を、比較を変える技術の問いをverify-technical-feasibilityへ依頼し、返った事実・不足を候補と費用へ戻す方法へ更新する。**

今は同節に「頼む先のskillを、まだ吟味していない」とある。一方、76で技術検証の方法は利用可能であり、83と88では選定前にも必要な専門の根拠を得る構造を採用した。未確認の両側で比較することは残しつつ、取得可能な根拠を取得せず通す経路を直す。

##### 依頼と返りを、選ぶ仕事へ戻す

```text
比較の境目が依る、未確認の技術の性質
  -> 答えで何が変わるか、対象・条件・既存根拠・使える操作範囲を渡す
  -> verify-technical-feasibilityが事実・反例・未取得と限界を返す
  -> how-to-solveが同じ対象と条件へ照合して受ける
       + 根拠が足りる -> 候補の流れ・保証を更新し、費用と人の負担を再見積もり
       + 足りない   -> 不足を返す／両側で比較し、保留・別案・実験版を採否へ
```

例えば、外部の予定を自動で作る道を選ぶ決め手が「止まっても人が一件ずつ調べなくて済む」なら、正常に返ったIDで予定を取れたという結果だけでは足りない。結果保存前に止まり、手元にIDが無くても何を根拠に照合できるかを問う。返った結果が別条件なら頼み直し、照合・訂正する部品や人の作業が増えるなら、候補の比較と費用へ戻す。
候補全ての本実装を先に作る指定は置かない。既存の根拠で足りる所は再利用し、手元で再生成するだけの案に外部APIの検査を課さず、今回の比較に効く問いと粒度から頼む。

##### 未確認でも比較は続けられるが、成立済みへは替えない

技術の対象へ届かなければ、未取得の理由と答えの両側の比較を残す。技術的に不可能と決めつけず、確認済みの改善にも替えない。
保留、別の根拠で成立する道、未知を調べる実験版を選ぶ余地は残す。実験版なら、試す範囲、得られない改善と負担、何を観測して見直すかを利用者の採否へ載せる。
選んだ版を実施するために不可欠な未確認は設計へ引き継ぎ、閉じる前に根拠を得るか、その未知に依らない版へ選び直す。部分的な改善や未知を引き受ける判断を禁止せず、何の約束を届けられる版かを区別する。
