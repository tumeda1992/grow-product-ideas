# 保留メモ: テーマの解消から逆算して指摘一覧も再レビューする

## 保留時の内容

対象: tumeda-devのexhaustive-reviewと、それを実行するAstraレビューの終了判定。関連: https://github.com/tumeda1992/ai_agent_dev_skill_plugin/issues/16

提案: 挙動維持を全レビューの暗黙の前提にせず、利用者が指定したテーマを保持する。一周の指摘抽出後、既存指摘を全て解消すればテーマを満たせるか、指摘一覧自身をレビューする。原因・重要度・修正範囲・依存・欠けを再評価し、必要なら指摘を磨き、別の観点から対象を再走査する。重要な未説明の崩れが残る間は繰り返す。残る候補がテーマの達成に寄与しない些末なものだけなら、水増しせず終了する。

具体例と根拠: 一回目の修正後に同じテーマで追加の重要問題が見つかると、利用者はレビューと反映を何度も依頼する必要がある。項目が多いことや周回数ではなく、「この指摘集合の解消でテーマへ届くか」という不足の検討が必要である。未確認や検証限界は明示し、未知の欠陥が存在しないという保証とは区別する。

出典: 2026年11月21日、このセッションで利用者が全件適用・再レビュー・その後のプラグイン反映を指定した発言。以下は原文。

> もうレビュー指摘全部適用して良いや。それ終わったらコミットプッシュして。その後、少し大きい企画（前のレビュー意図のやつ）に対してもちゃんと回せるか、スキル使ってastraでレビューして。ゼロベースで厳しくレビューして。再度回したくないから、あげられるところは全部あげつくして。これですら2周目だから。それは重箱の隅をつついて重要なやつを逃すことを許容する、という意図ではなく、重要なやつ中心に指摘をあげるんだけど、1周回った後にもう1周見て上がった指摘以外に今回のテーマ上での指摘がないか洗い直して、終わったらまたやってを繰り返して、指摘点が上がらなくなったら、つまり、それらを直しきればテーマについての問題はなくなると言える状態まで、指摘をちゃんとあげて。
>
> これ終わった後、コミット・プッシュだけど、同時にエスカレ案件としてもあげたい。astra使うレビュースキルのやつ、 https://github.com/tumeda1992/ai_agent_dev_skill_plugin/issues/16 の反映としても機能させて今回の指摘も一緒に反映していいかも。挙動を変えないはテーマの1つに過ぎなくて、「レビューして」はテーマに沿って1周レビューするだけでなく、その指摘点を全てクリアしたらテーマが解消して、1回の指摘反映後に何周も回さなくてもいいように、するってこと。
> これは今回の指示には入れてなかったけど、1周目で出したレビュー指摘自体をレビューして、それが解消されると、テーマが解消されるのかをレビューして、そうでない場合は、どうやったらテーマの解消ができる指摘になるのかとブラッシュアップしたり、もう1周レビューしたり、必要なことを行う。別の観点の指摘として、何周も回していると、新しく出る指摘が重箱の隅の指摘ばかりになる可能性がある。それらが解消して価値がない指摘で、その時点で既存の指摘点を解消すればテーマが満たせるならレビューを打ち切るとかもする指摘自体のレビュー。
>
> 進め方は、
> - 今のスキル使ったastraのレビューのブラッシュアップ点を保留エスカレ項目にあげる
> - 前のレビュー指摘をスキルに従って修正。終わったらコミット・プッシュ
> - スキル使ってastraでレビュー。終わったら指摘点をディスカッションに反映し、コミットしてプッシュ
> - 今回のエスカレ対象だけを個別でプラグインに適用
> - このリポジトリに戻ってきて、レビューの指摘点をディスカッションで1つずつユーザと解消

保留指示と再開条件: 現行レビューの全件適用とcommit・push、その後のAstra再レビュー結果のdiscussionへの保存とcommit・pushが完了した後に、この改善だけをプラグインへ引き渡して適用する。現在の再レビューは現行skillと上記の利用者の明示指示に従い、プラグインの先行改稿は行わない。

合意の範囲: 既存指摘の残り全件の適用・検証・commit・push、今回の再レビューと結果保存・push、このエスカレ対象だけのプラグイン適用まで委任された。再レビューで新しく出た指摘の適用は、製品repositoryへ戻って一件ずつ利用者と解消する。
