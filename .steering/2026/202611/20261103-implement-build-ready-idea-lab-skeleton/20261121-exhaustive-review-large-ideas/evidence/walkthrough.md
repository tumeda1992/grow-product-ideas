# 長文を入口から実装担当まで机上でたどる

[固定した二つの入力](long-inputs.md)を別案件として読む。実在の利用者の返事・料金・API・運営実績は得ていない。以下の「仮に採った枝」は、上流が実際に閉じたという記録ではない。未知に達した位置を明示し、追加設定を一つ置いたときに下流で何を問えるかを追った。A・Bとも実際の採否は未取得である。

## A　依頼文から比較へ

| 原文から拾ったもの | その意味と、判断が変わる境目 |
| --- | --- |
| 服が直って戻る／次回は自分で直し方を選べる／教える人も次に学ぶ | 「預ければ直る窓口」「一緒に学び、次の人へ技が渡る場」「相互に学べる場」は別目標。同じ日に全員の服が直っても、全て裏で直せば後二者は失う。教える係が毎回固定なら相互性も成り立たない。 |
| 第二会場と夜の参加 | 含めると初めて来られる人がいる一方、連携当番が増える。二会場を最初から必須にしない。週末一人20分を跨ぐなら候補を組み直す。 |
| どこが預かり、返せるか／写真の教材利用／断っても同じ順番 | 受付の受領、先生の引受け、営みの終了、本人への物の返還は四つの出来事。教材公開の拒否が参加拒否に化けないことを、どの案でも守る必要がある。 |
| 紙の予約表・手帳・サイト | 前二つは現状の手掛かり。手帳にあることから既に教える人が確約しているとは読めない。サイトは着想。作る指定なしのopen。 |
| 匿名要点だけ引渡し可／検討中は連絡も会場予約もしない | 前者は企画資料の共有先、後者は今回の検討操作。実運用で使える予約・本人への返却まで対象から落とさない。 |

whyの体験理解・価値発見・目標設定を行き来した。依頼者が語った「選べる瞬間」は起点になる。拒否しても教わりたい参加者や夜番の気持ちは未取得。gather-target-user-voicesに渡す問いは「写真を断った後、受付から学ぶ場に戻るまで、誰が何をし、なぜ途中で離れたか」。入力にはその一回の記録がない。別人の成功談では当該第二班の当番や本人の許諾を確かめられない。whyが条件付き候補を保ち、週末20分を左右する受付・照合・返却をpropose-alternativesへ予備照会する。写真を送れることだけで「同じ順番で教わる」に届くとは言えない。

仮に一会場で「同意の選択にかかわらず、持ち主が預け先と返却を確認でき、希望者は次に自分で直す方法を選べる」を選んだ枝を使う。whatの条件例は、①預けた物と受付・現在の保管者を照合できる、②教わる順を決める時、写真利用の可否が同じ条件の人の優先を変えない、③引渡し相手・現物・受領を確認して初めて返却と読める、④教わりたい人が修繕の方法を選ぶ一回に関われる。たとえば紙の札でも①〜③は支えられる。写真を撮らないと服を識別できないという条件は番号札と現物で反証できる。対照として、①〜③だけ真でも全修繕を裏で終えれば選んだ価値は偽になるため④が要る。④がある新版で裏作業だけなら条件違反であり、「全条件真」の反例と数えない。

**同じ上着A17での解き方比較**。原状の予約は一件を受けたという手掛かりに過ぎず、期限内返却や共同作業の事実は未確認。紙の控え＋現物札＋持ち主がその場で一針試す方式なら、受付がペアを確認し、引受けた人に実物を渡し、本人が受け取る直前に控えと現物を照合する。遠隔の人にこの場面は届かない。予約サイト＋同じ現物札は来訪前に引受可否を知らせうるが、手元の物の受領・教材許諾を代行しない。来訪時に次の開催回だけ予約する方式は班をまたぐ連携時間と交換に、今週の修繕を見送る。現状維持は当番移行が不要。全ての案で持ち主が不在・札が重複・別班が返却予定を引き受けていない枝を試した。追加作業も失う機会も同じ基準で比べられる。

**費用の派生例**。仮に平常回を受付4分＋引継ぎ5分＋返却4分、訂正一件を8分とする。平常時13分、一件の訂正時21分。週20分を守れるとはまだ言えず、頻度・交代・打切時に預かった服を誰が返すかが必要。現行のhow-to-solve 180–187、278–291行でこの計算を戻せる。一方、会場へ9,000円先払い・最終日7,000円返還なら純額2,000円でも初日の6,000円枠を超す。先払い3,000円・返還なしは支払える。会場や相手の実在する料金ではない。条件をまたぐのは期間の総額に加えて、立替主体と時点である（LR-006）。

## A　画面と業務を接続する

仮に第一会場でだけ使う受付用の小さい版を比べる。同じ例を専門に渡したときに返せる内容を次に示す。これはレビュー者が各skillの手順に沿って組んだ机上の材料。製品の採用・実装はしていない。

```text
受付当番の控え              引受担当の札                返却担当の控え
A17　上着／第一会場         A17　第一会場               A17　受領確認待ち
旧予約 R7／照合待ち         現物札17を照合［引受］       現物札17・持主控え照合
学び方［一緒に試す］        次の行い　一緒に一針         ［手渡して受領を記録］
教材公開［許可なし］        返却済みの根拠　未取得       ［未引渡しとして引き継ぐ］
```

| 専門で当てた手順 | この一件で返るもの／成立を断定できない境界 |
| --- | --- |
| sketch-experienceで受付→現物札→次の担当へ渡す | 受付画面が表示されても上着は入口の棚にある。現物と札を確認しない画面だけの「引受」は不成立。「教材許可なし」を選んで同じ待ち順へ戻れるかを紙の控えと照合する。 |
| design-core-logicで同じ始点・二つの入力を通す | 仮規則「対応する現物札・控えの組と持ち主の受領で返却確定」。控えA17＋札17＋受領ありは返却、控えA17＋札71は状態を保って要照合。R7と新札7は別起源で番号一致だけで統合しない。 |
| design-data-modelで同じ対象を読み書きする | A17の預り、授受、教材範囲の三つは別。引受をXからYに替えた後も持ち主の教材拒否は変わらない。旧予約、新受付、物品、授受の対応を一意に決める根拠が無いときは仮対応を確定しない。 |
| functional-structure-designで責任の受渡しを確かめる | 受付は受付済みを返す。担当は現物札照合後の引受を返す。返却は持ち主への手渡しで成立。教材利用は別の許諾を読み、完了通知はこの三者の成立を代作しない。 |
| implementation-structure-designで停止・競合を通す | 手渡し直後、記録前に端末停止。次の人の画面には「受領未確認」が残る。同じ札を二度返却済みにせず、控えと現場担当に照合してから訂正する。紙のみ・端末＋紙のどちらで新たな当番が増えるかを費用へ戻す。 |
| verify-technical-feasibilityで実証に必要な問いを特定 | 外部予約製品X（仮）に作成が届き、手元の応答だけを失った場合、復旧担当の手元に残る入力で照合できるか。正解を持つ試験者のIDを使う検査は無効。対象・設定・利用可能な識別子が無いため未確認。二重予約確定を避ける紙の照合は比較できる。 |

受入れの入力は、持主Aの控え、別人の札を途中で混ぜた操作、旧予約の残件、手渡し後の停止。結果は物の現在地／人の未完作業／受け入れた未達に分ける。担当が照合できる根拠、当番の引受け、費用境界が揃わない枝はbuild-readyにしない。openで非開発を選ぶ枝では、日常の紙一巡まで作れても、旧予約R7を既に約束していた人と、新しい札7を渡された人が同時に来る初日を当てた。ソフト版ならhow-to-buildで既存データの導入を問う。同じ業務を紙で行う版にはその受入れを持つ工程が薄い（LR-007）。第二班の担当だけ確定しても教材利用同意は未取得として残る（LR-001）。

## B　混ざった未来を仕分ける

「居られる余白」「返答が届く」「別室へ育つ」は互いに置換できない。同じ部屋の同じ人が一行を置くとして、①名乗らず立ち去り、後の人が続きを書ける、②書いた人が返事の札を受け取り後で戻る、③返事は任意で、居て聞くだけの人にも次を譲る合図がある、を描いた。「受け取る」の意味を、読むこと、返事を書くこと、自分に届いたと感じることに分ける。一切集めない沈黙も価値候補。Bは実質のある制作を明示しているのでrequire-build。制作意欲は他の人が参加する根拠にはならない。

**LR-002への反証を実際に通した。** whyの担当から、同じ開始の一行「窓に灯が戻った」を二つの別依頼としてsketchへ渡した。終点①は匿名で手放せること、終点②は「返りを受け取るか本人が選べる」こと。どちらも仮の価値と明示すればsketchの入力が埋まる。紙Aでは一行を箱へ置いてそのまま立ち去る。紙Bでは裏面の一回用札を持ち帰るか、その場に返して出る。戻った人は札で一件の返りを探す。空札なら返事は未到着。返事を約束したことにはしない。共通README 145–158行により依頼したwhyが両方を読み、why 153–177・183–197・264–276行の比較に戻す。本人へ残る問いは「札を持たない選択を残しても、隣の誰かが読んだと分かることを望むか」。専門は選定しない。この返りが未取得でも本人の望みを捏造する必要はない。費用差がなくてもこの経路を組めるため、専門を呼べないという指摘は撤回した。

次の段は仮に「初めて来た人が、沈黙も含めて自分の番を選び、望んだ一行を次へ渡せる」を選んだ場合。匿名、退出の自由、他室へ無断転用しない約束を制約にする。『投稿が出た』だけでは黙っていた人が順番を奪われた場合に目標が偽になる。whatで①明示の譲りと考え中の別、②拒否・退出しても以後の参加権を消さない、③無応答のまま固定の終演へ向かう場合にも次の人の機会を損ねない最低線、を比べる。本人が合図できるケースは紙の札でも照明でも区別できる。無応答時の猶予が本番で何秒なら適切かは未取得。実際の観測でのみ区別できるとの派生条件を置くと、本番の線を確定しないwhatから試行版の選定へ進めない（LR-003）。ただし猶予を数値にする必要がなく、全範囲を明示の合図で回せる派生ではこの指摘は出ない。

**同じ一行を候補に当てる。** 公開壁では残す選択から閲覧まで早い反面、後で同じ人が引き取れない。匿名返信札は読取／受領／返信を区別できるが、紛失時には個人の特定なしで再発行できるとは限らない。会場ごとの紙の一往復は、体験比較の強い非開発基準だが、本人の制作指定に従う採用版にはそれだけでは足りない。例えば『一回だけ帰ってきた札の返りを受け取れる』仕組みを作ることは独立した制作候補。全室検索や本人登録を作る必要はない。未来の他室接続に価値があるなら、①初室のみ、②今は非公開で後に本人が範囲を選べる、③最初から公開、を区別し、匿名のまま誰も戻らない派生を当てる。初日同じ体験でも、あとから救える断片の集合が変わる（LR-005）。

```text
初参加者の札       次の人の札        返りを読む札
［続ける］         考え中／譲り待ち   返りなし／返りあり
［譲る］           ［譲りを受取る］   ［この場だけで読む］
［何も残さず出る］  次は未確定         他室公開は別の選択
```

状態の最小例は「考え中→明示の譲り→次の人が受領」。無応答を「譲った」にしない。古い札からの遅い操作が次の人の一行を上書きしないため、logicは受けた番と現行の番を照合、dataは番と返事の対象を分け、機能は譲りと受領を別結果にする。実装構成は同じ一回札が二画面から同時に使われたとき、一方だけが受領したと読める根拠を必要とする。実技術の選定と挙動は未確認。端末復帰によって投稿者の身元を得る前提を足さない。入場4人・投稿2人と、入場20人・投稿2人・途中退出多数の二世界で同じ二投稿と二回答を作る。匿名の来場者数を取れても沈黙の理由はその数で判定できない（LR-004）。

さらに「初回は入口と退出の案内係が人数と任意回答を別々に数えられる」と仮定すると、whyの測りは同じ二投稿の二世界を人数の範囲では区別できる。後に〈常駐の案内係を置かない通常版〉を採る派生では、物語を渡す操作だけは全て残っても計数者がいない。ラフ、担当、継続費、whyの測りのうち、何を変更するかを判断する必要がある。これは実験版で何を観測するか既に決めた枝とは異なる（LR-004）。

## 保留から持出しまでの反例

| 渡す入力・状態 | 通る判断、残る不足 |
| --- | --- |
| Aで会場側の識別子だけが届き、当番の可否は来ない | 停止理由が候補別なら、該当する利用条件・費用の照会を進められる。当番と教材利用は未確認。再開指示なしの状況照会では新しい採否を作らない。 |

本線の入出力と手順を机上で使った結果である。紙の例はここに示した操作と結果まで。端末操作、運営、エンドユーザーの選好形成、別クライアントでの自律進行、新リポジトリへの実移管を観測した結果ではない。
