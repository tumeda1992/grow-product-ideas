#### 解きたい痛みは何で、今どうしのいでいるか

- identifier: `why-to-build/pain-to-solve`
- 状態: 閉じた
- このアイデアでの問い:
  - 言い直した文面: 使っていないサブスクに払い続けてしまうのは、どの場面で何に気づけていないからか。今どうしのいでいるか
  - 足した満たさない例: 「更新日を忘れる」。痛みが、更新日を知らないことなのか、使っていないことに気づけないことなのか、気づいても止めないことなのかを区別していない（一般の例: 「家計管理が面倒」「タスク管理ツールが欲しい」「同じ悩みの人は多い」）
  - 詰める深さ: 詰める。理由: 痛みの核心が変わると、代案の比較軸、要求、解き方の全てが変わる。受け入れ時の入力は一文で、確信度が低い
  - 立てた下位の問い: 痛みは「気づけない」「気づいても止めない」「止められない」のどれか。月払いと年払いの内訳はどうか
- 答え: 痛みの核心は「使っていないことに気づけない」と「気づいても止める判断を先送りする」の二つであり、更新日を知らないことではない。6件のサブスクのうち2件（語学アプリ、ニュース）を半年使っておらず、毎月のカード明細で他の支払いに混ざって気づかなかった。気づいたのは明細をたまたま眺めた時だけで、気づいた後も語学アプリは「また使うかも」で1か月以上先送りしている。月払いが5件で、更新日の通知は毎月届くだけになり痛みを解かない。年払いの1件（クラウドストレージ）だけ、更新日の前に知ることに意味がある
- 確認結果: 痛みの場面（毎月の明細に混ざる）、頻度（毎月、気づくのは半年に一度）、回避策（たまたま明細を眺める）とその不便さ（偶然に依存、気づいても先送り）が書かれている。足した例（更新日を忘れる）に当たらず、痛みを三つに区別した。声の出典と件数は材料にある
- 材料: [target-user-voices](materials/target-user-voices/README.md)、利用者役の回答（[決定過程](discussion.md)）
- 決定過程: [論点1](discussion.md)

#### 既にある道具やその組み合わせでは、痛みのどこが残るか

- identifier: `why-to-build/existing-alternatives-fall-short`
- 状態: 閉じた
- このアイデアでの問い:
  - 言い直した文面: 使っていないことに気づけない痛みと、気づいても先送りする痛みは、既にある道具ややり方の変更で、どこまで解けてどこが残るか
  - 足した満たさない例: 「サブスク管理アプリがあるので足りる」。管理アプリは支払いを見せるが、使っていないことを見せるかを確かめていない（一般の例: 「競合はいない」「〇〇はあるが使いにくい」「専用サービスだけを挙げている」）
  - 詰める深さ: 水準で止める。理由: 答えが「足りる」なら作らない出口へ向かう影響の大きい問いだが、材料で候補の性質が明確に分かれ、確信度が高い
  - 立てた下位の問い: なし
- 答え: 既にある道具の組み合わせで痛みの核心は解ける。毎月決まった日にカレンダーで見直しの予定を立てて一覧を見ながら「先月使ったか」を自問すれば、明細をたまたま眺めることに頼らずに気づける。「1か月使わなかったら解約し、要る時に入り直す」と基準を先に決めれば、先送りしない。専用サービス（サブスク管理アプリ、家計簿アプリ、カード会社の一覧）は払っていることを見せるが使っていないことは見せず、核心に届かない。残るのは、一覧の手入力（初回の6件）と毎月の見直しを続ける規律という周辺の手間である。年払いの1件は、カレンダーに更新日の前の予定を入れれば足りる
- 確認結果: 三つの範囲（専用サービス、汎用の道具、やり方を変える）で候補を挙げ、候補ごとに二つの痛みのどこが残るかを書いた。探した範囲は材料にある。足した例（管理アプリがあるので足りる）に当たらないよう、管理アプリが使っていないことを見せないことを確かめた
- 材料: [existing-alternatives](materials/existing-alternatives/README.md)、[解きたい痛み](#解きたい痛みは何で今どうしのいでいるか)

#### 作る費用は、代案を使い続ける費用に見合うか

- identifier: `why-to-build/build-cost-pays-off`
- 状態: 閉じた
- このアイデアでの問い:
  - 言い直した文面: 使っていないサブスクに気づき止める道具を作る時間は、カレンダーとやり方の変更で済ませる時間に見合うか
  - 足した満たさない例: 「無駄に払っている月2,500円を取り戻せるから見合う」。止められる額はどの案でも同じで、作る案と代案の差になっていない（一般の例: 「週末で作れる」「代案は月500円かかる」「保守の時間を入れていない」）
  - 詰める深さ: 水準で止める。理由: 論点2で代案が核心を解くと分かっており、この答えが変わっても出口の判断はほぼ変わらない
  - 立てた下位の問い: なし
- 答え: 見合わない。作る案は1年目に約8〜19時間、以降も毎年約4〜7時間（保守と見直し）かかる。代案は初めに約30分、以降は毎年約2時間であり、作る案が安くなる時点は来ない。止められる無駄の額（月約2,500円）はどの案でも同じため、比較の差にならない
- 確認結果: 作る時間を画面の枚数と主要な操作から見積もり、保守の時間を入れ、代案と同じ時間の尺度で並べ、逆転点を確かめた。足した例に当たらないよう、止められる額が差にならないことを書いた
- 材料: [experience-sketch](materials/experience-sketch/README.md)、[cost-comparison](materials/cost-comparison/README.md)
- 決定過程: [論点3](discussion.md)

#### 作ることのリスクは何か

- identifier: `why-to-build/risks-of-building`
- 状態: 閉じた
- このアイデアでの問い:
  - 言い直した文面: 使っていないサブスクに気づき止める道具を作ることに、法務・規約、依存、実現性、運用、機会損失のリスクはあるか
  - 足した満たさない例: 「自分用の小さな道具なのでリスクは小さい」。五つの観点を見たかが分からない（一般の例: 「リスクはない」「技術的に難しいかもしれない」「起きた時にどうするかが無い」）
  - 詰める深さ: 水準で止める。理由: 論点2・3で出口が「作らない」に寄っており、リスクはその向きを強めるだけである
  - 立てた下位の問い: なし
- 答え: 法務・規約と実現性は当てはまらない（自分で入れる情報だけを扱い、処理は一覧と定期の通知だけ）。依存の継続性は作る案Bで一部当てはまり（表計算サービスの連携の仕様変更で通知が止まる）、手当ては受け入れる。運用（保守が毎年約4〜7時間）と機会損失（作る時間8〜19時間）は当てはまり、手当ては作らずに代案を使うことで避ける
- 確認結果: 五つの観点それぞれに、当てはまるかと理由、当てはまるものに手当てを書いた
- 材料: [technical-feasibility](materials/technical-feasibility/README.md)、[existing-alternatives](materials/existing-alternatives/README.md)（依存先の候補）

#### それでも作る理由は何か

- identifier: `why-to-build/reason-to-build-anyway`
- 状態: 閉じた
- このアイデアでの問い:
  - 言い直した文面: 代案で痛みが解け、作る方が高くつくと分かった今も、使っていないサブスクに気づく道具を作る理由はあるか
  - 足した満たさない例: 「せっかく思いついたから」。作りたい動機をそのまま書いており、受け入れ時の動機（家計の無駄を減らしたい）とも比べていない（一般の例: 「作りたいから」「勉強になるから」「保留の再開条件が無い」）
  - 詰める深さ: 水準で止める。理由: 判断軸の三つが全て同じ向きを指し、確信度が高い
  - 立てた下位の問い: なし
- 答え: 作らない。代案（毎月の見直しの予定、一覧のメモ、「1か月使わなかったら解約し、要る時に入り直す」基準、年払いの1件は更新日前の予定）を使う。代案で痛みの核心が解け（なぜ作るか層の2問目）、作る費用は代案より毎年多くかかり逆転せず（3問目）、作ると運用と機会損失のリスクが残る（4問目）。受け入れ時の動機は家計の無駄を減らすことであり、作る楽しみや学びは含まれていない。代案で始めて残る痛みだけを作る案も、残る痛み（初回の手入力、見直しの規律）が小さいため採らない
- 確認結果: 四つの選択肢を比べ、判断軸の三つ（残る痛みが核心か、費用の差、取り返せないリスク）に照らした。動機を費用の比較と分けて扱った

## 出口

- 出口: 作らない
- 判定した時点: なぜ作るか層が閉じた時
- 理由: 既にある道具の組み合わせとやり方の変更で、痛みの核心（使っていないことに気づけない、気づいても先送りする）が解ける。作る費用は代案より毎年多くかかり、逆転しない
