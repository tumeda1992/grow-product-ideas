# Kindleのハイライトを週ごとに読み返したい

## 状態

- 状態: 保留
- 最後に閉じた層: why-to-build

この1件は、レールの受け入れ確認のための自演である。利用者役の回答はassistantが演じており、決定過程に「利用者役の回答（自演）」として区別して記録する。

## 受け入れ時の入力

利用者から受け取ったものを、言い換えずに残す。

### アイデア

Kindleで線を引いたハイライトを、一度も読み返していない。週に一度、ハイライトが手元に戻ってきて読み返せるようにしたい。

### 作りたい動機

読んだことを忘れたくない。読書メモは自分の頭の中のようなものなので、外部のサービスには預けたくない。

### 既にある着想

毎週日曜の朝に、その週と昔のハイライトが数個ずつ届く感じ。

#### 既にある道具やその組み合わせでは、痛みのどこが残るか

  - 言い直した文面: ハイライトを外部に預けずに、定期的に読み返す場面を作る手段は既にあるか。何が残るか
  - 足した満たさない例: 「手でコピーして読み返せばよい」。その習慣が続くかを、利用者の経験と照らしていない（一般の例: 「競合はいない」「〇〇はあるが使いにくい」「専用サービスだけを挙げている」）

  - 立てた下位の問い: なし
- 答え: 外部に預けない代案では、痛みの核心が残る。Readwiseは毎日の振り返りメールで核心を解くが、ハイライトを外部に預けるため、受け入れ時の動機と両立しない。AIのノートは定期の場面が無く外部に預ける。手でコピーして毎週カレンダーで読み返す代案と、読み終えたら3つだけ書き写す代案は外部に預けないが、手で写す習慣に頼り、その習慣は利用者の経験で3冊で途切れている
- 確認結果: 三つの範囲で候補を挙げ、定期の場面と外部に預けないことの二軸で残る痛みを書いた。足した例に当たらないよう、手で写す習慣を利用者の経験と照らした

#### 作る費用は、代案を使い続ける費用に見合うか

- identifier: `why-to-build/build-cost-pays-off`
- 状態: 閉じた
- このアイデアでの問い:
  - 言い直した文面: ハイライトを毎週届ける仕組みを作る時間は、手でコピーする代案に見合うか。作る案は核心を解くか
  - 足した満たさない例: 「手で貼り付ける仕組みなら6時間で作れるので見合う」。手で貼り付ける案が、続かなかった習慣に頼ったままかを見ていない（一般の例: 「週末で作れる」「代案は月500円かかる」「保守の時間を入れていない」）
  - 詰める深さ: 水準で止める。理由: 核心を解く案が一つ（自動取得）に絞られ、その採否はリスクの問いで決まる
  - 立てた下位の問い: なし
- 答え: 手で貼り付ける作る案は1年目約12時間で、手でコピーする代案（約6時間）より高く、同じく手で写す習慣に頼るため核心を解かない。核心を解くのは自動で取り出す案だけで、1年目約22時間かかる。その採否はリスクで決まる
- 確認結果: 時間の尺度で作る案二つと代案を並べ、保守の時間を入れた。足した例に当たらないよう、案ごとに習慣への依存を確かめた

#### 作ることのリスクは何か

- 状態: 閉じた
- このアイデアでの問い:
  - 言い直した文面: ハイライトを自動で取り出して届ける仕組みを作ることに、法務・規約、依存、実現性、運用、機会損失のリスクはあるか
  - 足した満たさない例: 「自分のデータを自分で取るだけなので問題ない」。ログインが要るページの自動取得が規約でどう扱われるかを確かめていない（一般の例: 「リスクはない」「技術的に難しいかもしれない」「起きた時にどうするかが無い」）

- 答え: 法務・規約が当てはまる。核心を解く自動取得の案は、ログインが要る「メモとハイライト」ページを読み取る必要があり、公式のAPIは確認できず、Amazonの規約は自動化された収集を認めていないとする解説が複数ある。アカウントの停止は取り返しがつかないため、手当ては待つ（公式の取り出し手段が出るまで）。依存の継続性（ページ構造の変更で止まる）と運用（追従に月1時間）も当てはまる。実現性は技術的には当てはまらないが、規約の懸念のため試していない。機会損失は作る時間約10時間
- 確認結果: 五つの観点に、当てはまるかと理由、手当てを書いた。立てた下位の問い（公式の手段、規約の扱い）に答えた。規約の本文は読んでいないことを材料に書いた

## 出口

- 出口: 保留
- 判定した時点: なぜ作るか層が閉じた時
- 理由: 痛みの核心（読み返す場面が来ない）は、ハイライトを外部に預けない代案では、続かない手作業の習慣に頼るため解けない。解ける作る案（自動で取り出して届ける）は、ログインが要るページの自動取得であり、取り返しのつかない規約のリスク（アカウントの停止）を持つ
- 復活する条件: Amazonが「メモとハイライト」の公式の取り出し手段（エクスポートやAPI）を出す。または、利用者が外部のサービスに預けてもよいと考えを変える（その時は作らずReadwiseを使う）
- 保留の間: 読み終えた時に3つだけ手元のメモへ書き写し、毎週読み返す
- 何を作るか・どこまで作るか・どう作るかの層の問いは、保留と判定したため答えていない
