# 解決策・提供範囲の探索と選定（二人の夕食）

- 状態: 決めている
- 決めるもの: 候補と選定。

## 受け取った物差しと前提

[why](../README.md#なぜ作るか)のG1〜G3と[条件](../README.md#満たすべき条件)、[require-build](../README.md#開発方針)を保つ。30分の初期整備/平日各5分検討/全数帳簿無し/継続有料契約回避を比較へ渡す。これを新しいソフトの制作が楽しいという目的にしない。

## 解き方の選択肢の決め方

### 1. 出どころの事実を確かめる

希望はC2/D2のその時の本人、食材/残りは現物と消費した本人、誰が確認したか/引受け/実行結果は実際に動く本人から生じる。既存共有メモに料理名を書き双方のスマホで読んだこと、メッセージで連絡する道は設定にある。サービス名/同時編集/通知/既読/圏外同期は分からない。担当や在庫の現状をメモの空欄から作らない。

### 2. 出どころを直接見る形と、足りない点を出す

基準は、週末に二人で候補を話し、帰宅/希望変更/残りを使う時に本人へ尋ねる・現物を見られる人が確かめる・次の行いを返答で引き受け結果を返すこと。これでも在宅者がいない時の食材は不明。確認の依頼がC2へ寄り、変化が次の判断へ渡らない点が残る。P1候補/変更の現行と確認時点、P2食材の既知/不明と残りの変化、P3本人の引受けと結果の返しを補う。

### 3. 補う点ごとに、選択肢を出す

R1/R2に依頼。まだ採用版は置かない。

## 返りの受領と残る判定

R1 [alternatives](../materials/alternatives/README.md)から、N1の非開発基準、B1既存メモ上の集約処理、B2相談文生成の独立部分案、B3共有アプリを受領した。R2 [experience-sketch](../materials/experience-sketch.md)から同じ火曜の変更→現物不明→本人返答/実行までのラフを受領。どの道も本人の食材確認/引受け/結果返しを要する。

R1の[認識合わせ](../materials/alternatives/discussion.md#論点1-スマホで使う既存道具と制作の入口を確かめる)を依頼側が利用者役へ渡し、固定入力にはサービス/端末/制作入口の事実が無いとの応答を同じ材料へ保存した。未取得を便利な拡張や確定した不可能性にしない。

### 5. 得るもの・払うものを出す

R1の費用でN1は処理実装0、B2の既知の部品のみ0.75/1.5/3hの無補正見積りだが、入口/配置/検査/誰が作るかが未定で全体値ではない。B1/B3は構成に必要な対象が未定で総額を出せない。本人二人の初期30分へ制作/配置/導入を結べる根拠は無い。毎日の記入/返答も回数/所要分数は未確認。制作の楽しみは未提供で、時間不足をその目的で正当化しない。

## 解き方の選定の決め方

### 1. 決め手が依る事実を確かめる

B1の拡張が使えれば小さい集約処理へ、無ければB2の単体入口が使えるかへ分かれる。B2が両スマホで開ければ相談文組立ての部分案を比較でき、開ける経路が無ければその版は使えない。今はどちらかの答えを取得していない。B3も同様。技術probeに渡す対象サービス/端末が特定できず、検査用共有API/任意の端末を作って通さない。

### 2. 補う点（組）ごとに、境目で比べて選ぶ

P1/P2/P3のN1は強い非開発基準だがrequire-buildの採用資格は無い。B1は入力の転記を処理で補う。B2は火曜の相談文を組む部分だけを作り、食材確認と引受けは人へ残す。この小さい部分でも本人のスマホへの入口/制作の負担を確かめなければ、有用に使い始められる版とは選べない。非開発が安いことだけでopenへ変えず、範囲/作り方を三通り比べた後の不足である。

### 3. 作る理由を切り分ける

制作を選ぶなら、候補/未確認/引受けの混同を減らす処理にする。作る楽しみ/学びが主理由とは言えない。相談文生成だけでも動く機能は作れるが、使える経路/本人の行いを繋がなければこの案件の改善ではない。

### 4. 選び直す条件を書く

同じ入力版のまま必要なサービス/端末/制作入口を得られない時は保留。復活時には本人の実物資料を追加履歴へ残し、B1/B2/B3の対象技術の事実/費用と初期30分、残る人の行いを確かめる。枠を守る作る部分案が成立すれば選定/必要設計へ続く。

## 確認

出どころと未確認、基準の届く点/不足、非開発/作る規模/独立部分案と費用、崩れやすい時点は具体に記録した。成立する作る版の選定は満たしていない。必要な本人の事実と作る経路が無いため、層を閉じて作る設計へ渡さない。専門が不足を返したことと成立したことを区別し、正式な保留の採否へ進む。

## 正式な保留

[論点1の合成採否](discussion.md#論点1-作る入口と初期負担が分かるまで保留する)で案件を保留。層は決めている状態のまま、未完の選定から再開する。層の閉じ/設計完了とはしていない。

## 読戻しでの再評価と復活条件の追加

原文へ戻るとD2は既に希望変更をメッセージで伝えていた。B2は変更の文章を作れることだけではその現状を改善せず、未確認食材/確認役の偏りを残し、入力/貼付け/現行照合を増やしうる。専門の[値打ちの再評価](../materials/alternatives/README.md#読戻しでの再評価-b2の値打ちも未確認)と[同じ場面での差](../materials/experience-sketch.md#読戻しでの再評価-生成文と現状の具体の差)を受領した。これまでの候補/採否は当時の記録として保持する。

入口/制作の不足に加え、B2がN1へ必要項目を加えた道より誰のどの迷い/記入/往復を変えるかの根拠又は実験版として選ぶ採否が不足する。復活は入口が分かるだけでは足りず、同じ火曜の内容で両案の一巡/残る食材確認/引受けと入力/貼付け/照合の負担、部分改善の仮説を比べ直し、価値へ働く作る版又は必要な検証を選ぶことが必要。保留の出口は変わらない。
