## 決め方

### 解き方の選択肢

#### 1. 出どころの事実を確かめる

規則・山札順と六手は[初期入力](../input.md)。見込みと後の評価は当人の記した語りであり、過去の全ての理由は得られない。CLIの実行・保存の性質はまだ確認していない。

#### 2. 出どころを直接見る形と、足りない点を出す

基準は紙の規則と12枚を直接扱い、自分で手を選び計算し、元の記録から次を選ぶ一巡。計算の手間自体を条件違反にはしない。戻す時に元の順・理由を失う点は補う必要がある。変える手の直前の局面と理由を別紙へ写すだけでも改善が成立する可能性がある。


#### 3. 補う点ごとに、選択肢を出す

比較したい基点と理由を失う所へ、Pの記録手順、Sの式と紙、Cの計算と分岐を当てる。P-dayは当日だけの独立改善と翌週のW5未達を分ける。Cを選ぶために紙を落とさない。候補×条件の返りを[材料](../materials/alternatives.md)から読み、Cの根拠が未確認なので構成・技術の問いを作る。

| 追加依頼先 | 使う判断と渡す入力 | 粒度・必要な返り |
| --- | --- | --- |
| implementation-structure-design | Cの同期の一回／常駐で結果を確定する違い。規則・元と分岐を失わないW1/W5、同じ一件 | 粗い構成案と停止後の根拠、必要な技術の性質、費用の部品 |
| verify-technical-feasibility | ローカルで停止時に元の記録を残せるか。対象は実際のPythonと一時directoryだけ | 書込み前／切替前の停止、切替後、同時起動拒否、危険な直接上書きの対照。方法と期待を実行前に記す |

#### 4. 崩れやすい時点で、確かめ方を問う

原記録を見る時点で規則・初期順を確認する。手を分ける時点で元と別のIDを確かめ、後の比較で当時の理由と追記を見分ける。再開時に何手目かと保存済みnodeを読む。P/P-dayは人の写し・保管の省略、Sは複製と式の破損、Cは保存前後の停止と入力の重複が崩れる時点となる。PとCの記録を併用してどちらも現行にする案は、どれから再開するか割れるため選ばない。Cの記録を正本にし、紙は故障時の別試行として元を区別する。

技術材料の6件では直接上書きは壊れ、切替前後は旧／新の全量が読めた。採用の根拠は今のLinux上のprocess停止・排他に限定する。Cの起動時は現行を示し、表示前停止の再入力で二重に手を進める危険を扱う設計を要請する。

#### 5. 得るもの・払うものを出す

部品別三点は[費用](../materials/alternatives.md#構成技術の受領後に返す費用)。Cの三点130/250/470分は未校正で、上限6時間を超える枝がある。基準の12分の内訳も回数も無いため、時間の節約で元が取れるとは言えない。

### 解き方の選定

#### 1. 決め手が依る事実を確かめる

技術・構成の返りを受領。現行Linuxだけを対象とする。将来の当人PCや別OSへ持ち出す動作は未確認なので約束しない。作る楽しみと6時間の割付けが決め手であり、楽しみを実測済みとしない。完成時間と遊びの改善は未確認で、選ぶなら6時間で止める実験として扱う。完了しなければPで遊びを続け、失敗を成功へ読み替えない。

#### 2. 補う点（組）ごとに、境目で比べて選ぶ

計算と分岐を保存する一組をCとPで比べる。理由と次の問いは両方で本人に残す。Sは製品と保存を特定・検査する必要があり、紙より優位との事実が無い。今はPを強い次点に残す。

| 八つの軸 | CとPの境目 |
| --- | --- |
| 手間が減る | Cは毎手の計算と分岐の写しを機械が行う設計。Pは人。削減の分数・回数は未測 |
| 得たいもの | Cは自分の規則を動かす楽しみがある。Pは作る楽しみを得ない |
| 変化に強くなる | Cは元の履歴から別試行へ、Pは紙を残して写す。新しい規則を無制限には支えない |
| 作る時間 | C 130/250/470分、P 15/30/60分。未校正、Cは6時間超過リスク |
| 続ける時間 | Cも理由の入力と保管は残る。Pには手計算・写し。3週の回数不明、年間換算なし |
| 崩れやすさ | Cは保存と結果の再読取り、Pは写しと保管忘れ。技術6件はCの一部の根拠のみ |
| 満たさない条件と失う価値 | 両方ともW1〜W5に届く設計候補だが実利用は未観測。P-dayはW5未達で次週の比較を失う |
| お金 | 両方新規契約0円。金額の差なし |

採否は[論点1](discussion.md)。P-dayの小さい改善は認めるが、今回の3週の比較を捨てる割にPからの準備差が小さく、Pを次点にする。

#### 3. 作る理由を切り分ける

Cの計算・写しを減らすのは設計上の期待。実証した節約ではない。作る時間を支払う主な理由は自分の規則を動かす楽しみであり、価値の達成に自作が必須だからとはしない。

#### 4. 選び直す条件を書く

6時間で受入れに通らない、導入に別OSが必要、W1〜W5が支えられない、世話が遊びを圧迫する、のいずれかならCの継続を止めPへ選定を戻す。遊び自体を止めない。新しい共有・自動最適化は別の選定へ返す。

## 材料の受領

[構成](../materials/implementation-structure.md)のLを費用へ使い、Bの常駐は今回不要と判じた。[技術の観測](../materials/technical-feasibility/README.md)6件を保存境界の根拠として読み、未確認の電源断・他OSを保証から外す。[候補と費用](../materials/alternatives.md)の三点を選定へ読み、470分を上限以内に丸めない。

## 差し戻し（詳細の費用差）

[詳細の構成](../materials/implementation-structure.md)と[候補の更新](../materials/alternatives.md)から、Cの旧130/250/470分に35/60/100分が加わり165/310/570分となった。更新前の論点1/2は当時の判断で、現費用はこの節を使う。技術・規則・W1〜W5・0円・6時間上限は変わらない。

選定の決め手の費用へ効くため開け直した。比較し直すのはC/Pの準備と世話の差。Pは15/30/60分のまま。価値の機会、未測の節約・楽しみ、規則変更の支援、3週で本人に残る比較と保管、Cの保存/紙の写しの脆さ、両者の設計対象のW1〜W5、0円は前の八軸と変わらない。6時間で完成しないリスクが増えたことだけを隠さず採否へ返す。
