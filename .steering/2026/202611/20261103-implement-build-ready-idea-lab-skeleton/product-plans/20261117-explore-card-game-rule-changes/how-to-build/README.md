## 受け取った物差しと前提

[正本](../README.md)のWHYとW1〜W5、Cの同期の手元道具、理由と次の問いを人に残す分担、0円・計6時間の制作上限、130/250/470分の未校正推定とPへ戻る条件を受け取る。実行は検査したLinux/Python、実利用の効果は未観測。未達を隠して範囲を下げない。

## 決め方

### 1. 選んだ版の一巡から、設計すべき判断を取り出す

| 全場面 | 始まりと人・道具の仕事 | 完了の根拠／設計の問い |
| --- | --- | --- |
| 導入 | 当人がscriptと保存場所を選び、規則・固定順から開始 | 0手のrootと規則が読める。過去の六手の理由を作らない |
| 日常の一手 | 手札を読み本人が手と見込みを選び、規則を計算・保存 | 成功したnodeと現行値、又は不成立の理由。保存前は成功にしない |
| 同じ規則で別の手 | 本人が分けたい直前のnodeを指定 | 元と新node、共通の親が残る。元を消さない |
| 規則V1を試す | 初期順を同じにしてV1の別rootから開始 | V0の途中値を混ぜない。prefixを試すなら各手をV1で再入力する |
| 比較と次の遊び | 本人が二つのnodeを選び規則・経過・結果・理由を読む | 元が途中か終了かを見て自分で次を選ぶ。次の一回を開始できる |
| 中断・成否不明 | 次の起動で保存済みnode一覧と現行を読む | 表示前停止でも手を重ねず、保存前なら元から続ける |
| 誤記・破損・終了 | 理由の訂正を追記、誤った手は元から別に試す。破損なら退避し紙へ | 原記録を勝手に修復・消去しない。遊ぶための規則・順と最後の読めた控えから別試行 |

W1はroot規則と順、W2は遷移、W3は見込みと追記の区別、W4は比較から本人の開始、W5は消さない経過と保存境界で支える。設計の問いは、node同一性、遷移の順序、理由の時点、確定と再開、全操作の表示に分ける。

### 2. 必要な専門材料を、依存と粒度を持って揃える

先に規則の結果と残す記録を照らす。表示・責務はその同じrootとnodeを使う。構成には既に得た6検査だけを根拠として渡し、本製品の実装済み保証へ変えない。人の自発的な楽しみは実利用後の測りであり、設計に不可欠な未取得の他者の同意は今回無いので追加の体験収集を型のために呼ばない。

### 3. 設計の案を同じ一件へ当て、継ぎ目を照合して選ぶ

[規則](../materials/core-logic.md)と[情報](../materials/data-model.md)は同じr0/n0→n1で、A3を出した後0/3/[A2,B5,B2]を返す。[表示](../materials/experience-sketch.md)は保存済みnodeだけを成功とし、[処理](../materials/functional-structure.md)はその返りをcommit後に表示へ渡す。[構成](../materials/implementation-structure.md)は同じdocumentを切替、6件の技術の根拠へ接続する。

比較案はsnapshotだけ／親を持つ行い、暗黙の現行menu／親ID指定、巨大command／共通遷移と調整、同期／常駐。名前の多さではなく、原記録と理由を残し、表示前停止でも次の手へ勝手に進まない方を選定材料とした。

継ぎ目の実例: 元のV0とV1はどちらも7点だが蓄え2対5。点だけを出すラフでは比較を失うため、表示材料に経過・蓄え・手札と理由を追加して受領した。規則V1へV0の途中nodeを繋ぐ案は情報の同根制約と矛盾し拒否した。元の理由なしを後の評価で埋めない扱いは三材料で一致。

詳細から準備が165/310/570分へ変わった。選定の6時間との余裕を減らすため、その差だけを閉じたhow-to-solveへ返す。価値とW1〜W5は変えず、設計は受領を待って止める。

### 4. 導入・修正・復旧と、受入れの確かめ方を設計する

導入・訂正・退避の具体手順は[構成](../materials/implementation-structure.md)、操作は[全場面のラフ](../materials/experience-sketch.md)。全て当人が起動し、保存先を保管する。現版はLinuxのローカル保存だけ。原記録が壊れたら自動修復ではなく退避し、読める控え又は紙の新しい試行へ戻る。失った理由を生成で復元しない。

| 実装後に行う受入れ（全て未実施） | 入力・操作 | 期待する具体の結果 |
| --- | --- | --- |
| 元の六手 | 初期順、V0でA3/rest/A2/rest/B2/rest | 手ごとにcore-logicの手札・蓄え・得点と一致。最後2/7、6手終了 |
| 無効と終了後 | n1からB5、n3からA6、初期でA1、6手後rest | いずれも記録・revision・手数が変わらず理由を示す |
| 6手目の補充 | V0の初期からrest/rest/A2/rest/A3/B2 | 最後の蓄え1/得点7、手札[B5,A6,B1]、山札位置6、終了。補充を省略しない |
| 上限で休む | 初期からrest/rest/rest | 蓄え5→6→6、手数1→2→3。満杯の休みも消費する |
| 同じ規則の分岐 | n0からA2、元のA3も保存 | 共通親n0、別の手札と蓄え。元n1の見込みと結果不変 |
| V1と比較 | r0と同じ順でV1新root、元と同じ六手 | 蓄え0,3,1,4,2,5／得点3,3,5,5,7,7。規則差と途中手を表示 |
| 理由なし・訂正 | b1は見込みなし、evaluationとcorrectionを追記 | 当時の見込みは未記録、追記は別。元を置き換えない |
| 中断と表示前停止 | 3手目で終了、切替前後にprocess終了 | 旧又は新の全量をlistで確認し、親を指定して続ける。途中を終了済みにしない |
| 競合と不正記録 | 同時起動、schema不明、親欠け、循環、不正な手、重複ID | 後発書込み拒否又は読取りエラー。原記録を上書きせず復帰案内 |
| 保存失敗と移動 | 書込不可の保存先、別directoryへ停止中のコピー | 成功を早出ししない。新しい保存先でlistして元を残す |

取得済みなのは技術の小検査6件で、上の製品受入れを合格にしていない。初回利用は当人が比較の基点・変えた手/規則・当時の見込み/未記録・結果・次を示せるかと、考える時間/記入・復旧の時間を分け記録する。3週目には自発的に遊びを続けたいか、世話が遊びを押し出していないかを本人が評価する。12分の架空設定から削減実績を作らない。6時間内に受入れを満たせなければ制作を止めPへ。世話が圧迫すれば継続を選定へ戻す。

### 5. 決めた設計を渡し、裁量と選び直す差を残す

rootと行いの木、親node指定のCLI、純粋な規則再生、共通の一回の調整、固定lockと全量切替を設計案とする。理由は元と理由を消さず、規則V1を混ぜず、保存の前後で次を判断できること。同期のLは常駐の依頼照合と運用を不要にする。

ファイル内の関数・classの分割、helpの文体、並び順、色は実装へ委ねる。親の明示、規則/順と全経過、見込みと追記の区別、成功表示の境界、制約検査と保存、6時間上限・紙への復帰は裁量で削らない。別OS、共有、汎用規則、履歴削除、外部サービス、費用増は該当する選定又は設計へ返す。

残る未知は当人の実装速度と実際の楽しみ・操作負担。制作と初回/3週目に測れるものであり、今の仕様の穴ではない。電源断とdevice故障の耐久性は保証しない。実装担当に独自の規則・見込みの復元・故障復旧の意味を発明させる未決は残さない。
