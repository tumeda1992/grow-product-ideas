# 必要な替芯を期限までに得る道を選ぶ

固定した検査用入力を、価値の探索から順に検討する。実在の利用者の望み又は実利用の結果とはしない。

- 状態: 保留
- 閉じた層: why-to-build、what-must-hold

## 受け入れ時の入力

アイデアの引用は検査用の利用者役の原文。動機と着想の補足は設定の地の文から整理したもので、本人の追加発言ではない。全ての出来事・制約と未確認は[初期入力](input.md)に保持する。

### アイデア

> 仕事帰りに、いつも使うペンの替芯を買いに行った。最初の店に無くて次へ行ったけど、似た物しか見つからなかった。行く前に今ある店が分かれば寄り道を減らせそう。在庫をまとめて見るものを作れないかな。

### 作りたい動機

設定の地の文: 特定のペンに合う黒の0.5mm替芯が欲しく、来週までに1組あれば間に合う。

### 既にある着想

アイデア原文の「在庫をまとめて見るものを作れないかな」という着想。

## 前提にする条件

準備1時間まで、新規継続費0円、買物前の確認5分程度。電話1件も候補にできる。外部連絡・購入の実行はこの試運転に含めない。[前提の採否](why-to-build/discussion.md#決定論点1)

## なぜ作るか

### 体験と価値

2店へ寄っても互換が分からず買わなかった一回から、表示の便利さだけでなく誤購入せず期限までに必要な物を得る道を選ぶ価値を選んだ。全網羅/最安/今日必須の価値は今回含めない。

### アウトカム

> 当人が次回の買物から来週の必要時点までに、自分のペンに合う黒0.5mmの替芯1組を得るため、対象の同一性とその時の入手根拠を取り違えずに店へ寄るか別の入手を選び、予定が崩れた時にも期限と残る不確かさから次の行いを選べる。

当人のこの1組、次回から来週の必要まで。初回の互換/時点/対象の根拠と実際の入手、確認・寄り道分数、必要時点に使えたかを測る。外部による実際の入手は保証できず、出来なければ未達として読む。

### 作ることで得たいもの

開発自体への強い望みは語られていない。

根拠: [過程](why-to-build/README.md)、[閉じ](why-to-build/discussion.md#決定論点2)
