## 決め方

### 1. 選んだ版の一巡から、設計すべき判断を取り出す

| 場面・境界 | 始まり/入力 | 次へ渡る結果と設計の問い |
| --- | --- | --- |
| 事前準備と当日開始 | catalogueの写し、3つの運営の問い、原札/控え、掲示時刻 | 番号と展示場所・出所の一致、初期表示、時計と起動の確認 |
| 受取/不参加/紙の投稿 | 人の意思、対象番号、本人の範囲選択 | 投稿せず読める、原札を預かることと引受けの区別 |
| 適格性/空き枠/集中 | 確認済みの内容と確認完了時刻 | 対象別の将来枠と受付キー、拒否理由 |
| 四回の更新 | 当該枠、旧い紙と画面 | 覆う→回収→現行確認→提供。DBと物理確認の違い |
| 誤記/取下げ/旧画面 | 原札と控え、現行rev | 本文は勝手に直さず、紙と画面を止める。古い更新は409 |
| 交代/中断/結果不明 | 確定した記録、未確認の紙、停止した時刻 | 再送前の照合、未実施と不明の区別 |
| 土曜閉場と日曜再開 | 原札・紙・DB・期限/取下げ | 表示を閉じて管理下に保持、日曜に再確認 |
| 日曜終了とF0 | 表示/原札/DB本文/印刷の残存、集計 | 全ての本文を消し、個人に結ばない集計と許された運営の問いだけ残す |
| 価値の測り | 観察枠の延べ入室・出来事・任意の応答 | 同じ人を数え分けず欠測を残す。投稿や操作の成功と価値を分ける |

### 2. 必要な専門材料を、依存と粒度を持って揃える

体験と規則から保存に要る意味を取り出し、情報と機能の受渡しを構成へ結ぶ。粗い候補材料は同じ識別子で育て、選定時の未確認を無言で保証へ替えない。実際の他者の反応は今回取得できず、採用済みの観測へ残す。架空の声を追加して設計の使いやすさを実証した扱いにしない。

月曜の判断の資源の不足はwhyへ返し、二人各15分/計30人分の追加の合成設定で元の採否を維持できる返りを受領した。土日の配置/制作/測り/F0へ変更は無く、後続の条件/選定は確かめ直した。変わらない。同じ採用の再承認は求めない。

### 3. 設計の案を同じ一件へ当て、継ぎ目を照合して選ぶ

採る構成はPC内の単一アプリ/SQLite＋localhost管理とLANの読取り専用＋一台の貸与端末/紙。一つの責任の中で受付と予約を原子的に確定でき、分散workerを足しても紙/端末の物理確認は消えないため、不要な分散を増やさない。本文を上書きする一表や、全本文の永久履歴でなく、受理後不変の本文と状態rev、対象別slot、現物copyの関係を分ける。
同じQ17について、10:05確認完了→17/10:20予約→accepted rev1→Q17-P1と画面/左室の一致→active rev2→旧rev1拒否→覆いと紙回収→withdrawnを往復した。別Q18/18を17枠へ結ぶ場合は複合外部キーで拒否した。正しい拒否を規則違反とせず、acceptedを実際の閲覧/効果にしない。
[model-observations](../materials/technical-feasibility/model-observations.json)は、coveredでは本文を返さず、回収の合成入力が無い紙をplacedのまま残し、F0で個別行0/aggregateだけとなった根拠。最初の検査codeのplaceholder数の不備と修正/再実行は技術材料へ残した。
[s1配分](../materials/technical-feasibility/allocation-observations.json)、[HTTP競合と再送](../materials/technical-feasibility/http-observations.json)、[commit前後停止/escape/片付け互換](../materials/technical-feasibility/observations.json)も対象を合わせて受領。実装全体や施設実機はこの結果で保証していない。

### 4. 導入・修正・復旧と、受入れの確かめ方を設計する

[運用と受入れ](operations-and-acceptance.md)へ、事前/当日の配置、原札と紙・端末の確認、誤記と取下げ、停止と旧画面、土曜閉場/日曜再開、F0と片付けの残件、観測と欠測を具体化した。二人の20分の照合を保ち、月曜の次方向の判断は別の二人各15分として受領した。
開始前はcoveredで時計・場所・出所・読取り/書込みの分離・原札からの試し通し・印刷の保持を確かめる。満たせなければ実施前に戻る。終了/復旧は単なるボタンでなく、人が確かめる物と記録を結ぶ。片付け担当の受領を実施済みにせず、未受領ならA/Bが残件の責任を保持する。

### 5. 決めた設計を渡し、裁量と選び直す差を残す

守る入力/結果・slot/rev/epoch/コピーの根拠・F0・同じ対象と番号・全体の範囲/費用/未達は実装時に変えない。moduleやframework、見た目の余白、同じ検査を保つ内部の分割は実装側の裁量。論点1の採用を受領し、正本へ反映した。
制作5/9/16h・12h上限、同僚準備2h、当日の内数と月曜30人分は[再見積り](../materials/alternatives/README.md#設計へ育てた後の再見積りと残る時間の問い)で確認した。詳細化した保存/確認/消去は既存の部品/行いの中に入るが実測時間の保証ではない。本文印刷を制御できず手書きが増える、拒否/支援/再試行で配置や測りを崩す等の差は選定へ戻す。
