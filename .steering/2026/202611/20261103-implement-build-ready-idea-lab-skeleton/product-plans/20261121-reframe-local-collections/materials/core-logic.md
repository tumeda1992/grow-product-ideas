## 中身

### 必要な結果と、提案0の不成立

入力は本人の範囲選択を確認した問い、資料番号、当日の時刻と空いている出力枠。必要な結果は『この問いを何時のどの対象の札へ出すと引受けたか』又は『まだ引受けられない理由』。単なる入力成功ではC5の提供を引受けたと言えない。
提案0の一対象一枚・四回更新へ17の問い12件を早い時間に当てると出せるのは4件で8件が残る。11:09に同じ17を3件受けた場合、残る11:15の枠は一つしかない。入力が不正なのではなく、受理した全件を渡せるとした案の不足である。

### 方式S: 引受け前に後の対象別枠を確保する

候補規則s1: 当日の17/18/19それぞれに10:20/10:40/11:00/11:15の枠を一つずつ持つ。適格性と本人の期間選択を確認済みで、10:00以後・11:10以前、かつ承認時刻から5分以上後の未予約枠がある時だけ、最も早い枠を同じtransactionで予約して『提供引受け』へ変える。枠が無ければ引受けない。入力開始時刻でなく、確認を終えた時刻で判断する。
受付開始・終了の境界は10:00と11:10を含む。5分の準備余地はこの候補の運用上の線として提案する値で、実測した最低能力ではない。原札を一度預かったことと提供の引受けを分け、枠が無い時はその旨を本人へ示して返す/廃棄を選んでもらい、勝手に別の資料へ割り当てない。
資料ごと最大4件/日、全体の理論上限12件。遅い集中はさらに少なく、空いている他の対象枠があっても17の問いを18へ移さない。取下げで空く未開始の枠は11:10以前かつ準備余地がある時だけ再利用でき、開始済み枠は消費済みとする。

### 方式T: 同じ対象へ全件を束で出す

対象ごとの一枚をやめ、最大12件の適格な問いを同じ現物の前と端末で全て選べる束へする道。偏りで枠が足りなくなる問題は避けられるが、紙の枚数・表示・回収の対象と初見の選びやすさを変える。単に12件受け、出さない道ではない。表示と業務を育て、費用と負担を別に比較して採否する必要がある。

### 同じ入力へ当てた有限例

全て構成例で、実際の来館者の提出ではない。

| 入力・開始状態 | s1の途中判定と結果 | 照合する別の根拠 |
| --- | --- | --- |
| 10:05に確認済み17が12件、全枠空 | 最も早い17枠を順に4個確保、5件目以後は対象枠無しで引受けない | 予約4件=17の枠4件。18/19枠を流用しない |
| 10:05に17/18/19が4件ずつ | 各々4枠、計12件引受け | 対象3×時刻4=12の保存量と一致 |
| 11:09に確認済み17が3件、最後の17枠のみ空 | 11:15まで6分あるので1件だけ引受け、残2件は拒否 | 残る対象枠1個と一致。早い枠へ遡らない |
| 11:10ちょうど、最後の18枠空 | 5分の余地と締切を含むので1件引受け | 11:10を1秒超える入力は拒否 |
| 二接続が最後の17枠を同時に読む | 予約と受理を一transactionで確定し、一方だけが枠を使う必要がある | UNIQUEと実行による裏づけを技術材料へ求める |

次の情報設計には、同じ問いと受付キー、対象のnumber、予約したday/number/time、引受けの状態、現在のrevが必要。版や保存欄を置くだけで二重予約を防いだとはしない。実行検査は[技術材料](technical-feasibility/README.md)へ依頼側から渡す。

## 確かめた方法と限界

規則s1の入力・境界・保存される枠数を机上で独立に照合した。全枠使用を実際の提供・実際の見直しへ替えていない。技術の二重予約と、紙/端末へ出す行いは別の根拠が要る。s1/Tの採否と受付の損失は依頼側へ返す。

### 選定後に育てた規則s2

[採用されたK-S](../how-to-solve/discussion.md#論点2-今回届ける版を選び解決策の層を閉じる)からs1を引き継ぐ。次の詳細は同じ引受け・提供・回収を実行できるようにするもので、提供する人数や範囲を増やさない。

| 判定する場面 | 入力/規則 | 結果と残る行い |
| --- | --- | --- |
| 引受け | 本人の土日だけの提供選択、対象番号、確認完了時刻。本人の言葉は一枚に収まる短さ（実装の初期値120文字）、無許可の過去の語りを転用せず、AIで本文を埋めない。運営が勝手に要約/書換えしない | 適格性の確認後、同じ対象の将来枠と当日の累積受理4件以内を一transactionで確認・確保してaccepted。原札を預かっただけなら未受理。長い/不明な内容は本人が直す又は引受けない |
| 同じ受付の再実行 | 受付キーと同じ本文/対象/範囲のdigest | 同じ既存結果を返し、枠や受理数を増やさない。違う内容は409。終了後は410で再開しない |
| 提供準備 | 予約した枠と現行の状態、同じ問IDの紙 | 端末を覆ってruntimeをcoveredにし、旧札を回収。本文と出所を同じ記録から画面/転記・印刷へ出す。紙を置いたことと画面を再読したことを担当が確認するまでopenにしない |
| 提供確認 | 現物の紙ID・画面の問ID/対象/出所・回収済みの旧紙 | 同じ対象の現在の提供候補を切替え、紙placed/画面確認の根拠を記録しopen。『誰かが読んだ/見方が変わった』の結果ではない |
| 取下げ/誤記 | 原札又は本人の控えから特定した問い、現行rev | 先に端末を覆い、該当紙を全回収。新しい読取りを止め、withdrawnとして確認。本文の訂正は勝手に上書きせず、本人が新しい言葉を選んだ場合に新規の確認と空き枠へ戻す |
| 旧画面/同時操作 | expected_revと現行revの一致をUPDATEで判定 | 不一致は409。再読して何が変わったかを確認し、押した操作を成功にしない |
| 取下げた未開始枠 | まだ開始しておらず、締切と5分の余地を満たす空き枠だけ再利用可 | 受理の累積数は取下げでも戻さず各対象4件/日を保つ。同じキーの再送は新受理にしない |
| 停止/再開 | 最後にcommitした受付・予約・紙の状態・runtimeと今の時刻 | 必ずcoveredで再開し、紙と画面を照合。過ぎた枠を提供済みにしない。未提供を明示し、後の同じ対象の空き枠で戻せる所だけ戻し、無ければ不足を選定へ返す |
| 終了 | 11:25以後又は別の日/時刻異常 | 新しい受付/読取りを拒否し覆いと回収へ。日曜はF0消去、土曜は管理下で閉じ日曜に再確認。消去後の再送は元本文を復元しない |

文字数120は一枚のラフを具体化する初期値で、来館者の能力や処理時間の実測ではない。採用済みの『短い問い』を勝手に要約する仕組みは持たない。役割はA/Bという当日の担当だけで、人を識別する来館者の追跡はしない。

### 同じQ17で状態を往復する

土曜10:05に範囲確認を終えたQ17/資料17/来館者の言葉/土日だけを、10:20枠へ予約しaccepted rev1にする。原札の番号と本文を確かめて準備し、紙Q17-P1と画面を一致させ、回収済みの旧紙と現在画面を担当が確認してactive rev2へ進める構成例。
rev1の旧画面から取下げても不一致で拒否し、現行rev2を再読してから取下げる。取下げは端末を覆う・Q17-P1の回収と新GETの除外を確かめる。DBの空欄やクリックだけを物理回収にしない。紙の確認が無ければcoveredのまま未完にする。
同じQ17の結果保存が返る前に止まっても、同じ受付キーから既存結果と枠を読む。未保存ならtransactionは確定しておらず、部分的に受理した状態を作らない。全17が12件と最後の一枠の競合は[有限の実測](technical-feasibility/allocation-observations.json)の範囲で裏づける。
