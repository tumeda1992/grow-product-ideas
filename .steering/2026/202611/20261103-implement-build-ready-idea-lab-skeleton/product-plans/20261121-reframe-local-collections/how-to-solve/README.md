## 決め方

以下は順に取得した当時の問いと返りを残す。「未取得」「未採用」はその段の開始時点であり、現在は冒頭のK-S採用と正本、末尾の配分訂正の記録を使う。

### 変更する共有物を既に使う仕事を調べる

fixtureはcatalogの数値numberとshelfをpacking_list.pyが片付け札として出す。17は袋/A1、18は道具/B2、19は写真/C1。同じ題名でも番号を表示順に替える候補は既存の片付け先の意味を変える。候補は読取り専用の同定と分離を比較し、本番サイトの改修を前提にしない。

### 1. 出どころの事実を確かめる

公開説明と番号はfixtureを原物として確認可能。来館者の新しい言葉と期間の選択は当人、実際の展示位置と提供時間は運営から生まれる。開場時間・物が実際に展示中か・紙の道具が使えるか・運営者の時間配置は未取得。比較を変える所だけ材料の認識合わせへ返す。

### 2. 出どころを直接見る形と、足りない点を出す

原状では同席して口頭で意味が増えた一回がある。公開済み説明を現物の番号で見る基準に、運営が用途・期間・出所付きの紙の問い札を受けて置き、取下げで回収する運用を新たに加える。この基準なら後の人に紙で届く見込みがあり、この良さをソフトウェアの便益へ付け替えない。
補う点は、(G1)同席しない人へ現物を指す別の見方を渡すこと、(G2)出所・期間・取下げ・交代を複数媒体で食い違わせないこと、(G3)その場限りと未来に残す物を分け撤収すること。G1の媒体、G2の運営と制作は一巡として組み、別々の案の便益を足さない。

### 3. 補う点ごとに、選択肢を出す

[alternatives](../materials/alternatives/README.md)へ、基準の新運用と制作の増分を分け、紙の基準・QRの着想・局所の二つの制作案を依頼した。操作の流れと見積りに必要な画面はsketch-experienceへ、PC/貸与端末の実行と物理的な消去の責任配置はimplementation-structure-designへ依頼する。どの案も未採用。

### 4. 崩れやすい時点で、確かめ方を問う

保存・再送・二接続・期限除外は[局所probe](../materials/technical-feasibility/README.md)の条件に限って受領した。画面と紙の消去はDB更新で済まず、[体験と構成](../materials/experience-sketch.md)へ覆う・回収・現行確認を戻した。元のnumberとshelfは片付けの意味を保ち、展示場所は別にする。責任者が認めた分離設計の範囲を越えて本番を変更しない。
PCのPython/browserとLAN読取りは[論点1の合成提供設定](discussion.md)で利用可能と受領。施設で試したことにはせず、アプリの振舞いは局所試作へ、実機と施設での接続は実装後の受入れへ渡す。

### 5. 得るもの・払うものを出す

[部品別の費用](../materials/alternatives/README.md#対案ごとの費用二日と撤収まで)の初回値はKが4.75/8.5/15h、Rが2/4/7h。現在の配分訂正Sは5/9/16hで全て未補正の見積り。共通の同僚準備2h、当日二人各2hの拘束の内に準備20・観察30・照合40人分/日を置き、残150人分で提供等を比較する。有限のK構成例は85人分/日で、追加の修正・長い支援・再試行は未知。悲観値・予算・操作上限は区別する。
F0は[論点1](discussion.md)で採用し、この層の持越しの判断へ反映済み。方式を決める前に、原文を破棄した後の再参加ゼロ・一部・全員の差を受け入れた。whyの長期収蔵を今回約束しない範囲は変わらない。
