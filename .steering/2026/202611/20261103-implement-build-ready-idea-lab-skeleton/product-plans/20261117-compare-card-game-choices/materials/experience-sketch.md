# experience-sketch: 同じ初手・分岐・版比較を各候補の表示/操作と一巡に落とす

担当方法: sketch-experience。同一実行者が専門の役割へ切り替えて適用。独立した別agentの回答ではない。案の採否は依頼側へ返す。

## 依頼と粒度

| 依頼した層と決めるもの | 何のため | 求めた粒度 | この材料で満たしたか |
| --- | --- | --- | --- |
| [how-to-solveの材料依頼](../how-to-solve/README.md#材料への依頼) | 同じ初手・分岐・版比較を各候補の表示/操作と一巡に落とす | 比較に使う一巡、差と成立不足 | 下の中身で応答する。未確認と成立を分ける |

## 中身

### 同じ始点と終点

始点は入力の順序、V0初期3/0/0と手札A2/B5/A3。終点はV0/V1の六手と開始へ戻した初手A2の分岐の各理由/状態を混ぜずに見返すこと。これは机上の設計例で、C1が端末を好んだ事実ではない。

### 主要操作のラフ

N1の紙とB1のsheetを同じ内容で描く。

```text
版V0 / 順序[A2,B5,A3,...] / 試行R1 / 分岐元なし
手 | 行い | 理由(本人記入) | 手札 | 山札位置 | 捨札 | 蓄え | 点
0  | 開始 |              | A2,B5,A3 | 3 | - | 3 | 0
1  | A3   | A2を残す…    | A2,B5,B2 | 4 | A3 | 0 | 3
別試行R2: R1の手0から分岐。R1は消さない。
```

N1は全列をC1が計算/記す。B1は蓄え/点と一部可否だけ式、カード列/複製/理由はC1。式の入力と紙を二か所で変える継ぎ目を持つ。

B2の端末ラフ:

```text
R1 V0 回復2 / 手0/6 蓄え3 点0 / 順序O1
手札 A2 B5 A3 / 残山札9 / 捨札なし
play <ID> <本人の理由> | rest <理由> | branch <run> <手>
new V0|V1 <12 IDs> | show <run> | compare <run1> <run2> | quit
> play A3 小さいA2を残したい
保存済: R1 手1 蓄え0 点3 手札A2 B5 B2
> branch R1 0
R2 V0 元R1手0 / R1の手1以降は保持
> play A2 初手A2ならどうなるか
R2 手1 蓄え1 点2 手札B5 A3 B2
```

B3は同じ情報/入力を一画面の設定・現在状態・履歴/比較欄へ置く。クリック/入力欄という操作差はあるが画面を減らしても保存の仕事は消えない。

### 一巡の照合と不足

| 境界 | N1/B1 | B2/B3 |
| --- | --- | --- |
| 合法でないB5を指定 | 紙の規則を見て本人が拒否。sheetのカード整合は未確認 | 入力は受けても行いは拒否、理由付き成立履歴に足さず状態を保つ |
| 開始へ分岐 | 元紙/複製を残して初期状態を写す | 別runとして元と分岐点を表示。旧runは変更しない |
| V0からV1 | 別紙/sheetと版を書き換える | 新runに固定し、途中では変更不可 |
| 六手終了 | 人が止める | play/rest拒否、show/branch/new/compareは可 |
| 中断 | 最後に紙へ書いた所が根拠 | 最後の確定保存から再開。保存失敗なら未確定と示す |

次へ返す不足: 端末の文字入出力とJSON保存/停止境界は技術へ。branchが履歴の削除にならないための同一性は情報/logicへ。本人が実際に入力しやすいかと理由入力の負担は実利用まで未観測。ラフを好反応の証拠にしない。


## 確かめた方法と限界

入力V1の原文とW1〜W3を用いた机上設計。観察・実装・実利用は未実施。道具の性質は技術の観測に依る範囲だけを後で引き継ぐ。専門は価値・範囲を選んでいない。

### 追加依頼R2-B4: 入力fileを読むcommandの主要操作

R1で生じたB4について同じ始点/終点と粒度で追加した。入力履歴を人が保ち、計算と再生を作る版である。

```text
本人: notes-v0.jsonへ版/順序/行動A3/理由を記す
  -> python replay.py notes-v0.json
道具: 読取/検証 -> 全状態表と現在の合法手を表示
本人: 次の行いと理由を末尾に追加 -> 再実行
  -> 初手を替えたくなったら、元を保存して別fileへコピー
本人: branch-a2.jsonの行動を開始まで戻しA2/理由を記す
  -> python replay.py notes-v0.json branch-a2.json
道具: 同じ順序か検証 -> 別の試行として横又は縦に比較
本人: notes-v1.jsonで版V1と同順序、新しい行いを一手ずつ選ぶ
```

ラフ入力は `{ "rule":"V0", "order":["A2",...12枚], "actions":[{"play":"A3","reason":"本人が記す理由"}] }`。休みは `{"rest":true,"reason":"本人が記す理由"}`。元の紙に無い理由を例の本人の発言として作らない。

出力はfile名・版/回復量・順序と、各手の行い/本人理由/手札/山札位置/捨札/蓄え/得点、未完/六手終了、次に可能な行い。二つの入力では各表を別試行として表示し、同順序の一致と版の一致/差を明記する。勝った方の自動推薦は無い。

不正入力は行番号又はaction番号のエラーと、その前までに成立したprefixを区別して返す。成立しなかったactionを手として進めない。file自体が読めない時は結果を表示せず失敗。元fileは書換えない。上書き/コピー漏れは人に残る損失で、B2と比べるべき差である。

## 追加依頼H1: B4の全場面と現行の表示/操作

[設計依頼H1](../how-to-build/README.md#材料への依頼)を受け、上の比較用ラフを残して育てた。現行入力は[data-model](data-model.md)のschema1/kind形式。以前のplay/restキーのラフは比較用で、実装の入力形式として使わない。

| 場面 | 表示/操作と終わり | 失敗時/残る仕事 |
| --- | --- | --- |
| 開始 | 説明の空actions例を保存、`python replay.py run.json`。path/hash、V0回復2/順序12枚、手0の手札3/蓄え3/点0、合法A2/A3/restを読む | 読取/parse/schema失敗は位置と期待を示す。元を変えず本人が直す |
| 一手 | 本人がactionsへkind/card/reasonを追記保存し再実行。全手の表と現在合法手を読む | 不正playは直前prefixと不成立位置を示す。本人が不成立の入力を直す。手は進まない |
| 分岐 | 保存済元を保持→別fileへcopy→after_turnまでprefixを残す→別action/reason→元と別fileを2引数で比較 | source hash/prefix不一致は不整合と示す。単独では元未照合。本人は保管したcopyを確かめる |
| 版比較 | 新fileを同順序/ruleV1/空actionsで始め一手ずつ。二fileで実行するとrule差と行動差/各表 | 異順序は比較不能。片方未完なら途中比較。どちらの方が良いかは本人が振り返る |
| 終了 | 六手終了/最終点を明示。残蓄え/手札は参考表示で加点しない。本人が入力を保持して終える | 七手目は不成立。直前六手だけが成立したprefix、入力全体の成功とはしない |
| 中断/修正 | 途中出力は捨て、保存済入力で再実行。誤記は本人が直し別hashとして再生 | 元fileを失った時に道具が理由を推測して復元しない。紙へ戻す/その回を中止する判断は本人 |

画面は端末の出力一種。読み順は入力同一性→版/順序→全prefix表→現在の合法手又は終了→比較の照合/未知/エラー。旧理由がnullなら『未記録/理由保持未達』を表示する。色/装飾の仕上げは未定で裁量にできるが情報は落とさない。

通し検査で、当初の『分岐点を表示する』だけでは元が本当に保たれたか分からないと分かった。元copyを人が残し、比較時にhash/prefixを確かめる行いへ繋いだ。これは保管の保証を自動化したことではない。

### D2の全場面への差

D案のラフにあったsource_sha/after_turnの記入と照合エラーを省く。本人は元を保存して別pathへコピーし、戻りたい手までactionsを残して別行動/理由を足す。二つを指定すれば道具が共通行動prefixと最初の違いを表示する。元を保持する仕事は省けない。親来歴は証明しない。異版なら同じ状態からの分岐と表示しない。他の場面/表示/エラーは変わらない。H1の現行仕様は層がD2を採る場合この差を使う。
