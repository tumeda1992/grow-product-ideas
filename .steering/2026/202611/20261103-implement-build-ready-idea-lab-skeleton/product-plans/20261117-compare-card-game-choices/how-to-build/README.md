# 選んだ版の実現設計（六手の蓄え）

- 状態: 閉じた。[論点2](discussion.md#論点2-層を閉じる)
- 決めるもの: [正本のどう作るか](../README.md#どう作るか)へB4/D2の設計を反映済み。

## 受け取った物差しと前提

[選んだB4](../README.md#解き方の選定)は、read-onlyの履歴再生commandを作り、行い/理由の記入、保存/分岐前の元file保持は本人に残す。W1〜W3、6h上限・0円、初回V0/V1+1分岐、入力の負担と面白さは未測定という境界をそのまま受ける。端末対話/自動保存の版へ戻したり、理由/分岐を黙って削らない。

## 決め方

### 1. 選んだ版の一巡から、設計すべき判断を取り出す

| 場面 | 始まり/行い/終わり | 条件と設計事項 |
| --- | --- | --- |
| 導入/開始 | 本人が説明を見て入力を保存し、Pythonで実行。初期3/0と先頭手札が表示される | W1: schema/版/順序の正しい受付 |
| 一手ずつ | 表示の合法手を参考に本人が理由と行いを選び、fileに一つ足す→再生出力の次状態を読む | W1とW2: 不正入力の拒否、本人理由の保持、元fileと読込snapshot |
| 分岐 | 元を保存して別fileへコピー、分岐手以降を消し別行動を記す→二fileを比較 | W2: 元を保ち分岐元/理由を読み分ける |
| V1/比較 | 同順序で別fileを始め、六手の違いを本人が見る | W3: 回復量固定、順序一致と未完の明示 |
| 誤記/終了/中断 | parse/規則エラーを直す、又は途中出力を破棄して同入力を再実行。六手後は終わり | W1: エラーのprefix、正本非変更、導入/復旧の案内 |

### 3. 設計の案を同じ一件へ当て、継ぎ目を照合して選ぶ

設計Dは分岐元注記を人に書かせ来歴を照合する。D2は実際に渡された二つの行動列を再生し共通prefix/最初の差を導く。元file保持はどちらも人に残り、親hash欄だけでは保証できない。D2なら本人の転記/来歴部品を増やさず、同版A3→A2の分岐と別版比較へ届く。この差を次の提案で採否にする。

同じ原文の順序/V0六手をH1入力→H3のschema1/kind形式→H2の全状態→H4のcomplete=true→H5の表出力へ渡すと、原表の点7/蓄え2/next6と一致する。理由は原紙で初手しか分からないのでlegacy=trueのnullを用い、W2全理由保持を満たしたことにはしない。新しい試行では各actionに本人理由を要請する。

分岐A2の新入力は元のcopyを人が保持し、開始までactionsを削ってA2と理由を一つ追加。同版の元と比較すれば共通行動0、初手A3/A2とその時の理由、手1の0/3対1/2が並ぶ。道具は親来歴を証明せず、今回渡された二snapshotを比較したと示す。

同じ行動列V1は点7/蓄え5、V0点7/蓄え2。版/行動列の差を明示するので、単なる点差を回復量の因果効果や最適手へ替えない。不正B5を開始に入れるとschema上IDが正しくても規則再生が拒否し、手0を保つ。三手後の入力ならその前までの成立prefixだけを区別して示す。理由の訂正は別hashへ反映し、古い出力を現行へ付け替えない。

parse失敗は再生へ進めず、片側失敗は比較成功へ進めず、途中出力/OS例外は再実行へ戻す。read-onlyなので処理停止の前後で入力正本を新規に壊さない。人の誤編集/元copyの喪失は自動回復できず、その損失を選定から引継ぐ。

### 4. 導入・修正・復旧と、受入れの確かめ方を設計する

初回構築後、同じ環境でscript/説明/空actionsの入力例を置き、C1が保存した入力を起動する。初期手札/蓄え/点を規則と照合→一手選択/理由追記→再実行→元file保持と分岐→版比較→whyの初回振返りへ進む。新しいサービス/定期処理は無い。人が元fileを保つのを忘れれば失う損失を説明に書く。

誤記は本人がJSON/action位置を直して保存し再実行。理由不明の旧紙はlegacy=true/nullとして未達を表示。未知schema/規則は推測せず停止。新しい規則へ対応する場合は選定/規則設計へ返す。入力を失った時は本人の保管copyを確認し、無ければその回は失われたとし、新回又は紙へ戻る。道具に復元済と表示させない。

取得済み検証は[技術の限定観測](../materials/technical-feasibility/README.md)のみ。ゲーム本体と下記の実装後受入れは未実施。

| 実装後の入力/操作 | 期待 |
| --- | --- |
| 原文順序/V0六手 | 全状態がH2原表に一致、六手点7、next6。各IDは一度だけ存在、得点は捨札値合計 |
| 同列V1とV0の比較 | 版差と同じ行動列、各状態/理由、最終点7対7/蓄え2対5を表示 |
| V0開始からA2へ別file分岐 | 旧file/hashは変わらず、新手1はhand B5/A3/B2/蓄え1/点2/next4、共通行動0 |
| 開始でB5/手札外B1/使ったA3再利用 | 直前状態/手数を変えず拒否。残りをskipして成功としない |
| 休みの上限と蓄え6での休み | min(6,…)、一手は消費 |
| 訂正した六手目補充のV1列 | A3,rest,A2,rest,B2,B1で点8/蓄え1/next7/hand B5,A6,A4。旧い不正例を成功根拠にしない |
| 7個目のaction/未完/異順序二入力 | 7個目を拒否、未完を最終結果にせず、異順序は比較不能 |
| UTF-8理由/null legacy/不正schema | 本人文字列を保持、未知は明示、推測理由無し、新試行の空理由は不足 |
| 実行前後の入力hash/二重起動/途中停止 | 入力一切変更無し、出力の読込snapshotを識別、再実行で同値。部分出力を成功としない |

実利用後、同じ初回の範囲で成立手の記入と不正修正/再実行を別に数え、時間/管理の行い/迷いへ戻れたか/楽しさを本人が振り返る。速度の改善や好反応を先に合格にしない。6hを越える制作/毎週保守/世話だけになる時は選定へ返す。

### 5. 決めた設計を渡し、裁量と選び直す差を残す

D2を選ぶなら、schema1/kind形式、read-only、一回のsnapshot、全prefix/理由と未記録の表示、同版の共通行動prefix、異版比較と未完の区別、入力/不成立/OSエラーの扱いを正本へ渡す。関数名/内部の分割/表の横縦/文言装飾は裁量。ただし情報や不正拒否/元保持の分担、選んだ範囲を変えない。

実装2/3.75/6hは保証でなく、6h上限へ達する前に完成不能なら止めて選定へ返す。18成立手の基準回数へ修正/再入力が増える負担は未知で、実利用初回で測る。新たな親hash転記/永続化/同期を足す場合や時間・費用・人の負担が変わる場合は選定へ返す。

## 差し戻し

whatの不正入力と不正遷移の区別を受領し、H2と受入れへ適用。H2の六手目補充の誤りは材料内で訂正し、上の値を再照合した。why/whatの目標・条件は変わらない。H6のD2は選定した同じ人の分担と工数の境目を保つ。how-to-solveへ確かめ直しを返す。
