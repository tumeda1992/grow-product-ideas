## 解き方の選択肢の決め方

### 1. 出どころの事実を確かめる

規則・版差・順序は入力原文、状態はその規則と本人の行いから生じる。理由は選ぶ時のC1からのみ生じる。未知の理由を自動生成しない。紙/筆記具/四則表計算が使えることは設定。表計算の具体サービスやmacro可否は未取得。ローカル検査環境のOS/runtimeは未取得なので技術へ依頼する。

### 2. 出どころを直接見る形と、足りない点を出す

基準は紙の12枚を規則原文で扱い、その場で状態と理由を紙へ記すこと。正しい計算をすればW1へ届くが、状態の写しと山札の復元に迷った原事例がある。紙を残して分岐を新紙へ書けばW2/W3に届く見込みだが手作業は残る。足りない点P1は状態の管理、P2は元の試行と理由・分岐の対応、良くする点P3は自分の小道具を作る楽しみ。自動最適化は補う点でない。

### 3. 補う点ごとに、選択肢を出す

専門依頼R1を下へ記録。選定はまだしない。

## 解き方の選定の決め方

### 1. 決め手が依る事実を確かめる

このローカル環境でPythonと日本語JSONは実観測。本人の実装速度と端末/file編集の慣れは入力に無く、得られない。速度の補正無しを受け入れた見積りであり6hで完成を保証できない。実装時は6hへ達する前に止め、範囲を勝手に削らず同じ選定へ返す。別browserの事実が必要なB3、表計算機能が必要なB1は必要な答えが無い。B4はその事実に依らない。

### 2. 補う点（組）ごとに、境目で比べて選ぶ

P1規則管理とP2分岐/理由は同じ履歴を使い組で比較する。N1は安いが全状態を手計算する。B2は対話/保存を買うが上限を越える。B4は状態の再生を作り、file複製と理由記入は本人が担う。P3はB2/B4でこのゲームを動かす楽しみ、N1では処理を作らない。採否は次の論点へ出す。

### 3. 作る理由を切り分ける

B4の処理を作る理由は、正しい状態を入力履歴から再計算し山札を人が戻さず試すことと、自分の小道具を作る楽しみ。便益は仮説、制作の楽しみは資料の望み。楽しさが増えたと測定してはいない。

### 4. 選び直す条件を書く

6h超の実装見込み、毎週の保守が要る、file編集/コピーで遊ぶ代わりに世話になる、原試行を失う、別の端末/規則が必要、同じ入力で規則不一致が出る時。初回比較後に入力の負担と迷いへ戻れるかを本人が測り、次の一回を続けるか判断する。
