# 何を作るか（`what-to-build`）

この層の問いに、このアイデアについてどう決着をつけたかの一覧である。

- 決まった内容は、正本（[README](../README.md)）の各節にある
- 問いごとの立て直し、詰めた深さ、確認は、`questions/`の問いのfileにある
- 判断の変遷は、[この層の決定過程](discussion.md)にある

| 層の状態 | 利用者が受け入れた応答 |
| --- | --- |
| 未閉じ | 要求の問いを答え直したため閉じていない状態に戻した（一度は[論点4](discussion.md#論点4-予約の代行をスコープの外に置く)で受け入れた） |

## この層で広がった視野

問いに答える中で、発案者の視野の外にあった点。起きた順に並べる。

| 気づいたこと | どの問いで | 論点 |
| --- | --- | --- |
| 共有表計算は思ったより強い代案である | [代案](questions/existing-alternatives-fall-short.md) | [論点1](discussion.md#論点1-共有表計算を代案の本命として比べる) |
| 家族だけの道具でも、通知に乗せた時点で子どもの情報が外部に渡る | [リスク](questions/risks-of-building.md) | [論点3](discussion.md#論点3-子どもの情報をlineへ送ることを受け入れ送る内容を絞る) |
| 着想の手段（LINE）も前の解き方の形（どの端末からも一覧）も、満たされた状態で書くと一つの手段にすぎない。夫は家でしか予約しない | [要求](questions/requirements.md) | [論点6](discussion.md#論点6-要求を満たされた状態で書き直しmustの線を分担が解けるかで引く) |
| 作らなくても、家族のカレンダーで期限に気づける。作る必要があるのは通知ではなく、残り回数を数えることと期限を写すこと | [代案](questions/existing-alternatives-fall-short.md) | [論点9](discussion.md#論点9-作らずにmustのほとんどを覆えるが作る楽しみと照らして作る道とも比べる) |
| 知らせは家族のカレンダーに任せ、作るのは残り回数を数えることと期限を写すことにすると、作る時間は着想どおりの半分以下になる | [解き方](questions/solution-shape.md) | [論点10](discussion.md#論点10-今日から共有カレンダーで覆い残り回数と期限の写しを作るものに置き換える) |
| 着想（LINE）を中心から外すと、子どもの情報を新しい外部のサービスへ送るリスクも無くなる | [リスク](questions/risks-of-building.md) | [論点11](discussion.md#論点11-lineを使わず子どもの情報の送り先を増やさない残るのはscriptが止まることと確かめていない権限) |
