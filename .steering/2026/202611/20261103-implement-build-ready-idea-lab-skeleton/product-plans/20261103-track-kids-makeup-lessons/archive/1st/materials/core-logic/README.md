# core-logic: 振替の期限と残り回数を、教室ごとの規則で決める

## 要求した問いと粒度

| 問いのidentifier | 問いの文面 | 求めた粒度 | この材料で満たしたか |
| --- | --- | --- | --- |
| `how-to-build/tables` | データをどのテーブルに分けて持つか | 入力と出力、例外と境界が分かる程度 | 満たした |
| `how-to-build/modules` | コードをどのモジュールに分けるか | 一番難しい部分と、その解き方の案が分かる程度 | 満たした |

## 中身

### 入力と出力

- 入力: 教室、欠席日、その教室の規則、その教室のこれまでの振替
- 出力: 振替が発生するか、期限の日付、その期間の残り回数

| 教室（利用者役の回答） | 規則 | 例: 欠席日 → 期限、残り回数 |
| --- | --- | --- |
| スイミング | 月2回まで。欠席した月の翌月末まで | 2026-11-10 → 2026-12-31、11月の残り1回 |
| ピアノ | 年度に4回まで。年度末（3月31日）まで | 2026-11-10 → 2027-03-31、今年度の残り3回 |
| 英会話 | 欠席ごとに発行。発行日から60日 | 2026-11-10 → 2027-01-09、上限なし |

### 例外と境界

- 上限を超えた欠席（スイミングの月3回目）: 振替は発生しない。登録はするが「振替なし」として残す
- 年度をまたぐ（ピアノの3月の欠席）: 期限は3月31日で、残りが少ない。年度が変わると回数は4回に戻る
- 講師都合の休み: 期限なし。利用者が期限を手で上書きする
- 欠席日の取り消し（登録の誤り）: 振替を消し、回数を戻す

### 一番難しい部分

教室ごとに違う規則を、教室が増えても計算の本体を書き換えずに扱うこと。

### 回避案と正面から解く案

| 案 | 内容 | 楽になること | 残ること |
| --- | --- | --- | --- |
| 回避案: 教室ごとに計算を書く | 三つの教室それぞれに期限と回数の計算を書く | 今の三つは単純に書ける | 教室が増えるたびにcodeを足す |
| 正面から解く案: 規則をdataで持つ | 規則を「回数の上限の単位（月／年度／なし）と上限」「期限の基準（欠席月の翌月末／年度末／欠席日からN日）」の組で表し、一つの計算で扱う | 同じ型の教室は設定の追加だけで足せる | 三つの型に当てはまらない規則が来たら、型を足すcodeが要る |

## 確かめた方法と限界

利用者役の回答の三つの教室の規則から書いた。他の教室の規則は、材料`target-user-voices`の教室の案内（数日前までの予約、曜日で振替不可の枠）を見たが、予約の締切は期限と回数の計算の外として扱った。
