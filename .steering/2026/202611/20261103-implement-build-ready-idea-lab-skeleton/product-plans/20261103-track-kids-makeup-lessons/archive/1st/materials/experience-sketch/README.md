## 中身

### 費用の見積り用の粗い案

| 画面 | 主要な操作 |
| --- | --- |
| 振替の一覧 | 期限の近い順に振替を見る。振替を予約済み・使用済みにする |
| 欠席の登録 | 子ども・教室・欠席日を選ぶと、期限が決まる |
| （通知） | 期限の7日前と前日に、家族の二人へLINEで知らせる |

画面2枚、通知1種、家族の二人が見られる仕組み。

### 解き方の案

| 案 | 主要な操作の流れ | 必須の要求との対応 |
| --- | --- | --- |
| A: LINEだけで完結する | 欠席をLINEへ書き込む → ボットが期限を返す → 期限の前にLINEで知らせる → 「使った」と書き込む | 登録・期限・通知・使用済みは満たす。一覧は会話を遡る形になり、残り回数を一目で見られない |
| B: ウェブの一覧とLINEの通知 | 欠席をウェブの一覧で登録 → 期限が計算される → 期限の前にLINEで二人へ知らせる → 一覧で予約済み・使用済みにする | 全ての必須の要求を満たす |
| C: 共有表計算と定期の通知 | 共有表計算に欠席を行として足す → 計算式で期限が出る → 定期の処理が表を読み、期限が近い行をLINEで知らせる | 全ての必須の要求を満たすが、スマートフォンでの表計算の入力が手間で、妻以外が入力しない恐れ |

### 最初に作る分の区切りの案

| 案 | 含む場面 | 痛みの核心の場面が一度通るか |
| --- | --- | --- |
| A: 核心を一本通す | 欠席の登録 → 期限の計算 → 期限の前の通知 → 使用済みにする | 通る。ただし一覧が無く、自分は残り回数を通知でしか知れない |
| B: 全場面を薄く通す | Aに、振替の一覧（期限順、教室ごとの残り回数）と予約済みの印を足す | 通る。自分が一覧を見て予約を代われる |

### 体験の流れの案

最初に作る分の場面は四つ（欠席の登録、期限の前の通知、予約、受講）である。

| 案 | 組み立て方 | 流れ |
| --- | --- | --- |
| A: きっかけから組む | 欠席の連絡をした直後を入口にする | 教室へ欠席を連絡した直後、一覧を開いて欠席を登録 → 期限と残り回数が表示される → 期限の7日前に二人へ通知 → 通知から一覧を開き、教室のアプリで振替を予約し、一覧で「予約済み」にする → 受講した日に「使用済み」にする（しなければ受講日の翌日に一覧の上部へ出る） |
| B: 今の回避策をなぞる | 妻が週末にまとめて確認する今の手順を置き換える | 週末に一覧を開き、その週の欠席をまとめて登録 → 期限の近い順に並ぶ → 予約・受講は案Aと同じ |

失敗した時・途中でやめた時: 登録の途中で閉じたら何も保存されない。通知を見ても予約しなかったら、前日にもう一度通知する。期限を過ぎたら「失効」として一覧の下へ移り、失効の回数が残る。

### 画面構成の案

| 案 | 画面 | 表示する情報と操作 |
| --- | --- | --- |
| A: 一画面にまとめる | 振替の一覧（1枚） | 上部: 欠席の登録（子ども・教室・欠席日の3つを選ぶ）。中部: 期限の近い順の振替（子ども、教室、期限、残り日数、状態）。各行で「予約済み」「使用済み」を押せる。下部: 教室ごとの今期の残り回数と、失効した振替 |
| B: 一覧と登録に分ける | 振替の一覧、欠席の登録（2枚） | 一覧はAの中部・下部、登録はAの上部を別の画面にする |

体験の流れの四つの場面との対応: 欠席の登録（Aの上部／Bの登録画面）、通知（LINE、画面なし）、予約（一覧の行の「予約済み」）、受講（一覧の行の「使用済み」）。

## 確かめた方法と限界

利用者の着想（家族で見られる一覧、LINEの通知）と、各層の問いの答えから描いた。文字の配置図であり、見た目の細部は描いていない。実際の使い心地は作って使うまで分からない。
