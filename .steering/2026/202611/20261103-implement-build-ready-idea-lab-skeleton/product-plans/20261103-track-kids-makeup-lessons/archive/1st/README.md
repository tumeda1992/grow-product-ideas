# 習い事の振替を、家族で期限内に使い切るための一覧と通知

子ども二人が通う三つの習い事の振替について、教室ごとに違う規則で決まる期限と残り回数を一つの一覧にまとめ、期限が近づくと家族の二人へLINEで知らせる。妻だけが頭の中で担っていた振替の管理を、二人で分けられるようにする。

- 状態: build-ready

## 解く痛み

子ども二人が、スイミング、ピアノ、英会話の三つの教室に通っている。欠席した分の振替は、教室ごとに規則が違う。

| 教室 | 振替の規則 |
| --- | --- |
| スイミング | 月2回まで。欠席した月の翌月末まで |
| ピアノ | 年度に4回まで。年度末（3月31日）まで |
| 英会話 | 欠席ごとに発行。発行日から60日 |

痛みは三つある。

- 期限と残り回数が、三つの教室のアプリ・LINE・紙に散らばる
- 期限が近いことに気づけないまま失効する。昨年度は5回（約12,500円）失効した
- 管理を妻だけが担い、夫は残り回数も期限も分からず、予約を代われない

核心は三つ目の分担である。一つ目と二つ目は、妻が一人で抱える負担の中身である。今は、妻の記憶と、各教室のアプリをときどき開くことでしのいでいる。

根拠: 論点 なぜ作るか 論点1（規則と失効の実態）、論点2（痛みの核心を分担に置く）。材料 [target-user-voices](materials/target-user-voices/README.md)

## 作る理由

既にある道具では、計算と入力を妻だけが担う構造が残る。

- 家族の共有カレンダーは、期限を予定にすれば気づきと共有を解くが、欠席のたびに教室の規則で期限を計算して予定を手で作る必要があり、残り回数は見えない。
- 共有表計算は、規則を計算式で書けて代案として強いが、自分から知らせず、スマートフォンでの入力が手間で、妻以外が入力しなくなる。
- 教室のアプリは教室ごとに別で、教室向けの振替管理アプリは親が選べない。

時間だけで比べると、作る方が代案より毎年約10時間多くかかり、逆転しない（作る1年目約28時間、代案約2.7時間）。それでも作るのは、次の二つのためである。

- 代案では、欠席ごとの規則の計算と入力を妻だけが担い続け、二人で分けられない
- 費用の外の理由として、作ること自体が利用者の楽しみである

作るのは、代案で残る痛み（規則の計算、二人での共有、期限前の通知）に絞る。

根拠: 論点 なぜ作るか 論点3（共有表計算を代案の本命として比べる）、論点5（作る理由を費用の外に置き、対象を絞る）。材料 [existing-alternatives](materials/existing-alternatives/README.md)、[cost-comparison](materials/cost-comparison/README.md#作る案と代案)

## 何を作るか

### 要求

必須:

| 要求 | 解く痛み |
| --- | --- |
| R1 欠席を登録すると、その教室の規則で、振替が発生するか・期限・その期間の残り回数が決まる | 散らばる |
| R2 期限の7日前と前日に、家族の二人へ知らせが届く | 気づけない |
| R3 家族の二人が、どの端末からも振替の一覧（期限順）と教室ごとの残り回数を見られる | 分けられない |
| R4 振替を予約済み・使用済みにでき、失効したものは失効として残る | 気づけない |
| R5 教室ごとの規則（回数の上限の単位と上限、期限の基準）を設定できる | 散らばる |

あれば嬉しい: R6 教室のサイトへの予約の代行、R7 月謝の記録。

根拠: 材料から導いた（論点は立っていない）。[解く痛み](#解く痛み)の三つの場面に一対一で対応させた

### 解き方

ウェブの一覧と、LINEの通知を組み合わせる。知らせは家族が日常で開くLINEに置き、一覧はウェブで二人とも見られるようにする。

LINEだけで完結する形は、残り回数を一目で見られない。共有表計算と定期の通知の形は、スマートフォンでの入力が手間で、妻以外が入力しなくなる。

根拠: 論点 何を作るか 論点（解き方の形の選択）。材料 [experience-sketch](materials/experience-sketch/README.md#解き方の案)

### スコープの内と外

- 内: R1〜R5
- 外:
  - R6 予約の代行。各教室のアプリで手で予約する。教室ごとに予約の仕組みが違い、作る時間が40時間以上に膨らむ
  - R7 月謝の記録。今のまま家計簿で扱う
  - 送迎の分担

根拠: 論点 何を作るか 論点（予約の代行を外に置く）。材料 [cost-comparison](materials/cost-comparison/README.md#スコープの案)

## 最初に作る分

欠席の登録、期限と残り回数の計算、二人への通知、一覧（期限順、教室ごとの残り回数）、予約済み・使用済みの印を、最初に作る（約16時間）。

規則の編集画面は最初に作らず、規則は設定fileで持つ。規則の変更が年3回を超えたら、編集画面を作る。

通知だけを先に作る区切りは、夫が一覧を見られず予約を代われないため、分担の痛みが解けない。

根拠: 論点 どこまで作るか 論点（一覧を最初の分に含める）。材料 [experience-sketch](materials/experience-sketch/README.md#最初に作る分の区切りの案)、[cost-comparison](materials/cost-comparison/README.md#区切りの案)

## 体験

1. 教室へ欠席を連絡した直後に、連絡した方が一覧を開き、子ども・教室・欠席日を選んで登録する
2. 期限と残り回数が表示される
3. 期限の7日前に、二人へLINEで知らせが届く
4. 知らせから一覧を開き、教室のアプリで振替を予約し、一覧で「予約済み」にする
5. 受講した日に「使用済み」にする

- 予約しなかったら、前日にもう一度知らせる
- 期限を過ぎたら「失効」として一覧の下へ移り、失効の回数が残る
- 登録の途中で閉じたら、何も保存しない

根拠: 論点 どう作るか 論点（予約しなかった時と失効の流れ）。材料 [experience-sketch](materials/experience-sketch/README.md#体験の流れの案)

## 画面

一画面にまとめる。欠席の連絡の直後にスマートフォンで素早く登録する場面が最も多いため。

| 画面 | 表示する情報 | 操作 |
| --- | --- | --- |
| 振替の一覧 | 上部: 欠席の登録欄。中部: 期限の近い順の振替（子ども、教室、期限、残り日数、状態）。下部: 教室ごとの今期の残り回数、失効した振替 | 欠席の登録（子ども・教室・欠席日を選ぶ）、各行の「予約済み」「使用済み」「削除」 |

通知はLINEで届き、画面を持たない。一覧は、家族の二人だけの合言葉で守る。

根拠: 論点 どう作るか 論点（登録を一覧と同じ画面に置く）。材料 [experience-sketch](materials/experience-sketch/README.md#画面構成の案)

## データ

| テーブル | 一行が表すもの | 項目 |
| --- | --- | --- |
| `children` | 子ども一人 | 名前、色 |
| `schools` | 子どもが通う教室一つ | 子ども、名前、上限の単位（月／年度／なし）、上限の回数、期限の基準（欠席月の翌月末／年度末／欠席日からN日）、期限の日数 |
| `makeup_lessons` | 欠席によって生まれた振替一つ | 教室、欠席日、期限、状態（未予約／予約済み／使用済み／失効／振替なし）、予約した日、受講した日、メモ |
| `sent_notifications` | 送った通知一回（出来事の記録） | 振替、種類（7日前／前日）、送った日時 |

残り回数は、`makeup_lessons`を教室と期間で数えて出す。振替は状態が変わっても持つべき項目が変わらないため、状態を項目で持つ。同じ通知を二度送らないため、送った通知を出来事として記録する。

根拠: 論点 どう作るか 論点（通知の二重送信を防ぐ記録を持つ）。材料 [core-logic](materials/core-logic/README.md)、[tables](materials/tables/README.md)

## モジュール

| モジュール | 役割 | 持たないもの |
| --- | --- | --- |
| `rules` | 規則から、振替が発生するか・期限・残り回数を計算する純粋な計算 | 保存、画面、通知 |
| `makeup_lessons` | 欠席の登録、状態の変更、一覧の取得。`rules`を呼んで期限を決め、保存する | 通知 |
| `notifications` | 毎朝、期限の7日前・前日の振替を選び、送っていなければLINEへ送り、送った記録を残す | 期限の計算 |
| `web` | 一覧の画面 | 判断 |

依存の向き: `web` → `makeup_lessons` → `rules`、`notifications` → `makeup_lessons` → `rules`。新しい型の規則は`rules`だけを触る。

根拠: 論点 どう作るか 論点（心臓部を切り出す）。材料 [core-logic](materials/core-logic/README.md)、[modules](materials/modules/README.md)
