## 中身

- 期限と残り回数の計算: 日付の計算と数え上げであり、技術的な不確実性は無い（材料`core-logic`の三つの規則の例で、手計算で期限と残り回数が出ることを確かめた）。
- LINEの通知: LINE公式アカウントから家族の二人へ送る。無料の枠（月200通とする記事が複数）に対し、送る量は月に十数通の見込み（振替が月2〜3件、一件あたり2回、二人へ）で、枠に収まる。Messaging APIでの送信が無料の枠に数えられる仕様は未確認だが、収まらなくても月の上限に達するだけで、取り返しのつかない影響は無い。

動かして確かめることはしていない。動かさないと分からない挙動のうち、出口や作るものを変えるものは無いと判断した。

### フォームと表計算と、カレンダーへ写すscript

解き方の答え直しで、作るものが、表計算の計算式と、毎朝表を読んで家族の共有カレンダーに予定を作るGoogle Apps Scriptに変わった（正本の[解き方](../../README.md#解き方)）。確かめたい問いは次の一つである。

> Google Apps Scriptの時間主導のトリガーで、毎朝表を読み、家族の共有カレンダーに終日の予定を作り続けられるか。止まった時に気づけるか

| 確かめたいこと | 分かったこと | 出どころ |
| --- | --- | --- |
| 一回の実行の時間の上限 | 個人のGoogleアカウントでは、一回の実行は6分までで、超えると止まる。毎朝の処理（表の数十行を読み、数件の予定を作る）は、これに十分収まる見込み | 第三者の解説（[labnol](https://labnol.org/code/20016-maximum-execution-time-limit)） |
| 割り当て（上限）の決まり | 割り当ては個人向けとWorkspaceで違い、利用者ごとにかかり、24時間で戻る。予告なく変わることがある。超えると例外で止まる | 公式（[Apps Script の割り当て](https://developers.google.com/apps-script/guides/services/quotas?hl=en)） |
| 時間主導のトリガーの数と、一日の合計の実行時間の上限 | 確かめていない。公式の割り当てのページの数値は、検索の結果からは読めなかった | — |
| 共有カレンダーへ予定を作れるか | 確かめていない。家族のカレンダーの持ち主が、scriptを動かす人に「予定の変更」以上の権限を与えている必要がある、というのは一般の知識であり、公式の文書で確かめていない | — |
| 止まった時に気づけるか | 確かめていない。トリガーの実行が失敗すると、トリガーの持ち主へ失敗の知らせのメールが届く仕組みがある、というのは一般の知識であり、公式の文書で確かめていない。script自身が失敗を捕まえてメールを送ることはできる | — |
| 規則の計算（期限、残り回数） | 三つの型は、表計算の日付の関数（月末、年度末、日数の足し算）と、期間ごとの数え上げで書ける。前の確かめ（三つの規則の例で手計算できること）と同じで、技術的な不確実性は無い | 前の確かめ（上の「中身」） |

動かして確かめることはしていない。確かめるには、利用者のGoogleアカウントと家族のカレンダーでscriptを動かすことになり、確かめる行為が利用者の本物のアカウントとデータを使う操作に当たるためである。安全に確かめる手段として、検証用のGoogleアカウントと検証用のカレンダーで動かす方法があるが、それを用意するのは利用者である。

一番難しい部分（毎朝の写し）は、広く使われている仕組み（時間主導のトリガー、カレンダーへの予定の作成）の組み合わせであり、実現できない見込みは小さい。確かめきれていないのは、権限、上限の数値、止まった時の知らせ方の三つである。

## 確かめた方法と限界

- フォームと表計算と、カレンダーへ写すscriptについては、ウェブ検索で、Apps Scriptの割り当ての公式のページと、実行時間の上限の第三者の解説を読んだ。共有カレンダーへの書き込みの権限と、失敗の知らせのメールは、検索の結果で確かめられず、一般の知識として書いた。動かして確かめていない（確かめること自体が利用者の本物のアカウントを使う操作に当たる）。

codeは書いていない。LINEの料金・通数は第三者の記事による。
