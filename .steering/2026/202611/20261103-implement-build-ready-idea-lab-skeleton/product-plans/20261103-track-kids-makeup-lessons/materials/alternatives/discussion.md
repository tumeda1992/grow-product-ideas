# alternatives の決定過程（振替の件）

## 論点1: 二人の毎日の道具の使い方、今のしのぎ方、過去に作った時の見立てと実績

**ステータス:** 決定

**種別:** 認識合わせ

### イテレーション0（論点1）: 対案の材料が要る事実

#### 提案0（論点1）

対案の材料（`alternatives`）を作るのに、利用者しか持たない事実が要るとskillが返した。何が成り立てばよいか層の論点1（前の記録の何を作るか論点5）で、二人が毎日見るもの（LINE、共有のGoogleカレンダー、冷蔵庫の横のボード）は分かった。その先を教えてほしい。

| 問いたいこと | 答えで材料のどこが変わるか |
| --- | --- |
| 共有のGoogleカレンダーを、二人はどう使っているか（誰が予定を入れるか、通知を受けているか） | カレンダーに寄せる対案が、今の使い方の延長で済むか、新しい習慣が要るか |
| 冷蔵庫の横のボードは、誰が書き、どれくらいの頻度で書き換えているか | ボードに寄せる対案の、状態を保つ操作が、今の習慣に乗るか |
| 妻は今、振替の期限と残り回数を何で覚えているか（記憶だけか、手帳やメモか） | 「今のしのぎ方から少しずつ変える」切り口の出発点 |
| 表計算やフォームを、家のことで使ったことがあるか | 表計算に寄せる対案を、二人が使い続けられるか |
| 過去に何かを作った時、作る前にどれくらいかかると見立て、実際にどれくらいかかったか | 作る対案の作る時間の補正 |

#### 検討記録（論点1・イテレーション0）

起点: 旧レールの何を作るか層・`existing-alternatives-fall-short`の依頼（[依頼と粒度](README.md#依頼と粒度)）。前の記録では、[何を作るか 論点7](../../archive/2nd/what-to-build/discussion.md#論点7-二人の毎日の道具の使い方今のしのぎ方過去に作った時の見立てと実績)として、層の決定過程に立っていた。材料についての論点は材料の決定過程に置く（steeringの論点36）ため、ここへ移した

材料`propose-alternatives`の手順2が返した問いである。最も強い対案は、既に毎日開いている道具の中で済む道であり、探す範囲そのものがこの答えで変わる。

#### 提案0へのフィードバック（論点1）

**結果:** 回答

> カレンダーは家族の予定（子どもの行事や通院）を主に妻が入れていて、二人とも予定の30分前の通知は受けている。夫も自分の予定はたまに入れる。ボードは学校のプリントを貼るためのもので、書き込みはほとんどしていない。妻は振替を、教室のアプリをときどき開いて確かめているのと、頭で覚えているだけ。表計算は夫が仕事で使うが、家のことでは使っていない。前に家計の記録のアプリを作った時、週末二回くらいで作れると思っていたら、結局二か月くらいの土日がかかった。画面は三枚くらいだった。

（ユーザー役。この試運転では、assistantが利用者の応答を想定して書いた）

### 決定（論点1）

共有のGoogleカレンダーは主に妻が家族の予定を入れ、二人とも予定の通知を受けている。冷蔵庫の横のボードはプリントを貼る場所で、書き込む習慣は無い。妻は振替を、教室のアプリを時々確かめることと記憶でしのいでいる。表計算は夫が仕事で使うが、家のことでは使っていない。過去に画面三枚ほどのアプリを作った時、見立ては週末二回、実績は約二か月の土日だった。

## 論点2: 共有カレンダーで、相手が作った予定に自分の既定の通知が付くか

**ステータス:** 決定

**種別:** 認識合わせ

### イテレーション0（論点2）: 利用者の環境で試してほしいこと

#### 提案0（論点2）

作らない道で「期限の7日前に二人が気づく（S1）」を覆う一番の候補は、家族で共有しているGoogleカレンダーである。この道は、二人がそれぞれ家族のカレンダーの既定の通知を「7日前」にしておけば、どちらが作った期限の予定にも、二人ともに通知が届く、という前提に立つ。

材料`alternatives`は、通知が利用者ごとの設定で、カレンダーごとに既定を置けることまでは公式の文書で確かめたが、相手が作った予定に自分の既定が付くかは確かめきれなかった。家族のカレンダーで、次を試してほしい。

1. 夫が、家族のカレンダーの既定の通知に「7日前」を足す
2. 妻が、家族のカレンダーに8日後の終日の予定を一つ作る
3. 翌日、夫のスマートフォンに通知が来るかを見る

#### 検討記録（論点2・イテレーション0）

起点: 旧レールの何を作るか層・`existing-alternatives-fall-short`の依頼（[依頼と粒度](README.md#依頼と粒度)）。前の記録では、[何を作るか 論点8](../../archive/2nd/what-to-build/discussion.md#論点8-共有カレンダーで相手が作った予定に自分の既定の通知が付くか)として、層の決定過程に立っていた。ここへ移した

材料の「確かめた方法と限界」が、最初に確かめるべき事実として挙げたものである。ウェブの文書では確かめきれず、利用者の環境で試すしかない（steeringの試運転の摩擦7）。

#### 提案0へのフィードバック（論点2）

**結果:** 回答

> 試した。夫の側で家族カレンダーの既定の通知を7日前にしておいたら、妻が作った終日の予定にも、夫のスマホに通知が来た。ただ、終日の予定の通知は時刻を別に設定する欄があって、初めは前日の9時になっていたので直した。

（ユーザー役。この試運転では、assistantが利用者の応答を想定して書いた）（実際には試していない。試運転のための想定の答えである）

### 決定（論点2）

家族の共有カレンダーで、夫の側の既定の通知（7日前）は、妻が作った終日の予定にも付いた。終日の予定の通知の時刻は、既定とは別に設定する必要がある。

## 論点3: 教室のアプリのアカウントを、家族で使ってよいか

**ステータス:** 決定

**種別:** 認識合わせ

### イテレーション0（論点3）: 候補C9の規約

#### 提案0（論点3）

どう解くか層の論点1で、夫も、スイミングと英会話のアプリに同じ家族のアカウントでログインしていると分かった。この候補（C9）は、出どころを二人が直接見る形の前提になっている。

それぞれのアプリの利用規約が、一つのアカウントを家族で使うことを認めているかを確かめたい。規約は教室ごとのアプリにあり、ウェブで一般に読める文書かが分からない。アプリの規約のページを開いて、アカウントの共有や、家族での利用について書かれた所があるかを見てほしい。

| 答え | 材料のどこが変わるか |
| --- | --- |
| 認めている、または家族で使う前提になっている | C9の規約・安全を「反しない」にする |
| 禁じている | C9の規約・安全を「反する」にし、夫は自分のアカウントを作れるかを問い直す。作れなければ、スイミング・英会話の情報も、基準では夫に届かず、どう解くか層の補う点が増える |
| 書かれていない | 確かめていないまま残し、どう解くか層へその旨を返す |

#### 検討記録（論点3・イテレーション0）

起点: どう解くか層・解き方の選択肢の依頼（[依頼と粒度](README.md#依頼と粒度)）と、[変えた所](README.md#変えた所)のC9。確かめること自体は規約・安全に触れない（規約を読むだけ）が、読めるのは利用者の端末のアプリの中だけであり、利用者に頼む。

#### 提案0へのフィードバック（論点3）

**結果:** 回答

> 二つのアプリとも、規約に「保護者アカウントは同じ世帯の保護者で共有して使える」って書いてあった。

（ユーザー役。この通し直しでassistantが想定して書いた）

### 決定（論点3）

スイミングと英会話のアプリは、保護者のアカウントを同じ世帯の保護者で共有して使うことを規約で認めている。候補C9の規約・安全は「反しない」にする（[変えた所](README.md#変えた所)）。
