# 二人で選ぶ夕食を平日の変化へ繋ぐ

固定した検査用入力を、価値の探索から順に検討する。実在の利用者の望み又は実利用の結果とはしない。

- 状態: 作らない
- 閉じた層: why-to-build、what-must-hold、how-to-solve

## 受け入れ時の入力

以下は検査用の利用者役の原文である。全ての出来事・制約と未確認は[初期入力](input.md)に保持する。

### アイデア

> 週末に二人で何を食べるか話すのは好き。平日の帰りに「今日何にする、家に何がある」とやり直して、帰宅が遅くなる。献立を自動で決めてほしいのかというと、それもちょっと違う。

### 作りたい動機

> 昨日食べたかった物が今日も同じとは限らない。変更したいと言いにくくなるのは困る。毎回C2に冷蔵庫を確認させているのは減らしたい。

### 既にある着想

> 二人で見られるメモへ今週の候補と買う物を置く

## 前提にする条件

準備30分、新規有料契約なし、週末15〜20分、平日一人5分程度。常時の全食材記帳・担当固定は継続の自信が無い。[合意](why-to-build/discussion.md#決定論点1)

## なぜ作るか

<!-- この節を決める層と決めるもの: why-to-build／体験と価値、アウトカム、作ることで得たいもの -->

### 体験と価値

料理名だけの共有では、気分・帰宅・残りの変化から夕食までを繋げられなかった。一緒に選ぶ良さと変更の自由を残し、候補/不明/実際の引受けを混同しない価値を選ぶ。全固定・全在庫より双方の語りに合う。

### アウトカム

> 二人が週末に一緒に選んだ良さを保ち、平日の気分・帰宅・残りの変化を受けて、その日の候補と確かめられていないことを取り違えず、引き受けられる行いを選び直して実際の夕食へ繋げられる。

二人の週末と平日を対象とする。栄養点数・最安・全在庫追跡は含めない。初週の変更時の経過と実際の夕食・確認分数、2週後の楽しみと変更の抵抗・帰りの再相談を二人別々に測る。効果は未観測。

### 作ることで得たいもの

開発自体の楽しみの望みは無い。

根拠: [過程と確認](why-to-build/README.md)、[閉じ](why-to-build/discussion.md#決定論点2)

## 解き方

### 解き方の選択肢

<!-- この節を決める層と決めるもの: how-to-solve／解き方の選択肢 -->

現物と相手へ直接確かめる基準、現状N、全確認の非開発F、共同候補と変更の入口だけのP、自作Bを比較。料理名の共有だけで現物/引受けへ届かない。Fが不可能だとはせず、負担を含めて比べた。[候補と費用](materials/alternatives.md)

### 解き方の選定

<!-- この節を決める層と決めるもの: how-to-solve／解き方の選定 -->

Aの共同候補と変更希望を既存のメモ/連絡で扱うPを選び、Bの全現物/引受け管理は今回導入しない。日曜に候補と変更可を揃え、変更者が日付/本人/希望/不明を元を消さず追記し、連絡で同じ記述を引用して相談する。読めたことを了承・引受けへ替えない。5分程度で決まらなければ未確定を残し帰宅後へ。新規契約0、準備10/20/30分は未校正。新ソフトを作らず、開発自体の加点は無い。

### 今回届ける範囲と、受け入れる未達

共同候補と変更の入口から一から話し直さず相談を再開する部分だけを2週試す。W1と希望の保持を支えるが、購入前の相互確定、現物と残り、実際の引受け・夕食への全接続はこの版の達成外。W2の残りとW3/W4/W5の全体は満たした扱いにしない。重複購入と帰宅後の相談・食事の遅れは二人に残る。未知の効果を実証済み又は保証された改善にしない。

強い次点Fより先に小さいPを試すのは、全記帳・全確認を全面導入せず共同選択と自由の入口を保てるか見たいから。初週に同じ火曜/水曜のような変更を辿り、2週後に二人が楽しみ・変更を言えるか・確認分数と残る痛みを評価。負担が5分程度を常に超える、自由を損なう、希望を確定と誤るなら中止又はFの組を選び直す。

根拠: [比較と確認](how-to-solve/README.md)、[採否](how-to-solve/discussion.md#決定論点1)、[実際に試せるラフと全体の未達](materials/experience-sketch.md)

## 出口

作らない。選んだPに新しいソフトを作る所が無い。既存のメモと連絡で部分改善を2週試す。全体目標を達成した扱いにはせず、how-to-buildは不要。

2週後の両者の評価で現物/引受けの全確認F又は中止を選び直す。新ソフトが必要なら、その理由と未達・費用をhow-to-solveへ戻してから設計する。

根拠: [出口の採否](discussion.md#決定論点1)。全ての当人役の応答は検査用の自演である。
