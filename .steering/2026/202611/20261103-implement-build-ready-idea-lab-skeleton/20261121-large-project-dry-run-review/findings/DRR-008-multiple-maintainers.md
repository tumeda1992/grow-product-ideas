# DRR-008　二つの保守先を同時に変える版を引き渡せないという疑い（撤回）

- 状態　再検討で撤回。有効な指摘と適用候補から除外。
- 固定版　`80b3836aae18bdc4e9f2daf9db6fa2eb0e359c34`
- 対象　[引渡し規約117–125行](../../../../../../product-plans/README.md)、[保守先・製品版・依存前提157行](../../../../../../what-defines-a-product/how-to-build.md)、[構成の責任と保証](../../../../../../.agents/skills/implementation-structure-design/SKILL.md)

台帳Aの仕様と表示器Bを両方変える版を想定した。両方の案内の相対リンクが各repo内に閉じれば、同じ共通契約の採否を両方で独立に更新するしかない、と当初判断した。しかし案内が示す先は各保守者の実在する局所の判断記録・適用版でよい。そこに共通契約v2の責任者A、対象とした相手の版、A2/B2を提供の条件として記すことを禁じる規約はない。A2/B1とA2/B2は依存先の同定・変更に対する既存の照合と、各保守者が読む局所記録で区別できる。後続の導入順は後続で決められる。

小さな二つの保存先で、共通契約の責任者・組・双方の版を書いた局所記録への参照が両方の状態で通ることを実際の検査器で確認した。隣repoへの直接の相対リンクだけは拒否された。参照の成功が契約を自動検証するとは現行規約も主張していない。資料室の独立アプリにはこの疑いは発生していない。[合成入力](../evidence/check_decision_boundaries.py)・[観測](../evidence/decision-observations.json)
