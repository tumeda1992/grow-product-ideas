# 再生成できる手元の一覧での構成の比較

入力は確定した版L1と生成時の設定である。一人が手元で一覧を使い、外部への作用は無い。同じ入力と設定から作り直せる。これは論点90の局所確認の模型であり、実製品の要件ではない。

## 生成した構成と差

案L-Aは、一つの呼出しがL1を読み、一時出力を生成し、完成した出力へ切り替える。再実行の根拠は保存済みのL1と設定で、別の実行者への引継ぎは無い。
案L-Bは、L1と設定を参照する依頼を別の実行者へ渡す。長い生成中に操作を終えられる可能性を持つが、依頼・結果の対応と待ちの表示、実行者の配置・起動・停止の扱いが増える。
この入力では、常駐実行や端末終了後の継続は要求されていない。L-Bの追加の意味があるかを示して返し、workerを前提にはしない。ここで利用者に代わってL-Aを採用したことにもならない。

## 同じ停止と変更に当てる

生成途中で止まった場合、一時出力を完成した一覧として公開しなければ、元のL1と設定から再生成できる。外部の予定作成のような、見えない外部効果の二重化を前提にする必要は無い。
完成した出力の切替の途中で壊れない性質は、保存先と更新方法に依る。単にfileを使うと書いただけでは成立を主張しない。実際の保存先の性質を技術への問いとして返す。
生成中にL2へ変更可能な仕様へ広げるなら、L1の結果と現行L2を区別する根拠が必要になる。元の入力を失えば再生成の前提も変わる。その変更時に構成を見直す。

## 受渡しと限界

情報へは入力版・設定・生成結果の対応を、費用へは生成と一時出力・切替、L-Bに追加される依頼と実行者の部品を渡せる。
外部作用が無いことは、全ての失敗や競合が無いことを意味しない。今回の入力で何を保つかから必要な仕掛けを選べる範囲を確認した。実fileの公開方法やhostでの実行は試していない。
