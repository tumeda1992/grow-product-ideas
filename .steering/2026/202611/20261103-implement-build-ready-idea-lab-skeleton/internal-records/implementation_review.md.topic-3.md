## 開始context

論点2で、決定過程を全ての問いで`facilitate-discussion`の全手順で記録すると決めた。利用者から「discussionは全テーマ1つで書く？」と問われた。今の決まりは、アイデア1件で一つの`discussion.md`である。

<a id="iteration-0"></a>

## イテレーション0: 記録の分け方

<a id="iteration-0-record-1"></a>

### 調査: 一つの記録のまま全手順で書くと何が起きるか

- `facilitate-discussion`の分割（`split-discussion.md`）: 単一形式の実論点が10件を超える更新で、論点番号5件ずつの範囲fileへ分割する。番号から所属を求める。
- 振替の件は16問で16論点。層の閉じでの修正や出口判定の論点が加わると、さらに増える。分割の境目は番号であり、層の境目と一致する保証は無い。
- `facilitate-discussion`は、別の論理記録の論点を親にせず、file pathと論点番号で参照する。

<a id="iteration-0-record-2"></a>

### 判断

| 読む人と場面 | 一つの記録 | 層ごとの記録 |
| --- | --- | --- |
| 層の閉じの利用者 | 番号の範囲fileをまたいで探す | 一つのfileを開く |
| build-ready後の後続 | 全体から必要な層を探す | 必要な層だけ読む |
| 還元skill | 層fileとの照合に番号を引く | 層fileと一対一 |
| 後続のプロダクトへ積み上げる時 | 番号の並びで混ざる | 層ごとに過去の判断を並べられる |

一つの記録の利点（通し番号、層をまたぐ親子）は、層をまたぐ関係が材料の再利用であり参照で足りるため、小さい。層ごとに分ける案を推す。出口判定は判定した時点の層の記録に置く。
