# 内部検討記録: 論点106 — 原文の話者と出典を保ち、設定と見立てを本人の発言へ変えない

**discussion:** [implementation_review.md](../implementation_review/implementation_review.md)

## 開始context

C3の初期入力には、架空の当人C3の言葉として示した引用と、assistantが用意した状況・制約の地の文が混在する。初回の正本は動機などの地の文を本人の逐語引用のように示し、後で分類を訂正した。原inputとhash、採否は変えていない。
既存growには受け取った言葉を言い換えず残す指定があり、正本雛形の体験/価値にも本人の語り・見立て・仮説・事実・未確認の区別がある。これらの規則が無かったことにはせず、複合入力を誰の何として写すかの適用を具体化する。sharedのfacilitate-discussionは実応答を保存し、合意を補完しない。この共通skillは改稿しない。
103の開発方針、104の反例判定、105の参照検査は反映・局所検査済み。今回の採否は出典を保つ記録だけに閉じ、部分案の価値や一式の完了判定を混ぜない。新しい作る前提のドライランは個別改善の後である。

## イテレーション0: 受け入れから採否まで、誰のどんな記述かを保つ

### 診断: 既に確認したC3の誤分類と、既存の記録指示

#### 取得した事実と、まだ断定しないこと

本論点を作る前の105後の読取りで、C3のinput/READMEと100の検査結果、growと正本雛形、記録規約を照合した。この段落はその取得後の記録であり、未実施の調査の予定を過去へ補わない。
[初期入力](../product-plans/20261117-find-compatible-pen-refills/input.md)の「元の言葉、動機と既にある着想」は、検査用当人の言葉を引用した後、特定のペンの黒0.5mm替芯等を設定の地の文で示している。「来週までに1組」も地の文の条件である。[正本](../product-plans/20261117-find-compatible-pen-refills/README.md)は訂正後、アイデアだけを原文引用にし、動機に「設定の地の文」、着想に「アイデア原文」と出典を示す。入力の語をコピーできても、その話者まで本人へ替えてよいわけではない。
100の結果には出典分類の訂正と原入力の保持が残る。growの「受け入れ時の入力は言い換えず」は既にあり、正本雛形にも本人の語り等を分ける指定がある。方法の全面的な不足ではなく、原文を写す時に記述の役割・話者を保たなかった適用の誤りである。現時点の資料からshared skill全体の欠陥とは断定しない。

<a id="iteration-0-record-2"></a>

### 判断: 原文を残す指定を、話者と出典を保つ保存へ繋げる

#### 判断対象・必須条件・根拠

元の依頼/資料を保持し、引用は出典と話者が分かり、設定/資料の説明とassistantの整理が本人の追加発言に見えないことを必須とする。採否のokから資料中の全事実の確認を作らない。反対に、通常の本人の短い発言を保存するためだけに新しい台帳や全行の分類、再質問を強制しない。
既存C3の訂正だけで終える案と、growの受入れ・雛形・記録規約の接続を直す案を比べる。全quoteを禁止する案は元の言葉を保持する目的を壊すため採らない。句読点やquoteの有無だけの自動判定では、実在の話者/出典と意味の帰属を検出できないため、新しい自動validatorを解決の中心にしない。
今の正本雛形は三欄の内容が単なるplaceholderであり、受け入れの地の文や整理との混在時に、どの根拠でその欄へ置いたかが落ちうる。記録規約へ保存時の分担を置き、growと雛形から同じ規約へ繋ぐ案を具体化する。実物のC3の短い分類で足りる範囲と、新しい事実を確かめる必要のある範囲を比較し、追加の質問は判断が依存する不明だけに限定できるかを机上で確かめる。

#### 比較結果と、案に残す代償

出力だけを訂正する案は既にC3で完了しており、原事例の誤解は解いた。ただし受入れの三欄の雛形は依頼/設定からの整理と本人の原文の境界を示さずに埋められるままで、次の同種入力を扱う時の書き方は実行者の注意に依存する。
規約・grow・雛形を繋ぐ案は、原文を残す意味を話者/出典も保つ保存へ具体化し、受入れと後の発言/資料の受渡しで同じ読み方を適用できる。原文にない情報を取得する機能は加わらず、明記を読まない実行者の失敗まで防ぐ保証にはならない。元の入力へ戻って帰属を判定する仕事がwriterへ残るのが代償である。
原文引用の全面禁止は、利用者の言葉を保つ要件を満たさない。quoteの記号だけを検査する自動化でも、設定の説明が本人の発言であるかは分からない。新しい台帳や毎行の分類を必須にすることは避け、混ざるblockの区別と案件内の原文への導線で足りる案を推奨する。

### 検証: C3の原文と、混ざり方の異なる入力へ候補を当てる

#### 主張と確かめ方

これは方法文の候補の机上照合であり、新しい一式の実行ではない。C3のinputと訂正後の正本を再照合し、アイデア引用の語が一致すること、動機の設定と原文の話者を区別して保存できることを確かめる。通常の本人発言、資料に含まれる他人の引用、assistantの解釈、帰属不明、短い採否の応答、試運転の役の応答を構成caseとして当て、原文/整理を保てるか、余計な再確認や事実の補完を要求しないかを評価する。原Cや固定入力は書き換えず、明示と原文照合以上の保証を主張しない。

候補の具体例の読戻しで、「来週までに1組あれば間に合う」という省略した文を引用扱いにしていた。原の地の文の「来週までに1組買えれば今回は間に合う」へ、提示前の候補を訂正した。これは本人の引用ではなく設定の記載として扱う例であり、原文の語も変えない。過去の原入力を書き換える訂正ではない。

#### 期待と照合結果

C3のinputのアイデア引用全文と訂正済み正本の引用は一致した。方法の候補に使う地の文の抜粋も原inputの実際の語へ一致した。元のCの64fileのownership/hashは保持した。以下は候補を文書として読み、境界を当てた机上評価であり、新しい利用者への適用や自動テストの実測ではない。

| 当てた場面 | 候補へ従った返りと判定 |
| --- | --- |
| C3の当人役のアイデアと、地の文の期限/対象 | アイデアは当人役の原文。動機は「設定の地の文からの整理: 特定のペンに合う黒0.5mm替芯を来週までに1組得たい」と根拠へ結ぶ。整理を本人の新しい発言としない |
| 通常の本人からの短い動機の発言 | 話者が明らかな原文をそのまま保存できる。三種全ての欄や再回答を要求しない |
| 依頼文に家族の言葉を引用している構成case | 依頼文が伝える家族の言葉として出典を保つ。assistantが家族へ直接質問して得た回答とはしない |
| assistantが、電話回避の理由を不安と読んだ構成case | 理由は原入力にないため、仮説としてしか残せない。事実として必要なら認識合わせへ返し、本人の言葉へ替えない |
| 文の話者が不明だが、他の事実だけで進められる構成case | 当該文の帰属は未確認と残し、独立した検討は継続できる。誰の動機かに選定が依存する所では、その不足を問いにする |
| この案への短いok | この提示した判断の採用として記録できる。提示外の解釈や未取得の事実を本人が実証した扱いにはしない |
| 試運転の役として生成した返答 | 原文を保存しても由来は試運転の役である。実利用や実際の利用者の採用へ替えない |

一つのcaseだけに合わせた「地の文は書くな」という方法ではなく、説明を説明として残し、解釈を解釈として使える境界を確認した。選択の根拠が不足する場面では質問が残る。単にラベルを付ければ意味の帰属が常に正しいという保証はしない。

### 変更集合の設計reviewと残す範囲

候補は記録規約の一節、growの受入れ/論点への接続、正本雛形の受入れ欄の3file。C3の本文は訂正済みで追加の変更は不要。sharedのfacilitate-discussionの発言保存・合意の境界は維持し、cacheを編集しない。原文専用の新しいfileや台帳を必須にはせず、既存の入力/応答/材料へ辿る。
設計時のskill-update-reviewを、growの現行SKILL.mdと二つの雛形全体および変更候補へ当てた。入力の出典を保つことは受入れ/記録の一部であり、独立した採否・状態・再開・完了条件を持つ工程を抱え込む変更ではない。記述の種類の例を変えても規約と雛形で扱え、層選択等を直す必要はない。切り出し候補無し。
document-reviewでは、「原の文面を保つ」を削って自由な要約へ替えていないか、原文の保持と整理の区別がともに必要か、既存の台帳だけで出典へ戻れるか、記述者の同定を事実の検証へすり替えていないかを照合した。修正した具体の引用語も原inputへ一致。完全差分74行のgit apply --checkは通った。方法は本線へ未反映で、新しい一式で守れたかは後続の実行で確かめる。
