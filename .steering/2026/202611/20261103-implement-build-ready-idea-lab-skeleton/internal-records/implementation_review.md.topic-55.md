# 内部検討記録: 論点55 — 予約完了の条件を模型へ戻す

**discussion:** [implementation_review.md](../implementation_review/implementation_review-51-55.md#論点55-模型のwhatに締切までの予約完了を求める条件を戻す)

**論点:** 論点55

## 開始context

親論点19のイテレーション2で、改稿したwhyを振替の自演で使い、価値の仮説から条件付きのアウトカムまで進めてwhatへ試し割りした。
旧模型の八条件は、担当と能力が決まることを予約の実施の代わりにしていた。予約しないまま締切を過ぎる日は、新しい価値の採否と関係なく、旧アウトカムの「使い切る」でも崩れる。
この反映単位は、家族の目標を選び直すことではなく、既に閉じた目標を満たすための条件の適用漏れを戻すことである。whyや共有skillの一般則の不足とは現時点で判定しない。

## イテレーション0: 担当者と、締切までに済んだ状態を区別する

### 検証: 予約が済まない日を八条件が通すかと、変更集合の範囲

#### 主張・合格条件・方法

元の八条件を一件ずつ当て、予約しないまま締切を過ぎる日の整合性を机上で確かめる。
予約の完了を条件6へ混ぜること、条件7の共有へ混ぜること、独立して追加することを、確かめる時点と問う状態の違いで比べる。八という数を維持するためにも、数を増やすためにも切らない。
元のアウトカムから必要な変更として、正本の条件・層の記録・その決定過程を揃える完全diffを用意する。既存の価値やアウトカムとhowの選定自体は変えない。
条件の追加でwhatが閉じ直せたとせず、層の記録を開け直しとし、旧確認の範囲と未検証を明示する。
予約完了はアプリや先生とのやり取りのどちらでも判定でき、予約の意向・担当の決定・入力途中を予約済みと数えない必要がある。
枠が無い時や振替日に休んだ時の既存の外部事情の扱いは変えず、家族が予約を実施しなかったことをその例外へ混ぜない。
検証は自演の論理的な日と文書の接続を扱い、教室のサービスを実際に操作した検証ではない。

#### 旧八条件へ当てた結果

締切をDとし、欠席の連絡と記録は既に済んでいる。枠があり、担当者に予約する時間もあるが、Dまで予約しない日を置いた。

| 旧条件 | この日に成り立つこと |
| --- | --- |
| 1 規則と期限・締切が正しく分かる | 教室の規則どおりの情報を二人とも知っている |
| 2 欠席の記録が済む | 欠席した日に、連絡した人が記録を済ませている |
| 3 二人とも欠席を連絡できる | 二人とも連絡できる状態である |
| 4 予約しようとする時に未予約の一件が分かる | 担当が平日の夜にアプリを開いた時、その一件と期限・締切を正しく分かっている。予約の確定だけをしない |
| 5 担当が締切の7日前までに自分で気づく | D-7までに、担当の夫は自分で気づいた |
| 6 予約できる担当が発生日に決まり、二人とも誰か言える | 担当は夫であり、二人とも相手に聞かず同じ答えを言える。夫には予約できる時間もある |
| 7 予約・受講した日のうちに相手が知れる | 今回は予約も受講もしておらず、共有する行為が発生していない。過去の行為の共有は正しくできている |
| 8 使えないものを使えるものに数えない | 規則どおりに区別し、締切・期限を過ぎたら使えるものに数えない。これは、使える間に予約しなかったことを成功へ読み替えるものではない |

八条件を破らず、枠や体調の例外も使わずに、予約が済まない日を作れた。旧アウトカムに必要な条件が欠けていると支持できる。
元の層の記録には「二人とも相手が予約すると思い、どちらも予約しなかった」日と、それに条件6を足した判断がある。しかし追加した条件6の本文が要求するのは、担当と能力の成立であり、予約の完了ではない。修正した事実を、修正後の文で塞げたことと同一視してはならない。

#### 戻す条件の切り分け

条件6へ予約完了まで合わせる案は、発生日に担当が分かることと、予約締切までに予約が済むことを、一つの条件と確かめ方に混ぜる。
条件7へ合わせる案も、予約の完了と、予約後の状態共有を一緒にする。共有が正しくても行為自体が無い今回の日を読み取りにくくする。
そこで、条件9として予約の実施を独立させる。八という数を保つ必要はないが、増やすこと自体も理由にはせず、問う状態と時点の違いを根拠にした。
追加する一文は「使える振替の一件ずつについて、予約の締切までに予約が済んでいる」とする。
確認では教室側に成立している予約を根拠とし、担当の決定や、意向・入力途中は数えない。自動予約を要求するものではなく、人の行いを含む解き方でも必要な結果である。

机上で、予約していない担当者確定の日と、入力途中の日、締切後に予約した日には満たさず、締切までに教室側の予約が成立している日には満たすと判定した。
アプリの場合も先生とのやり取りの場合も、成立した予約という同じ状態を問える。ここでは実在のアプリや先生への連絡はしていない。
空き枠が無いという既存の受け入れを取り消さず、家族の予約忘れを「手の外の事情」に入れない。新しい仮目標の意図した見送りの採否も、この修正で決めない。

#### 適用する三fileと、実行権限

今回のsteeringの合意済みdesignは、自演で見つかった摩擦をこのsteeringの中で該当fileへ戻して解消することを、実施範囲に含めている。直前の利用者の継続応答に従い、その自演の検証を進めている。
修正するのは、家族の新しい目標の選択ではなく、旧アウトカムでも必ず要る予約の実施の適用漏れである。目標や一般則の新しい採否は追加せず、検証の実行側がこの既存権限で模型へ反映する。
対象は、模型の正本の条件9と状態、whatの層の記録の状態・再検証・未完、その決定過程への導出と結果の三fileである。条件6・7は保ち、whyの目標やhowの選定を変えない。
whatを開け直しとし、旧8条件の確認を九つ全体へ流用しない。howの旧選定は旧8条件に対する結果と明記し、whatを閉じ直した後に確かめ直す既存の順序を保つ。

三fileの完全な変更前後を一時draftへ保存し、完全diffにした。`git apply --check --whitespace=error /tmp/grow-booking55/change.patch`は成功した。
次に適用後の全文をdraftと比較し、追加した内部参照が解決すること、他の模型fileや層fileへ意図しない差分を足していないことを確認する。
この修正では、受講までの十分さや、what全体の閉じ直しを完了したとはしない。

#### 適用結果と検査の範囲

三fileを保存した変更後全文どおりに反映し、全文比較で一致した。新しく加えたfile・見出しへの相対参照は実在する対象へ解決した。
模型のwhatの決定過程は、元の本文をprefixとして一文字も変えず、論点6の変更の記録を末尾へ加えた。追加した記録に、架空の利用者の承認文や新目標の合意は作っていない。
`git apply --reverse --check --whitespace=error /tmp/grow-booking55/change.patch`と`git diff --check`は成功した。逆適用による変更はしていない。
模型のwhatのdiscussion helperは6論点・次番号7・問題なしで、分割不要を返した。

予約しない日を条件9で満たさないと判定できることを確認した。ただし、これは必要条件の欠落を塞いだ結果であり、運用する人が必ず予約することを保証した検証ではない。
whatは開け直しのままにし、予約後から受講までの行い、担当不在、取り直しを含む条件群の再検証と閉じ直しを未完として残した。
whatを閉じ直す前にhowの旧選定を新しい条件へ合格と読み替えないことも、正本と層の記録へ明記した。

### doc-enricher提案レビュー（論点55のoriginについて一回）

既存のwhat本文は、条件が全て成り立つのに言い分が崩れる日を作ること、条件間の隙間を拾うこと、述語と確かめ方を同じ強さにすることを既に指示している。
今回の具体の欠落はこれらを模型の予約の完了まで適用できていなかったことなので、同じ原則をREADMEや共有skillへ追加する候補はGate G（重複）で見送った。
新しい一般則やplugin修正の提案は無い。今回の証拠は模型の検討記録へ残す。

### document-review — 変更報告と適用結果のemit前レビュー

正本には必要な状態を、層の記録には導いた理由と未完を、決定過程には修正の根拠を置いた。今回の完了が条件9の反映に限られることと、what・模型全体の閉じ直しが未完であることを、実fileと外向き報告の両方へ残す。
既存の目標と、新しいwhy自演の条件付き試作を混ぜない。新しい価値を採用しなくても成り立つ反例と、予約完了の必要性を報告の根拠にする。
変更対象の三fileと完全diffを示し、以前の利用者役の応答は保存したまま、今回の修正に架空の承認を付け足さない。内部参照は模型のdirectory内で読み切れる形を保つ。
構造・指示対象・暫定性・既存内容の保持の観点から、追加の骨子変更を要する不整合は見つからなかった。レビューを、受講までの十分さや実利用での効果の保証にしない。
