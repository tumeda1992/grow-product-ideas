# 内部検討記録: 論点12 — why-to-build.mdの並び順の理由と、出口判定の時期の食い違い

**discussion:** [implementation_review.md](../implementation_review/implementation_review.md)

**論点:** 論点12

## 開始context

`why-to-build.md`冒頭は「代案で足りれば作らない出口へ向かい、以降の問いが不要」と言い、`grow-product-idea`は出口判定を層の閉じに置く。サブスクの件で、代案で足りると分かった後に残りの問いを答えるか迷った。

<a id="iteration-0"></a>

## イテレーション0: どちらを直すか

`reason-to-build-anyway`の定石は、代案で足りても費用の外の理由で作る選択肢を持ち、水準は4問の閉じを要する。冒頭の「以降の問いが不要」はこれと矛盾するため、冒頭を直す。手順6は変えない。代案で足りる時に費用・リスクを浅くするのは、settle-questionの深さの判断が既に扱う。

<a id="iteration-1"></a>

## イテレーション1: 層が何を問う場所か

利用者の応答: whyのヒアリングは代案では止まらない。代案で止まるのは分かるが、それはwhyで問うのか。

why-to-buildの5問を、答えの出どころ（利用者が持つ／レールが調べる）と、代案が出た時に止まるかで分けると、二種類に割れる。閉じ条件と出口判定は判定の側に置かれており、層の名前は聞き出す側を指す。

方向の候補は、層を分ける、名前を改める、what-to-buildへ移す、文面だけ直す、の四つ。層を分ける方向を推す。聞き出す側の閉じ条件を判定から独立させられ、動機を詰める置き場所ができる。変更は広いため、方向を合わせてから細部を示す。

<a id="iteration-2"></a>

## イテレーション2: 作るかが分かる時点

利用者の問い: 作るかはどこのレイヤの後わかる？

層fileの必要な材料から、代案は要求（what）、費用は最初に作る分（how-far）と画面の数（howの材料）、リスクは解き方（what）と実現性（howの材料）と比べる。確定はhow-farの後。今はwhyの閉じで粗く判定している。

作るかを層にせず、各層の閉じで確かになっていく判定として扱い、問いを比べる相手が揃う層へ移す方向へ改める。明らかに代案で足りる場合はwhyの閉じで出られる。

<a id="iteration-3"></a>

## イテレーション3: 出口のきっかけ

利用者の応答: 作らない結論は、how-farでの代案との比較や、whatで作れないと分かる等、問いの中で出る。閉じに明示的に置く必要は無いかも。

| 案 | 評価 |
| --- | --- |
| どの問いでも、答えが作らない・保留を示したら出口判定へ向かう | 結論が出た時点で出られ、どの答えが出口を決めたかが残る |
| 層の閉じに判定を割り付ける（提案2） | 作れないと分かった後も層の残りを答えることになる |

比較だけで出口にしないため、why-to-buildの得たいものとの照らし合わせを、出口へ向かう条件にする。reason-to-build-anywayは、得たいものの問いと出口判定の照らし合わせに分かれる。

<a id="iteration-4"></a>

## イテレーション4: 移し先

| 問い | 候補 | 選んだ理由 |
| --- | --- | --- |
| 代案 | what先頭 / 要求の後 | 要求が代案の答えで優先度を下げる依存を保つため先頭 |
| リスク | 解き方の後に一問 / 観点ごとに散らす | 解き方が決まれば五観点とも見られる。散らすと定石が崩れる。機会損失だけ費用へ |
| 費用 | how-farの最初に作る分の後 | 作る費用は最初に作る分の画面と操作から見積もる |
| それでも作る理由 | 廃止。得たいもの（why新設）と共通の節へ | 費用の外の理由は聞き出す側、結論の選択肢はどの問いでも出る |
