# 内部検討記録: 論点45 — why全体の中で価値発見を磨く

**discussion:** [implementation_review.md](../implementation_review/implementation_review-41-45.md#論点45-価値発見をwhy全体の中でどんな仕事として磨くか)

**論点:** 論点45

## 開始context

論点43で、体験理解・価値発見・目標設定をwhyの構成の出発点として受け入れた。
利用者は、各仕事を無前提の単独工程にせず、全体のストーリーを忘れず有機的につなぐよう明示した。
全体の目的は、一部しか見えていない症状・要望から、体験と可能性を広げ、何を変える価値があるかを見つけ、目指す変化を選び、whatへ渡せるアウトカムへ畳むことである。
この回は価値発見の役割と接続を一つの判断として扱い、詳細な手順や層fileの実装は確定しない。

## イテレーション0: 価値発見が、前後の仕事とともに成し遂げることを定める

<a id="iteration-0-record-1"></a>

### 判断対象・必要条件・確かめる対応

価値発見を、体験理解に根を持ち、目標設定が選べる価値の仮説を育て、不足や反証を前後へ返し合う仕事とする案を検討する。
これは七工程の特定の番号から選ぶのではなく、全体への影響、今の議論での誤りやすさ、後ろで拾えるかから、価値発見の仕事を先に吟味する進行判断である。
体験理解の誤りは本人の事実との照合で指摘しうるが、価値を見落とした目標は整った小さな目標としてwhatへ渡り、条件が正しく導けても、もっと良くなれる可能性を失ったことを後ろで拾いにくい。
今回の議論でも、入口と出口へ説明を縮め、広げる仕事を落とす後退が起きた。このため価値発見を具体化する必要性が高い。

必要条件は、why全体の目的とwhatの入力を共有すること、当人の事実と価値の仮説を混ぜないこと、本人がまだ言葉にしていない可能性も育てること、目標設定が判断できる違いと根拠を渡すこと、不足と反証を体験理解・目標設定へ返せることである。
これを、振替の自演にある「頼む負担」と「ピアノは自分でやりたい」という材料へ当て、発見した価値の仮説に何が必要になり、どの仕事へ戻すかを確かめる。
実際の利用者へ新しく聞いたり、この家族の目標を再確定したりする検証ではない。


#### 接続を具体的な材料へ当てた結果

振替の自演のwhy-to-build/discussion.mdの論点1・2を読み、語りと、自演であることの注記を確認した。
「自分が覚えていなくても大丈夫だと思えたらいい」「全部あなたにやってほしいわけじゃない」「ピアノは先生とのやりとりがあるから自分でやりたい」「スイミングと英会話は、あなたが自分で気づいて取ってくれたら助かる」という材料がある。
ここから、単に作業を減らすという価値を一般化すると、本人が残したい関わりまで奪う可能性があると分かる。

価値の仮説は、妻が覚えて依頼する負担から自由になり、夫も必要に気づいて関われるという変化として育てられる。
ただし、それを全部の教室で同じ分担にするかは未確定であり、本人が何を手放したくて何を残したいかへ戻る必要がある。
この問いは、体験理解の作業が完成してからしか出せないものではない。価値を考えたことが、次にどの体験を詳しく理解するかを規定する。

目標設定の側では、失効だけを防ぐ価値、一人に覚えて頼む負担を残さない価値、本人が望む関わりを残す価値が、どの範囲で両立し、どこが選択になるかを知る必要がある。
その違いと根拠が出て初めて、何を引き受ける目標にするかを選べる。候補名だけでは選べない。
選べない理由が判明した場合には、価値の違いの描き直しや、本人の事実・望みの確認へ戻る。単に受け取り口と返却欄を設けただけでは、この接続は成立しない。

以上から、価値発見を「why全体の文脈の中で、体験に根ざし、目標設定が選べる価値の仮説を育て、前後と問いを返し合う仕事」とする役割案を推す。
担当を独立させて順番に完了させる契約ではなく、同じ全体目的の下で、判断の専門性と往復の責務を持つ形にする。
この回では仮説を育てる役割と接続の採否を問う。発想の詳しい技法、探索を止める基準、候補の記録形式の固定までは混ぜない。


### 方向性への了承と別件の指示の扱い

利用者の「あってそうに見えるよ。」を、価値発見の役割と前後との接続の方向性への了承として、discussionの論点45に保存した。
詳細な技法・止める基準・記録形式を確定したという意味には広げていない。
同じ発言の後半の、専門化した部品が全体で協調できる構成と薄いハンドリングの要求は、独立した論点46に原文を保存し、保留メモ005へ分けた。
この一般化された要求では、個々が全体を知るかどうかにかかわらず全体で機能することが目標である。
whyの各仕事へ全体の文脈を持たせる今回の役割案を、全ての部品が全体の全情報を理解しなければ協調できないという一般契約へ広げない。

役割の方向性に関する今回の了承と、別件として保存する指示の反映を確認した。
同じ暫定内容を恒久のREADMEへ重複して追加する提案はしない。新しい一般の改善提案は、利用者の明示指示に従って別件の005に所在を持たせた。
