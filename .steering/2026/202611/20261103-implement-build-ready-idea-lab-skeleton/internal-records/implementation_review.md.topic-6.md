# 内部検討記録: 論点6 — ドライランのやり直し

**discussion:** [implementation_review.md](../implementation_review/implementation_review.md)

**論点:** 論点6

## 開始context

利用者の指摘「ちゃんと回るかを見て欲しかったのに、手順に握りつぶして結果だけ揃えてるから、検証できない」を受け、受け入れ基準の自演をやり直す。

<a id="iteration-0"></a>

## イテレーション0: 先の自演で確かめていなかったこと

<a id="iteration-0-record-1"></a>

### 調査: 先の自演で実際に起動したもの

- 起動したskill: `grow-product-idea`（1件目の受け入れ時）、`settle-question`（1件目の最初の問い）、`gather-target-user-voices`（1回）
- 起動しなかったもの: 他の材料skill、2問目以降の`settle-question`、`facilitate-discussion`（全件）、`refine-what-defines-a-product`
- 振替の16問: 答えを組み立てた後、pythonでまとめて正本と決定過程へ書き出した
- 見本: 既にある正本と材料から、pythonで層ごとの記録と内部検討記録を生成した

### 判断

手順が回るかは確かめていない。やり直しは、skillを起動し手順どおりに進め、利用者役を利用者に演じてもらう。振替の件は消して受け入れから始め直す。範囲はまずwhy-to-build層の出口判定まで。

<a id="iteration-1"></a>

## イテレーション1: 決定過程の整理と、正本の問いと答えのまとめ方

入口は利用者の応答。認識は合っている。ドライランの回し直しではなく、決定過程の整理と問いと答えのまとめ方をやり直して提案する。

<a id="iteration-1-record-1"></a>

### 判断: 正本と決定過程の役割

- 論点が判断の単位になると、問いの順に結論を読む場所が別に要る。正本の問いと答えをその場所にし、決定過程を判断の変遷の場所にする。
- 正本の答えは決定過程を読まずに分かるように書き、根拠に論点をlinkする。論点が立たない問いは材料から導いたことを書く。
- 「広がった視野」を正本に置く。論点2の目的（視野を広げる）を、層ごと・時系列に分かれた決定過程からは一目で読めないため。

<a id="iteration-1-record-2"></a>

### 調査: 振替の件のなぜ作るか層を判断の単位で並べ直す

先の自演の正本・材料・決定過程（問いごとの5論点）を読み、判断が生じた箇所を拾った。

- pain-to-solve: 利用者の事実の確認（認識合わせ）、痛みの核心が分担にあること（視野）
- existing-alternatives-fall-short: 共有表計算が強い代案であること（視野）
- build-cost-pays-off: 材料から一意。論点は立たない
- risks-of-building: 子どもの情報を外部へ送ること（視野）
- reason-to-build-anyway: 作る理由を費用の外に置き対象を絞る（採否）
- 層の閉じ: 出口判定

6論点になる。手順を通した結果ではなく、形の例である。
