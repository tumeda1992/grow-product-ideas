# 比較設計のための事前調査

## 調査の目的と現在地

3ブランチの成果物と制作・検証条件にどのような違いがあるかを確認し、比較方法を設計する際の前提を得る。調査結果が比較単位や評価方法を変え得るため、この記録を `design.md` と同じディレクトリに置く。

ユーザーは3ブランチの比較と調査結果の保存を依頼している。この段階では、その範囲内で Git の読み取りによる成果物の所在・到達段階・来歴の確認を行った。共通評価観点、点数、共通入力の実行、追加時の保存形式は未合意であり、本比較を完了したとは扱わない。

設計前確認の終了条件は、3ブランチすべての先端コミットと追跡対象一覧、入口資料から確認できる成果物の役割、比較方法を変え得る条件差を特定すること。この終了条件は満たした。全資料を精読した比較評価は未実施である。

先端には `.gitignore`、`README.md`、`CLAUDE.md` と、既存 steering の `design.md`、`discussion.md`、`task-design-discussion.md` が存在する。実体としての `SKILL.md` やアイデア用テンプレートは追跡対象に存在しない。

`design.md` の「元の依頼内容」（5行目）は opus と人がラフ骨格と名前を決め、後続モデルへ渡すことを依頼している。「このdesignの対象範囲」（23〜42行目）は骨格段階を明示し、各 skill の本文、問いの全項目、テンプレート本文、実行して初めて分かる摩擦を対象外としている。

ここから直接言えるのは、運用成果物を全部完成させる目的の試行ではないこと。運用ファイルがない事実を、そのまま制作時の要件未達と評価できない。一方、現在どこまで使えるかを比較する場合、その到達段階の差は観測対象になる。

根拠: `d88ed099c7e9498a6cd3626f7c13c99fa5063778` の追跡対象一覧と `.steering/2026/202609/20260912-design-build-ready-idea-lab-skeleton/design.md`。

### 3方針は成果物の質を、文書量ではなく次の行動に使える水準として定義している

期待するアウトプットの質を比較観点へ含めるため、固定コミットにある品質条件と出口成果物の定義を追加で確認した。

- `feature-1` は、問いごとに必要材料、水準、満たさない答えの例、定石としての対案と判断軸を持たせる。調査系では答えが材料から導かれること、生成系では複数案、全体、選択理由を確認する。出口は build-ready、作らない、保留であり、それぞれ問いと答えの全体、作らない理由、復活条件を残す。
- `feature-3` は、問題と代案の選択理由、根拠、具体的な到達点、要求から合格例までのつながり、受取担当が単独で使える引き継ぎを進行条件にする。build-ready だけでなく、導入準備完了と見送りを定義し、導入では構成・順序・費用・確認・復旧、見送りでは理由・根拠・再検討条件を求める。レビューは全案件へ同じ文書量を求めず、具体的な場面と数値、原文を超えない根拠、観測可能な到達点、体験と構造の整合、引き継ぎの単独利用可能性を確認する。
- `feature-7` は `validate-first`、`use-existing`、`park`、`stop`、`build` を出口に持つ。アイデアごとの正本を、読者が現在地と次の一手を把握し、問題を根拠付きで判断し、代案から選択し、build なら実装判断なしで仕様をたどれるための成果物として定義する。非buildでも、検証計画、採用・移行・運用手順、理由と再開条件のように、出口に応じた次の行動を要求する。

3件に共通するのは、体裁や項目数ではなく、結論を選べること、具体的な場面と境界があること、根拠から結論と後続成果物をたどれること、不確実性を過大評価しないこと、次の担当が追加のプロダクト判断なしに行動できることを質として扱う点である。一方、出口の種類と必要成果物は異なるため、build-ready 用の成果物一式を全出口へ要求する方法は適用できない。

根拠: `d88ed099c7e9498a6cd3626f7c13c99fa5063778` の骨格 `design.md`、`f6481b8cc4241b5923e0bcb91929dd6b473028ed` の `playbook/workflow.md` と `skills/review-idea/SKILL.md`、`83c9dbf5f77f025e98e6a7c8f1952fa6abc4e5b5` の `docs/operating-model.md` と `.agents/skills/refine-product-idea/SKILL.md`。

## 比較設計への影響

| 観測した条件差 | 設計で解消する判断 | 今の資料だけでは言えないこと |
| --- | --- | --- |
| 骨格設計と運用成果物が混在する | 設計内容・現時点の利用可能性・各試行の達成範囲をどう分けるか | ファイルが多い方のモデルが優れていること |
| 制作モデルの申告と評価実行担当が異なる例がある | 制作条件と評価条件をどう記録し、比較単位を定めるか | 成果物差の原因がモデルだけであること |
| 保存された評価根拠の量と種類が異なる | 元資料の評価記録と今回の独立評価をどう表示するか | 評価記録のない案は検証に失敗したこと |
| 3組の共通祖先は同じ | Git の系譜と、会話・入力の継承をどう区別するか | 条件を統制した3回の独立試行であること |
| 今後ブランチ先端が更新され得る | 対象時点の固定、原本保持、追加・改訂の識別 | 現在のブランチ名だけで過去結果を再現できること |

この表は設計判断への入力であり、比較方法の確定ではない。未合意の方法は `design.md` に既決事項として反映していない。
