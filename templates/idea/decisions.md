# 判断履歴

現在の採用内容は proposal.md または design.md を正本とする。ここには判断が変わった理由を残す。単なる作業ログは書かない。

## 記録形式

判断ごとに `D1` 等の ID を付ける。

- 日付・判断者：ユーザー／担当エージェント。
- 状態：自律確定／ユーザー決定／仮置き／置換済み。
- 問い：何を決めたか。
- 結論と理由：要求・証拠 ID、比較した対案と弱点。
- 依存する前提・逆転条件：どの情報で見直すか。
- 反映先：現在案、設計、引き継ぎの対象箇所。
- 変更時：旧判断 ID と、新判断によって変わる範囲。

ユーザーの返答がない仮置きを「ユーザー決定」へ変更しない。上書きで以前の判断を消さず、置換関係を残す。
