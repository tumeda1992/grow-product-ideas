# gather-target-user-voices

材料`target-user-voices`を作る。受け取るもの、粒度、再利用は`what-defines-a-product/README.md`の「材料」節に、置き方と入口の形は`product-plans/README.md`に従う。

## 作る手順

1. 正本の受け入れ時の入力から、誰が使うかを読む。利用者が自分だけか、自分以外も使うかを分ける。
2. 使う人の像を書く。属性を並べるのではなく、どんな場面で、何に困り、今どうしているかで書く。
3. 同じ痛みを持つ人の声を、ウェブ上（質問サイト、SNS、ブログ、アプリのレビュー、掲示板）で探す。痛みの場面を表す言葉で探し、製品名だけで探さない。
4. 声ごとに、どこで見たか、何に困っているか、今どうしのいでいるかを書く。
5. 声から読める、痛みの頻度、回避策、代案への不満をまとめる。

利用者が自分だけの時は、声は自分の痛みを確かめる参考にとどめる。自分の行動の記録（痛みが起きた場面と回数）があれば、それを主にする。

## 個人版の代替であることを記録する

この材料は、利用者へのインタビューの個人版の代替である。「確かめた方法と限界」に次を必ず書く。

- 一般通説では利用者へのインタビューで得るものを、ウェブ上の声で代替したこと
- 落ちる精度: 声を上げる人に偏り、声を上げない多数の不便さを拾えない。古い声が混ざる
- 集めた声の数と、探した場所

精度が落ちたことを書かずに渡すと、`settle-question`が確信度を過大に見積もった答えを作る。
