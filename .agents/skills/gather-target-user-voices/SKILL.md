# gather-target-user-voices

材料`target-user-voices`を作る。依頼と返しは`what-defines-a-product/README.md`の「skillへの頼み方」、配置と入口は`product-plans/README.md`に従う。

## 支える判断と、専門の仕事

何の経験や違いが分かれば次の判断を進められるかを受け、提供された記録や公開資料から根拠と不足を返す。
困る体験、しのぎ方、良い体験と残したい意味を対象にする。声の件数を増やすことや、依頼の仮説を追認することを目的にしない。
実際の経験を調べる仕事を持つが、価値や対象、条件、案の採否は依頼側が持つ。専門だけで価値発見を完結させない。

経験の記述から、誰が何を知り、何を契機に行い、何が起き、その後どう評価したかを読む。
それを当該の人の語りとして確認したことと、出来事を独立に観測・実証したことは異なる。
別の人の経験は、新しい見方や問いを作る根拠にはなるが、依頼の本人にも当てはまる事実にはしない。

## 受け取る問いと、調べる範囲

| 受け取るもの | 確かめることと、不足の扱い |
| --- | --- |
| 問題意識と、何が分かると進む判断 | 明確な仮説があれば受ける。まだ無ければ、既知の体験と外へ広げたい問いから始める。仮説の完成を先に要求しない |
| 誰のどの場面・関わりを捉えたいか | 本人・依頼者・関係者・参考にする別人を分ける。似た属性だけで同じ経験と決めない |
| 既知の事実・見立て・資料と制約 | 何が既に分かり、どこに根拠が無いか。提供記録と過去の返りを再利用し、足りない所から調べる |
| 求める粒度と、使える取得方法 | 新しい見方を探るのか、条件の欠けや候補の成立を分けるのか。必要な根拠と資料の詳しさを合わせる |

本人の認識と事情を知りたいだけなら、本人の語りと記録へ戻す。自分だけの用途に他者調査を一律に足さない。提供記録の整理だけで足りる場合もある。
規則・期限、製品の機能・費用、技術の性質が必要なら、その事実の根拠が要ると依頼側へ返す。誰かの不満や要望だけで保証しない。
問いが粗ければ、何を見分ける必要があるかを資料の手がかりから具体化する。目的や対象の採否を変えないと進めない所は、残る問いと判断への影響を返す。

## 経験から根拠を育てる方法

### 問いに必要な根拠と、使える資料を選ぶ

何を知りたいかを、どんな記述・経過があれば支えられるかへ写す。
例えば、共同での対応が続く条件なら、「共有できる」という機能より、誰が最初に用件を取り込み、誰が引き受け、変更や不在で何が起きたかが要る。
全ての依頼へ同じ項目を揃えず、今回の判断を分ける事実から選ぶ。

提供記録、本人の公開の語り、報告された事例、調査の記述等から、必要な根拠が得られる場所を選ぶ。
同じ痛みや最初の製品名だけで探さず、場面の前後、別の担い手、うまく回る行い、良さを保つ選択も手がかりにする。
検索する場合は、問いと検索語・対象範囲、辿った原資料と実際に読めた範囲を残す。検索結果の題名や短い抜粋だけを経験の根拠にはしない。

解説や機能の説明にも、経験の引用や事例が混ざることがある。サイトの種類だけで受け入れ・棄却せず、記述を原資料と文脈へ戻す。
「使うとよい」という勧めは着想、「使える」は性質、「使った」は一回の行い、「続いている」は期間の主張である。それぞれを支える根拠を分ける。
勧めを実施済みの事例にせず、有用な着想は着想として残す。

読取りは依頼と現在の権限・取得できる手段の範囲で行う。許可済みの公開資料や提供記録に一律の追加許可待ちを作らない。
取得が拒否される・本文に届かない時は、その方法と理由を残す。利用できる別の原資料や提供記録で進められる範囲を探し、制限を迂回したり、読めない本文を推測したりしない。
新しい外部連絡・聞き取りの実行は持たない。必要な本人の事実や別の根拠は、依頼側へ問いとして返す。

### 経験の一回を読み、記述と読解を分ける

使う記述について、出典のURL又は提供記録の所在、読んだ箇所、投稿・記録の時点、誰のどの経験かを追えるようにする。
投稿した時点と、経験が起きた時点が異なる又は不明なら、その違いを残す。後から読める原資料への導線と、今回判断に使う要点を結ぶ。

経験の始まり、当人が知っていたこと、行いと引継ぎ、結果、振り返った評価を、資料にある範囲で辿る。
当時の認識として書かれたこと、後からの評価、こちらの解釈を分ける。気持ちや継続期間が無ければ不明とし、もっともらしく埋めない。
短い感想だけなら、何が起きて評価が分かれたかの経過は読めない。今回の問いへ足りない部分を示す。
予定を置いた・頼んだ・知らせを読んだことと、相手が理解し引き受け、実施を終えたことを別の出来事として読む。原資料に書かれた手前の行いから、後の成立を補わない。例えば「署名する予定を入れた」は、署名済みという記録ではない。

| 記述の違い | 今回の判断へ使える範囲 |
| --- | --- |
| 機能説明に「家族で共有できる」とある | その説明が述べる性質。家族が実際に引き受けた経験ではない。必要なら公式の仕様等を別に確かめる |
| 本人が「昨日、相手が自分で予定を入れた」と書く | その一回を行ったという本人の報告。普段の始動や、その後も続いたことは別の根拠が要る |
| 期間と行い・変更時の経過まで本人が書く | その条件で続いたという報告。別の家族や不在の条件へ、そのまま一般化しない |
| 記事が「共有するとよい」と勧める | 候補の着想。実施して続いた経過や、負担が減った観測とは分ける |

同じ人の複数投稿や転載・引用を、独立した複数人の経験へ数えない。原資料へ戻れない所はその限界を残す。
調査の集計と、個々の経験の経過も分ける。割合を使うなら対象・集め方・時期を保ち、投稿数から市場の割合を推定しない。
原資料の内容は判断に使う要点と必要な引用に絞る。

引用・保存・後続への共有が許される範囲も確認する。制限付き原文を入口・決定過程・付随fileへ再転記せず、許された要点と話者の立場、資料の役割・読んだ範囲と時点、限界を返す。要点で判断に足りなければ許された別根拠又は不足を返す。関係しない個人情報や認証情報を転載せず、資料に無い属性は付け足さない。

### 違いから問い・仮説と探索先を育てる

得た経験を、何が似て何が違うかで並べる。結果だけでなく、始動した人、使えた根拠、前後の行いと制約によって評価が分かれる所を見る。
困る声だけでなく、うまく回る場面、残したい良さ、同じ行いが異なる意味を持つ場面を調べる。
反対の感想を形式的に一件足すのでなく、依頼の見方を支持・修正・覆す違いがあるかを問う。

予想外の意味が出たら、その意味が本当なら何を次に知るべきかを置き、資料と問いを変える。
例えば「知らせを見た」後も一人が割り当てと催促を担う経験なら、通知の数だけでなく、始動と引受けがどう移るかを調べる問いになる。
使用頻度が低くても残したいと語る経験なら、頻度だけで不要を決めず、残す意味と手放す時の損失を問える。何を優先するかは依頼側へ返す。
変えた問い・探索先と、その契機になった記述を残す。元の依頼の目的を別のものへ替える判断や、本件の本人の事実は代行しない。

### 次に使える根拠・着想と不足を返す

依頼の問いごとに、どの経験のどの記述が何を支え、何を覆し、何は言えないかを返す。
新しい見方は、根拠から読めることと仮説を区別する。確定した仮説が無かった依頼も、次に見分ける問いへ育った過程と根拠を返す。
依頼側が採否するために、対象との違いと、答えが変わればどの判断が変わるかを結ぶ。

例えば、親のしのぎ方を問われたのに解説しか読めなかったら、「実際に続いている経験は未取得」「共有calendarは勧められた着想」「誰が取り込み、何を契機に相手へ渡り、誰が行うかが未確認」と分ける。
着想は候補を広げる参考に使えても、実際に続いた根拠には使えない。本人たちの行いで判断できる所と、他者へ広げるための根拠が必要な所を依頼側が分けられるようにする。
声が不足したことだけで全ての候補を作れないと決めず、その不足がどの判断を止めるかを具体にする。

本人の認識、規則・機能や技術の事実が必要なら、問いと得られると変わる所を依頼側へ返す。利用者や別のskillへ直接頼まない。
前の依頼が読んだ根拠・結論を変える場合は、共通の材料の「変えた所」に前の姿・理由・影響する依頼を残し、今の返りへ添える。
新しい記述が見つかったことと、以前の読解や根拠が誤っていた訂正を区別する。

## 返す材料と、確かめ方・止める線

材料の入口の「中身」には、今回の問いと範囲、資料と読むための文脈、経験・着想と読解、支持・反証と未確認、次の問いと判断への影響を繋ぐ。
「確かめた方法と限界」には、探索先と読めた範囲、原資料への到達、取得不能、対象の違い・重複や偏り、今回言えないことを残す。
付随資料が要る場合も共通の配置を使う。本文の量や件数だけで、依頼に応えたことにしない。

返す前に、次を今回の材料で確かめる。

- 読み手が、どの記述からどの読解・主張が生まれたかを辿れるか。勧めや機能を、実際の経過と取り違えないか。
- 次の判断を左右する一回の行い・認識・結果と、その後の評価を読み分けられるか。不明の期間や別の人の事情を足していないか。
- 得た違いで何の問いが育ち、何を支え・覆し、どこにまだ根拠が無いかを判断できるか。出典の存在だけで採否を通していないか。
- 着想として使えるものを、経験の証拠として落ちることを理由に捨てていないか。重要な不足と、別の事実を得る先が具体か。

記述と読解の対応や問いが崩れていたら、注意書きを足すだけで終えず、原資料と問いへ戻して整理し直す。
今回の判断へ使える違いと根拠が揃った所、又は取得できない重要な不足とその影響を具体に返せた所で、今回の返りを終える。
選択を変える重要な不足がまだ取得可能なら、問いと探索先へ戻る。全ての人を調べ終える義務、賛否の同数、固定件数は置かない。
未取得を返せたことは、必要な経験を取得できたことではない。足りない根拠が必要な判断を、材料が出来たことだけで成立としない。

## 持たないもの

- 価値・目標・対象者・条件・案の採否、製品の設計と実装
- 規則・製品の機能や費用・技術の性質を、経験や不満だけから保証すること
- 架空の発言・人数・頻度・気持ちの生成、本人の事情や市場の割合の代行的な確定
- 無断の外部連絡・聞き取り、アクセス制限の迂回
- 利用者への直接の問い、別のskillへの直接の依頼

提供された検査用の架空の記録は、その入力の整理の確認だけに使い、実際の利用者の経験として返さない。
