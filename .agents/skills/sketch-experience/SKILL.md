# sketch-experience

材料`experience-sketch`を作る。依頼と返し方は`what-defines-a-product/README.md`の「skillへの頼み方」、配置と入口は`product-plans/README.md`に従う。

## 支える判断と、専門の仕事

案を使う人が、暮らしや仕事の中で何をきっかけに始め、誰と何を受け渡し、何を行い終えると、受け取った状態へ届くかを、辿って判断できる形にする。
価値や目標を新たに発見・選定する仕事ではなく、受け取った価値・状態・前提に対して、検討中の解き方がどんな体験になるかを設計し、確かめる仕事である。
画面だけでなく、手作業・既存の道具・相手の仕組み・人の引受けを含む。作らない案も、自作画面を持たない案も対象になる。

専門の方法として、タスク分析で目的を行いと前後の状態へ割り、サービスブループリントのように人・相手・仕組みの境界を辿り、ラフを使ったウォークスルーで一巡を確かめる。
個人版では、与えられた具体の場面と事実から机上で実行する。実際の利用者の観察や操作の試行を行っていない場合、使いやすさ・所要時間・価値の実現を観測できたことにはしない。
全体の状態へ届く筋を示すことと、依頼された狭い範囲を詳しくすることを両立させる。狭い部分の外にある必要な行いを、無いものにしない。

## 依頼の目的で、描く範囲を決める

| 何のため | 返す粒度と、描かない細部 |
| --- | --- |
| 選択肢ごとの、主要な操作の流れを見る | 各案で同じ始点・到達したい状態を置き、誰の行い・受渡し・必要な道具が違うかを辿れる。全画面・全分岐の詳細は作らない |
| 画面の枚数と主要な操作で、作る時間を積む | 作る部分の表示・入力・状態の変化、既存の道具や相手へ出る境界、画面を持たない処理を指せる。費用の値そのものは出さない |
| 最初に作る分の、場面の流れを見る | その版の一巡と、その外に任せる行い・残る未達を繋ぐ。後の版の全画面を先に作らない |
| 全ての場面を決める | 指定範囲の場面を、始まり・行い・受渡し・途中や失敗からの続き・終わり方まで揃える。範囲を全生活へ広げない |
| 全ての画面を決める | 対象の全場面に必要な画面・状態ごとの表示情報と操作を揃える。相手の画面を自作画面として数えない |

全体を一度に並べるのは、この粒度と範囲の中で行う。一枚ずつ継ぎ足すことも、粗い比較依頼で全画面設計まで膨らませることもしない。
同じ材料を、後の依頼で必要な所から育てる。粒度ごとに別の材料を作らない。

## 受け取る入力

| 入力 | 確かめることと、不足の返し方 |
| --- | --- |
| 依頼の目的、描く案と範囲 | どの判断に使い、どの案の何を描くか。作る部分に限定しない。比較対象が無ければ、候補探索を代行せず何が必要かを依頼側へ返す |
| その案で届けたい価値・状態と前提 | 誰に何が成り立てばよいか、残したい関わりや時間、変えてはいけない制約。部分案なら届ける範囲と残す未達を区別する。曖昧なら勝手に決め直さず依頼側へ返す |
| 既にある着想・ラフ・操作の流れ | あれば一つの案として扱う。着想を無条件の正解や、全案の共通の形にはしない |
| 利用者と相手の事実 | いつ・どこで・何をきっかけに動け、原情報・原本・連絡先を誰が使え、相手が何で完了と扱うか。無ければ仮説と区別し、判断に必要な不足だけを返す |

利用者しか持たない事実は、材料の決定過程に、問いと答えで何が変わるかを記録して依頼側へ返す。利用者へ直接問わない。
机上検査のために仮の場面を置く時は、検証用の追加設定と明示する。実在の利用者の反応・合意・実績へ替えない。

## 作る手順

### 場面を、必要な状態から起こす

依頼の目的と範囲を確かめ、各案で比べる始点と、誰に何が成り立つ終点を置く。
与えられた状態を一つずつ見て、その人が何を知り、選び、行い終える場面が要るかを出す。画面の一覧から場面を逆算しない。
人や相手へ受け渡す所、材料・規則・予定が変わる所、未完から続ける所も、その状態へ届くために必要なら場面へ含める。
全体の関係を先に並べ、同じ場面の重複と、どこにも繋がらない場面、間に必要なのに無い行いを探す。

比較の依頼なら、各案を同じ範囲へ当てる。部分案を全体案と同じ達成に見せず、その版の外に残る行いと痛みを繋いで示す。
例として、原本への署名と相手への提出を分けないと、署名の画面が出来た一点で、提出まで追う負担が消えたことにしてしまう。

### 人・相手・仕組みの一巡を辿る

具体の一件を置き、原情報や出来事の発生から、受け手が何を使い、判断し、実施して終点へ至るまでを辿る。
各境界で、前の人や仕組みが何を渡し、次の人がいつ何を使って続けるかを示す。情報があることと、その人が引き受けたことを分ける。
紙・既存のアプリ・自作部分・相手の受付を、行為が実際に起きる所として区別する。道具の名前だけを矢印で繋いで済ませない。
行ったこと、記録したこと、相手側で完了したことを分け、その案の完了を支える根拠を辿る。
原本・相手の情報・その人の使える時間が無い所を、便利な画面や自動処理で埋めない。不明ならそこで何が未確認かを残す。

正常な一巡だけでなく、受渡しで次の人が動かない、途中で中断する、相手側で失敗する等、その案の成立や比較を変える場面を通す。
粗い比較では差のある重要な境界を先に問い、全場面の依頼では対象範囲の続き方まで揃える。無関係な障害を網羅する作業へ膨らませない。

### 意味のある違いを案にする

既に比較する案が与えられていれば、その案を同じ場面へ当てる。各案の中にさらに二案ずつを機械的に増やさない。
こちらで体験の案を作る依頼なら、始めるきっかけ、触る人、受け渡す場所、まとめて行うかその場で行うか等、効く前提の違う案を作る。
例えば通知から始める案と、原本を受け取った時に始める案では、記録の漏れや次の人への渡り方が変わる。その違いを一巡で確かめる。
一つの案が未完なのを埋めるためだけの弱い対抗馬や、色・配置だけを替えた複数案にはしない。
案の数や最初の分け方を固定せず、同じ体験なら統合し、意味のある違いが一つしか無ければ水増しせず理由を返す。案から一つを選ばない。

### 流れに必要な情報と操作をラフへ落とす

各場面でその人が何を見て次の行いを決めるか、何を入力・変更するか、その後何が起きるかを抽出する。
その情報がその時点で原情報や前の行いから得られるかを確かめ、表示欄を置けば情報が生まれるようには描かない。
依頼の粒度で、流れと必要な表示・操作の対応が読める文字の配置図又は画像にする。画像を使う時は同じ材料の付随fileへ置く。
紙の用件票、既存の予定、通知本文もラフにできる。自作画面が無い案を、無理に自作の一覧・詳細画面へ置き換えない。

画面の構成を比べる必要がある時は、次の差を、実際の一巡に当てて選択肢にする。

| 分け方 | 比べる差 |
| --- | --- |
| 一覧と詳細 | 複数件から次の一件を選ぶ情報と、一件を判断・変更する情報を分ける。どの行を探し直すかを見る |
| 一画面にまとめる | 行き来を減らせる一方で、見る情報と入力が混ざらないかを見る |
| 段階ごとに分ける | 入力・確認・実施の段階を分け、途中で閉じた時に何が保存済み・未実施かを辿る |
| 自作画面を持たない | 通知・紙・既存道具の中で完結させ、必要な引受けや根拠へ実際に到達できるかを見る |

見た目の色・余白・文言の仕上げは行わない。画面の枚数が少ないことを、その案の操作・受渡し・作る量が少ない証拠にはしない。
画面を持たない処理、通知の受渡し、失敗した時の訂正や続きも、見積り・設計に必要な粒度なら外との境界として示す。
ここで見つけるのは必要な操作や境界であり、認証・定期実行・連携等の技術設計や費用は別の専門の仕事である。

### ラフを使って通し、判断できる材料へ返す

描いた流れを、前の案や文章の意図で補わず、示された情報と操作だけで通す。
与えられた状態ごとにどの場面が支えるかを結び、どの人のどの行いが欠けると届かないか、どの案でも人に残る仕事、案で変わる受渡しと負担を返す。
担当名があるだけで引受けが無い、相手へ提出していないのに完了表示になる、途中の変更で元の済みが残る、といった当該案の反例を問う。
不足を見つけたら、同じ案の流れやラフを直すもの、案や事実の説明が要るもの、届ける状態の判断が要るものを区別し、後二者は依頼側へ具体に返す。
与えられた価値や条件を黙って弱めたり、今回の部分の外を成立済みにしたりして案を通さない。

## 返す材料と、止める線

材料の入口の「中身」へ、依頼の判断を辿れる形で次を置く。全項目を同じ長さの表に揃えるのでなく、流れ・分岐・案の差に合う表現にする。

- 入力と今回の範囲、既知の事実・検証用の設定・未確認の区別
- 各案の場面と一巡、表示・操作のラフと場面との対応
- 状態への対応、通して見えた欠けと直し、案の間で違うものと共通して残る仕事
- 判断又は別の材料へ返す不足と、その答えで何が変わるか

候補比較なら受渡しと体験の差が読め、見積り用なら自作の表示・操作・外との境界を指せ、全場面・全画面の依頼なら指定範囲の対応と続き方が揃った所で止める。
必要な事実が無く通せない場合は、完成した材料として黙って閉じず、止まる所と不足を依頼側へ返す。
他の材料の見立てを使った時は出典として区別する。同じ値をこちらでも観測したことにせず、費用から画面・操作を逆算して見積りの根拠へ返さない。
細かく育てた時は以前に読まれた範囲を消さず、変わる所と理由、依っていた依頼への影響を材料の入口へ残す。

## 水準

| 読み手が出来るべきこと | 満たさない例 |
| --- | --- |
| 同じ範囲で、誰の行い・受渡しがどう違うかを案ごとに辿れる | 紙の案は一行、自作の案だけ全画面を描き、同じ終点へ届くか比べられない |
| 与えられた状態から場面が出た理由と、その一巡が分かる | 一覧・登録・通知の画面名だけで、原情報の受領や実際の提出の場面が無い |
| 次の人が必要な物と情報を使って続けられるかを問える | 担当名や通知の既読を、その人の引受けと同じにする |
| 記録・操作と、相手側の実施・完了を区別できる | 予約済み・提出済み・解約済みを押せることだけで、その出来事が済む |
| 依頼の粒度で、ラフの情報と操作だけを使って検査できる | 表示欄に出す情報が原情報から得られず、実行者の記憶で続きを補う |
| 未達・未確認・実利用の観測の違いを理解できる | 描けたことを使いやすい証拠にし、仮の反応を利用者の採否にする |

局所の記法や参照の欠けなら直して確かめ直す。場面の導出・案の前提・一巡の成立が欠ける場合は、ラベルを足して埋めず、その案の組立てへ戻る。

## 持たないもの

- 案の選定、価値・目標・条件や部分の採否の決定
- 候補サービスの探索・現行の規約や料金の確認、費用や作業時間の見積り
- 技術・データ・モジュールの設計、実装や運用の実行
- 利用者への直接の問い、別のskillへの直接の依頼

必要な他の仕事とその粒度は依頼側へ返す。選ばずに返すことで、次の判断に必要な情報・操作・不足を受け渡す役割を果たす。
