# sketch-experience

材料`experience-sketch`を作る。受け取るもの、粒度、再利用は`what-defines-a-product/README.md`の「材料」節に、置き方と入口の形は`product-plans/README.md`に従う。

## 粒度

要求する問いによって、要る粒度が違う。求められた粒度で止め、作り込まない。

| 要求する問い | 粒度 |
| --- | --- |
| `what-to-build/solution-shape` | 解き方の案ごとに、主要な操作の流れが分かる程度 |
| `how-far-to-build/first-build-cut` | スコープの内の主要な場面の流れが分かる程度 |
| `how-far-to-build/build-cost-pays-off` | 最初に作る分の画面の枚数と主要な操作が分かる程度 |
| `how-to-build/experience` | 最初に作る分の全ての場面について、きっかけ、操作、起きること、終わり方が分かる程度 |
| `how-to-build/screens` | 最初に作る分の全ての画面について、表示する情報と操作が分かる程度 |

粗い粒度で作った材料を、細かい粒度を求められた時に育てる。粒度ごとに別の材料を作らない。

## 作る手順

1. 正本の受け入れ時の入力にある「既にある着想」を読む。利用者が既に描いているラフ画や流れがあれば、それを案の一つにする。
2. 全ての場面、全ての画面を一度に並べる。一つの場面、一枚の画面ずつ作らない。一つずつ作ると、場面の間の行き来と情報の重複が見えず、後で継ぎ足すパッチワークになる。
3. 案を二つ以上作る。二つ目以降の案は、流れの組み立て方や画面の分け方を変えて作る。組み立て方と分け方の選択肢は、`what-defines-a-product/how-to-build.md`の体験と画面の問いの定石にある。
4. ラフ画は、文字の配置図（文字で描いた画面）か、画像にする。どちらでも、表示する情報と操作が読めればよい。画像は付随fileとして同じdirectoryに置く。
5. 案ごとに、どの場面・どの画面が、どの要求（`what-to-build/requirements`の答えがある時）に対応するかを書く。

## 作り込まない

見た目の細部（色、余白、文言の調整）は作らない。この材料は判断の材料であり、作るものの完成品ではない。
