# sketch-experience

材料`experience-sketch`を作る。頼まれ方と返し方は`what-defines-a-product/README.md`の「skillへの頼み方」に、置き方と入口の形は`product-plans/README.md`に従う。

## 粒度

何のための依頼かによって、要る粒度が違う。頼まれた粒度で止め、作り込まない。依頼した側は、何のための依頼かを、次の「何のため」から名乗る。

| 何のため | 粒度 |
| --- | --- |
| 選択肢ごとの、主要な操作の流れを見る | 選択肢ごとに、主要な操作の流れが分かる程度 |
| 画面の枚数と主要な操作で、作る時間を積む | 作る部分の画面の枚数と主要な操作が分かる程度 |
| 最初に作る分の、場面の流れを見る | 最初に作る分の主要な場面の流れが分かる程度 |
| 全ての場面を決める | 最初に作る分の全ての場面について、きっかけ、操作、起きること、終わり方が分かる程度 |
| 全ての画面を決める | 最初に作る分の全ての画面について、表示する情報と操作が分かる程度 |

粗い粒度で作った材料を、細かい粒度を頼まれた時に育てる。粒度ごとに別の材料を作らない。

## 入力

| 入力 | 渡すもの | 足りない時 |
| --- | --- | --- |
| 描く対象（どの選択肢の、どの作る部分か）と、それが覆う状態 | 依頼した側 | 何が足りないかを付けて依頼した側へ返す |
| 受け入れ時の着想（利用者が既に描いているラフ画や流れ） | 依頼した側（正本） | 無ければ無いものとして扱う |
| 利用者の事実（いつ、どこで、何をきっかけに使うか） | 依頼した側 | 流れの組み立てに要るのに無ければ、この材料の決定過程に論点として立て、依頼した側へ返す |

## 作る手順

1. 受け入れ時の着想を読む。利用者が既に描いているラフ画や流れがあれば、それを案の一つにする。
2. 全ての場面、全ての画面を一度に並べる。一つの場面、一枚の画面ずつ作らない。一つずつ作ると、場面の間の行き来と情報の重複が見えず、後で継ぎ足すパッチワークになる。
3. 案を二つ以上作る。二つ目以降の案は、下の「流れの組み立て方」と「画面の分け方」の選択肢から、一つ目と違うものを選んで作る。選択肢ごとの流れを頼まれた時は、選択肢ごとに全ての場面を並べる。
4. ラフ画は、文字の配置図（文字で描いた画面）か、画像にする。どちらでも、表示する情報と操作が読めればよい。画像は付随fileとして同じdirectoryに置く。
5. 案ごとに、どの場面・どの画面が、どの状態に対応するかを書く。
6. 並べて見えたこと（どの案にも残る行き来、案の間で違うのがどの場面だけか等）を書く。案から一つを選ばない。

### 流れの組み立て方

| 組み立て方 | 中身 | 向く時 |
| --- | --- | --- |
| きっかけから組む | 利用者が使い始めるきっかけ（知らせが来た、作業を終えた）から流れを組む | 日常の中で使う道具 |
| 結果から逆算する | 利用者が最後に得たい結果から、そこへ至る最短の流れを組む | 目的がはっきりした道具 |
| 今の回避策をなぞる | 今やっている手作業の流れを、そのまま道具へ置き換える | 慣れた手順を崩したくない時 |

### 画面の分け方

| 分け方 | 中身 | 向く時 |
| --- | --- | --- |
| 一覧と詳細に分ける | 対象の一覧と、一件の詳細・編集を分ける | 扱う対象が多い時 |
| 一画面にまとめる | 入力と結果を一つの画面に置く | 操作が少なく、すぐ終わる時 |
| 段階ごとに分ける | 流れの段階ごとに画面を分ける（入力、確認、完了） | 途中でやめると困る時 |
| 画面を持たない | 知らせや、既にある道具の中で完結させる | 描く対象が、知らせや自動の受け渡しの時 |

## 作り込まない

見た目の細部（色、余白、文言の調整）は作らない。この材料は判断の材料であり、作るものの完成品ではない。

## 持たないもの

- 案から一つを選ぶこと（依頼した側が行う）
- 利用者へ直接問うこと（材料の決定過程に論点を立て、依頼した側へ返す）
- 別のskillへ直接頼むこと（依頼した側へ返す）
