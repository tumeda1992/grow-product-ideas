# find-existing-alternatives

材料`existing-alternatives`を作る。受け取るもの、粒度、再利用は`what-defines-a-product/README.md`の「材料」節に、置き方と入口の形は`product-plans/README.md`に従う。

## 作る手順

1. 正本から、`why-to-build/pain-to-solve`の答え（無ければ受け入れ時の入力）を読み、痛みの場面を比べる軸にする。
2. 次の三つの範囲を全て探す。一つの範囲で見つからなくても、他の範囲を省かない。
   - 同じ目的の専用サービスやアプリ: ウェブ検索、アプリストア、比較記事
   - 汎用の道具の組み合わせ: 表計算、ノート、自動化サービス、既存アプリの設定で代わりになるか
   - やり方を変える: 痛みの原因の作業そのものをやめる、減らす
3. 主な候補は、無料枠や試用で触れるなら触る。触れない時は、公式の説明と利用者の評判から読む。
4. 候補ごとに、痛みの場面のどこが解け、どこが残るかを書く。
5. 依存先の候補を求められた時（`why-to-build/risks-of-building`）は、候補が外部サービスやAPIに依存するか、それが終了・値上げした時に何が起きるかも書く。

## 代わりになるとみなす基準

痛みの核心の場面が解けるなら、手間が残っても代わりになる候補として挙げる。残る手間は「痛みのどこが残るか」に書く。
完全に同じ機能でなくても、痛みが解ければ候補である。

## 「見つからない」で終えない

三つの範囲のどこを、どの言葉で探したかを入口に書く。見つからなかった時も、探した範囲と言葉を書く。
「競合はいない」だけを書かない。
