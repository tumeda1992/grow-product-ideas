# settle-question

`what-defines-a-product/`の問い一つに、このアイデアについての決着をつける。

問いは、どのアイデアにも当てる一般の問いである。一般の問いのまま答えると、答えも一般的になり、このアイデアに特有の浅さを捕まえられない。そのため、答える前に、一般の問いをこのアイデアの問いへ立て直し、どこまで詰めるかを決める。

## 持つもの

- 一般の問いを、このアイデアの問いへ立て直すこと
- 詰める深さを決めること
- 材料skillを起動し、必要な材料を揃えること
- 定石の対案と自分の案を並べて選び、答えを書くこと
- 立て直した基準で、書いた後の漏れを確認し、「閉じた」と記録すること

## 持たないもの

- 次の問いの選択、出口判定（`grow-product-idea`が行う）
- 材料を作ること（材料skillが行う）
- 層ごとの中身。問い、必要な材料、水準、定石は`what-defines-a-product/`の層fileが持つ。このskillは層ごとの分岐を持たない

## 受け取るもの

- `product-plans/<slug>/`の場所
- 決着をつける問いのidentifier
- `grow-product-idea`から戻された時は、足りなかったもの

正本、決定過程、材料の入口の場所は`product-plans/README.md`で引く。

## 品質は答えを作る段階で担保する

立て直した問いの基準は、答えを作る時の目標であり、書いた後に漏れを確認する基準でもある。
基準を満たす答えを作ろうとして材料を集め、対案を並べ、答えを書く。書いた後の確認は、それでも漏れたものを拾うためにある。確認で直せばよいという前提で、答えを緩く作らない。

## 手順

```text
1. 立て直す
2. 材料を揃える
3. 対案を並べて選ぶ
4. 決定過程と正本に書く
5. 立て直した基準で漏れを確認する
   ├─ 局所的な漏れ → 直して5をやり直す
   ├─ 骨子の漏れ → 2か3へ戻る
   └─ 漏れなし → 6
6. 「閉じた」と記録して戻る
```

### 1. 立て直す

identifierから層file（identifierの`/`より前が層file名）を引き、問いの文面、系統、必要な材料、水準、定石を読む。正本から、受け入れ時の入力と、閉じた問いの答えを読む。

そのうえで、次の三つを決める。

- 問いを、このアイデアの言葉で言い直す。例: `what-to-build/requirements`「何を満たせば、痛みが解けたと言えるか」を、サブスクの更新日を忘れるアイデアでは「更新日が近いことに、何をすれば気づけ、払い続けを止められたと言えるか」と言い直す。
- 水準の満たさない例に、このアイデアで起きやすい浅い答えの例を足す。層fileの一般の例は外さない。例: 「更新日の前に通知が来ること」。更新日がメールや明細に散らばっていて、集めること自体が痛みの核心かもしれない点を見ていない。
- 詰める深さを決める。この問いの答えが変わった時に、出口や下位の問いがどれだけ変わるかと、今ある材料での確信度を見る。
  - 影響が大きく、確信度が低い: 材料をより細かい粒度で求め、必要ならこのアイデア固有の下位の問いを立てて詰める。
  - それ以外: 水準を満たしたところで止める。

深さを一律に最大にしない。毎回の紆余曲折を減らすというレールの目的に反する。深さを一律に止めもしない。影響の大きい問いが浅いと、上に積み上がる答えが崩れる。

一般の問いがこのアイデアに合わない時（答える意味が無い、別の問いが要る）は、その旨と理由を立て直しに書く。問いを飛ばすかは、`grow-product-idea`へ返して判断させる。この記録は、還元で問いのセットを見直す根拠になる。

### 2. 材料を揃える

問いが挙げる必要な材料ごとに、材料の入口を確かめる。

- 入口が無い、または立て直しで決めた粒度に足りない時は、その材料の材料skillを起動する。渡すものは`what-defines-a-product/README.md`の「材料」節にある。材料skillの対応は、同じ節の材料の識別子の表で引く。
- 材料が別の層のもの（例: なぜ作るか層の問いが、どう作るか層の材料であるラフ画を要する）でも、このskillが直接起動する。下位層の問いを先に答えるのではない。
- 他の問いの答えを材料にする時は、その問いが閉じていることを正本で確かめる。閉じていなければ、`grow-product-idea`へその旨を返す。

材料は、問いが挙げる順に揃える。層fileが並び順の理由を添えている時は、それに従う。

### 3. 対案を並べて選ぶ

問いの定石から選択肢と判断軸を読み、自分の思いつきと並べる。

- 調査系の問いでは、材料から答えを導き、定石の判断軸で結論を確かめる。
- 生成系の問いでは、材料にある複数案を、定石の判断軸に照らして比べ、一つを選ぶ。

着想・作りたい動機・体験の質感が無いと答えられない時だけ、利用者へ問う。それ以外は利用者へ問わず、材料と定石で詰める。

### 4. 決定過程と正本に書く

`tumeda-dev`の`facilitate-discussion`を、`discussion_directory`に`product-plans/<slug>/`を渡して使い、問いごとに一つの論点を立てる。論点には次を書き、提案として保存する。

- 立て直した問いと基準
- 比べた選択肢の中身と、選んだ答え
- 判断軸に照らした選んだ理由
- 使った材料

論点の決定は、層の閉じで利用者が応答した時に行う（`grow-product-idea`の5）。

正本の該当する問いに、このアイデアでの問い（言い直した文面、足した満たさない例、詰める深さとその理由、立てた下位の問い）、答え、材料へのlink、決定過程の論点へのlinkを書き、状態を「回答済み（確認待ち）」にする。

`product-plans/README.md`の「directoryの中だけで読み切れるようにする」に従って書く。

### 5. 立て直した基準で漏れを確認する

正本を後で読む人（層の閉じや出口判定で読む利用者、build-ready後に受け取る後続の`steering`／`task-design`）の立場で、正本に書かれた答えと材料だけを見て、正本に書いた立て直しの基準（一般の満たさない例と、足した例）に照らして確かめる。
答えを考えた時の推論で補わない。書かれていないことは、無いものとして扱う。

| 漏れ | 戻り先 |
| --- | --- |
| 言い回し、linkの欠け等の局所的な漏れ | その場で直し、5をやり直す |
| 材料が足りない、対案を比べていない、答えが材料から導かれていない、立てた下位の問いに答えていない等、答えの骨子の漏れ | 2か3へ戻って作り直す。一文を足して満たしたことにしない |

### 6. 「閉じた」と記録して戻る

正本の該当する問いに、確認結果（基準のどの点を満たしたか、局所的に直した箇所）を書き、状態を「閉じた」にして`grow-product-idea`へ戻る。

## 基準を下げない

立て直す側と答える側が同じため、答えやすいように基準を下げる恐れがある。次を守る。

- 層fileの一般の満たさない例は外さず、このアイデアの例を足すだけにする
- 立て直した問いと基準を正本に書く。層の閉じで利用者が見る
- 確認は、頭の中の基準ではなく、正本に書いた基準で行う
