# design-modules

材料`modules`を作る。受け取るもの、粒度、再利用は`what-defines-a-product/README.md`の「材料」節に、置き方と入口の形は`product-plans/README.md`に従う。

## 作る手順

1. 先に読む。正本の「データ」の節と、材料`core-logic`を読む。これらが無い時は、`settle-question`へ返す。
2. 全てのモジュールを一度に並べた案を、二つ以上作る。モジュールを一つずつ足していかない。
3. 案ごとに、各モジュールの役割と持たないもの、モジュール間の依存の向き、全てのテーブルと心臓部のロジックがどのモジュールに属するかを書く。
4. 依存が循環していないかを確かめる。
5. 案ごとに、`what-to-build/scope-in-and-out`でスコープの外に置いたものを足す想定を数件当て、触るモジュールがいくつかを書く。

## 判断の参照先

分け方の選択肢（層で分ける、扱う対象で分ける、心臓部を切り出す）は、`what-defines-a-product/how-to-build.md`のモジュールの問いの定石にある。

## 落とし穴

- 使う技術の名前（フレームワーク、ライブラリ）だけを書く。コードをどう分けるかを書く。
- 心臓部のロジックを複数のモジュールに散らす。一つのモジュールにまとめられるかを先に見る。
