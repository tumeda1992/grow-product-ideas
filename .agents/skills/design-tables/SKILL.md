# design-tables

材料`tables`を作る。受け取るもの、粒度、再利用は`what-defines-a-product/README.md`の「材料」節に、置き方と入口の形は`product-plans/README.md`に従う。

## 作る手順

1. 先に読む。正本の`how-to-build/experience`と`how-to-build/screens`の答え、材料`core-logic`を読む。これらが無い時は、`settle-question`へ返す。体験と画面より先にテーブルを決めると、画面が表示する情報とずれる。
2. 画面が表示する全ての情報と、心臓部のロジックの全ての入力と出力を、一覧に書き出す。
3. 全てのテーブルを一度に並べた案を、二つ以上作る。テーブルを一つずつ足していかない。
4. 案ごとに、2の一覧の全ての項目が、どのテーブルのどの項目から来るかを対応させる。対応しない項目があれば、案を直す。
5. 状態が変わるものについて、状態を項目で持つか、別のテーブルへ移すか、出来事を記録して状態を計算するかと、その理由を書く。
6. 具体的な値を数行入れて、画面の表示と心臓部のロジックが成り立つかを確かめる。

## 判断の参照先

- 状態の持ち方と、テーブルの名前の付け方は、`what-defines-a-product/how-to-build.md`のテーブルの問いの定石にある。
- テーブルの名前は、一行が何を表すか（出来事の記録か、状態を持つ物か）が分かる形にする。

## 落とし穴

画面ごとにテーブルを作ると、同じ情報が複数のテーブルに重複し、片方だけを直す事故が起きる。
