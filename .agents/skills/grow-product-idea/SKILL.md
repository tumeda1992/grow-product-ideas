# grow-product-idea

アイデア1件を、`what-defines-a-product/`の層に沿って決めて閉じ、出口まで運ぶ。

## 持つもの

- アイデアの受け入れと、`product-plans/<slug>/`と正本の作成
- 次の層の選択と、層を始める時の層の記録の作成
- 層fileの決め方に沿って、層の決めるものを決めること（skillに頼むこと、論点を立てることを含む）
- 層の閉じでの、利用者への確認と、正本への書き込み
- 差し戻しを、順に回すこと
- 出口の判定と記録

## 持たないもの

- 層ごとの中身（何を決めるか、決め方、止める時）。層fileが持つ。このskillは層ごとの分岐を持たない
- 層と層、層とskillの間の決まり。`what-defines-a-product/README.md`が持つ
- 記録の置き方と形。`product-plans/README.md`が持つ
- 専門の仕事（候補と事実と費用、ラフ画等）。skillが行う
- 閉じた層を開け直すかの判断。返された層が、自分の決め方で判じる

## 引くもの

| 引くもの | 場所 |
| --- | --- |
| 層、層の順、層の状態、層の閉じで示すもの、差し戻し、前提にする条件、skillへの頼み方とskillの一覧 | `what-defines-a-product/README.md` |
| 層ごとの決めるもの、決め方、止める時、層の閉じ | `what-defines-a-product/`の層file |
| 記録の置き方、記録の役割、材料の入口の形 | `product-plans/README.md` |
| 正本の雛形 | [templates/canonical.md](templates/canonical.md) |
| 層の記録の雛形 | [templates/layer-record.md](templates/layer-record.md) |

## 流れ

```text
1. 受け入れ（新規）／ 再開
        ↓
2. 次の層を選ぶ ←──────────────────────────────┐
        ↓                                      │
3. 層を決める（層fileの決め方に沿って）         │
   ├─ 後の層の側で、前の層に元があると分かった │
   │    → 6. 差し戻しを回す ──────────────────┤
        ↓                                      │
4. 層の閉じを利用者へ確認する                   │
   ├─ 修正 → 3へ ──────────────────────────────┤
   └─ 受け入れ → 正本に書く ───────────────────┘
        ↓ 作らないへ向かう、または全ての層が閉じた
5. 出口を判定し、記録する
```

### 1. 受け入れ／再開

新しいアイデアの時:

1. 利用者から、アイデア、作りたい動機、既にある着想を受け取る。足りないものだけを利用者へ尋ねる。動機と着想は寝かせないと出てこないものであり、このskillが代わりに作らない。
2. slugを決める。`tumeda-dev`の`name-work-directory`が使える時はそれでアイデアと今日の日付から`YYYYMMDD-slug`を決め、使えない時は同じ形（日付と英小文字のkebab-case）で決める。
3. `product-plans/README.md`に従って`product-plans/<slug>/`を作り、[templates/canonical.md](templates/canonical.md)から正本を作る。受け入れ時の入力は、利用者の言葉を言い換えずに書く。

既にある`product-plans/<slug>/`を再開する時は、正本のプロダクトの状態と、各層の記録の状態を読み、2から続ける。

### 2. 次の層を選ぶ

`what-defines-a-product/README.md`の「層」の表の順に、閉じていない最初の層を選ぶ。次の層は、前の層が閉じてから始める（同じREADMEの「層の順」）。

なぜ作るか層は、まだ今の形で書いていない。それが書かれるまでは、何が成り立てばよいか層を始める前に、受け入れ時の入力から、痛み、作ることで得たいもの、アウトカムを利用者と置き、正本の「なぜ作るか」に、なぜ作るか層の閉じを通っていない仮のものとして書く。

### 3. 層を決める

1. [templates/layer-record.md](templates/layer-record.md)から、層の記録を作る（`product-plans/README.md`が定める場所）。状態を「決めている」にする。
2. 層fileの「何を決めるか」「決め方」「止める時」に沿って、決めるものを決める。決め方の段ごとに出したものを、層の記録のその段に書く。
3. 専門の仕事は、`what-defines-a-product/README.md`の「skillへの頼み方」に従ってskillに頼む。頼んだことは層の記録の「材料への依頼」に書き、返ったものは層の決めるものの形へ読み替える。skillが利用者の事実や別のskillの結果を要ると返した時は、その材料の決定過程の論点を利用者に問い、または別のskillに頼み、答えを渡して続けさせる。
4. 利用者の採否が要る判断、利用者しか持たない事実、発案者の視野の外の点が生じた時は、`tumeda-dev`の`facilitate-discussion`で、層の決定過程に論点を立てる（`product-plans/README.md`の「決定過程の役割」）。
5. 止める時に達したら、層の記録の確認に、層fileの「揃えば満たした」を写し、それぞれ満たしたかと、どこで満たしたかを書く。満たさないものがあれば、その段へ戻る。
6. 層の記録の状態を「閉じ待ち」にし、4へ進む。

後の層を決める中で、崩れの元が前の層の側にあると分かった時は、層の記録に、何を見つけ、どの層の何に返したかを書き、6へ進む。

### 4. 層の閉じを利用者へ確認する

`what-defines-a-product/README.md`の「層の閉じ」に従い、利用者へ確認する。

- 層fileの「この層の閉じ」が挙げるもの、層の決定過程の論点、層が頼んだ材料の決定過程の応答待ちの論点を示す
- 利用者は論点ごとに応答する。合意した論点は決定になる。修正があれば、その段について3へ戻る
- 利用者が層を受け入れたら、層の記録の状態を「閉じた」にし、正本に、その層の決めるものの節を書く（正本の各節のcomment「この節を決める層と決めるもの」で引く）。正本のプロダクトの状態の行に、閉じた層を足す
- 前提にする条件が合意されたら、正本の「前提にする条件」に書く。閉じた層があれば、6で差し戻しとして回す

### 5. 出口を判定し、記録する

出口判定は、次の時に行う。

- 層の閉じで、層fileが作らない・保留へ向かうとした時（例: どう解くか層で、選んだ選択肢に作る所が無い）
- 全ての層が閉じた時。今は、どこまで作るか層とどう作るか層をまだ今の形で書いていないため、build-readyにしない。二つの層が閉じた時は、プロダクトの状態を検討中のままにし、まだ通していない層があることを正本に書く

build-readyにする前に、`product-plans/<slug>/`の中に、directoryの外へのlinkや、外を見ないと分からない参照（層fileの段の番号だけ等）が無いかを確かめる（`product-plans/README.md`の「directoryの中だけで読み切れるようにする」）。

出口は、利用者へ確認してから確定する。正本の「状態」と「出口」を書く。作らない時は作らない理由を、保留の時は復活する条件を書く。build-readyの時は、このdirectoryの写しを新しいリポジトリへ持っていき、初回構築の入力にすることを書く。写しを作ること、名前を変えること、リポジトリを作ることは、利用者が行う。

### 6. 差し戻しを回す

`what-defines-a-product/README.md`の「閉じた層への差し戻し」に従って、順に回す。

1. 返された層の記録へ、何がどこから返ったかを渡す。開け直すかは、返された層が自分の決め方で判じる。判じる時は、その層の決め方に沿って3と同じように行い、このskillは判じない
2. 開け直した時は、層の記録の状態を「開け直し」にし、直して、4で閉じ直す。開け直さなかった時は、層の記録に「確かめ直した。変わらない」とあることを確かめる
3. 閉じ直した層を物差しや入力にしている下の層を「確かめ直し待ち」にし、上から順に、1から同じように回す

材料の返しに、前の依頼が読んだ所が変わったと添えられた時も、読んでいた層へ、同じように回す。

## 利用者へ問う場面

- 受け入れ時（アイデア、動機、既にある着想）
- 層を決める中で立った論点（採否、認識合わせ、視野の外の点）。材料の決定過程の論点を含む
- 層の閉じ
- 出口判定

それ以外は、層fileの決め方とskillで詰める。利用者の頭は、寝かせないと出てこないものと、利用者しか持たないものと、利用者が選ぶものにだけ使う。
