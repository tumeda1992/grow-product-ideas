# what-defines-a-product

プロダクトのアイデアを、作り始める前に決めるべきことが全部決まった状態（build-ready）まで詰めるための層を持つ。

層は、決めるものと、その決め方を持つ。層fileは、層ごとの中身（何を決めるか、決め方、止める時、限界）を書く。このREADMEは、層と層、層とskillの間の決まりを書く。アイデアごとの記録の置き方と形は、[product-plans/README.md](../product-plans/README.md)に書く。

| 層 | file | 決めるもの |
| --- | --- | --- |

どこまで作るか層と、どう作るか層は、まだ今の形で書いていない。

## 層の進め方

### 層の順

次の層は、前の層が閉じてから始める。

前の層の決めるものは、次の層の物差しや入力になる。物差しを変えうる採否が残ったまま次の層の選択肢を見ると、その採否が、見た選択肢に寄る。例えば、作りたい選択肢が満たしにくい条件を、受け入れる側へ倒したくなる。物差しを変えない採否だけが残っているかを見分けて先へ進む例外は置かない。見分けること自体を、選択肢を見たい側が行うためである。

### 層の状態

| 状態 | 中身 |
| --- | --- |
| 決めている | 決め方を進めている |
| 閉じ待ち | 決め方を終え、利用者の応答を待つ論点がある |
| 閉じた | 利用者が、層を受け入れた |
| 開け直し | 閉じた後に差し戻しを受け、直している |
| 確かめ直し待ち | 物差しや入力にしている上の層が変わり、開け直すかを判じる前 |

層の状態は、層の記録に書く。

### 層の閉じ

閉じで、利用者は、層fileの「この層の閉じ」が挙げるものを確かめ、論点ごとに応答する。

示すのは、層の決定過程の論点に加えて、層が頼んだ材料の決定過程のうち、応答待ちの論点である（層の記録の「材料への依頼」から辿る）。材料の論点が応答待ちの間は、それに依る所を、確かめた事実として扱わない。確かめた事実が要る所では、その事実の両側で書く。

### 閉じた層への差し戻し

閉じた層は、次の時に差し戻される。

| 起き方 | 返す者 | 返す先 |
| --- | --- | --- |
| 後の層の決め方で、崩れの元が前の層の側にあると分かる | 後の層 | 前の層 |
| 材料が、閉じた層の読んだ所を変える | skillが、今の依頼の返しに添える。依頼した層が受ける | 読んでいた層 |
| 前提にする条件が足される | 足された層 | 閉じた全ての層 |

- 開け直すかは、返された層が、自分の決め方で判じる。返されたものが自分の決めるものの何に効くかを見て、効かなければ開け直さずに、層の記録へ「確かめ直した。変わらない」と書く
- 返す側は、層の記録に、何を見つけ、どの層の何に返したかを書く
- 返された側は、層の記録の状態を「開け直し」にし、「差し戻し」の節に、何がどこから返り、前の姿と直した後を書く。直したら、閉じで利用者と合意し直す
- 直して閉じ直したら、その層を物差しや入力にしている下の層を「確かめ直し待ち」にする。下の層も、開け直すかを自分で判じる

正本には今の決めるものだけを書く。前の姿は、層の記録の「差し戻し」の節に残す。

### 前提にする条件

前提にする条件は、利用者が、どの手段にも課す制約である（例: 子どもの情報を、家族の二人以外に見せない）。満たすべき条件と違い、アウトカムの言い分からは出ない。

- 出た層の決定過程で、論点として立てる。利用者が対案を退けた理由のうち、他の選択にも効くものを、利用者に確かめる
- 合意したら、正本の「前提にする条件」に書き、根拠としてその論点へlinkする
- 閉じた層があれば、差し戻しとして回す
- 後の層は、前提にする条件に反する選択肢を、どの条件に反するかを書いて外す

## skillへの頼み方

### skillの立ち位置

skillは、層が頼む外部の専門家である。依頼した側の判断とは別の専門の判断を持ち、選ばずに並べ、誰がどの粒度で読むかを自分で知り、同じ結果を粗いものから細かいものへ育てる。

依存は、層からskillへの一方向である。層は、skillに何を頼めるかを知る。skillは、層の名前も決め方も知らない。

### 頼む時に渡すもの

層は、skillの言葉で頼む。層の決めるものを、skillの入力の言葉へ写すのは層である。

- 何のための依頼か（skillの一覧の「何を頼めるか」から）
- 何を覆う・描くか、とその条件
- 既に分かっている利用者の事実
- 粒度

頼んだことは、層の記録の「材料への依頼」に書く。skillは、受けた依頼を、材料の入口の「依頼と粒度」に書く。

### 返ったものの読み方

層は、返った形を、自分の決めるものの形へ読み替える。skillの出す形を、層の形に合わせさせない。層が持つのは、受け取る時の基準（層fileの決め方の「揃えば満たした」）であり、skillのやり方ではない。基準を満たさない時は、何が足りないかを付けて頼み直す。

層が依った値（決め手の境目の作る時間等）は、層の記録に読み込む。細部は、材料の入口の節を指す。

### skillが、利用者の事実や別のskillを要る時

- skillは、利用者へ直接問わない。問いたいことと、答えで材料のどこが変わるかを、その材料の決定過程に論点として立て、依頼した側へ返す。依頼した側が利用者に問い、答えを同じ論点に残して、skillに続けさせる
- skillが別のskillの結果を要る時は、依頼した側へ返す。依頼した側が、別のskillに頼む。skillどうしで直接頼むと、どの層が何のために、どの粒度で作らせたかが、層から見えなくなる

### 前の依頼が読んだ所を変える時

材料を育てる時は、消さずに足す。前の依頼が読んだ所を変える時は、材料の入口の「変えた所」に、前の姿、変えた理由、前に読んだ依頼を書き、今の依頼への返しに、前の依頼が読んだ所が変わったと添える。前の依頼をした層が退いている時は、変えた所に書くだけで、知らせない。

### skillの一覧

| 材料の識別子 | skill | 何を頼めるか |
| --- | --- | --- |
| `alternatives` | `propose-alternatives` | 作らずに覆えるかを見る。覆う点ごとに、作らない道を含む候補と、候補の事実を見る。どの道で覆うかを選ぶために、道ごとの費用を出す。依存するあり物の規約と継続性を見る。作る部分を部品ごとに見積もる |
| `experience-sketch` | `sketch-experience` | 選択肢ごとの、主要な操作の流れを見る。画面の枚数と主要な操作で、作る時間を積む。最初に作る分の、場面の流れを見る。全ての場面を決める。全ての画面を決める |
