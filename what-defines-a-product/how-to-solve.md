# どう解くか（how-to-solve）

この層は、「満たすべき条件を、どの解き方で満たし続けるか」を決める。作らない解き方を含む。

決めるものは、解き方の選択肢と、解き方の選定の二つである。二つは一緒に作る。選定は、選択肢の上で利用者が重み付けるだけであり、作り直しが安いため、選択肢を先に閉じる必要が無い。

この層の答えから、作る境界が決まる。作る境界とは、何を作り、何を既にある道具・やり方・人の手に任せ、何を満たさずに受け入れるかである。どこまで作るか層とどう作るか層は、選んだ選択肢から作る所を切り出して受け取る。

## この層の閉じ

閉じで、利用者は次を確かめ、論点ごとに応答する。

- 決め手。補う点（組）ごとに、選んだものと次点の間で、何を得て何を払うかの、どちらを重く見たか
- 満たさずに受け入れる条件があれば、その理由
- 作る選択肢を選んだ時に、その得るものが、手間や変化への強さなのか、作ることで得たいもの（作る楽しみ等）なのか

選んだ選択肢に作る所が無い時は、作らないへ向かう。作る所を、作ることで得たいものだけを理由に選ぶ時は、なぜ作るか層の得たいものと照らし、続けることを利用者の採否の論点にする。

## 解き方の選択肢

### 何を決めるか

満たすべき条件を満たす道の候補である。出どころを直接見る形を基準にし、それだけでは足りない点と、良くしたい点（あわせて補う点）ごとに、選択肢を出す。

選択肢は、情報の流れで書く。情報の流れで書くのは、崩れやすい時点で確かめ方を問えるようにし、得るもの・払うものを出せるようにし、作る所を指せるようにし、作らない時には家族がそのまま運用できるようにするためである。「フォームで記録する」「共有カレンダーで知らせる」のような道具の名前では、どれもできない。

| 書くもの | 中身 |
| --- | --- |
| 出どころ | 条件の終点（誰が、いつ、何を知る・できる）で要る情報が、最初に生まれる所。相手の仕組み（教室のアプリ）、相手の決まり（規約）、家族の中の出来事（欠席の連絡）、家族の決めごと（誰が予約するか）のどれかになることが多い |
| 置き場所 | 情報が置かれる所 |
| 受け渡し | 置き場所から置き場所へ、または人へ、情報を渡すこと。人が渡す時は、担い手ときっかけを持つ。自動で渡す時は、何が動かすかを持つ |
| 当てにする事実 | 置き場所と受け渡しが成り立つために真であるべき事実と、それを確かめたか（出典を読んだ、利用者に問うた、動かした） |
| 得るもの・払うもの | 基準に足すことで得るものと、払うもの（八つの軸。決め方の5） |

一緒に選ばないと成り立たない選択肢（ある選択肢が、別の点の選択肢を選んだ時だけ成り立つ、または安くなる）は、組にする。全ての点で劣る選択肢は、理由を付けて外す。

後ろでは、解き方の選定が、これを比べて選ぶ。選んだ後は、どこまで作るか層・どう作るか層が、作る所の情報の流れ（何を受け取り、何を出し、何をし、既にある道具とどの受け渡しでつながるか）を受け取る。

### 決め方

#### 1. 出どころの事実を確かめる

満たすべき条件の一文の「何が」から、終点で要る情報を一件ずつ出す。情報ごとに「この情報が変わる時、最初にどこで変わるか」を問い、出どころを出す。

出どころが分かったら、出どころが何を見せるか、誰が見られるかを確かめる。多くは利用者しか持たない事実（自分の教室のアプリに何が出るか、夫が自分のアカウントで見られるか）であり、利用者に事実として問う（認識合わせ）。この事実は、基準と、どの点が足りない点になるかを決めるため、他のどの選択肢より先に要る。`propose-alternatives`に候補を頼む時にも、既に分かっている利用者の事実として渡す（[頼む時に渡すもの](README.md#頼む時に渡すもの)）。

- 揃えば満たした: 終点で要る全ての情報に出どころがあり、出どころが何を見せ、誰が見られるかが、確かめた事実で書けている。
- 外れている時: 出どころを確かめずに、こちらに置き場所を作る選択肢から始める。振替の件では、教室のアプリが振替の残りと期限を表示するかを一度も問わないまま、全ての情報をこちらの表計算へ集める道を選びかけた。

#### 2. 出どころを直接見る形と、足りない点を出す

基準は、終点の人が、終点の時点で、出どころを直接見る形である。受け渡しが無いため、受け渡しの崩れも無い。

基準で終点に届かない情報ごとに、届かない理由を書く。理由は次のどれかになる。この理由のある所が、足りない点である。

- 終点の人が、出どころを見られない（アカウントが無い）
- 出どころが、その情報を見せない（期限を表示しない）
- 情報を計算しないと出ない（規則と欠席の日から、締切を出す）
- 終点の時点に、人が見に行くきっかけが無い（締切が近いことを、知らせる必要がある）

基準は、ゴールではない。足さないと条件に届かない所（作る境界の下限の候補）を浮かび上がらせ、足すものごとに得るものと払うものを測る物差しになる。

例として、振替の件で届かない理由が確かに残るのは、締切の◯日前に気づくこと（知らせが要る）、誰が予約するか（家族の決めごとで、置き場所が要る）、期限を表示しない教室の期限と締切（計算が要る）の三つである。欠席、予約、まだ予約していない振替は、教室のアプリを見れば届く見込みがある。

- 揃えば満たした: 終点で要る全ての情報について、基準で届くか、届かない理由が書けている。
- 外れている時: 基準で届く情報まで、足りない点に数える。振替の件の前の答えは、欠席と予約までこちらへ集め、届かない理由が無いのに受け渡しを増やしていた。崩れやすい時点で確かめ方を問うと見つかった崩れ（欠席の記録忘れ、予約の写し忘れ、scriptの停止）は、そこから出ていた。

#### 3. 補う点ごとに、選択肢を出す

補う点は二つの種類がある。

| 種類 | 中身 | 選び方 |
| --- | --- | --- |
| 足りない点 | 基準で条件に届かない点 | 選択肢から一つを選ぶか、満たさずに受け入れる |
| 良くする点 | 基準で届くが、足すと手間が減る、作ることで得たいものが満たせる、変化に強くなる点 | 選ばないことも選択肢である |

選択肢の候補と、候補の事実は、`propose-alternatives`に頼む（何のため: 覆う点ごとに、作らない道を含む候補と、候補の事実を見る）。渡すのは、補う点を覆う点としたものとその条件（足りない点がmust、良くする点がbetterに当たる）、満たすべき条件、出どころの事実である。

返った候補×覆う点の表から、補う点ごとの選択肢を読む。skillが組んだ対案からは、一緒に選ばないと成り立たない組を読む。対案を、そのまま選択肢に写さない（下の、対案を丸ごと並べる）。

どの補う点にも、作らない選択肢を入れる。受け入れ時の着想が触れる補う点には、着想どおりの選択肢を入れる。着想が触れない補う点は、触れないと書く。着想を特別扱いするためではなく、比べる対象から外さないためである。

人が渡す受け渡しには、担い手ときっかけを書く。きっかけは次の四つのどれかである。

| きっかけ | 中身 | 情報が変わってから渡すまで | 崩れる時 |
| --- | --- | --- | --- |
| ついでに渡す | 情報を変える出来事（欠席の連絡、予約）を、渡す人自身が行う時に、そのついでに渡す | 時差が無い | 出来事が、いつもと違う人・違う道で起きる時。まれな道では、ついでが習慣にならない |
| 知らせを受けて渡す | 情報が変わったことを知らせるもの（相手のお知らせ、プリント、自動の通知）が、渡す人に届いた時に渡す | 知らせが届くまで | 知らせの来ない変化がある時。知らせが二人に届き、どちらも動かない時 |
| 決まった日に見比べる | 決まった日（週に一度等）に出どころを見て、こちらと違えば渡す。決まった日そのものは、自動の通知（繰り返しの予定等）で起こす | 最長で、間隔の分 | 決まった日を起こす通知が無く、習慣に頼る時 |
| 覚えていて渡す | きっかけが無い | 決まらない | いつでも崩れうる。避ける |

選べるきっかけは、その情報を誰が変えるかで決まる。家族が自分の行いで変える情報（欠席、予約）は、ついでに渡せる。相手が変える情報（規則の改定、教室の都合の休講）は、相手の知らせが届くなら知らせを受けて渡し、届かないなら決まった日に見比べる。時が経つことで変わる情報（締切が近い）は、人に起きるきっかけが無いため、自動の受け渡し（予定の通知）に任せ、人はその自動の受け渡しを仕掛ける所（予定を作る）だけを渡す。担い手は、きっかけが起きる人にする（ついでなら出来事を行う人、知らせなら知らせが届く一人）。

作られたもの（scriptの定期実行等）が黙って止まることへの備えも、決まった日に見比べる受け渡しとして書く。

- 揃えば満たした: 全ての補う点に作らない選択肢があり、着想が触れる補う点には着想どおりの選択肢がある（触れない補う点は、触れないと書かれている）。人が渡す全ての受け渡しに、担い手と、四つのどれかのきっかけがある。足した置き場所ごとに、それが届かせるためか、何を得るためかが書かれている。
- 外れている時（道具の名前だけ）: 「フォームで記録する」。誰が、何をきっかけに記録するかが無く、三か月後に満たすかを決められない。
- 外れている時（対案を丸ごと並べる）: 補う点ごとではなく、道具の組み合わせ（対案）を丸ごと並べる。同じ所を対案の数だけ書き、どの点で対案が分かれるかが埋もれる。振替の件では、補う点ごとに出して初めて「教室ごとに予約の担当を決めておく」という選択肢が出た。

#### 4. 崩れやすい時点で、確かめ方を問う

選択肢（組を含む）ごとに、満たすべき条件の確かめ方を、作った日ではなく、崩れやすい時点で問う。時点は次の五つである。

| 時点 | 問うこと |
| --- | --- |
| 時を進める | 一週間後、三か月後、一年後に、確かめ方に答えられるか |
| 人を抜く | 片方が二週間いない時、片方が忙しい月に、確かめ方に答えられるか |
| 置き場所を見比べる | 同じ事実が二か所以上にある時（相手の仕組みと、こちらの記録）、どちらかだけが変わることはあるか |
| 外を変える | 相手の決まり、使っている道具、端末が変わった時に、何が黙って間違うか |
| 作ったものを止める | 作ったものが止まった時に、どの条件が満たされなくなるか |

崩れやすさは、選択肢そのものではなく、選択肢を組み立てる情報の流れの要素が持つ。そのため、時点は、要素ごとに、要素の種類から選び、要素ごとに一度だけ問う。選択肢は、自分の要素の答えを受け継ぐ。

| 情報の流れの要素 | 効く時点 |
| --- | --- |
| 人が渡す受け渡し（担い手がいる） | 人を抜く。きっかけが習慣に依る時（ついで、決まった日、覚えていて）は、時を進めるも |
| 自動で渡す受け渡し（作ったもの、あり物の通知） | 作ったものを止める（作ったものの時）、外を変える |
| 当てにする事実（相手の仕組みが見せるもの、相手の決まり、あり物の振る舞い） | 外を変える |
| 置き場所のうち、同じ情報の二か所目（写し） | 置き場所を見比べる |
| 置き場所のうち、家族の決めごと（担当等） | 人を抜く |

一緒に選ばないと成り立たない組は、組の中の置き場所どうしにも、置き場所を見比べるを問う。

答えられない時は、きっかけを強めるか、決まった日に見比べる受け渡しを足すか、崩れやすさとして払うものに書く。

問うてみて、崩れの元が手段ではなく条件の側にあると分かることがある。全ての条件を満たしても言い分が崩れる日が作れた時、一文の述語が確かめ方より緩い時、確かめ方が本当の記録と一致するかまで問うていない時である。この時は、[何が成り立てばよいか](what-must-hold.md)層へ返し、条件を答え直す（返し方は[閉じた層への差し戻し](README.md#閉じた層への差し戻し)）。手段に合わせて条件を緩めない。

- 揃えば満たした: 全ての選択肢の要素について、種類から効く時点で確かめ方を問い、答えられない所の扱いが決まっている。組の中の置き場所どうしも見比べている。
- 外れている時: 作った日の姿だけで判定する。振替の件では、ホワイトボードの道を「二人が毎朝見るなら満たす」と判定し、見る習慣に頼る所を判定の外に出した。
- 外れている時（条件を手段に寄せる）: 選びたい選択肢が満たせない条件を、条件の側で緩める。例: 夫が教室のアプリを見られない選択肢を選びたくて、「二人のどちらも」を「妻が」に変える。

#### 5. 得るもの・払うものを出す

時間を共通の軸にし、時間にできないものを決まった軸で並べる。全てを時間に換算しない。換算すると、頭に残る負担や作る楽しみが消えるか、根拠の無い換算になる。

| 側 | 軸 | 中身 |
| --- | --- | --- |
| 得るもの | 手間が減る | どの操作の何分が、年に何回減るか |
| 得るもの | 得たいもの | なぜ作るか層の、作ることで得たいもの（作る楽しみ、学び等）のどれを満たすか |
| 得るもの | 変化に強くなる | どの当てにする事実が変わっても、崩れなくなるか |
| 払うもの | 作る時間 | 部品ごとの三点（楽観・最も確か・悲観）。利用者の過去の見立てと実績で補正する |
| 払うもの | 続ける時間 | 受け渡しの手間×年の回数と、保守 |
| 払うもの | 崩れやすさ | きっかけの弱い受け渡し（覚えていて渡す、習慣に頼る、まれな道のついで）と、それが崩れた時に満たされなくなる条件 |
| 払うもの | 満たさない条件 | 満たさずに受け入れる条件（受け入れを選ぶ時） |
| 払うもの | お金 | 代金、外部サービスの費用 |

条件を満たすこと自体は、得るものに入れない。条件は全ての選択肢が満たすか、満たさないなら払うもの（満たさない条件）に出る。

作る時間、続ける時間、お金は、`propose-alternatives`に頼む（何のため: どの道で覆うかを選ぶために、道ごとの費用を出す）。受け取る時は、作る時間が部品ごとの三点で出ていて、描かれにくい部品（利用者の見分け、配置と設定、外部サービスとの連携、定期実行、失敗した時の扱い、データの修正の手段）を見ていて、利用者の過去の見立てと実績による補正の有無が書かれているかを見る。満たさなければ、何が足りないかを付けて頼み直す。

崩れやすさは、材料の費用のうち、きっかけの無い操作と忘れた時の損失と、決め方の4の答えから読む。手間が減ること（基準との差）、変化に強くなること、満たさない条件は、この層で出す。依った値は、層の記録に読み込む。

- 揃えば満たした: 選択肢（組）ごとに、値のある軸が全て書かれ、どの選択肢でも値の無い軸は、無いと一行で書かれている。作る時間は部品ごとの三点で、補正の有無が書かれている。
- 外れている時: 一つの軸だけで比べる。例: 「継ぎ目が少ない」「作る時間が短い」。例: 「作る時間 約16時間」。内訳も幅も補正の有無も無い。

### 止める時

全ての補う点に選択肢が揃い、新しい切り口を使っても、足りない点を満たす新しい選択肢が出なくなり、全ての選択肢が情報の流れと八つの軸で書けた時に止める。

### この決め方の限界

一般には、解決策の候補を広く出して評価し、システム分析では情報の流れ（外部の実体、データの置き場、処理と流れ）で現状と案を描く。この層の情報の流れは、それを家族の暮らしの規模に縮めたものである。

個人の企画では、候補を探すのがウェブ上の情報と利用者の知っている道具に限られ、同じ立場の人に聞いて回ることはできない。候補の事実のうち、確かめること自体が規約・安全に触れるもの（ログインが要るページの自動取得等）は、動かして確かめられない。作る時間の補正は、利用者の過去の一、二件に依る。

## 解き方の選定

### 何を決めるか

補う点（組）ごとに選んだ選択肢（作らない、満たさずに受け入れる、を含む）と、決め手である。

決め手は、選んだものと次点の選択肢を分けた境目として書く。その境目で、何を得て、何を払い、利用者がどちらを重く見たか。作る選択肢を選ぶ時は、その得るものが手間・変化への強さなのか、作ることで得たいものなのかを分ける。選び直す条件は、この境目の得るもの・払うもの・当てにする事実が変わった時である。

後ろでは、次のように使われる。

- どこまで作るか層・どう作るか層が、選んだ選択肢の作る所を受け取る
- 家族が、選んだ選択肢の受け渡し（担い手ときっかけ）のとおりに運用する。作らない時は全てを
- 後で選び直す時に、比べ直さずに、決め手の境目を読んで、何が変わったかだけを見る

### 決め方

#### 1. 決め手が依る事実を確かめる

選ぶ前に、境目になりそうな所が、確かめていない当てにする事実に依っていないかを見る。依っていれば、選ぶ前に確かめる。確かめられない時は、その事実の両側で選定を書き、どちらになったかで分かれることを、選び直す条件にする。

確かめる先は、事実の種類で分ける。

| 事実 | 確かめる先 |
| --- | --- |
| 利用者しか持たない事実（自分の教室のアプリに何が出るか） | 利用者に、認識合わせで問う |
| 出典を読めば分かる、あり物の事実（規約、上限、今も使えるか） | `propose-alternatives`に、その事実を確かめるためと言って頼む。既にある候補の事実で足りれば、それを読む |
| 動かさないと分からない事実 | 頼む先のskillを、まだ吟味していない。確かめられない事実として、両側で書く |

例として、振替の件で一覧を作る組を取るかの境目は、教室のアプリが振替の残りと期限を表示するかに依る。三つとも表示するなら、一覧を作る組が買うのは、三つを一度に見られることと作る楽しみ（小さい）だけになり、表示しないなら、手で数える残り回数の取り違えを防ぐことが加わる。

- 揃えば満たした: 決め手の境目が依る事実が全て確かめられているか、確かめられない事実の両側で選定が書かれている。
- 外れている時: 確かめていない事実を、確かめたかのように扱って選ぶ。決め手が推測に乗る。

#### 2. 補う点（組）ごとに、境目で比べて選ぶ

対案を丸ごと比べず、補う点（組）ごとに、選択肢を並べ、得るもの・払うものの差で選ぶ。選ぶのは利用者である。assistantは、境目（選んだものと次点の差）を、八つの軸で並べて示す。重み付けを代わりに決めない。

例として、振替の件で選ぶ所は、二つに縮む。

| 選ぶ所 | 得るもの | 払うもの |
| --- | --- | --- |
| 一覧を作る組（フォーム、表計算、script） | 予定作り（年約1時間）が記録（年約10分）に減る。三つのアプリを一度に見られる。期限を表示しない教室の残り回数を、手で数えなくて済む。作る楽しみ（小さい） | 作る時間: 補正後16〜62時間（最も確かで32時間）。保守: 年約2時間。崩れやすさ: 予約の写し、scriptが止まる |
| 週に一度の見比べ（独立） | 夫が連絡したまれな欠席と、scriptが止まった時を拾う | 続ける時間: 年約4時間。崩れやすさ: 繰り返しの予定で起こさないと、習慣に頼る |

- 揃えば満たした: 全ての補う点（組）で、選んだものと次点の境目が八つの軸で示され、利用者が選んでいる。
- 外れている時: assistantが重み付けて「この道が最もよい」と言い切る。選ぶのは利用者である。
- 外れている時: 作る組を、得るものの合計が大きいことだけで選ぶ。得るものの多くが安い補う点（予定作りの手間）から来ていて、高い点（作る時間）が買うものは小さい、という境目が見えない。

#### 3. 作る理由を切り分ける

作る選択肢を選んだ時は、その得るものを、手間・変化への強さと、作ることで得たいものに分けて書く。作ることで得たいもの（作る楽しみ等）のために作るなら、決め手にそう書く。

例として、振替の件で教室のアプリが三つとも振替の残りと期限を表示するなら、一覧を作る組を選ぶことは、約32時間を、一度に見られることと作る楽しみに払うことになる。それを選ぶのは利用者の自由であり、レールはそうと分かるように書く。

- 揃えば満たした: 作る選択肢ごとに、作る理由が手間・変化への強さか、作ることで得たいものかが分かれて書かれている。
- 外れている時: 作る楽しみで選んだのに、手間が減ることを主な理由として書く。後で選び直す時に、手間が減らなかったと気づいても、選び直す理由にならないことが見えない。

#### 4. 選び直す条件を書く

決め手の境目から、選び直す条件を書く。境目の得るもの・払うもの、当てにする事実のどれが変わったら、選び直すか。

例として、振替の件では、教室のアプリの表示が変わる、手で数えて間違えた、三つのアプリを見比べる手間が思ったより重い、のどれかが起きた時である。

- 揃えば満たした: 選んだ全ての補う点（組）に、境目から出した選び直す条件がある。
- 外れている時: 「足りなくなったら移る」のように、何が起きたら足りないのかが無い。

### 止める時

全ての補う点（組）で選択肢が選ばれ、決め手が境目として書かれ、作る理由が切り分けられ、選び直す条件が書けた時に止める。

### この決め方の限界

一般には、評価の軸に重みを付けて点数で比べることもある（重み付けの評価表）。この層では点数にしない。点数にすると、利用者がどの差を重く見たかが合計の中に消え、選び直す時に境目を読めないためである。

個人の企画では、利用者が自分で使い、自分で作るため、作る楽しみと手間の重み付けが一人の中で混ざりやすい。作る理由の切り分けは、その混ざりを見えるようにするためにある。
