# grow-product-ideas

プロダクトのアイデアを、作る価値と作る範囲から検討し、あとは作るだけの状態まで育てる場所。
詰めれば決まることはここで引き受け、頭の中で寝かせる余白を着想に残す。

## 使い始める

このリポジトリを開いたエージェントに、次のように渡す。最初から要求や仕様を揃える必要はない。

> アイデアを育てて。〔作りたいもの・使いたい場面を自由に記述〕。
> 自分で進められるところは進め切り、私にしか決められないことを最後にまとめて。

エージェントは [grow-idea](skills/grow-idea/SKILL.md) に従い、`ideas/YYYYMMDD-slug/` を作る。原文、調査、判断、設計、再開位置をそこへ残す。途中からなら「`ideas/対象ディレクトリ/` を続けて」でよい。明示的に skill を読ませる場合は「`skills/grow-idea/SKILL.md` を読んで進めて」と伝える。

普段の担当は **sol**。決定済み内容の反映は **terra**、前提や対案が行き詰まったときの相談は **astra** を想定する。これはこの場所での役割の指定であり、モデル間の性能比較や自動切替設定ではない。

## 何ができる場所か

| 区間 | 決めること | 次へ進める根拠 |
| --- | --- | --- |
| 要求を明らかにする | 誰が、いつ、何を達成したいか | 現状と望む変化を具体的に説明できる |
| 調べて代案を比べる | 自作・既製品・組み合わせ・現状維持、広げる案・絞る案 | 必須要求と費用・手間・弱点で比較できる |
| 到達点を決める | 何をどこまで実現すれば運用へ移れるか | 対象範囲、非目標、観測できる合格条件がある |
| 体験と構造を揃える | 体験・画面・データ・処理の整合 | 実際の操作例を一貫して追える |
| 引き渡す | 実装者が何を読み、どこから作るか | 重要な未決事項がなく、残る負債が明示されている |

自作しない結論も成果。需要が未検証でも、仮説として扱い、作って学ぶ範囲と撤退条件を決められる。市場での成功を保証する場所ではない。

## 読む場所

- [進め方](playbook/workflow.md)：工程、分岐、再開、完了条件の正本。
- [具体的な考え方](playbook/methods.md)：調査、費用比較、体験と構造の詰め方。
- [判断と記録の型](templates/idea/)：アイデアごとの成果物。
- [品質の確認](skills/review-idea/SKILL.md)：完成判定と差し戻し。
- [レールの改善](skills/improve-rail/SKILL.md)：実案件で見つけた問題をフローへ戻す。
- [背景と初版の設計判断](playbook/rationale.md)：共有された決定と、今回選んだ運用方針。
- [初版の検証・残る確認事項](evaluations/initial-review.md)：確認できた範囲と限界。

## Skill の入口

正本は `skills/`。`AGENTS.md` から読めるので、skill 一覧への登録に依存せず進められる。
Codex の自動発見用に `.agents/skills/` から三つの skill へ相対シンボリックリンクを配置している。一覧に反映されない場合はセッションを開き直すか、上記のファイルを直接指定する。配置仕様は [公式ドキュメント](https://learn.chatgpt.com/docs/build-skills) を参照。モデル設定や個人の plugin 設定はこのリポジトリで変更しない。

## 初版を育てる

実際のアイデアはまだ投入されていない。[検証用の例](evaluations/scenarios.md) は架空の条件であり、ユーザーの案件や需要調査として数えない。
一件を回したら、ユーザーが考え直した箇所、設計の手戻り、不要だった工程を記録する。改善はその失敗を再現できる例と一緒に行い、文書量やチェック項目の数を成果指標にしない。
